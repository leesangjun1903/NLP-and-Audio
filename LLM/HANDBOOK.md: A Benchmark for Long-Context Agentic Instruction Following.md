# HANDBOOK.md: A Benchmark for Long-Context Agentic Instruction Following

---

## 1. Executive Summary (10문장 이내)

HANDBOOK.md는 LLM 기반 에이전트가 기업 핸드북과 같은 **장문의 정책 문서**를 얼마나 충실히 따르는지를 측정하는 벤치마크다. 65개의 태스크는 금융, HR, 보험, 물류, 의료청구 5개 도메인의 가상 기업 환경에서 구성되며, 에이전트는 20~124페이지 분량의 SOP 문서를 기반으로 업무를 수행해야 한다. 평가는 LLM 판단 없이 Python 기반의 결정론적 루브릭(824개 기준)으로 진행된다. 루브릭은 필수 행동(EXPECTED-OUTPUT)과 금지 행동(INCORRECT-BEHAVIOR) 두 측면을 모두 검증한다. 오염 방지를 위해 각 태스크는 기본 핸드북을 변형(mutation)한 고유한 정책 문서를 사용한다. 30개 모델 설정을 평가한 결과, 최고 성능인 Claude Fable 5조차 strict pass@1 36.2%에 그쳤다. 주요 실패 패턴은 ① 환경 내 즉각적 요청이 정책을 무력화, ② 검증 실행 후 결과 무시, ③ 검증 생략 후 성공 가정, ④ 실제와 무관한 준수 보고 등 4가지로 수렴된다. 이 벤치마크는 현재 에이전트가 장문 정책 문서를 **지속적 권위(persistent authority)**로 취급하지 못함을 실증한다. 저자들은 단기적 해법으로 정책을 결정론적 도구 호출 가드로 컴파일하는 방식을 권고한다. 모든 태스크, 환경, 평가 하네스는 공개 배포된다.

### 1-1. 연구의 목적과 필요성

| 항목 | 내용 |
|------|------|
| **문제 인식** | 실제 배포 환경에서 LLM 에이전트는 시스템 프롬프트, 정책 파일, 스킬 문서 등 장문의 standing instruction 하에 작동하지만, 기존 벤치마크는 이를 직접 평가하지 않음 |
| **기존 한계** | 기존 벤치마크(SWE-bench, WebArena, τ-bench 등)는 태스크 **완료 여부**만 측정하며, 정책이 짧고 태스크 간 공유됨으로써 반복 노출로 정책을 암기할 수 있음 |
| **필요성** | 기업 핸드북처럼 장문·고유한 정책 문서가 에이전트의 모든 행동을 실제로 제약하는지 측정하는 도구가 없음 |
| **목적** | 에이전트가 장문 정책을 **올바르게 읽고, 장시간 유지하며, 금지 행동을 실제로 거부**하는 능력을 측정하는 현실적 벤치마크 제공 |

## 2-1. 해결 문제 / 제안 방법 / 모델 구조 / 성능 향상 및 한계 상세 설명

### 해결하고자 하는 문제

LLM 에이전트가 컨텍스트에 배치된 장문 정책 문서를 **장시간 멀티툴 작업에 걸쳐 일관되게 준수**하는지 측정하는 벤치마크의 부재. 특히:

- **Rule–request 분리 문제**: 요청 자체에는 정책이 명시되지 않고, 정책은 별도 문서에 존재
- **장기 호라이즌 문제**: 평균 17 reasoning step, 30 tool call에 걸쳐 규칙을 유지해야 함
- **금지 행동 평가 부재**: 기존 벤치마크는 완료 여부만 측정하며, 에이전트가 해서는 안 될 행동을 했는지 평가하지 않음

### 제안하는 방법 (수식 포함)

**주요 평가 지표**:

$$\text{pass@1} = \frac{1}{|T|} \sum_{t \in T} \mathbf{1}\left[\prod_{c \in R_t} \text{verify}_c(\hat{s}_t) = 1\right]$$

여기서:
- $T$: 전체 태스크 집합 ($|T| = 65$)
- $R_t$: 태스크 $t$의 루브릭 기준 집합
- $\hat{s}_t$: 에이전트 실행 후 최종 환경 상태
- $\text{verify}_c$: 기준 $c$의 Python 검증 함수 ($\{0, 1\}$ 반환)
- 각 태스크는 4회 실행하여 평균

**완화 지표 (Near-miss)**:

$$\text{pass@1}(N-1) = \frac{1}{|T|} \sum_{t \in T} \mathbf{1}\left[\sum_{c \in R_t} \mathbf{1}[\text{verify}_c(\hat{s}_t) = 0] \leq 1\right]$$

즉, 기준 1개까지의 실패를 허용.

**루브릭 구성**:
- EXPECTED-OUTPUT 기준: 592개 (71.8%) — 필수 행동 발생 여부 확인
- INCORRECT-BEHAVIOR 기준: 232개 (28.2%) — 금지 행동 미발생 여부 확인 (정확한 카운트 불변식 포함)

**정책 변형(Mutation) 설계**:

$$H_t = \mu(H_{\text{base}(t)}, \delta_t)$$

여기서 $H_{\text{base}(t)}$는 기본 핸드북, $\delta_t$는 태스크별 변형 연산(승인 권한, 금액 임계값, 유효기간 등 변경), $H_t$는 태스크 $t$의 고유 핸드북.

### 모델 구조 (벤치마크 환경 구조)

```
[Agent]
   │
   ▼ (OpenHands SDK)
[MCP Endpoint] ─── 6 MCP Servers × 82 Tools
```

## 4. 저자 보고 결과 vs. 분석자 해석 분리

### 4-1. 연구 주제

**저자 보고**: "LLM 에이전트가 장문 정책 문서를 얼마나 충실히 따르는지 측정하는 벤치마크 HANDBOOK.md를 제시한다." (p.1, Abstract)

**분석자 해석**: 이 연구는 단순한 벤치마크 제시를 넘어, AI 에이전트의 **규범적 추론(normative reasoning)** 능력의 근본적 한계를 폭로하는 연구다. 특히 에이전트가 정책 문서를 '참조 문서'가 아닌 '지속적 제약'으로 처리하지 못한다는 점을 체계적으로 증명한다.

---

### 4-2. 방법 (수식 포함)

**저자 보고**: 
- Strict pass@1: 모든 루브릭 기준 통과 시에만 성공 (p.5, §3.5)
- N−1 완화: 기준 1개 실패 허용 (p.5, §3.5)
- 태스크당 4회 실행 후 평균

$$\text{pass@1}_{\text{strict}} = \frac{1}{|T|} \sum_{t} \mathbb{E}_{\text{run}}\left[\prod_{c} \text{verify}_c\right]$$

**분석자 해석**: 
- 4회 실행 평균은 분산 추정에 통계적으로 부족할 수 있음 (65 × 4 = 260 trial, 95% CI 계산 필요)
- N−1 지표는 실패의 **심각도(severity)**를 측정하지 못함. 금지 행동 1회 위반과 형식 오류 1회는 동등하게 처리되지만 실제 위험도는 전혀 다름

---

### 4-3. 결과

**저자 보고**:
- Claude Fable 5 (adaptive/max): 36.2% (Table 2, p.7)
- 대부분 프론티어 모델 < 25%
- N−1 완화 시 ~2배 향상 (p.7, §5.3)
- reasoning effort 증가가 항상 유익하지 않음 (p.6, §5.1)

**분석자 해석**:
- 36.2%는 단순 수치 이상의 의미를 가짐: **2/3 이상의 태스크에서 실제 업무 배포 시 통제 위반이 발생**한다는 의미
- N−1 완화 시 점수 급등(21.9% → ~46%)은 현재 모델이 "거의 맞지만 핵심 제어 하나를 놓치는" 패턴이 지배적임을 시사
- reasoning effort의 역효과(GLM 5.2: −2.7%)는 extended thinking이 때로 올바른 판단을 overrule하는 **reasoning-induced hallucination**의 증거

**구성**: (a) 핸드북 길이 분포, (b) 루브릭 기준 수 분포, (c) 도메인별 기준 수

### Figure 3 (p.9): Strict vs N−1 grading 비교

**구성**: 20개 모델의 Strict pass@1(원형)과 pass@1(N−1)(다이아몬드) 병렬 비교

**해석**:
- 대부분의 모델에서 N−1 완화 시 **2배 내외의 점수 향상** 발생.
- Opus 4.8: 21.9% → ~46%, Opus 4.8 default: 18.9% → ~41%
- 하위 모델(Grok 4.3, Nemotron 3 Ultra)은 두 지표 간 차이가 거의 없음 → **거의 모든 기준을 실패**하는 상황

**분석자 해석**: 상위 모델의 큰 Strict/N−1 격차는 희망적이기도 하고 우려스럽기도 함. 희망적인 면: 에이전트가 대부분의 작업을 올바르게 수행. 우려스러운 면: 놓치는 단 한 개의 기준이 **바로 그 작업에서 가장 중요한 제어(approval gate, hold condition)**인 경우가 많음. N−1 완화가 모델 순위를 변경(Opus 4.8 default가 GPT-5.5 추월)한다는 점도 주목할 만함.

### 8-1. 모델의 일반화 성능 향상 가능성 (중점 분석)

논문에서 직접 제시된 일반화 관련 내용:

1. **오염 저항성**: 정책 변형(mutation) 설계로 기본 핸드북 암기가 성능에 도움이 되지 않도록 구조화
2. **포맷 다양성**: PDF/Word/HTML 세 형식 사용으로 파싱 일반화 요구
3. **도메인 다양성**: 5개 도메인, 10개 회사로 도메인 특화 해법 방지

**분석자의 일반화 향상 가능성 분석**:

현재 모델의 일반화를 저해하는 핵심 병목:

$$\text{Generalization Gap} = \text{Score}(N-1) - \text{Score}(\text{strict}) \approx 2\times$$

이 격차는 단순히 "거의 맞는" 수준이 아니라, **정책 준수의 마지막 단계(critical control)에서의 일반화 실패**를 의미.

**일반화 향상을 위한 기술적 방향**:

**(a) 정책 구조화된 표현 학습**:

$$\mathcal{L}_{\text{policy}} = -\sum_{(s,a,r)} r \cdot \log \pi_\theta(a|s, H_t)$$

정책 문서 $H_t$를 구조화된 제약으로 파싱하고 이를 액션 선택에 명시적으로 통합하는 학습.

**(b) Constraint-conditioned RLHF**:
모델이 규칙 위반 시 음의 보상을 받는 강화학습; HANDBOOK.md의 컨테이너 환경이 이를 위한 자연스러운 RL 환경 제공.

**(c) Retrieval-Augmented Policy Checking**:
각 액션 전 관련 정책 조항을 능동적으로 검색·확인하는 RAG 패턴; "read once, apply forever" 패러다임 탈피.

**(d) Scratchpad-based Compliance Tracking**:
장기 호라이즌에 걸쳐 정책 체크리스트를 외부 메모리에 유지하는 전략.

**Claude Fable 5의 성능 급등(+14%p)**: 논문은 원인을 설명하지 않지만, 이는 특정 training signal(정책 준수 특화 RLHF 또는 더 긴 컨텍스트 학습)이 실질적 일반화 향상을 가져올 수 있음을 시사. 단, 단일 데이터포인트로 결론 도출에는 한계가 있음 ⚠️.

### 해당 논문이 앞으로의 연구에 미치는 영향

**1. 벤치마크 표준화 영향**:
- 정책 준수 평가에서 **"두 방향 루브릭"(required + prohibited)**이 표준이 되어야 한다는 주장을 실증적으로 지지
- 태스크별 고유 정책(mutation)이 오염 방지의 표준 방법론으로 확산될 가능성

**2. 시스템 설계에의 영향**:
- 에이전트 아키텍처에서 **외부 결정론적 정책 가드** 레이어를 필수 구성요소로 보는 시각 강화 ([19], [34]의 방향)
- "정책을 컨텍스트에 배치하고 에이전트를 신뢰"하는 현재 패러다임의 위험성에 대한 경각심 제공

**3. 훈련 방향에의 영향**:
- RLHF/RLAIF에서 정책 준수를 보상 신호로 사용하는 연구 촉진
- HANDBOOK.md 환경을 RL 훈련 환경으로 활용하는 연구 가능

### 앞으로 연구 시 고려할 점

**방법론적 고려**:

1. **통계적 검증력 강화**: 65개 태스크는 서브그룹 분석에 부족. 도메인별·길이별 분석을 위해 태스크 수 확장 필요

$$n_{\min} = \frac{(z_{\alpha/2} + z_\beta)^2 \cdot 2\sigma^2}{\delta^2}$$

유의수준 0.05, 검정력 0.8, 효과 크기 0.1 기준으로 최소 수백 개의 태스크가 필요

2. **다국어 확장**: 비영어 정책 문서(일본어 컴플라이언스 문서, 독일어 DSGVO 지침 등)로의 확장

3. **동적 정책 업데이트**: 실제 환경에서는 정책이 실행 중 업데이트될 수 있음; 이를 평가하는 태스크 필요

4. **인간 baseline 구축**: 도메인 전문가의 성능 측정으로 모델-인간 격차 정량화

5. **실패 패턴의 정량화**: 4가지 실패 패턴의 빈도를 자동으로 분류하는 분류기 개발

6. **다중 에이전트 환경**: 복수의 에이전트가 동일 정책 문서 하에 협업할 때의 정책 준수 평가

7. **정책 복잡도 지표화**: 섹션 간 의존성(§12 → §4 → §18), 조건부 규칙 수 등을 정량화하여 난이도 예측 모델 개발

$$\text{Complexity}(H) = \sum_{s_i \in H} \text{deps}(s_i) \times \text{conditions}(s_i)$$
