## 2. 연구의 목적과 필요성

### 2.1 저자가 해결하려는 문제

**저자 보고.** 연구의 출발점은 “모델만 좋아지면 에이전트도 자동으로 좋아지는가?”라는 문제입니다. 동일한 모델이라도 어떤 정보를 받는지, 작업을 어떻게 분해하는지, 다른 에이전트의 결과를 언제 전달받는지에 따라 실행 결과가 달라질 수 있으므로, 저자들은 모델과 하네스가 함께 발전하는 순환을 제시합니다〔p.3〕. 2607.15524v1

그 순환은 다음처럼 구분됩니다.

$$
\text{하네스 개선}
\;\longrightarrow\;
\text{더 좋은 실행 궤적 생성}
\;\longrightarrow\;
\text{모델 학습}
\;\longrightarrow\;
\text{다음 하네스 개선}
$$

**이 논문이 실제로 연구하는 범위는 앞부분, 즉 고정 모델 아래에서 하네스를 개선하는 단계입니다.** 제공업체의 범용 실행 체계를 계속 수정하는 것은 비용이 크기 때문에, 사용자가 과제별 프롬프트만 바꾸어 적용할 수 있는 경량 방법을 목표로 합니다〔pp.3–4〕. 2607.15524v1

또한 여러 후보 하네스를 생성하고 모두 실행하는 탐색은 비쌉니다. RHI는 이를 줄이기 위해 많은 후보를 동시에 비교하는 대신 **현재 버전과 직전 버전의 국소 비교**를 사용합니다〔pp.5–7〕. 2607.15524v1 2607.15524v1

> **용어 — 국소 비교:** 가능한 모든 대안을 평가하는 대신, 현재 상태 주변의 제한된 대안만 비교하는 방식. 비용은 줄지만 더 좋은 다른 경로를 놓칠 수 있습니다.

**제 해석.** 이 연구의 핵심 가치는 새로운 신경망 구조가 아니라, **“어떤 정보를 누구에게 언제 전달할지”를 최적화 가능한 연구 대상으로 명시했다는 점**입니다. 다만 최종 산출물이 좋아졌다는 사실과 그 산출물을 만든 실행 궤적이 좋은 학습 데이터라는 사실은 별개의 주장입니다. 논문은 주로 산출물을 평가하므로, 후자의 학습 가치는 직접 검증되지 않았습니다〔평가 범위: p.11; 후속 계획: p.28〕. 2607.15524v1 2607.15524v1

### 2.2 모델 구조: 신경망이 아니라 실행 구조를 바꾼다

RHI에서는 코딩 에이전트의 기반 모델, 평가자, 하네스 최적화 모델을 고정하고 **텍스트로 표현한 하네스만 반복 수정**합니다. 따라서 논문 제목의 “self-improvement”는 모델 가중치나 최적화 프로그램 자체의 자기수정을 뜻하지 않습니다〔p.26〕. 2607.15524v1

| 구성요소 | 원문에서의 의미 | 이해를 위한 예시 |
|---|---|---|
| **Role** | 각 에이전트의 전문 역할 | 데이터 담당, 모델 구현 담당, 검증 담당 |
| **Instruction** | 해당 에이전트가 수행할 행동 | 데이터 분할을 점검하고 누출 위험을 보고 |
| **Contract** | 에이전트가 다른 에이전트나 총괄자에게 전달할 정보의 규약 | 결과 파일 경로, 수치, 근거, 검증 상태를 정해진 필드로 반환 |
| **Hop** | 호출·전달·재검토의 순서와 제어 흐름 | 모델 구현 → 독립 검증 → 실패한 담당자만 재호출 |
| **보조 규칙** | 종료 조건, 실패 시 대안, 재호출 조건 | 필수 파일이 없으면 종료하지 않음 |

구성의 출처는 Figures 3–4와 §3.3입니다〔pp.9–10〕. 2607.15524v1 2607.15524v1

> **용어 — 오케스트레이터(orchestrator):** 여러 에이전트의 일을 배분하고 결과를 통합하는 총괄 에이전트.  
> **Contract:** 여기서는 법적 계약이 아니라 “무슨 정보를 어떤 형식으로 넘길지”를 정한 인터페이스 규약.  
> **Hop:** 여기서는 신경망 층 수가 아니라 작업 흐름의 호출·전달 단계.

**구체적 사례.** 부록 B에서는 `src/profile.py`가 필요한데 `src/profiler.py`를 생성한 문제, 보고서의 처리속도 배율과 JSON 수치가 맞지 않는 문제를 발견한 뒤, 정확한 파일 경로 관리와 독립적인 수치 검토 역할을 하네스에 추가합니다〔pp.40, 43〕. 이는 추상적인 “더 잘 생각하라”보다 **실패 사례를 실행 규칙으로 바꾸는 방식**에 가깝습니다. 2607.15524v1 2607.15524v1

## 3. 제안 방법과 수식

### 3.1 원래의 목표: 다른 하네스보다 선호되는 결과를 생성하기

**저자 정의 — Equation 1, p.4.**

$$
H_x^\star \in \arg\max_{H\in\mathcal H} f_x(H),
$$

```math
f_x(H)=
\mathbb E_{\substack{
H'\sim\mu(\cdot\mid H'\neq H)\\
y\sim\mathcal A(H,x),\;y'\sim\mathcal A(H',x)
}}
\left[
\mathbf 1
\left\{
\mathcal L_{\text{eval}}(y,y';x_{\text{eval}})
=
y\succ y'
\right\}
\right].
```

**기호 설명:** $x$는 해결할 과제, $\mathcal H$는 가능한 하네스의 집합, $H$는 현재 후보, $H'$는 경쟁 후보입니다. $\mathcal A(H,x)$는 고정 모델을 사용하는 코딩 에이전트의 실행이며, $y,y'$는 생성된 코드 저장소입니다. $\mu$는 경쟁 하네스를 뽑는 기준 분포, $\mathcal L_{\text{eval}}$은 평가 모델, $x_{\text{eval}}$은 평가 기준을 담은 프롬프트입니다. $y\succ y'$는 평가자가 $y$를 더 선호한다는 뜻이고, $\mathbf1\{\cdot\}$는 조건이 참이면 1, 아니면 0입니다. 따라서 $f_x(H)$는 **기대 선호 승률**입니다. 무승부는 이 식에서 승리로 계산하지 않습니다. 2607.15524v1

> **용어 — 기대값:** 여러 번 실행했을 때 얻을 값의 확률적 평균.  
> **중요한 구분:** 여기서 승률은 코드의 정답률이나 실제 연구의 성공률과 동일하지 않습니다.

### 3.2 RHI의 단순화: 직전 하네스만 이기도록 비교하기

**저자 정의 — Equation 3, p.6.**

```math
\widetilde f_x^{(i)}(H)=
\mathbb E_{\substack{
y\sim\mathcal A(H,x)\\
y^-\sim\mathcal A(H_x^{(i-1)},x)
}}
\left[
\mathbf1
\left\{
\mathcal L_{\text{eval}}(y,y^-;x_{\text{eval}})
=
y\succ y^-
\right\}
\right].
```

**기호 설명:** $i$는 업데이트 차수, $H_x^{(i-1)}$는 과제 $x$의 직전 하네스, $y^-$는 그 하네스가 만든 산출물입니다. 나머지 기호는 앞과 같습니다.

이 식은 경쟁 상대를 전체 후보 집합에서 직전 버전 하나로 바꿉니다. **저자도 이것이 원래 전역 목적함수의 불편추정량이 아니라, 목적 자체를 국소 개선으로 바꾼 것이라고 명시합니다.** 2607.15524v1

> **용어 — 불편추정량:** 같은 추정을 반복했을 때 평균적으로 실제 목표값과 일치하는 추정량. 여기서는 저자들이 그런 성질을 주장하지 않습니다.

**계산 비용.** Table 1에서는 이전 산출물을 저장해 재사용한다는 가정 아래, RHI의 반복당 비용을 **새 에이전트 실행 1회 + 쌍별 평가 1회**, 즉 $\Theta(1)$로 표현합니다〔p.7〕. 2607.15524v1

**제 해석 — 비교주의.** 여기서 $\Theta(1)$은 **후보 집단 크기에 대해 호출 횟수가 상수**라는 뜻입니다. 전체 토큰 수나 실행 시간이 상수라는 뜻이 아니며, 하네스 수정 모델의 호출과 길어지는 피드백 이력도 이 간단한 비용식에 반영되지 않습니다. 또한 모든 후보를 서로 비교하는 방식의 $\Theta(m^2)$ 비용을, 점수 기반으로 후보를 평가하는 모든 기존 방법의 필수 비용으로 일반화해서는 안 됩니다〔Table 1의 정의 범위〕. 2607.15524v1

### 3.3 피드백 이력과 하네스 업데이트

**저자 정의 — Equations 4–5, p.8.**

```math
\mathcal D_x^{(i)}
=
\left\{
\mathcal L_{\text{eval}}
\left(
y_x^{(k)},y_x^{(k-1)};x_{\text{eval}}
\right)
\right\}_{k=1}^{i},
```

```math
H_x^{(i+1)}
=
\mathcal L_{\text{harness}}
\left(
H_x^{(i)},\mathcal D_x^{(i)}
\right).
```

**기호 설명:** $\mathcal D_x^{(i)}$는 $i$차까지 누적한 비교 이력, $k$는 과거 반복의 인덱스, $\mathcal L_{\text{harness}}$는 다음 하네스를 작성하는 LLM입니다. $y_x^{(k)}$는 $k$번째 하네스의 산출물입니다. 2607.15524v1

Algorithm 1의 종료 조건은 다음과 같습니다.

```math
s_i=
\frac1n\sum_{j=1}^{n}
\mathbf1
\left\{
y_j^{(i)}\succ y_j^{(i-1)}
\right\},
\qquad
s_i < \epsilon
\;\Rightarrow\;
\text{stop}.
```

**기호 설명:** $n$은 과제 수, $j$는 과제 인덱스, $s_i$는 직전 버전보다 좋아진 과제의 비율, $\epsilon$은 종료 임계값입니다. 즉 개별 과제가 아니라 **과제 집합의 개선 비율**로 종료를 판단하는 형태입니다〔Algorithm 1, p.8〕. 2607.15524v1

**구현상 중요한 보충.** 수식만 보면 승패 이력만 사용한다고 읽기 쉽지만, 부록 C의 실제 최적화 프롬프트에는 **과제 설명, 현재 저장소의 파일 발췌, 사전 점검 결과, 평가 이유, 반복된 결함 목록**도 들어갑니다. 따라서 실제 방법을 “승패 한 비트만으로 하네스를 개선한다”고 설명하면 부정확합니다〔pp.67–70〕. 2607.15524v1 2607.15524v1

또한 평가 프롬프트를 최적화 모델에게 직접 주지 않더라도, 그 기준으로 생성한 상세 피드백은 제공됩니다. 따라서 **평가 기준에 대한 간접 최적화는 계속 일어납니다**〔p.9〕. 2607.15524v1

### 3.4 “국소 개선이 전역적으로도 좋은가?”에 대한 이론

**저자 가정 — pp.7–8.**

```math
\Pr(H\succ H')
=
\sigma\!\left(u_x(H)-u_x(H')\right),
\qquad
\sigma(0)=\frac12.
```

**기호 설명:** $u_x(H)$는 하네스의 관측되지 않는 실제 효용, $\sigma$는 효용 차이를 승리 확률로 바꾸는 엄격히 증가하는 함수입니다.

이 가정과 경쟁 분포에 관한 조건이 성립하면, 직전 버전보다 **진짜 승리 확률이 $1/2$보다 큰** 수정은 효용을 증가시킨다는 논리입니다. 2607.15524v1

**제 해석.** 이는 조건부 정당화이지 일반적인 수렴 보장이 아닙니다. 실제 선호가 하나의 효용으로 정렬되지 않거나, 평가 기준 사이에 충돌이 있거나, 비교가 잡음에 민감하면 가정이 깨질 수 있습니다. 특히 **한 번 이겼다는 관측**은 **실제 승리 확률이 $1/2$를 넘는다는 증명**이 아닙니다.

> **용어 — 잠재 효용:** 직접 관찰되지는 않지만 선택이나 선호를 설명한다고 가정하는 점수.  
> **수렴 보장:** 반복을 계속했을 때 일정한 해 또는 최적해에 도달함을 수학적으로 보장하는 성질.

### 4.1 비용 수치를 읽을 때의 핵심 주의점

원문은 각 과제의 비용을 그 과제의 기본 `high` 실행 비용으로 나눈 뒤 평균합니다〔p.13〕. 2607.15524v1

```math
\bar c_m
=
\frac1n
\sum_{j=1}^{n}
\frac{c_{m,j}}{c_{\text{high},j}}.
```

**기호 설명:** $m$은 실행 설정, $c_{m,j}$는 그 설정의 과제 $j$ 실행 비용, $c_{\text{high},j}$는 해당 모델의 기본 `high` 비용, $\bar c_m$은 평균 정규화 비용입니다.

**따라서 비교 불가능하거나 제한되는 해석은 다음과 같습니다.**

| 수치 | 가능한 해석 | 불가능하거나 근거가 부족한 해석 |
|---|---|---|
| Opus-4.8의 4.15→1.69 | 같은 그림의 기준으로 최종 실행이 `ultracode`보다 저렴함 | RHI 탐색·평가·수정까지 포함해 총비용이 60% 감소함 |
| 모델별 정규화 비용 | 각 모델의 `high` 대비 상대적 사용량 | Sonnet의 2.38과 Opus의 1.69를 직접 비교해 어느 쪽이 달러 기준으로 저렴한지 판단 |
| 평균 정규화 비용의 비율 | 과제별 기준으로 정규화한 평균의 비율 | 전체 실제 청구액 합계의 비율과 동일하다고 판단 |
| 캐시 읽기·쓰기 수치 | 보고된 에이전트의 캐시 관련 사용량 변화 | 실제 GPU 메모리 점유량이나 내부 attention 구조가 같은 비율로 감소했다고 판단 |

**제 계산 — 전체 비용 해석의 예시.** Figure 7e의 Opus-4.8 수치에서 $H[0],H[1],H[2]$를 모두 새로 실행해야 한다고 가정하면, 코딩 실행 비용만 단순 합산해도 다음과 같습니다.

$$
1.35+1.85+1.69=4.89.
$$

이는 `ultracode` 한 번의 4.15보다 큽니다. 이 계산은 전체 실험 비용의 재현이 아니라, **최종 실행의 약 60% 절감을 단발 문제 해결의 종단 간 비용 절감으로 바꾸어 말할 수 없다는 점**을 보여줍니다〔입력 수치: Figure 7e, p.14〕. 2607.15524v1

> **용어 — 종단 간 비용:** 초기 후보 실행, 평가, 수정, 최종 결과 생성까지 필요한 모든 비용.  
> **캐시:** 이전 계산 결과를 저장해 재사용하는 장치. 논문의 캐시 지표는 내부 작동 원리를 직접 관측한 결과와 구분해야 합니다.

## 5. 정보이론적 가설: 무엇을 설명하며 무엇을 설명하지 못하는가?

### 5.1 저자가 제안한 목적함수

**저자 가설 — Equation 6, p.23.** 읽기 쉽게 원문의 구성요소 타입 기호 `hc`를 $c$로 축약하면 다음과 같습니다.

```math
J(g_i)
=
\sum_{c\in\mathcal C_{\text{ext}}}
\frac{1}{K_{Xi}^{c}}
\sum_{k=1}^{K_{Xi}^{c}}
I\!\left(z_{Xk}^{c,(i)};X\right)
-
\beta\,
\text{TC}
\left(
\left\{
z_{Xk}^{c,(i)}
:
c\in\mathcal C,\;
k\in[K_{Xi}^{c}]
\right\}
\mid X
\right).
```

**기호 설명**

- $X$는 과제 분포에서 뽑는 확률변수이고, $x$는 실제로 주어진 과제입니다.
- $g_i$는 $i$차 RHI가 과제를 하네스로 대응시키는 함수로, $H_x^{(i)}=g_i(x)$입니다.
- $\mathcal C=\{\text{role},\text{instruction},\text{contract},\text{hop}\}$는 구성요소 타입의 집합입니다.
- $\mathcal C_{\text{ext}}=\{\text{contract},\text{hop}\}$는 최적화 프롬프트가 특히 강조하는 타입입니다.
- $K_{Xi}^{c}$는 해당 타입의 구성요소 개수, $k$는 그 안의 인덱스이며, $[K]$는 $1,\ldots,K$를 뜻합니다.
- $z_{Xk}^{c,(i)}$는 구성요소 텍스트의 정규화 임베딩입니다.
- $I(\cdot;\cdot)$는 상호정보량, $\text{TC}(\cdot\mid X)$는 과제가 주어졌을 때 구성요소들의 조건부 총상관, $\beta>0$는 두 항의 상대적 가중치입니다. 2607.15524v1

> **용어 — 상호정보량:** 한 변수를 알 때 다른 변수에 대한 불확실성이 얼마나 줄어드는지 나타내는 양.  
> **총상관(total correlation):** 여러 변수가 서로 얼마나 통계적으로 의존하는지 측정하는 양.  
> **조건부:** 여기서는 “어떤 과제인지 이미 알고 있다”는 조건을 붙인다는 뜻.

직관적으로 첫 항은 **과제에 필요한 정보를 contract와 hop에 담으라**는 방향이고, 둘째 항은 **모든 구성요소가 같은 정보를 반복하지 말고 서로 다른 기능을 맡도록 하라**는 방향입니다〔pp.23–24〕. 2607.15524v1

**중요:** 저자들은 이 식으로 RHI를 직접 훈련하지 않았습니다. $\beta$를 조정하며 이 목적함수를 최대화한 실험도 제시하지 않으며, 관찰된 변화가 이 가설과 부합하는지를 분석합니다〔p.22〕. 2607.15524v1

### 5.2 실제로 측정한 것은 임베딩 기반 대리 지표다

과제와 하네스 텍스트를 임베딩한 뒤 10차원으로 축소하고, 다음 형태의 가우시안 근사 지표를 계산합니다〔p.24〕.

```math
\widehat I(c;\text{task})
=
-\frac12\sum_r\log(1-\rho_r^2).
```

**기호 설명:** $\widehat I$는 추정한 상호정보량, $\rho_r$는 구성요소 표현과 과제 표현 사이의 $r$번째 정준상관입니다. $\log$는 자연로그입니다. 2607.15524v1

> **용어 — PCA:** 많은 숫자 차원을 주요 변동 방향 몇 개로 줄이는 방법.  
> **정준상관:** 두 벡터 집합 사이에서 가장 강하게 함께 변하는 선형 조합의 상관관계.  
> **가우시안 근사:** 데이터가 정규분포 형태에 가깝다고 가정하여 계산을 단순화하는 것.  
> **nat:** 자연로그를 사용해 표현한 정보량 단위.

총상관 추정은 다음과 같습니다〔Equation 7, p.25〕.

```math
\widehat{\text{TC}}
=
\frac12
\left[
\sum_{c\in\mathcal C}\log\det S_c
-
\log\det S
\right].
```

**기호 설명:** $S$는 전체 구성요소 표현의 공분산 행렬, $S_c$는 타입 $c$에 해당하는 대각 블록, $\det$는 행렬식입니다. 원문은 공분산 추정을 안정화하고, 과제별 평균을 제거한 잔차에 같은 계산을 적용하여 조건부 의존성의 대리 지표를 만듭니다. 2607.15524v1

> **용어 — 공분산:** 여러 수치가 함께 변하는 정도.  
> **잔차:** 평균이나 설명 가능한 부분을 제거하고 남은 차이.

### 5.3 해석상 가장 중요한 한계

**첫째, Table 3의 조건부 지표에서 hop은 실질적으로 빠집니다.** 저자의 각주에 따르면 hop은 과제·반복마다 하나의 벡터여서 에이전트 간에 동일하고, 과제별 평균을 제거하면 사라집니다. 따라서 조건부 추정은 사실상 다음을 측정합니다〔p.25, 각주 2〕.

$$
\text{TC}
\left(
\text{role},\text{instruction},\text{contract}
\mid \text{task}
\right).
$$

즉 이를 **네 구성요소 모두의 조건부 중복 감소가 직접 확인된 결과**라고 읽으면 안 됩니다. 2607.15524v1

**둘째, 높은 과제 정보량은 일반화와 동일하지 않습니다.** 제 해석으로는, 과제 문장이나 특정 파일명을 더 많이 복사하는 것만으로도 과제별 구분 가능성은 높아질 수 있습니다. 따라서 상호정보량 증가가 재사용 가능한 문제 해결 원리의 학습을 의미하려면, 새로운 과제에서 별도 검증해야 합니다.

**셋째, 이론을 엄밀하게 만들려면 확률변수 정의를 보완해야 합니다.** 원문의 $H_x^{(i)}=g_i(x)$를 결정론적 함수로 해석하고 정렬된 구성요소도 $X$만으로 결정된다고 가정하면, $X$를 조건으로 한 남은 확률적 의존성은 사라집니다. 실제로는 생성 난수, 피드백, 에이전트별 구성요소 선택 등이 들어가므로, 이를 포함한 확률모형이 필요합니다. 이는 **현재 가설을 이론으로 발전시키기 위한 제 지적**이지, 관찰된 성능 개선이 없었다는 주장은 아닙니다〔관련 정의: pp.22–25〕. 2607.15524v1 2607.15524v1

## 6. 통계적으로 취약한 부분과 비교 불가능한 수치

### 6.1 평가자 반복과 독립적인 문제 해결 반복은 다르다

**저자 보고.** 주요 결과는 30개 과제에 대해 평가를 세 seed로 반복한 평균과 표준편차입니다. Sonnet·Opus-4.8은 두 평가자 설정, Opus-4.7은 여섯 설정을 사용합니다〔p.13〕. 2607.15524v1

**취약점.** 같은 산출물에 대한 평가를 여러 번 반복한 것은 새로운 독립 과제를 추가한 것과 다릅니다. 따라서 “30과제 × 2평가자 × 3seed = 180개의 독립 성능 표본”으로 취급해서는 안 됩니다. 문서의 이 설명만으로는 코딩 실행과 전체 RHI 탐색 경로의 확률적 변동이 얼마나 독립 반복되었는지도 명확하지 않습니다.

> **용어 — 표준편차:** 반복 결과가 얼마나 흩어져 있는지 나타내는 값.  
> **신뢰구간:** 추정하려는 평균이나 효과의 불확실성을 나타내는 구간. 표준편차 막대와 같지 않습니다.

### 6.2 “20/30승”과 왕관 표시는 통계적 유의성 검정이 아니다

Figure 1의 왕관은 평균 승수가 19.5를 넘으면 붙이는 표시입니다. 유의확률 기준이라는 설명은 없습니다〔p.1〕. 2607.15524v1

**제 계산 — 설명용 가정:** 정확히 독립적인 30개 과제에서 20승 10패이고 무승부가 없다고 가정하면, 승률 50%에 대한 양측 이항검정의 유의확률은 약 $0.0987$입니다. **이는 논문의 실제 유의확률이 아니라**, 과반 승리만으로 통계적으로 확실한 우위라고 결론 내릴 수 없음을 보여주는 예입니다.

### 6.3 평가자가 전체 실행의 진실성을 검증한 것은 아니다

평가자는 저장소 전체가 아니라 지정된 산출물과 제한된 파일 내용을 봅니다. 긴 파일은 잘릴 수 있으며, 부록 E의 예시는 바이너리 파일을 생략하고 그림의 통합 상태를 경로와 발췌문으로 추정하도록 합니다〔p.11; pp.75, 87〕. 2607.15524v1 2607.15524v1 2607.15524v1

**취약점.** 보고서가 더 명확하거나 파일이 더 잘 정리된 효과와, 실제 실험이 올바르게 수행된 효과가 섞일 수 있습니다. 독립적인 코드 재실행, 숨겨진 테스트, 인간 전문가 검증을 병행해야 이 차이를 구분할 수 있습니다.

또한 평가 프롬프트 예시에는 A/B가 어떤 실행 유형인지 표시됩니다. 실행 유형을 숨긴 평가나 순서 교환 검증이 충분했는지는 문서에서 확인하기 어렵습니다〔p.74〕. 2607.15524v1

### 6.4 과제별 적응 결과를 미관측 과제 일반화로 바꿔 읽으면 안 된다

RHI는 **평가 대상 과제 자체에서** 하네스를 개선하는 설정입니다. 이는 연구 설정상 허용된 적응이지 그 자체로 부정한 평가라는 뜻은 아닙니다. 다만 새로운 과제를 전혀 보지 않은 상태에서 잘 작동하는 능력과는 다르며, 비교 기준선에도 같은 적응·피드백·탐색 예산을 허용해야 합니다〔pp.12, 26〕. 2607.15524v1 2607.15524v1

### 6.5 인과 설명과 관찰적 설명이 혼재한다

원문의 구성요소 분석은 주로 텍스트 임베딩의 이동·군집·유사도를 추적합니다. 최적화 프롬프트 자체가 contract와 hop을 강조하므로, 해당 부분이 크게 바뀌었다는 관찰은 그 부분이 성능 향상의 원인이라는 증명과 다릅니다. 저자도 상관적 분석임을 인정합니다〔p.19〕. 2607.15524v1

필요한 통제는 **contract 고정, hop 고정, 이력 제거, 무작위 피드백, 동일 예산의 산출물 직접 수정** 등입니다. 부록 A의 단일·멀티에이전트 비교는 유용하지만 이러한 통제를 모두 대신하지는 못합니다.

> **용어 — 제거 실험(ablation):** 한 요소만 제거하거나 고정하여 그 요소의 기여를 분리하는 실험.  
> **인과관계:** 어떤 요소를 실제로 바꾸었기 때문에 결과가 달라졌다는 관계.

### 6.6 정보량 추정의 불확실성이 충분히 제시되지 않았다

Tables 2–3은 두 임베딩 모델과 편향 보정 유무에서 같은 방향의 추세를 보여주지만, 해당 추세의 신뢰구간이나 유의성 검정을 제시하지 않습니다. 과제 수가 30개이고 한 과제에서 여러 구성요소가 파생되므로, 구성요소 행들을 모두 독립 표본처럼 보는 추정은 주의해야 합니다〔pp.24–25〕. 2607.15524v1 2607.15524v1

## 8. 일반화 성능 향상 가능성: 네 가지를 구분해야 한다

| 일반화와 관련된 질문 | RHI 원문에서 확인되는 범위 | 판정 |
|---|---|---|
| **같은 과제를 다시 수행할 때 더 잘하는가?** | 과제별 하네스를 반복 개선하고 같은 과제의 산출물을 비교〔Figures 5–7〕 | 주된 실증 대상 |
| **한 과제에서 개선한 하네스가 새로운 과제에도 좋은가?** | 별도 보류 과제에 하네스를 고정해 적용하는 전이 실험이 제시되지 않음〔§5–6의 평가 구성〕 | 미검증 |
| **같은 하네스를 다른 기반 모델에 옮겨도 좋은가?** | 세 기반 모델에서 각각 RHI를 적용하지만, 이는 동일 하네스의 교차 모델 전이와 다름〔p.12〕 | 방법의 적용 범위는 보이나 하네스 전이는 미검증 |
| **RHI 궤적으로 학습한 모델이 새 과제를 더 잘 푸는가?** | 모델 가중치를 업데이트하지 않으며, 이 단계는 후속 연구 계획〔pp.26–28〕 | 원문에서는 미검증 |

위 구분의 근거는 모델별 과제 최적화 설정과 연구 범위입니다. 2607.15524v1 2607.15524v1 2607.15524v1

> **용어 — 보류 과제(held-out task):** 하네스 수정이나 모델 학습에 사용하지 않고 마지막 평가용으로 남겨둔 과제.  
> **전이(transfer):** 한 환경에서 얻은 개선이 다른 과제·도메인·모델에서도 도움이 되는 현상.  
> **분포 외 일반화:** 학습·최적화 때와 다른 종류의 입력에서도 성능을 유지하는 능력.

**제 해석 — 향상 가능성이 있는 이유.** 파일 간 일관성 검증, 근거가 있는 정보 전달, 실패한 부분만 재호출하는 규칙은 특정 과제의 정답보다 재사용 가능한 절차에 가깝습니다. 이런 절차를 추출하거나 학습시키면 일반화에 도움이 될 가능성이 있습니다. 그러나 부록의 개선에는 특정 파일명, 특정 과거 오류, 특정 수치도 많이 들어갑니다. 따라서 현재 하네스에는 **재사용 가능한 절차와 해당 과제에만 맞춘 수정이 섞여 있습니다**〔예시: pp.40–46〕. 2607.15524v1 2607.15524v1

가장 중요한 후속 질문은 “하네스가 얼마나 상세해졌는가?”가 아니라 **“새 과제에서도 유효한 규칙이 무엇이며, 이를 과제 고유의 수정과 어떻게 분리할 것인가?”**입니다.

#### A. *Rethinking the Evaluation of Harness Evolution for Agents* — Wang 외, 2026

이 연구는 **동일한 피드백과 실행 예산**에서 단순 재시도와 하네스 진화를 비교합니다. 테스트가 제공되는 조건의 Table 2에서는 평균 `pass@1`이 병렬 샘플링 86.0%, Harness Evolution 75.8%이며, 별도 과제 분할을 사용하는 Table 3에서는 초기 하네스 67.7%에서 68.3%로 개선 폭이 작습니다〔pp.6–7〕. [arXiv](https://arxiv.org/pdf/2607.12227v1)

**제 해석.** 이는 RHI를 직접 반증하는 실험은 아닙니다. 다만 **최종 실행만 비교해서는 추가 탐색의 효과와 하네스 자체의 효과를 분리하기 어렵다**는 매우 직접적인 경고입니다. RHI 후속 연구의 필수 기준선은 동일 예산의 병렬 재시도와 산출물 순차 수정입니다.

**제 해석.** RHI보다 일반화를 직접 묻는 평가 설계입니다. 특히 **같은 과제의 성공·실패를 대비하고 여러 과제에서 반복되는 결함을 모은다**는 접근은, 우연한 한 번의 실패를 하네스의 일반적 결함으로 오인하는 위험을 줄이려는 시도입니다. 다만 실행 테스트 기반 점수이므로 RHI의 LLM 선호 승률과 수치상 우열 비교는 불가능합니다.

#### C. *Recursive Self-Improvement through Multi-Agent Self-Supervision* — Lee 외, 2026: MASS

2026년 10월 8일 공개된 MASS는 하네스·워크플로 최적화와 자기생성 궤적의 지도 미세조정을 번갈아 수행합니다. 이는 RHI가 남긴 **실행 궤적을 모델에 내재화하는 단계**를 직접 다루는 이후 연구입니다〔Figure 1; pp.1–3〕. [arXiv](https://arxiv.org/abs/2610.12176)

> **내재화:** 외부 프롬프트에 적어 주어야 했던 행동을 모델이 학습 후 스스로 수행하도록 만드는 것.

## 11. 결론과 후속 연구 방향

### 11.1 저자들이 제시한 시사점과 후속 계획

저자들의 결론은 **하네스를 단순한 추론 보조 장치가 아니라 미래 모델의 학습 데이터를 만드는 장치로 보아야 한다**는 것입니다. 이에 따라 과제별 사용자 하네스를 경량으로 개선하는 RHI를 제안하고, 다음 단계에서는 그 실행 궤적을 기반 모델에 효과적으로 학습시키겠다고 밝힙니다〔pp.27–28〕. 2607.15524v1

또한 구성요소별 개선을 더 잘 유도하도록 **평가 피드백의 품질과 구체성을 높이는 것**을 후속 방향으로 제시합니다〔p.21〕. 2607.15524v1

### 11.2 제가 제안하는 우선 후속 연구

**첫 번째 우선순위는 일반화와 적응을 분리한 평가입니다.** 하네스 수정용 과제, 수정 채택용 검증 과제, 마지막 평가용 과제를 분리해야 합니다. 특히 “하네스를 고정해 새 과제에 적용”하는 조건과 “새 과제에서도 제한된 예산으로 다시 RHI 수행”하는 조건을 따로 보고해야 합니다. 전자는 규칙의 재사용 능력, 후자는 적응 알고리즘의 효율을 평가합니다.

**두 번째는 동일 총예산의 인과 실험입니다.** 기반 모델, 추론 설정, 실행 환경, 평가 정보량을 고정하고 RHI를 병렬 재시도·산출물 직접 수정·초기 하네스만 제공하는 조건과 비교해야 합니다. 이때 최종 비용뿐 아니라 하네스 수정 모델과 평가자 비용까지 포함해야 합니다. 또한 contract와 hop을 각각 고정하거나 바꾸어, 정보 전달 개선의 실제 기여를 분리해야 합니다.

**세 번째는 검증된 실행 궤적의 학습 가치 측정입니다.** 다음 식은 원문 수식이 아니라, 이를 검증하기 위한 **후속 연구용 학습 목표의 예시**입니다.

```math
\theta_{\text{next}}
=
\arg\min_\theta
\left[
-
\mathbb E_{(x,\tau)\sim\mathcal D_{\text{verified}}}
\sum_t
m_t
\log p_\theta(\tau_t\mid x,\tau_{ < t})
\right].
```

**기호 설명:** $\theta$는 학습할 모델 가중치, $\mathcal D_{\text{verified}}$는 독립 검증을 통과한 과제·실행 궤적 데이터, $x$는 과제, $\tau_t$는 궤적의 $t$번째 토큰, $\tau_{<t}$는 그 이전 토큰입니다. $m_t$는 학습 대상으로 삼는 토큰에만 손실을 적용하는 마스크이고, $p_\theta$는 모델의 다음 토큰 확률입니다.

이 실험에서는 초기 하네스 궤적, RHI 궤적, 동일 예산의 단일 에이전트 궤적을 **학습 토큰 수와 학습 계산량까지 맞춰** 비교해야 합니다. 평가 때 개선된 하네스를 다시 제공하지 않는 조건도 필요합니다. 그래야 외부 지시문을 더 잘 따르는 효과와 모델이 절차를 학습한 효과를 분리할 수 있습니다.

> **용어 — 마스크:** 일부 토큰은 학습에 포함하고 다른 토큰은 제외하는 표시.  
> **망각:** 새 능력을 학습한 뒤 기존 능력의 성능이 떨어지는 현상. 일반화 개선 주장에는 기존 능력 보존 평가도 필요합니다.

**네 번째는 정보이론적 가설을 실제 최적화 실험으로 바꾸는 것입니다.** 과제 문장 복사만으로 정보량을 높이지 못하도록 통제하고, 같은 과제의 여러 독립 실행에서 구성요소를 정렬해 측정해야 합니다. 또한 중복을 줄이는 것이 필요한 공통 지식이나 교차 검증까지 제거하지 않는지 확인해야 합니다. 목표는 “모든 의존성을 없애기”가 아니라 **유용한 공유는 남기고 불필요한 반복을 줄이기**여야 합니다.

### 최종 판단

**RHI는 고정 모델의 능력을 더 효과적으로 끌어내기 위한 과제별 실행 구조 최적화 방법으로서 의미가 있습니다.** 그러나 원문이 가장 잘 뒷받침하는 것은 제한된 벤치마크에서의 산출물 선호와 최종 실행 효율 개선이며, 모델 자체의 일반화 향상·전체 탐색 비용 절감·정보 흐름의 인과적 설명까지 확립한 것은 아닙니다〔Figures 5–8; pp.19, 25, 28〕. 2607.15524v1 2607.15524v1 2607.15524v1 2607.15524v1

후속 연구의 성공 기준은 **“이번 과제에서 더 높은 평가를 받았는가?”에서 “독립된 새 과제에서도, 같은 총예산으로, 기존 능력을 해치지 않으면서 더 잘하는가?”로 이동해야 합니다.**
