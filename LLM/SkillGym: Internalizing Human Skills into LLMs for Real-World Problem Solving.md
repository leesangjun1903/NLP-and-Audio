## 1. Executive summary

SkillGym의 목적은 사람이 작성한 작업 절차인 ‘스킬’을 단순한 실행 시점 참고자료가 아니라, 모델이 재사용 가능한 문제 해결 능력을 학습하는 훈련 자원으로 바꾸는 것입니다.  
이를 위해 스킬 문서를 분야별 과제 템플릿과 결합해 실행 환경을 만들고, 코드 기반 검증기와 스킬 제공·미제공 대조 실행으로 환경을 평가합니다.  
저자들은 12개 대분류·63개 소분류에 걸친 2,756개 환경과 8,364개 성공 실행 기록을 구축했지만, 엄격한 대조 조건을 만족하는 ‘스킬 의존적’ 환경은 전체의 39.2%입니다. **[pp. 3–6, Figure 2, Tables 1–2]** 2609.27717v2 2609.27717v2

성공 기록으로 Qwen3.5-35B-A3B를 지도 미세조정한 모델은 Claude Code에서 GDPval-AA v2 **+199 Elo**, Terminal-Bench 2.1 **+19.10퍼센트포인트**, SkillsBench의 스킬 제공·미제공 조건에서 각각 **+28.13·+14.68퍼센트포인트**를 기록했습니다.  
특히 스킬 없이 얻은 26.81%가 스킬을 제공한 기본 모델의 23.34%보다 높다는 결과는, 개선이 외부 지침을 그대로 따라 하는 능력에만 국한되지 않을 가능성을 보여줍니다.  
다만 이 결과는 새로운 스킬 계열·새 도메인·새 도구에 대한 엄격한 분포 외 일반화를 입증한 것은 아닙니다. **[pp. 7–9, Table 4; 마지막 문장은 해석]** 2609.27717v2 2609.27717v2

> **용어 풀이**  
> **지도 미세조정(SFT)**: 성공적인 답변이나 행동 기록을 따라 하도록 모델을 추가 학습하는 방법  
> **Elo**: 결과물을 두 개씩 비교한 승패·선호 결과로 산출하는 상대적 평가 점수  
> **퍼센트포인트(pp)**: 두 백분율의 단순 차이이며 상대적 증가율과는 다름  
> **일반화**: 학습한 사례와 다른 상황에서도 유용한 행동을 수행하는 능력

여러 교사의 기록을 섞으면 실행·스킬 활용 성능은 개선되지만, 전문 결과물 평가나 스킬 미제공 성능에서는 일부 역전이 나타나므로 ‘다양성이 언제나 유리하다’고 결론내릴 수 없습니다.  
또한 Codex 비교에서는 시스템 프롬프트까지 바뀌고 외부 공개 모델들은 평가 조건이 달라, 모든 개선량이나 모델 순위를 순수한 학습 효과로 해석할 수 없습니다.  
따라서 이 논문의 가장 설득력 있는 기여는 **검증 가능한 인간 워크플로 기반 훈련 자원과 동일 백본의 성능 개선**이며, 강화학습을 통한 추가 향상은 아직 결과가 아니라 후속 연구 계획입니다. **[p. 9, Table 5; pp. 21–22, Appendix D]** 2609.27717v2 2609.27717v2 2609.27717v2

## 2. 연구의 목적·필요성과 핵심 주장

### 2.1 무엇을 해결하려는가?

**[저자 보고]** 실제 업무의 어려움은 개별 질문에 답하거나 도구 한 번을 올바르게 호출하는 데 그치지 않습니다. 필요한 입력을 확인하고, 여러 도구를 순서대로 조정하며, 오류를 복구하고, 최종 산출물이 요구사항을 만족하는지 검증하는 **절차적 역량**이 필요합니다. 기존 스킬 문서는 이러한 지식을 담고 있지만, 실행할 때마다 검색·주입하는 방식에서는 검색 품질, 문맥 관리, 지시 준수에 성능이 좌우됩니다. **[p. 1, §1]** 2609.27717v2

> **용어 풀이 — 절차적 역량:** “무엇이 정답인가”를 아는 것을 넘어, “어떤 순서로 무엇을 확인하고 실행해야 하는가”를 수행하는 능력

저자들이 지적하는 핵심 간극은 두 가지입니다. 첫째, 일반적인 작업 지침을 **입력·목표·실행 조건이 있는 구체적인 문제**로 바꿔야 합니다. 둘째, 모델이 지침과 비슷한 말을 했는지가 아니라 **업무를 실제로 완료했는지**를 판정해야 합니다. SkillGym은 이 두 간극을 환경 구성과 결과 검증으로 연결합니다. **[p. 2, §1]** 2609.27717v2

**[해석]** 따라서 이 논문은 새로운 언어모델 구조나 새로운 최적화 알고리즘보다는, **사람의 작업 지식을 실행 가능한 학습 문제로 변환하는 데이터·환경 구성 방법론**에 가깝습니다.

## 3. 제안 방법과 수식

### 3.1 전체 흐름: 스킬 문서에서 학습 경험으로

논문의 구성은 다음과 같습니다.

**인간 작성 스킬 → 스킬 카드·분야별 템플릿 → 실행 환경 생성 → 실행 가능성·스킬 의존성 검증 → 여러 교사의 실행 기록 수집 → 성공 기록으로 모델 학습**

스킬은 온라인 등록소에서 소분류별로 인기도가 높은 항목을 선택합니다. 설명, 예제, 스크립트, 실행 제약을 **스킬 카드**로 정리하고, 별도로 사람이 만든 템플릿이 과제 구조·입력·파일 배치·검증 조건을 규정합니다. 즉, 완전히 제약 없는 자동 생성 방식은 아닙니다. **[p. 4, §3.1; Figure 2A]** 2609.27717v2

> **용어 풀이**  
> **스킬 카드:** 특정 스킬의 절차와 제약을 정리한 구조화된 설명  
> **템플릿:** 여러 과제를 만들 때 공통으로 사용하는 설계 틀  
> **검증기(verifier):** 결과물이나 실행 상태가 정해진 성공 조건을 만족하는지 검사하는 프로그램

**[해석]** 인간 설계 템플릿은 생성 품질을 안정화할 수 있는 장치이지만, 템플릿이 반복되면서 모델이 특정 파일 구조나 문제 형식에 과도하게 적응할 가능성도 있습니다. 논문은 이를 분리해 측정하지 않습니다.

### 3.2 실행 환경 생성 — 논문 식 (1)

```math
E_i
=
\text{Instantiate}\left(K_i,\mathcal{T}_{c(i)}\right)
=
\left(x_i,A_i,\rho_i,V_i\right)
```

**기호 설명**

| 기호 | 의미 |
|---|---|
| $i$ | 스킬·과제 인덱스 |
| $K_i$ | 스킬 $s_i$에 대응하는 스킬 카드 |
| $c(i)$ | 해당 스킬의 소분류 |
| $\mathcal{T}_{c(i)}$ | 그 소분류를 위한 수동 설계 템플릿 |
| $\text{Instantiate}$ | 카드와 템플릿을 구체적인 과제로 구현하는 과정 |
| $E_i$ | 생성된 실행 환경 |
| $x_i$ | 에이전트가 받는 과제 지시문 |
| $A_i$ | 입력 데이터와 파일 등의 자산 |
| $\rho_i$ | 파일 구조, 실행 환경, 의존성, 접근 인터페이스, 실행 제약 |
| $V_i$ | 코드 기반 결과 검증기 |

각 환경은 Docker로 패키징합니다. 검증기는 필요한 경우 입력 조작, 정답 복사, 요구사항 우회, 허위 결과물 제출 등을 막는 검사도 포함합니다. **[p. 4, §3.2, 식 (1)]** 2609.27717v2

> **용어 풀이 — Docker:** 프로그램과 필요한 실행 조건을 묶어, 비교적 일관된 환경에서 실행하도록 하는 컨테이너 기술

**중요한 한계:** 콘텐츠 생성 과제에서는 섹션, 길이, 형식, 키워드, 파일명 등이 검사 대상입니다. 저자들도 이것이 **검사기에 명시된 완료 조건**이지, 산출물의 전체적인 질에 대한 판단은 아니라고 명시합니다. 따라서 “검증 통과”를 곧바로 “전문가 수준의 좋은 결과물”로 읽으면 안 됩니다. **[p. 4, §3.1]** 2609.27717v2

### 3.3 실행 가능성과 스킬 의존성의 분리 — 논문 식 (2)

$$
\ell_i=
\begin{cases}
\text{Skill-Dep.},
&
F_i=1,\quad (r_i^+,r_i^-)=(1,0),
\\
\text{Verifier-Passed},
&
F_i=1,\quad (r_i^+,r_i^-)\neq(1,0),
\\
\text{Discarded},
&
F_i=0.
\end{cases}
$$

**기호 설명:** $\ell_i$는 환경의 최종 분류입니다. $F_i=1$은 설계·구조·전체 실행 검사와 유효한 검증기를 통과했다는 뜻입니다. $r_i^+$는 기준 에이전트에 스킬을 제공했을 때의 성공 여부, $r_i^-$는 제공하지 않았을 때의 성공 여부이며, 각각 1은 성공, 0은 실패입니다. **[p. 4, 식 (2)]** 2609.27717v2

이 구분은 중요합니다. **Verifier-Passed는 실패한 환경이 아니라**, 실행·검증은 가능하지만 특정 대조 조건을 충족하지 않은 환경입니다. 최종 자원은 Skill-Dep. 1,081개와 Verifier-Passed 1,675개로 구성됩니다. **[p. 6, §4.1]** 2609.27717v2

> **용어 풀이 — 대조 실행:** 같은 과제를 스킬 제공 여부처럼 한 조건을 달리하여 실행하고 차이를 관찰하는 방법

**[해석]** 이 절차는 스킬과 과제의 연결성을 점검하는 유용한 장치입니다. 그러나 “한 설정에서 스킬을 줬을 때만 성공했다”와 “그 스킬이 원리적으로 필수다”는 다른 주장입니다. 저자들도 이 차이를 인정합니다.

### 3.4 여러 실행 구성에서 기록 수집 — 논문 식 (3)

$$
\tau_i^{h,m}
\sim
\text{Rollout}(E_i,\pi_{h,m}),
\qquad
(h,m)\in P
$$

```math
r_i^{h,m}
=
V_i\left(z\left(\tau_i^{h,m}\right)\right)
\in\{0,1\}
```

**기호 설명:** $h$는 하네스, $m$은 교사 모델, $P$는 수집에 사용한 두 요소의 조합 집합입니다. $\pi_{h,m}$은 해당 조합으로 동작하는 에이전트이고, $\tau_i^{h,m}$은 행동·관찰 실행 기록입니다. $\text{Rollout}$은 환경에서 실제로 실행하는 과정, $z(\tau)$는 실행 후 산출물과 상태, $r_i^{h,m}$은 해당 실행의 검증 결과입니다. **[p. 5, §3.3, 식 (3)]** 2609.27717v2

> **용어 풀이**  
> **하네스(harness):** 모델의 도구 호출, 환경 접근, 메시지 처리 등을 실제로 실행하는 주변 프로그램  
> **궤적·실행 기록(trajectory):** 문제 해결 중 이어진 행동과 환경 응답의 기록  
> **정책(policy):** 현재까지의 정보를 보고 다음 행동을 선택하는 규칙 또는 모델

수집 구성과 성공 기록 수는 다음과 같습니다.

### 3.5 실제 학습은 SFT이며, 강화학습 결과는 없다

**[저자 보고]** 수집한 기록으로 Qwen3.5-35B-A3B의 언어모델 파라미터 전체를 업데이트하는 장문맥 SFT를 수행합니다. 학습에는 ms-swift의 Megatron 백엔드와 NVIDIA H200 GPU 16개를 사용합니다. **[p. 7, §5.1]** 2609.27717v2

논문은 구체적인 SFT 손실함수를 제시하지 않습니다. 다음은 작동 원리를 설명하기 위한 **해설용 수식이며, 논문의 원래 식이 아닙니다.**

```math
\mathcal{L}_{\text{SFT}}(\theta)
=
-
\sum_{\tau\in\mathcal{D}_{\text{succ}}}
\sum_{t=1}^{L_\tau}
w_{\tau,t}
\log p_\theta
\left(
y_{\tau,t}\mid y_{\tau, < t}
\right)
```

여기서 $\theta$는 학습할 모델 파라미터, $\mathcal{D}\_{\text{succ}}$는 성공 기록 집합, $L_\tau$는 기록의 토큰 길이, $y_{\tau,t}$는 해당 기록의 $t$번째 토큰, $y_{\tau, < t}$는 앞선 토큰들입니다. $w_{\tau,t}$는 해당 토큰을 어느 정도 학습에 반영할지 나타내는 가중치로, 학습 제외 토큰에는 0을 줄 수 있습니다.

**[미검증]** 실제 구현에서 도구 출력, 스킬 본문, 명시적 추론 문장을 어떤 비율과 마스킹으로 학습했는지는 첨부 문서만으로 확정할 수 없습니다. 위 수식의 가중치나 정규화 방식이 실제 구현과 같다고 주장하지 않습니다.

> **용어 풀이 — 마스킹:** 입력에는 포함하되, 특정 부분은 정답 예측 손실 계산에서 제외하는 처리

환경과 이진 보상은 강화학습에도 사용할 수 있지만, 저자들이 제시한 강화학습은 **장기 계획·도구 조정·실패 복구를 개선하기 위한 미래 계획**입니다. **[p. 9, §6]** 2609.27717v2

## 4. 모델 구조와 실험 설정

### 4.1 새 신경망 구조가 아니라 기존 백본의 후속 학습

**[논문에서 확인되는 내용]** SkillGym-Agent는 Qwen3.5-35B-A3B를 출발점으로 사용하는 학습된 모델이며, Figure 2는 신경망 내부 구조도가 아니라 **훈련 자원 구축 파이프라인**입니다. **[p. 3, Figure 2; p. 7, §5.1]** 2609.27717v2 2609.27717v2

**[외부 공식 자료로 보충]** Qwen 공식 모델 카드에 따르면 백본의 언어모델은 총 35B 파라미터 중 토큰당 약 3B를 활성화하며, 40개 층과 희소 MoE 구조를 사용합니다. 전문가 수는 256개이고, 활성화 구성은 라우팅 전문가 8개와 공유 전문가 1개입니다. 이는 **Qwen 백본의 구조**이지 SkillGym이 새로 제안한 구조가 아닙니다. [Hugging Face](https://huggingface.co/Qwen/Qwen3.5-35B-A3B)

> **용어 풀이**  
> **백본:** 추가 학습의 출발점이 되는 기본 모델  
> **MoE, Mixture of Experts:** 여러 신경망 모듈 중 일부를 선택해 계산하는 구조  
> **활성 파라미터:** 한 번의 토큰 처리에 실제로 사용되는 파라미터  
> **주의:** 여기서 ‘전문가’는 신경망 모듈이며, 인간이 작성한 개별 ‘스킬’과 일대일로 대응한다는 뜻이 아님

**[해석]** 따라서 “35B 모델이 32B 모델보다 좋다”는 비교만으로 계산 효율이나 학습 효율까지 판단할 수 없습니다. 총 파라미터 수, 활성 연산량, 학습 데이터와 추론 예산을 함께 비교해야 합니다.

### 5.3 교사 혼합은 일관된 이득이 아니다

**[저자 보고]** GPT-5.4와 Nex-N2-Pro를 혼합하면 가장 좋은 단일 교사 설정 대비 Terminal-Bench가 +6.74 pp 개선되지만, GDPval-AA는 98 Elo 감소합니다. DeepSeek와 GLM 혼합 역시 Terminal-Bench는 +2.24 pp 개선되지만 GDPval-AA는 51 Elo 감소합니다. **[pp. 8–9, Table 5]** 2609.27717v2

Claude Code에서는 전체 교사 혼합의 스킬 미제공 성공률 26.81%가 DeepSeek+GLM 혼합의 28.41%보다 낮습니다. 또한 단일 GLM 교사 설정의 GDPval-AA 1,212가 전체 교사 혼합의 1,173보다 높습니다. **[p. 9, Table 5]** 2609.27717v2

**[해석]** 이는 데이터 다양성의 이점이 목표 능력에 따라 달라진다는 뜻입니다. 일반화를 높이려면 단순히 교사를 늘리기보다, **어떤 경험을 얼마나 섞어야 특정 능력이 유지·개선되는지**를 연구해야 합니다.

> **시드:** 학습·생성 과정의 무작위성을 재현하기 위한 초기 설정

### 6.2 스킬 의존성 검사는 왜 반복 검증이 필요한가?

논문 식 (2)는 제공 시 성공·미제공 시 실패라는 관측으로 의존성을 분류하지만, 반복 횟수와 라벨의 통계적 안정성이 충분히 제시되지는 않습니다. **[p. 4, §3.2]** 2609.27717v2

다음은 이 한계를 설명하기 위한 **가상 확률 예시이며 논문의 실측 결과가 아닙니다.**

스킬 유무가 실제로 아무 효과도 없고, 두 조건의 성공확률이 동일하게 $p$이며 두 실행이 독립적이라고 가정하면,

$$
P(r_i^+=1,r_i^-=0)=p(1-p)
$$

입니다. 여기서 $P$는 확률, $p$는 공통 성공확률, $r_i^+$와 $r_i^-$는 각각 제공·미제공 실행 결과입니다. $p=0.5$라면 한 쌍에서 제공 성공·미제공 실패가 나타날 확률은 25%입니다.

**이것은 SkillGym 라벨의 실제 오분류율이 25%라는 뜻이 아닙니다.** 다만 적은 대조 실행만으로 ‘필수 스킬’을 판단하면 우연한 차이를 의존성으로 오인할 수 있다는 논리적 예시입니다. 반복 실행과 효과 크기의 불확실성 보고가 필요합니다.

### 6.3 검증 통과와 실제 시스템의 정당성은 다르다

부록의 결제 승인 동기화 예제는 독립적인 `trusted_runtime`에서 신규 데이터 전달, 재시작 후 동기화, 캐시 재사용 등을 검사합니다. 이는 에이전트가 수정할 수 있는 로컬 검사 스크립트만 믿는 것보다 강한 검증 설계입니다. **[p. 19, Appendix C.2]** 2609.27717v2

하지만 이 환경은 실제 운영용 Electric/PostgreSQL/Kubernetes 클러스터가 아니라 **로컬 Python 서비스로 필요한 동작을 재현한 환경**입니다. 또한 Kubernetes 준비 상태 검사 설정이 `exec` 형식인지 확인하지만, 그 안의 셸 명령 자체는 실행하지 않습니다. **[p. 19, Table 10 및 설명]** 2609.27717v2 2609.27717v2

**[해석]** 따라서 현실 업무의 중요한 구조를 반영한 것은 맞지만, 그 자체로 실제 운영 시스템에서의 안정성까지 검증했다고 볼 수는 없습니다.

### 6.4 재현성 자료의 범위

공식 GitHub 저장소는 환경 구축기, 데이터·실행 기록, 모델 체크포인트를 제공한다고 안내하면서도, **독립적인 전체 학습 코드와 모든 외부 벤치마크를 재현하는 단일 스크립트는 포함하지 않는다**고 명시합니다. 따라서 공개 자원의 존재와 완전한 종단간 재현 가능성은 구분해야 합니다. [GitHub](https://github.com/ECNU-ICALK/SkillGym)

> **증류(distillation):** 교사 모델의 행동이나 출력 분포를 학생 모델이 학습하는 방법  
> **특권 정보:** 학습 중 교사에게는 제공하지만 실제 배포 시 학생에게는 주지 않는 추가 정보  
> **구성요소 실험, ablation:** 특정 요소를 제거·변경해 그 요소의 기여를 비교하는 실험

### 8.3 이 논문이 앞으로의 연구에 미칠 영향

**[해석] 첫째, 연구의 초점이 ‘좋은 스킬 문서를 쓰는 법’에서 ‘좋은 학습 경험을 만드는 법’으로 확장됩니다.** SkillGym은 문서를 실행 가능한 과제와 검증기로 변환하는 구체적인 자원을 제공합니다. 이 자원은 SFT, 강화학습, 스킬 조건부 증류를 같은 환경에서 비교하는 기반이 될 수 있습니다. **[pp. 3–5, Figure 2]** 2609.27717v2 2609.27717v2

**[해석] 둘째, 일반화의 목표를 ‘외부 스킬을 전혀 안 보는 모델’로 한정할 필요가 없습니다.** SkillGym의 결과 자체가 내재화와 외부 지침의 보완성을 보여주며, Skill0.5는 일반 절차와 과제 특수 규칙을 분리하는 설계를 제시합니다. 중요한 질문은 “얼마나 많이 외웠는가”보다 **“기존 절차를 재사용하면서 새로운 규칙을 얼마나 정확하게 수용하는가”**입니다. 2609.27717v2 [arXiv](https://arxiv.org/html/2605.28424v1)

**[해석] 셋째, 앞으로는 데이터 다양성보다 다양성의 원인을 분리하는 실험이 중요합니다.** 교사 수, 하네스 수, 분야 수, 과제 난도, 기록 길이를 동시에 늘린 결과만으로는 어떤 요소가 일반화를 개선했는지 알 수 없습니다. SkillGym의 현재 교사 혼합 실험은 이 문제를 제기하지만 해결하지는 않습니다. **[p. 9, §5.3]** 2609.27717v2

## 10. 결론과 후속 연구 방향

### 10.1 저자가 제시한 시사점과 계획

**[저자 보고]** 인간이 작성한 스킬은 실행 시점의 외부 지침을 넘어, 검증 가능한 학습 환경과 장기 실행 경험의 원천이 될 수 있습니다. 이 경험으로 학습하면 외부 스킬 활용과 스킬 없는 수행 능력이 모두 개선될 수 있다는 것이 결론입니다. 저자들이 명시한 다음 단계는 환경의 검증기 기반 보상을 이용한 **강화학습으로 장기 계획, 도구 조정, 실패 복구를 개선하는 것**입니다. **[p. 9, §6]** 2609.27717v2

### 10.2 추가 제안: 일반화 성능을 검증하고 높이기 위한 우선순위

#### A. 과제 단위가 아니라 스킬 계열 단위로 평가를 분리해야 한다

**[제안]** 동일 스킬 문서, 템플릿, 원본 저장소에서 파생된 과제는 같은 집합에 묶고, 학습과 평가에 나뉘어 들어가지 않도록 해야 합니다. 이후 새로운 입력, 새로운 스킬 조합, 새로운 도메인, 새로운 도구 규약을 각각 별도로 평가해야 합니다.

이 설계의 목적은 비슷한 문제를 다시 푸는 능력과 **새로운 절차를 이해·조합하는 능력**을 구분하는 것입니다. 표면적인 이름·파일 경로·데이터 형식을 바꾼 평가도 함께 시행하면 형식 암기 가능성을 점검할 수 있습니다.

#### B. 내재화의 원인을 분리하는 학습 대조군이 필요하다

**[제안]** 같은 백본, 학습 토큰 수, 계산량, 평가 프롬프트 아래에서 다음 자원을 비교하는 것이 우선입니다.

| 대조 조건 | 확인하려는 질문 |
|---|---|
| 스킬 문서만 학습 | 실행 경험 없이 설명만 읽어도 같은 효과가 나는가? |
| 일반 에이전트 실행 기록 학습 | 인간 스킬에서 출발한 것이 특별히 중요한가? |
| Skill-Dep. 기록만 학습 | 경험적으로 스킬 의존적인 과제가 더 유용한가? |
| fallback 기록만 학습 | 일반적인 실행 훈련만으로도 개선을 설명할 수 있는가? |
| 두 집합 혼합 및 교사·하네스 교차 구성 | 어떤 다양성이 어느 능력을 개선하는가? |

이때 성공 기록 수뿐 아니라 **총 학습 토큰과 실제 계산량**을 맞추는 것이 중요합니다. 긴 기록 몇 개를 추가한 효과를 교사 다양성의 효과로 오해하지 않도록 하기 위한 설계입니다.

#### C. 안정적인 절차와 변하는 규칙을 다르게 취급해야 한다

**[제안]** 입력 검증, 실패 원인 진단, 작업 후 확인 같은 일반 절차는 내부 능력으로 학습하되, 새 API 규격이나 최신 업무 규칙은 외부 스킬로 받아들이도록 훈련하는 방향이 유망합니다. 이는 Skill0.5의 일반 스킬·특수 스킬 분리와 연결되는 연구 가설입니다. [arXiv](https://arxiv.org/html/2605.28424v1)

학습 중 일부 스킬 지침을 제거하는 실험, 교사에게만 스킬을 제공하는 증류, 새로운 규칙이 기존 규칙을 대체하는 평가를 함께 수행할 수 있습니다. SKILL0와 Skill-SD는 각각 도움의 점진적 제거와 교사–학생 정보 비대칭이라는 구체적인 비교 방법을 제공합니다. [arXiv](https://arxiv.org/abs/2604.02268)

#### D. 강화학습은 ‘검증기 점수 상승’과 ‘일반화’를 분리해 평가해야 한다

저자 계획을 확장한 **후속 연구용 목적함수 예시**는 다음과 같습니다. 이는 SkillGym에서 실제 사용한 학습식이 아닙니다.

```math
\mathcal{J}(\theta)
=
\mathbb{E}_{
E_i\sim\mathcal{D}_{\text{train}},
\,
\tau\sim\pi_\theta(\cdot\mid E_i)
}
\left[
V_i(z(\tau))
-
\lambda C(\tau)
\right]
```

$\mathcal{J}(\theta)$는 최대화할 학습 목표, $\mathcal{D}\_{\text{train}}$은 훈련 환경 분포, $\pi_\theta$는 학습 정책, $\tau$는 실행 기록입니다. $V_i(z(\tau))$는 성공 검증 결과, $C(\tau)$는 도구 호출·실행 시간 등으로 정의한 비용, $\lambda\geq0$는 성공과 비용 사이의 가중치입니다.

**[제안]** 훈련 검증기와 독립적인 숨겨진 테스트, 입력 무작위화, 사람이 평가한 결과물 품질을 함께 사용해야 합니다. 그래야 검증기의 허점을 이용한 점수 상승과 실제로 더 나은 절차 학습을 구분할 수 있습니다. 비용도 저장 로그 토큰이 아니라 실제 호출·시간·입출력 사용량으로 측정해야 합니다.

> **용어 풀이 — 보상 해킹:** 본래 의도한 문제 해결 대신 평가 규칙의 허점을 이용해 높은 보상을 얻는 현상

#### E. 반복 실행·반복 학습과 과제별 결과를 공개해야 한다

**[제안]** 스킬 의존성은 여러 번의 제공·미제공 실행 차이로 추정하고, 학습 모델도 여러 시드로 반복해야 합니다. 평가에서는 과제를 통계적 단위로 삼아 두 모델의 결과를 대응시키고, 전체 평균뿐 아니라 분야별·난도별·실행 길이별 성능과 불확실성을 보고하는 것이 필요합니다.

추가로 기존 능력의 유지, 새 스킬 학습 후 망각, 새로운 하네스에서의 성능을 측정해야 합니다. 그래야 ‘일반화 성능 향상’과 ‘특정 벤치마크에 대한 적응’을 구분할 수 있습니다.

### 최종 판단

**SkillGym은 인간의 절차적 지식을 검증 가능한 실행 경험으로 바꾸는 유용한 훈련 기반을 제시했고, 동일 백본에서 상당한 성능 개선을 보고했습니다. 그러나 현재 증거로 확인되는 것은 여러 평가 과제에서의 개선과 스킬 미제공 조건의 성능 유지이며, 새로운 도메인·스킬 계열·도구 규칙에 대한 강한 일반화까지 입증한 것은 아닙니다.**

일반화 관점에서 가장 가치 있는 다음 연구는 **데이터 양을 통제한 원인 분리 실험**, **스킬 계열·도메인 단위의 엄격한 제외 평가**, 그리고 **일반 절차의 내재화와 새로운 외부 규칙의 활용을 함께 학습하는 방법**입니다.
