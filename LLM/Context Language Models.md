## 2. 연구의 목적·필요성과 핵심 주장

### 2.1 해결하려는 문제는 “문맥 창이 작다”보다 넓다

**[저자 보고]** 기존 에이전트는 대화, 검색 결과, 코드 실행 결과를 계속 추가합니다. 컨텍스트가 길어지면 외부 프로그램이 일정 기준에 따라 요약하거나, 모델이 미리 정의된 압축·검색 도구를 호출하는 방식으로 관리합니다. 저자들은 이러한 방식이 **언제, 무엇을, 어떻게 보존하고 제거할지에 대한 선택을 제한한다**고 주장합니다〔pp.1, 3, 13〕. 2609.37725v1 2609.37725v1 2609.37725v1

> **용어 풀이 — 하네스(harness):** 모델 호출, 도구 실행, 작업 종료, 요약 시점 등을 관리하는 바깥쪽 실행 프로그램입니다. 모델 자체와는 구분됩니다.

논문이 겨냥하는 문제는 다음 세 가지입니다.

| 문제 | 기존 방식에서 발생하는 일 | CLM이 시도하는 해결 |
|---|---|---|
| 정확한 정보 보존 | 요약 과정에서 문자열·숫자·중간 결과가 누락되거나 변형될 수 있습니다. | 필요한 부분은 원문 그대로 유지하고 불필요한 부분만 삭제합니다. |
| 국소적인 상태 갱신 | 일부 정보만 바꾸려 해도 전체 상태를 다시 생성해야 할 수 있습니다. | 파일의 특정 부분만 제자리에서 수정합니다. |
| 장기 작업의 계산 비용 | 컨텍스트가 누적되고, 중간 수정은 캐시 재사용까지 깨뜨립니다. | 컨텍스트 선택과 캐시 비용을 함께 고려하는 관리 전략을 학습합니다. |

**[해석]** 중요한 관점 전환은 **입력 용량을 늘리는 것**과 **다음 판단에 필요한 상태를 잘 구성하는 것**을 구분한 데 있습니다. 다만 관련 없는 정보가 판단을 방해한다는 일반적 문제와, CLM의 특정 편집 방식이 그 문제를 해결한다는 실험적 주장은 별개입니다. 외부 연구인 *Lost in the Middle*도 긴 입력의 어느 위치에 관련 정보가 놓이는지에 따라 성능이 달라짐을 보고했지만, 그것이 곧 CLM의 효과에 대한 직접 증거는 아닙니다〔외부 논문 p.1〕. ## 3. 제안 방법과 모델 구조: 수식 중심 설명

### 3.1 핵심 정의: 추가만 가능한 기록에서 수정 가능한 상태로

**[저자 보고]** 일반 언어모델의 컨텍스트 변화는 다음과 같습니다〔p.4, 식 1〕.

$$
c_{t+1}=c_t\oplus f_\theta^{\text{LM}}(c_t)
$$

기호의 의미는 다음과 같습니다. $c_t$는 $t$번째 호출의 컨텍스트, $\theta$는 모델 가중치, $f_\theta^{\text{LM}}(c_t)$는 모델이 새로 생성한 출력, $\oplus$는 기존 기록 뒤에 출력을 연결하는 연산입니다.

CLM은 이를 다음과 같이 일반화합니다〔p.4, 식 2〕.

$$
c_{t+1}=f_\theta^{\text{CLM}}(c_t)
$$

여기서 $f_\theta^{\text{CLM}}$은 **모델이 제어하는 컨텍스트 변환**입니다. 기존 정보를 남기는 것뿐 아니라 삭제·대체·압축하거나 재사용 가능한 편집 함수를 정의하는 행동을 포함합니다. 나머지 기호는 앞 식과 같습니다. 2609.37725v1

**[해석]** 두 번째 식은 새로운 신경망의 순전파 수식이라기보다 **모델과 도구를 포함한 시스템의 상태 전이 정의**입니다. 실제 구현에서는 기존 언어모델이 편집 명령을 생성하고, 실행 환경이 파일을 수정하며, 그 결과가 다음 입력이 됩니다. 따라서 “모델이 다음 컨텍스트 전체를 매번 처음부터 생성한다”거나 “기존의 토큰 생성 방식을 폐기했다”는 뜻은 아닙니다. 2609.37725v1

> **용어 풀이 — 상태 전이:** 현재의 작업 상태가 다음 단계의 작업 상태로 바뀌는 규칙입니다.  
> **용어 풀이 — 순전파:** 신경망이 입력을 받아 출력을 계산하는 과정입니다.

### 3.2 실제 구조: 기존 LLM + 컨텍스트 파일 + 동기화

**[저자 보고]** 구현의 흐름은 다음과 같습니다〔p.4〕.

**기존 LLM → Bash를 통한 파일 편집 → 실시간 컨텍스트 파일 갱신 → 다음 LLM 호출에 동기화**

모델은 시스템 프롬프트로 파일 경로를 전달받습니다. 파일을 수정하지 않으면 기존처럼 새 출력을 뒤에 붙이며, 수정하면 그 내용이 다음 호출의 입력으로 사용됩니다. 여러 에이전트는 각각의 컨텍스트 파일을 가질 수 있고, 파일 생성·삭제를 이용해 하위 에이전트를 시작하거나 종료할 수 있습니다. 2609.37725v1

> **용어 풀이 — Bash:** 명령과 스크립트를 실행하는 셸입니다. 여기서는 텍스트 파일을 검색·수정하거나 Python 코드를 실행하는 통로입니다.  
> **용어 풀이 — 하위 에이전트(subagent):** 큰 작업의 일부를 맡는 별도 모델 실행 주체입니다.

Figure 3에는 이러한 구조가 실제로 만들어낸 행동이 제시됩니다. 모델은 진행 상황 표를 제자리에서 갱신하고, `notes`라는 내부 메모용 역할 표기를 만들며, 반복문으로 불필요한 검색 결과를 지우고, `compact_turns`라는 함수를 정의해 재사용했습니다. 이는 **관측된 실행 사례**이지, 각 행동이 성능 향상을 얼마나 유발했는지 분리한 실험은 아닙니다〔p.5, Figure 3〕. 2609.37725v1

**[해석]** 이 구조의 신규성은 “파일을 사용한다” 자체보다는 **현재 모델 입력을 파일과 직접 연결하고, 그 변환 방법을 모델의 선택 대상으로 만든 것**에 있습니다. 또한 하네스가 완전히 사라지는 것은 아닙니다. 동기화, 예산 경고, 재시도 등은 여전히 실행 환경이 담당합니다〔pp.19, 22〕. 2609.37725v1 2609.37725v1

**외부 메모리와의 구분도 중요합니다.** CLM의 컨텍스트 파일은 다음 모델 호출에 직접 들어갈 내용을 지정합니다. 다른 파일은 필요할 때 읽어오는 외부 저장소가 될 수 있습니다. 따라서 “파일로 저장했다”는 사실만으로 컨텍스트 관리와 장기 기억을 동일시할 수 없습니다〔p.14〕. 2609.37725v1

### 3.3 자연어 지침을 통한 학습과 지침 자체의 최적화

**[저자 보고]** 모델 가중치를 바꾸지 않고 관리 지침 $s$를 제공하는 경우는 다음과 같습니다〔p.5, 식 4〕.

$$
c_{t+1}=f_\theta^{\text{CLM}}(c_t;s)
$$

$s$는 자연어 지침 또는 관리 절차를 적은 스킬 문서입니다. $c_t$, $\theta$, $f_\theta^{\text{CLM}}$은 앞과 같으며, 이 단계에서는 $\theta$를 고정합니다. 2609.37725v1

> **용어 풀이 — 인컨텍스트 학습:** 모델 가중치를 업데이트하지 않고 입력에 제공한 지침·예시·경험을 이용해 행동을 바꾸는 것입니다.  
> **용어 풀이 — 스킬 문서:** “언제 압축하고 무엇을 보존할지” 같은 재사용 가능한 작업 절차를 자연어로 적은 문서입니다.

지침 자체를 최적화하는 목표는 다음과 같습니다〔p.6, 식 5〕.

$$
s^*=
\underset{s}{\text{arg max}}\;
\mathbb{E}_{x\sim\mathcal{D}}
\left[R\bigl(\tau(x;s)\bigr)\right]
$$

$x$는 과제 사례, $\mathcal{D}$는 과제 분포, $\tau(x;s)$는 지침 $s$로 수행한 전체 실행 기록, $R$은 실행의 보상, $s^*$는 기대 보상이 가장 큰 지침입니다.

실제로는 학습 사례의 실행 기록을 읽은 제안 모델이 새 지침을 만들고, 개발 집합에서 후보를 평가한 뒤 다음 지침을 선택합니다. 최종 지침의 시험 집합 평가는 선택 절차와 분리합니다〔pp.6, 23〕. 2609.37725v1 2609.37725v1

> **용어 풀이 — 실행 궤적(trajectory), 롤아웃(rollout):** 한 문제를 풀기 위해 모델이 생성한 응답, 도구 호출, 관측 결과 등을 시간순으로 묶은 실행 기록입니다.  
> **용어 풀이 — 개발 집합과 시험 집합:** 개발 집합은 후보 선택에 사용하고, 시험 집합은 선택이 끝난 뒤 성능을 확인하는 데 사용합니다.

**[해석]** 이 실험은 “유용한 관리 절차를 텍스트로 학습할 수 있다”는 근거입니다. 그러나 과제별로 최적화한 문서가 다른 과제에도 그대로 통한다는 결론은 별도 실험이 필요합니다.

### 3.4 강화학습: 성공한 실행 사이에서만 효율을 보상

**[저자 보고]** 컨텍스트를 수정하면 마지막 기록만으로 과거 모델 호출의 입력을 복원할 수 없을 수 있습니다. 따라서 학습에서는 각 생성 구간을 **그 구간이 실제로 생성되었던 입력**과 연결하고, 전체 실행의 결과를 해당 구간들에 전달하는 stepwise GRPO를 사용합니다〔pp.6, 14〕. 2609.37725v1 2609.37725v1

> **용어 풀이 — 강화학습:** 행동의 결과로 받은 보상을 이용해 행동 선택 방식을 학습하는 방법입니다.  
> **용어 풀이 — GRPO:** 같은 문제에 대해 여러 실행을 생성하고, 그룹 안에서 상대적으로 좋은 실행의 행동을 강화하는 학습 방식입니다.  
> **용어 풀이 — 어드밴티지(advantage):** 어떤 행동이나 실행이 비교 기준보다 얼마나 좋았는지를 나타내는 학습 신호입니다.

성공한 실행들의 평균 계산 비용을 다음과 같이 정의합니다.

$$
\bar c_g=
\frac{1}{|\mathcal{G}_g^+|}
\sum_{k\in\mathcal{G}_g^+}c_k
$$

$g$는 같은 문제에서 생성한 실행 그룹, $\mathcal{G}_g^+$는 성공한 실행들의 집합, $c_k$는 실행 $k$의 prefix-reuse FLOPs, $\bar c_g$는 성공한 실행들의 평균 비용입니다. **여기서 $c_k$는 비용으로, 앞에서 컨텍스트를 나타낸 $c_t$와 용도가 다릅니다.**

효율 어드밴티지는 다음과 같습니다. 아래 표현은 원문 식 6에 본문의 “성공 실행이 두 개 미만이면 0”이라는 예외를 합친 것입니다.

$$
A_i^{\text{eff}}=
\begin{cases}
\text{clip}\left(
\dfrac{\bar c_g-c_i}{\bar c_g},
-1,1
\right),
&
i\in\mathcal{G}_g^+,\quad |\mathcal{G}_g^+|\ge 2
\\[6pt]
0,
&
\text{그 외}
\end{cases}
$$

$A_i^{\text{eff}}$는 실행 $i$의 효율 신호이고, $\text{clip}(z,-1,1)$은 값 $z$를 $-1$과 $1$ 사이로 제한합니다. 성공한 실행 중 평균보다 저렴하면 양수, 비싸면 음수이며, 실패한 실행은 효율 보너스를 받지 않습니다.

이를 과제 성공에 관한 어드밴티지와 결합합니다.

$$
A_i=A_i^{\text{out}}+
w_{\text{eff}}A_i^{\text{eff}}
$$

$A_i^{\text{out}}$는 최종 과제 결과에 따른 신호, $w_{\text{eff}}$는 효율 신호의 가중치, $A_i$는 결합된 신호입니다〔p.6, 식 6 및 주변 설명〕. 2609.37725v1

구체적 CLM 학습에서는 $w_{\text{eff}}=0.25$를 컨텍스트 관리 토큰에 적용하고, 실패한 도구 호출과 형식 오류에도 벌점을 부여합니다〔p.24〕. 2609.37725v1

**[해석]** 이 설계의 장점은 “아무것도 하지 않고 빨리 실패하는 실행”을 효율적이라고 보상하지 않는다는 점입니다. 반면 어려운 문제에서 성공 실행이 거의 없으면 효율 학습 신호도 사라집니다. 또한 전체 결과를 여러 단계에 전달하므로, **어떤 편집이 실제로 성공에 기여했는지**를 정밀하게 구분하는 문제는 남습니다.

### 3.5 계산량: 컨텍스트가 짧다고 반드시 저렴하지는 않다

**[저자 보고]** 표준 캐시 재사용에서는 입력 앞부분이 같을 때 기존 계산을 재사용합니다. 중간을 수정하면 수정 지점 뒤의 텍스트가 같아도 다시 계산해야 합니다. 논문의 식 3은 이를 다음과 같이 표현합니다〔p.5〕.

```math
F_{\text{prefix-reuse}}
=
F_{\text{prefill}}(\text{불일치 지점 이후 입력})
+
F_{\text{decode}}(\text{새로 생성한 토큰})
```

$F_{\text{prefix-reuse}}$는 해당 방식으로 계산한 추론 연산량, $F_{\text{prefill}}$은 입력을 처리하는 비용, $F_{\text{decode}}$는 새 출력을 생성하는 비용입니다. 2609.37725v1

> **용어 풀이 — 프리필(prefill):** 입력된 여러 토큰을 처리해 이후 생성에 필요한 내부 상태를 계산하는 단계입니다.  
> **용어 풀이 — 디코딩(decode):** 출력을 새 토큰 단위로 생성하는 단계입니다.  
> **용어 풀이 — 접두부 캐시(prefix cache):** 동일한 입력 앞부분에 대해 이미 계산한 내부 상태를 다시 사용하는 장치입니다.

부록의 좀 더 구체적인 한 턴 비용은 다음과 같습니다〔p.17, 식 9〕.

$$
F_t=
C_{\text{token}}(U_t+G_t)
+
C_{\text{attn}}
\left[
\frac{P_t^2-R_t^2}{2}
+
G_tP_t
+
\frac{G_t^2}{2}
\right]
$$

$$
U_t=P_t-R_t,
\qquad
F_{\text{trajectory}}=\sum_{t=1}^{T}F_t
$$

기호는 $P_t$가 입력 토큰 수, $R_t$가 재사용 가능한 앞부분의 토큰 수, $U_t$가 다시 처리할 입력 토큰 수, $G_t$가 생성 토큰 수, $T$가 전체 턴 수입니다. $C_{\text{token}}$은 처리 토큰당 선형 연산 비용이고, $C_{\text{attn}}$은 어텐션의 질의–키 쌍당 비용이며, 세부 계수는 원문 식 7–8에서 정의합니다. 2609.37725v1

> **용어 풀이 — 어텐션(attention):** 현재 처리 중인 토큰이 다른 토큰의 정보를 얼마나 참조할지 계산하는 장치입니다.

**[해석]** 앞쪽을 크게 수정해 $R_t$가 줄면 다음 호출 비용이 커질 수 있습니다. 따라서 효율적인 정책은 단순히 “많이 지우는 정책”이 아니라 **지우는 양·위치·시점과 이후 호출 횟수를 함께 고려하는 정책**이어야 합니다.

또한 이 비용 모델은 임베딩·출력 층, 선형 어텐션의 순환 상태 갱신, 정규화 등의 일부 연산을 제외합니다. 따라서 모든 하드웨어 연산을 직접 계측한 완전한 비용 지표로 해석해서는 안 됩니다〔p.17〕. 2609.37725v1

### 3.6 Suffix Cache Reuse: 더 빠르지만 의미적으로 근사적이다

**[저자 보고]** 컨텍스트가 $[A,B,C]$에서 $[A,B',C]$로 바뀌었다고 하겠습니다. 표준 방식은 $A$만 재사용하고 $B'$와 $C$를 다시 계산하지만, SCR은 살아남은 $C$의 내부 상태도 재사용합니다. 여기서 $A$는 수정 전후 공통 앞부분, $B$는 교체된 구간, $B'$는 새 구간, $C$는 그대로 남은 뒤쪽 구간입니다〔p.6, Figure 4〕. 2609.37725v1

> **용어 풀이 — KV 캐시:** 어텐션에서 사용하는 key와 value 벡터를 저장한 내부 계산 상태입니다. 뒤에서 등장하는 합성 과제의 **KV Store, 즉 키–값 사전**과는 다른 개념입니다.

구현은 살아남은 구간의 키·값을 재사용하고 위치 정보를 보정하며, 기본 실험에서는 최대 여섯 개의 긴 구간을 이동합니다. 선형 어텐션층이 섞인 모델에서는 편집 전의 순환 상태를 재사용하는 별도 근사가 들어갑니다〔p.15, Figure 10〕. 2609.37725v1

**[해석]** 핵심은 $C$의 상태가 **새 앞부분이 아니라 예전 앞부분을 보고 계산되었다**는 사실입니다. 이 때문에 SCR을 사용할 때는 눈에 보이는 컨텍스트 텍스트만으로 모델 상태를 완전히 설명하기 어려워집니다. 삭제한 정보가 캐시에 간접적으로 남아 도움이 될 수도 있지만, 잘못된 정보를 수정한 상황에서는 이전 상태가 불리하게 작용할 가능성도 검증해야 합니다. 후자는 이 논문이 입증한 실패가 아니라, 근사 방식에서 도출되는 연구 질문입니다.

### 6.2 일반화가 좋아질 수 있는 이유 — 아직은 메커니즘 가설

**[해석]** CLM의 일반화 가능성은 “더 많이 기억한다”보다 **더 적절한 상태를 유지한다**는 데 있습니다. 과거의 모든 검색 결과 대신 검증된 사실·실패한 시도·남은 목표를 유지하는 정책이 학습된다면, 실행 길이가 늘어나도 모델이 처리해야 할 작업 상태의 복잡도는 비교적 안정적으로 유지될 수 있습니다. Figure 3의 상태표·진행 메모 사례는 이 가설과 부합하지만, 그 메커니즘을 인과적으로 검증한 실험은 아닙니다. 2609.37725v1

이 관점을 표현하는 **해석용 기준**은 다음과 같습니다. 원문에 있는 수식은 아닙니다.

```math
P(y^*\mid H_t,q)
\approx
P(y^*\mid m_t,q)
```

$H_t$는 전체 과거 기록, $m_t$는 관리 후 남긴 상태, $q$는 이후 질문, $y^*$는 그 질문에 대한 올바른 답입니다. 의미는 **전체 기록을 줄이더라도 미래의 올바른 답을 결정하는 정보는 남겨야 한다**는 것입니다.

> **용어 풀이 — 충분한 상태 표현:** 과거의 모든 세부사항을 포함하지 않아도 다음 판단에 필요한 정보를 갖춘 요약된 상태입니다.

문제는 미래 질문 $q$가 무엇인지 미리 알기 어렵다는 데 있습니다. ContextBench처럼 버릴 정보가 명확하게 표시된 환경에서 배운 정책이, 나중에 중요해질 사실을 판단해야 하는 환경에서도 작동하는지는 별도 검증이 필요합니다.

### 6.3 일반화 주장을 제한하는 핵심 증거

**첫째, 작은 모델에서 자유도가 자동으로 이점이 되지는 않습니다.** 저자들은 작은 모델이 편집을 덜 사용하고, 최대 컨텍스트를 더 크게 유지한다고 보고합니다. 하지만 Qwen3.5-9B와 Qwen3.6-27B 비교에는 크기뿐 아니라 모델 계열·세대 차이도 있으므로, 이를 엄밀한 모델 크기 확장 법칙으로 읽을 수는 없습니다〔p.24, Figure 17〕. 2609.37725v1

### 7.2 이 비교에서 도출되는 세 가지 판단

**[해석 1] CLM의 신규성은 좁고 정확하게 정의해야 합니다.**  
“모델이 자신의 기억을 관리한다”, “컨텍스트를 학습한다”, “파일로 컨텍스트를 만든다”는 주장 각각에는 선행 연구가 있습니다. CLM의 중심 기여는 **실시간 컨텍스트의 일반 코드 기반 편집을 행동 공간으로 만들고, 이를 자연어 지침·강화학습·캐시 비용과 연결한 통합 설계**입니다. 이는 논문 자체의 관련 연구 정리와도 부합합니다〔pp.13–14〕. 2609.37725v1

**[해석 2] 일반화 평가에서는 일부 선행 연구가 더 직접적인 시험을 제공합니다.**  
MEM1의 학습 범위를 넘는 목표 수 실험과 MCE의 모델 간 컨텍스트 전이는, 단순히 여러 과제에서 좋은 결과를 얻는 것과 구분되는 평가입니다. CLM도 **정책을 고정한 채 무엇을 바꾸어 시험했는지**를 명시해야 일반화 주장이 강해집니다. [arXiv](https://arxiv.org/pdf/2506.15841)

**[해석 3] CLM의 비교표를 원래 방법들의 최종 성능 순위로 읽으면 안 됩니다.**  
CLM 논문은 통제 비교를 위해 여러 기존 방법을 추가 학습 없이 적용했고, MEM1은 추론 루프를 재구현했습니다. 따라서 여기서의 “MEM1 대비 우위”나 “ACM 대비 우위”는 **원 논문의 학습된 체크포인트·학습 데이터·기본 예산까지 포함한 전체 방법을 이겼다는 뜻이 아닙니다**〔pp.7, 19〕. 2609.37725v1 2609.37725v1

## 9. 결론: 저자의 시사점과 추가 후속 연구 방향

### 9.1 저자들이 제시한 시사점과 후속 방향

**[저자 보고]** 논문이 제시하는 중심 시사점은 컨텍스트 관리 절차를 외부 프로그램의 고정 규칙으로만 두지 말고, **모델이 탐색하고 학습할 수 있는 능력으로 옮기자**는 것입니다. 후속 연구로는 강화학습 규모 확대, 기존 하네스의 전략을 CLM으로 옮기는 학습, 모델 편집 가능 컨텍스트의 안전성 연구를 제안합니다〔p.10〕. 2609.37725v1

> **용어 풀이 — 증류(distillation):** 더 복잡한 시스템이나 강한 모델의 유용한 행동을 다른 모델이 재현하도록 학습시키는 것입니다.  
> **용어 풀이 — 절차적 기억:** 개별 사실이 아니라 “어떤 순서와 방법으로 일을 하는가”에 관한 지식입니다. 저자들은 하네스를 이런 형태의 기억으로 해석합니다.

부록에서는 컨텍스트 사용량 인식 능력을 학습하는 방향과, 캐시 재사용을 개선하기 위해 순환 상태를 더 세밀한 경계에 저장하는 방향도 제안합니다〔pp.17, 27〕. 2609.37725v1 2609.37725v1

| **효과의 원인 분리** | 편집 권한, 경고 메시지, 재시도, 추가 학습, SCR을 각각 켜고 끄는 요인 실험을 수행합니다. | 동일 조건에서 각 구성요소의 기여와 상호작용. |
| **불확실한 중요도에 대한 기억 관리** | 초기에는 중요하지 않아 보였던 정보가 나중에 필요해지는 질문, 사실 정정, 모순된 관측을 포함합니다. | 미래 질문 정확도, 잘못 삭제한 정보의 복구율, 출처 유지율. |
| **텍스트 기억과 캐시 기억의 분리** | 같은 컨텍스트를 캐시 유지·전체 재계산·선택적 재계산으로 각각 실행합니다. | 정확도 차이, 수정 전 정보의 잔존 효과, 장기 반복 편집 안정성. |
| **작은 모델로의 이전** | 자연어 스킬은 다른 모델에 그대로 적용하고, 가중치 기반 정책은 별도의 증류 실험으로 구분합니다. | 모델 간 스킬 전이, 증류 후 성능, 도구·형식 오류율. |
| **실사용 비용 평가** | 모든 실패 실행, 재시도, 하위 에이전트, 지침 탐색과 학습 비용을 포함합니다. | 전체 평균 비용, 상위 지연 구간, 단일 실행 성공률, 비용 회수 시점. |

추가로, 편집의 자유도와 안전성을 서로 배타적인 목표로 둘 필요는 없습니다. **보호해야 할 지시 영역, 수정 이력, 출처가 연결된 사실 저장, 편집 전후 검증, 선택적 캐시 무효화**를 결합하고, 그 제약이 일반화와 비용에 미치는 영향을 실험하는 방향이 타당합니다. 이는 논문이 이미 해결한 사항이 아니라, 실용적인 CLM으로 발전시키기 위한 제안입니다.

### 최종 판단

**이 논문의 가장 중요한 기여는 “더 긴 컨텍스트”가 아니라 “다음 판단에 필요한 컨텍스트를 모델이 직접 구성하도록 만드는 것”입니다.** 그 관점은 장기 에이전트의 효율과 일반화에 모두 의미가 있습니다.

그러나 현재 증거가 가장 강하게 지지하는 결론은 **특정 모델·과제·예산에서 유리한 성능–비용 절충을 얻을 수 있다**는 것입니다.  
**학습하지 않은 환경에서도 중요한 정보를 안정적으로 보존하는 범용 관리 능력**, **근사 캐시의 장기적 안전성**, **동일 조건에서의 재현 가능한 우위**는 여전히 검증 과제입니다.
