## 1. Executive summary — 10문장

1. 이 논문은 Gemini에 지리공간 데이터·전문 모델·계산 도구를 연결하는 **Geospatial Reasoning Agent, GRA**의 구조와 평가 체계를 제시하며, 기여의 중심은 새로운 신경망 학습보다 **도구를 활용한 분석 시스템의 설계와 검증**에 있습니다. **[원문 pp.1–3, 6–10]**
2. GRA는 필요한 기능만 불러오는 모듈형 스킬, 모델의 문맥 밖에 저장하는 중간 데이터, 분석 시작 전 계획, 실행 중 대응 지침을 결합합니다. **[원문 pp.7–9, Figure 2]**
3. 저자들은 두 Gemini 모델 각각에서 ‘모델 단독’, ‘기본 도구 추가’, ‘GRA 전문 도구 추가’, ‘전체 GRA’의 네 구성을 비교하여 전문 기능과 실행 조정 계층의 기여를 구분합니다. **[원문 pp.9–11, Figure 3]**
4. 가장 일관된 개선은 전문 도구 묶음에서 나타났으며, Gemini 3.8 Flash의 GeoExpertQueries 점수는 기본 도구 구성의 **3.3점에서 52.2점**으로 상승했습니다. **[원문 p.19, Table 4]**
5. 사전 계획과 실행 지침을 추가하면 같은 모델에서 **52.2점에서 62.7점**으로 상승하지만, Gemini 3.1 Pro에서는 **50.8점에서 47.6점**으로 낮아져 그 효과가 모델과 과제에 따라 달랐습니다. **[원문 pp.19–20, Tables 4–5]**
6. **62.7점은 정답률이나 완수율이 아니라 실행된 분석의 전문가 기준 충족도를 평가한 점수이며, 최종 수치·산술·결론의 정확성은 해당 채점에서 제외됩니다.** **[원문 pp.13–14, 25, 34–36]**
7. 전체 GRA와 Flash 조합은 GeoKTools에서 **85.9점**, CBGB에서 **86.4점**을 얻었지만, 두 벤치마크는 채점 방식이 달라 점수를 서로 직접 비교할 수 없습니다. **[원문 p.3 각주 1, p.19 Table 4]**
8. UnivEARTH의 140문항 평가에서는 도구 없는 모델도 높은 점수를 얻었고, 저자들은 이를 공개 기사에서 답을 기억하거나 검색할 수 있는 평가의 변별력 문제로 해석합니다. **[원문 pp.22–23, Table 8]**
9. GeoExpertQueries에서 GRA의 질의당 추론 비용은 Flash가 **0.199달러**, Pro가 **0.688달러**였지만, 이 금액에는 Earth Engine 등 외부 데이터·계산 서비스 비용이 포함되지 않습니다. **[원문 pp.11, 23, Table 9]**
10. 연구는 재훈련 없이 전문 기능을 연결해 분석 범위를 확장하는 접근의 유망성을 보여주지만, 새로운 국가·시점·센서·모델 계열에서의 일반화와 실제 분석 결과의 과학적 정확성은 추가 검증이 필요합니다. **[원문 pp.25–26; 해석]**

> **용어 풀이**
>
> - **에이전트:** 질문에 답하는 과정에서 여러 차례 도구를 선택하고 실행하는 AI 시스템입니다.
> - **스킬:** 특정 분야의 도구와 사용 설명을 묶은 기능 단위입니다.
> - **문맥, context:** 언어모델이 현재 입력으로 읽고 처리하는 정보 범위입니다.
> - **일반화:** 개발·검증에 사용하지 않은 새로운 문제나 환경에서도 성능이 유지되는 성질입니다.

## 2. 연구 배경·목표·필요성

### 2.1. 해결하려는 문제

**[저자 보고]** 홍수 위험 평가, 산림 훼손 감시, 시설 입지 선정과 같은 문제는 위성영상, 인구통계, 기상 자료, 행정경계 등을 함께 사용해야 합니다.  
이를 위해서는 자료를 찾는 일뿐 아니라 공간·시간 범위를 맞추고, 적절한 분석을 수행하며, 결과의 한계를 설명해야 하므로 상당한 전문 지식과 수작업이 필요합니다. **[원문 pp.1–2]**

이 연구가 다루는 문제는 두 층위입니다.

| 층위 | 해결하려는 문제 | 연구 목표 |
|---|---|---|
| 분석 시스템 | 다양한 자료와 도구를 자연어 질문에 맞게 선택·결합하기 어렵다 | 전문 기능을 모듈로 구성하고, 계획과 실행 지침으로 다단계 분석을 수행한다 |
| 평가 방법 | 복잡한 지리공간 문제에는 정답이나 올바른 절차가 하나로 정해지지 않는 경우가 많다 | 전문가 기준의 개방형 평가와 정답을 계산할 수 있는 통제된 평가를 함께 사용한다 |

**근거: 원문 pp.2–3, 6–16.**

### 2.2. 기존 평가만으로 부족한 이유

저자들은 다음 네 가지 어려움을 강조합니다. **[원문 p.2]**

1. **결과가 분석 설정에 의존합니다.** 같은 질문도 자료원, 관측 기간, 연구 지역, 분석법에 따라 타당한 결과가 달라질 수 있습니다.
2. **서로 다른 절차가 모두 타당할 수 있습니다.** 예를 들어 홍수 위험은 공식 홍수구역 지도와 고해상도 홍수 모의실험을 통해 각각 평가할 수 있습니다.
3. **자료 발견 자체가 문제의 일부입니다.** 필요한 데이터가 질문에 주어지지 않으므로 시스템이 대규모 목록에서 직접 찾아야 합니다.
4. **기준 정답이 시간이 지나며 바뀝니다.** 위성 자료의 재처리, 통계 수정, 행정·보호구역 경계 변경이 기존 정답을 바꿀 수 있습니다.

> **용어 풀이 — 기준 정답, ground truth:** 평가에서 맞는 답으로 사용하는 기준입니다. 이 논문에서는 고정된 숫자일 수도 있고, 전문가가 작성한 분석 절차일 수도 있습니다.

### 2.3. 목적과 필요성에 대한 해석

**[해석]** 연구의 핵심 질문은 “어떤 언어모델이 가장 똑똑한가”보다 **“동일한 언어모델에 전문 자료 접근과 실행 구조를 추가하면 무엇이 가능해지는가”**에 가깝습니다.  
모델을 고정한 채 도구와 실행 구조를 바꾸는 설계는 시스템 구성의 기여를 살펴보는 데 유용합니다.

다만 전문 기능 묶음에는 데이터 접근권, 전문 모델, 도구, 스킬 설명, 중간 데이터 처리 방식이 함께 포함됩니다.  
따라서 결과를 **추론 능력만의 개선**으로 해석할 수는 없습니다. **[원문 pp.6, 9–10, 26]**

## 3. 제안 방법과 시스템 구조

### 3.1. 무엇을 새로 제안했는가?

**[저자 보고]** GRA는 기존 Gemini 모델을 중심으로 지리공간 전문 기능을 조합하는 시스템입니다. 논문에는 새로운 신경망 계층, 파라미터 수, 사전학습 절차, 학습 손실함수에 대한 제안이 없습니다.  
따라서 이 논문의 ‘모델 구조’는 다음과 같은 **에이전트 시스템 구조**로 이해해야 합니다. **[원문 §3, pp.6–11]**

#### ① 도메인별 스킬과 필요시 로딩

처음에는 스킬의 이름과 짧은 설명만 모델에 보여줍니다. 모델이 필요하다고 판단하면 해당 스킬의 도구 정의와 사용 지침을 불러옵니다. 모든 도구의 상세 설명을 처음부터 문맥에 넣지 않으므로, 기능이 늘어날 때의 선택 부담과 문맥 사용량을 줄이려는 설계입니다. **[원문 pp.7–8]**

> **용어 풀이 — 점진적 공개, progressive disclosure:** 필요한 기능의 상세 정보만 필요한 시점에 보여주는 방식입니다.

**[해석]** 설계상 확장성은 분명하지만, ‘모든 도구를 처음부터 노출’하는 방식과 ‘필요시 공개’하는 방식만 따로 비교한 실험은 없습니다. 따라서 점수 개선을 이 기능 하나의 효과로 귀속할 수 없습니다. **[원문 pp.9–10, 26]**

#### ② 문맥 밖의 중간 데이터 처리

위성영상, 행정경계, 통계표 같은 큰 자료는 외부 작업공간의 **scratch datasets**에 보관합니다. 도구들은 데이터 자체를 대화문에 반복 삽입하는 대신 참조값으로 주고받으며, 모델은 검사 도구나 Python을 통해 필요한 부분을 확인하고 처리합니다. **[원문 p.8, Figure 2]**

> **용어 풀이 — scratch dataset:** 분석 중 임시로 보관하는 작업 데이터입니다. 여기서는 언어모델이 읽는 문맥과 분리해 저장합니다.
>
> **래스터 / 벡터:** 래스터는 위성영상처럼 격자로 표현한 자료이고, 벡터는 점·선·다각형으로 표현한 자료입니다.

#### ③ 기능과 제약을 고려한 사전 계획

실제 지리공간 데이터 도구를 호출하기 전에, 사용 가능한 기능과 제약을 확인하고 자료 검색·처리 계획을 세웁니다. 단순 질문은 하나의 목표로, 복잡한 질문은 여러 분야의 검색과 공간 결합을 포함한 단계로 나눕니다. **[원문 pp.8–9]**

> **용어 풀이 — 공간 결합, spatial join:** 위치 관계를 기준으로 서로 다른 자료를 연결하는 연산입니다. 예를 들어 침수지역 안에 포함되는 인구를 집계할 때 사용합니다.

#### ④ 결과에 따라 수정하는 실행

계획은 고정된 실행 스크립트가 아닙니다. 도구 결과에서 자료 부족이나 더 직접적인 해결 경로가 드러나면 계획을 수정할 수 있습니다. **[원문 p.9]**

#### ⑤ 실패·대체자료·불확실성에 관한 실행 지침

논문이 설명하는 주요 지침은 다음과 같습니다. **[원문 pp.9–10]**

- 전문 자료원이 있으면 이를 우선 사용합니다.
- 신뢰할 수 있는 자료원의 빈 결과를 무조건 실패로 취급하지 않습니다.
- 동일 도구에 대한 자료 요청이 세 번을 초과해 실패하면 막힌 경로로 처리합니다.
- 평가에 사용한 best-effort 모드에서는 이상적인 자료가 없을 때 정당화 가능한 대체자료를 찾습니다.
- 대체자료 사용, 공간·시간 범위, 불확실성을 최종 답에 설명합니다.

> **용어 풀이 — 대체자료, proxy:** 직접 필요한 값을 구할 수 없을 때 대신 사용하는 간접 자료입니다. 예를 들어 실제 침수구역 인구 대신 행정구역 전체 인구를 사용하면 공간적 의미가 달라질 수 있습니다.

#### ⑥ 함수 호출 신뢰성과 비용의 절충

스킬을 로드할 때 실제 함수 정의를 API에 추가하면 인자 구조를 검증할 수 있지만, 요청 앞부분이 바뀌어 이미 계산한 입력의 캐시를 다시 사용하지 못할 수 있습니다. GRA는 예상되는 스킬을 실행 초기에 함께 로드하도록 지시해 이 비용을 줄입니다. 이는 구현상의 설명이며, 별도 실험으로 효과를 분리한 결과는 아닙니다. **[원문 p.33, Appendix A.2]**

> **용어 풀이 — 접두부 캐시, prefix cache:** 이전 요청과 동일한 입력 앞부분의 계산 결과를 재사용하는 장치입니다. 입력 앞부분이 바뀌면 재사용 이점이 줄어듭니다.

아래 항목들은 대부분 **질의 실행 중 접근하는 자료와 기능**입니다. 이 논문에서 새로운 GRA 모델을 학습한 훈련 데이터셋으로 해석하면 안 됩니다. **[원문 p.7, Table 1; pp.31–33, Table 11]**

> - **앙상블 예보:** 여러 가능한 미래 예보를 함께 생성하여 평균과 불확실성을 살펴보는 방식입니다.
> - **POI:** 병원·상점·학교처럼 지도에서 관심 대상이 되는 장소입니다.
> - **다운스케일링:** 넓은 지역 단위의 정보를 더 작은 지역 단위로 세분화하는 것입니다.

**평가 범위에 관한 주의:** 기능 목록에 포함됐다고 해당 기능의 품질이 모두 검증된 것은 아닙니다. 저자들은 시공간 예측 기능은 이번 벤치마크가 평가하지 않았으며, Remote Sensing Foundations와 WeatherNext도 제한적으로 사용됐다고 명시합니다. **[원문 p.25, §6.1]**

### 4.3. 수식으로 설명하는 실제 방법

**원문에는 새로운 모델의 학습 목적함수나 신경망 수식이 없습니다.** 따라서 아래에서는 Figure 4에 실제로 등장하는 수학 표현과, 본문에 기술된 연산·채점 절차를 수학적으로 재표현한 식을 구분합니다.

#### A. Figure 4의 참조 계산 — 원문 의사코드에 있는 수식

질문은 “네브래스카에서 Carhenge와 가장 멀리 떨어진 카운티를 찾고, 그 카운티의 2019년 중위연령을 구하라”입니다. **[원문 p.15, Figure 4]**

```math
r^*=\underset{c\in\mathcal C}{\text{argmax}}\;\mathcal D[c],
\qquad
v^*=\mathcal T_{\text{DC}}[r^*].
```

**기호 설명**

- $\mathcal C$: 네브래스카에 속한 카운티의 집합.
- $c$: 그 집합에 속한 하나의 카운티.
- $\mathcal D[c]$: Carhenge의 대표 중심점과 카운티 $c$ 사이에서 참조 계산이 구한 거리.
- $\text{argmax}$: 값이 가장 큰 항목을 선택하는 연산.
- $r^*$: 가장 먼 카운티이며, 거리가 같으면 알파벳순으로 결정합니다.
- $\mathcal T_{\text{DC}}$: Data Commons에서 가져온 2019년 지역별 중위연령 표.
- $v^*$: 선택된 카운티의 중위연령.

원문 예시의 출력은 **Richardson County, 47.7세**입니다. 경계 조회 → 장소 좌표 조회 → 거리 계산 → 통계 조회의 네 단계를 거치지만, 사용한 도구 유형은 공간분석·장소검색·공공통계의 세 가지이므로 $K=3$입니다. **[원문 p.15]**

**명세의 한계:** 이 그림만으로는 점과 카운티 다각형 사이의 거리 정의를 세부적으로 확정할 수 없습니다. 카운티 중심점 거리나 특정 구면거리 공식을 사용했다고 추가로 단정하지 않습니다.

#### B. 임베딩 기반 변화 탐지 — 명시된 연산의 표준 정의

Table 11은 두 연도의 64차원 위성 임베딩에 대한 코사인 유사도를 이용한 지표 변화 탐지를 설명합니다. 다음은 그 연산의 표준 정의이며, 논문이 새롭게 제안한 수식은 아닙니다. **[원문 p.31, Table 11]**

```math
\text{cosine}(\mathbf e_{t_1},\mathbf e_{t_2})
=
\frac{\mathbf e_{t_1}^{\top}\mathbf e_{t_2}}
{\|\mathbf e_{t_1}\|_2\|\mathbf e_{t_2}\|_2}.
```

**기호 설명**

- $\mathbf e_{t_1},\mathbf e_{t_2}\in\mathbb R^{64}$: 같은 위치를 두 연도에 표현한 임베딩.
- $t_1,t_2$: 비교하는 연도.
- $\top$: 벡터 전치이며, 분자는 두 벡터의 내적입니다.
- $\|\cdot\|_2$: 벡터의 길이입니다.

> **용어 풀이 — 코사인 유사도:** 두 숫자 벡터가 얼마나 비슷한 방향을 가리키는지 측정합니다. 여기서는 두 시점의 지표 특성이 얼마나 유사하게 표현됐는지 살펴봅니다.

원문은 변화 판정 임계값이나 변화 영역을 다각형으로 만드는 구체적 규칙까지 제시하지 않습니다.

#### C. GeoExpertQueries 채점 — 본문 절차의 수학적 재표현

각 응답을 자동평가자가 세 번 평가합니다. 원 프롬프트의 등급은 0·1·2이며, 이를 0·0.5·1로 바꾸어 평균합니다. **[원문 pp.13–14, 34–36]**

```math
s_{ir}
=
\frac{1}{3}\sum_{j=1}^{3}\frac{g_{irj}}{2},
\qquad
g_{irj}\in\{0,1,2\}.
```

**기호 설명**

- $i$: 질의 번호.
- $r$: 에이전트 실행 반복 번호.
- $j$: 자동평가 반복 번호.
- $g_{irj}$: 자동평가자의 원 등급.
- $s_{ir}$: 한 응답의 최종 점수로, 0에서 1 사이입니다.

전체 벤치마크 점수와 세 번의 실행 평균은 다음과 같이 표현할 수 있습니다.

$$
B_r=\frac{100}{N}\sum_{i=1}^{N}s_{ir},
\qquad
\bar B=\frac{1}{3}\sum_{r=1}^{3}B_r.
$$

- $N$: 시험 질의 수이며, GeoExpertQueries에서는 76입니다.
- $B_r$: 한 번의 전체 실행에서 얻은 0–100점 점수.
- $\bar B$: 결과 표에 보고된 평균 점수.

**이 점수는 수행한 단계의 단순 비율이 아닙니다.** 평가자는 누락·대체·단순화가 전문가에게 제공하는 분석적 가치에 미치는 영향을 판단합니다. **[원문 pp.14, 35–36]**

#### D. GeoKTools 채점 — 본문 절차의 수학적 재표현

질의에는 1–7개의 답란이 있습니다. 완전 일치는 1점, 빈 응답은 0점이며, 나머지는 자동평가자가 각 요소의 점수를 주고 평균합니다. **[원문 p.16, pp.36–37]**

$$
s_i=
\begin{cases}
1, & \text{응답이 기준답과 완전히 일치할 때},\\
0, & \text{응답이 비어 있을 때},\\
\frac{1}{m_i}\sum_{\ell=1}^{m_i}u_{i\ell},
& \text{그 밖의 경우}.
\end{cases}
$$

- $s_i$: 질의 $i$의 점수.
- $m_i$: 질의 $i$의 답 요소 수.
- $\ell$: 답 요소 번호.
- $u_{i\ell}\in[0,1]$: 요소별 자동평가 점수.

잘못된 지역이나 장소를 선택하면 그 대상에 의존하는 후속 값도 0점을 받습니다. 수치 오차의 허용 수준은 단위와 문제 맥락에 따라 평가자가 판단하며, 본문은 고정된 오차 허용 공식을 제시하지 않습니다.

**따라서 정답 생성은 결정적이어도, 전체 채점 과정이 항상 결정적인 것은 아닙니다.**

| 분야 | 시험 질의 수 | GRA Tools → GRA | 점수 차이 |
|---|---:|---:|---:|
| 자연재해·위기대응 | 35 | 45.6 → 66.0 | +20.4 |
| 공중보건 | 17 | 42.5 → 55.6 | +13.1 |
| 입지·도시계획 | 20 | 71.4 → 65.6 | −5.8 |
| 운영·상업 | 4 | 55.6 → 50.0 | −5.6 |

**[저자 해석]** 계획이 없는 Flash 구성은 일부 자연재해 문제를 단순 웹 검색 문제로 처리했습니다. GRA의 계획과 지침은 전문 자료와 공간 분석으로 접근하도록 유도했습니다. 반면, 도구 장애를 만나면 더 자유롭게 코드를 작성하거나 보조 자료를 찾는 비계획형 구성이 유리한 사례도 있었습니다. **[원문 p.20]**

**[해석]** 이는 계획의 유무뿐 아니라 **계획을 수정하는 유연성과 실패 대응 정책**이 중요하다는 가설을 뒷받침합니다. 다만 원문은 실행 기록을 통해 가능한 설명을 제시했으며, 이 원인을 별도 통제 실험으로 입증하지는 않았습니다.

## 6. 통계적 취약점과 비교할 수 없는 수치

### 6.1. 자동평가자 검증의 강점과 한계

자동평가 검증에는 실행 기록 69개와 전문가 평가 207개가 사용됐습니다. 기록은 GRA 57개, GRA Tools 12개이며, 낮음·중간·높음 점수대에 걸쳐 선정됐습니다. 전문가에게 모델·구성·자동평가 점수는 공개하지 않았습니다. **[원문 p.14]**

| 검증 지표 | 보고값 |
|---|---:|
| 전문가 세 명의 Krippendorff $\alpha$ | 0.56, 95% 신뢰구간 [0.42, 0.67] |
| 자동평가자를 네 번째 평가자로 추가한 $\alpha$ | 0.57, [0.45, 0.67] |
| 자동평가와 전문가 평균의 Spearman 상관 | 0.72, [0.60, 0.82] |
| 자동평가와 전문가 평균의 평균 절대 차이 | 0.20, 0–1 척도 |
| 자동평가 − 전문가 평균의 부호 있는 평균 차이 | +0.01 |
| 두 점수의 절대 차이가 0.33 이내인 기록 | 87% |

> **용어 풀이**
>
> - **Krippendorff $\alpha$:** 여러 평가자가 우연한 일치를 넘어서 얼마나 비슷하게 평가하는지 나타내는 지표입니다.
> - **Spearman 상관:** 두 평가가 항목의 높고 낮은 순서를 얼마나 비슷하게 매기는지 나타냅니다.
> - **신뢰구간:** 표본을 바꾸어 반복 추정할 때의 불확실성을 표현하는 범위입니다.
> - **평균 절대 차이:** 두 평가값 차이의 크기를 평균한 값으로, 양수·음수 차이가 서로 상쇄되지 않습니다.

**[해석]**

- 자동평가가 인간 평가자들 사이의 일치 수준에 근접한다는 근거는 있습니다.
- 그러나 평균 절대 차이 0.20은 100점 척도에서는 20점입니다.
- “87%에서 0.33 이내”는 “87%에서 정확히 일치”를 뜻하지 않습니다.
- 모델 단독과 Basic Tools의 기록은 이 검증 표본에 포함되지 않았습니다.
- 전체 평균 편향이 +0.01이라고 해서 분야별·구성별 편향까지 없다고 볼 수 없습니다.
- 이 검증을 GeoKTools의 연속 부분점수 평가에도 그대로 적용할 수는 없습니다.

## 8. 일반화 성능 향상 가능성

### 8.1. 무엇의 일반화를 말하는지 구분해야 한다

**[해석]** 이 연구에서는 적어도 세 종류의 일반화를 구분해야 합니다.

| 일반화의 종류 | 의미 | 이 논문이 제공하는 근거 |
|---|---|---|
| 기반 표현의 일반화 | 학습한 임베딩이 다른 지역·예측 과제에서도 유용한가 | PDFM·AlphaEarth를 사용하지만 그 일반화 성능을 여기서 직접 검증하지 않음 |
| 분석 절차의 일반화 | 새로운 질문에 맞게 기존 도구를 조합할 수 있는가 | 시험용 템플릿 분리, 여러 분야 평가, 외부 CBGB 결과가 제한적 근거를 제공 |
| 환경 변화에 대한 적응 | 새 지역·시점·자료 버전·도구 장애에서도 잘 작동하는가 | 일부 대응 사례를 논의하지만 체계적인 분포 밖 평가가 부족 |

> **용어 풀이 — 분포 밖 평가, OOD evaluation:** 개발 때 접한 문제와 성격이 다른 조건에서 성능을 시험하는 것입니다. 예를 들어 개발에 쓰지 않은 국가 전체나 새로운 센서 자료를 시험용으로 남겨둘 수 있습니다.

### 8.2. 실제로 확인된 일반화 관련 증거

**[저자 보고]**

- GeoKTools는 같은 템플릿이 개발·시험에 겹치지 않도록 분리했습니다. **[원문 p.16]**
- GeoExpertQueries는 네 분야의 시험 문제를 포함합니다. **[원문 p.13]**
- 외부에서 작성한 CBGB에서도 전문 기능의 이점이 나타났습니다. **[원문 pp.21–22]**
- 전문 기능의 큰 이점은 두 Gemini 모델에서 반복됐습니다. **[원문 p.19]**

**[해석]** 이는 개발에 사용하지 않은 질문 형식과 외부 문제에 대한 적용 가능성을 보여줍니다. 그러나 새로운 국가·언어·센서·기후권·미래 시점을 분리해 평가한 결과는 아닙니다.

또한 도구의 지리적 적용 범위도 균일하지 않습니다. 예를 들어 원문은 개방 어휘 영상 검색을 미국의 2023–2025년 고해상도 영상에 대해 설명하고, PDFM 유사 지역 검색은 미국 카운티·우편번호 지역을 대상으로 기술합니다. 시스템 이름의 지구 전체 범위가 모든 기능의 전 지구적 검증을 뜻하지는 않습니다. **[원문 pp.31–32, Table 11]**

### 8.3. 향상이 기대되는 경로와 아직 입증되지 않은 부분

**[저자 주장]** 모듈형 스킬은 모델을 재훈련하지 않고 새 기능을 추가할 수 있게 합니다. 지속적으로 바뀌는 지리정보를 모델 파라미터에 모두 저장하기보다, 필요한 자료와 도구를 선택해 사용하는 능력이 중요해질 것이라고 봅니다. **[원문 pp.25–26]**

**[해석]** 가장 유망한 경로는 다음과 같습니다.

- 새 지역의 자료원을 연결해 **데이터 접근 범위**를 넓히기.
- 필요한 기능만 노출해 **도구 선택 부담**을 줄이기.
- 실행 결과에 따라 계획을 수정해 **오류와 자료 부족에 대한 대응력**을 높이기.
- 임베딩을 재사용해 새로운 예측 과제에 필요한 **수작업 특징 설계**를 줄이기.

다만 이 경로들이 **GRA 전체의 OOD 성능을 얼마나 개선하는지**는 이번 논문이 측정하지 않았습니다. 모델 가중치의 일반화, 도구 접근 범위의 확대, 실행 정책의 개선을 별도로 측정해야 합니다.

## 9. 가장 유망한 접근과 빠른 검증 실험

아래는 **[후속 제안]**입니다. 논문이 이미 입증한 개선책이 아니라, 보고된 결과와 한계를 바탕으로 설계한 작은 실험입니다.

| 우선 접근 | 유망한 이유 | 복잡한 모델 없이 검증하는 방법 | 확인할 지표 |
|---|---|---|---|
| **전문 자료·계산 도구의 최소 결합** | 가장 큰 개선이 전문 기능 묶음에서 발생 | 동일 LLM에 경계 조회·통계 조회·공간 계산처럼 소수 기능을 추가하고 기본 검색 구성과 비교 | 수치 정확도, 실제 자료 사용 여부, 실패율 |
| **계획과 실행 지침의 분리** | 현재 +10.5점의 원인이 묶여 있음 | 계획 유무 × 실행 지침 유무의 네 조건을 동일 모델·도구·예산에서 비교 | 개방형 점수, 결과 정확도, 비용, 중단 사유 |
| **수정 가능한 계획** | 모델별 결과 차이를 설명하는 가설 | 초기 계획 고정 조건과 도구 결과 후 수정 허용 조건을 비교 | 실패 회복률, 부적절한 대체자료 비율, 불필요한 호출 |
| **필요시 스킬 공개** | 도구 증가에 대응할 수 있는 단순 구조 | 같은 도구 집합에서 전체 설명 노출과 선택적 로딩을 비교 | 잘못된 도구 선택, 입력 토큰, 캐시 재계산, 성공률 |
| **과정·결과 이중 평가** | 현재 개방형 점수가 결과 정확성을 보증하지 않음 | 전문가 절차 점수와 별도로 수치·단위·좌표계·공간 산출물을 자동 검사 | 절차는 맞지만 결과가 틀린 비율, 실제 오류 유형 |

> **용어 풀이 — 제거·분리 실험, ablation:** 시스템의 일부를 제거하거나 켜고 끄면서 그 요소의 기여를 확인하는 실험입니다.
>
> **좌표계:** 지구상의 위치를 숫자로 표현하는 기준입니다. 서로 다른 기준을 부정확하게 결합하면 거리·면적·겹침 결과가 달라질 수 있습니다.

### 일반화를 검증하려면 추가해야 할 설계

**[후속 제안]**

1. **공간 분리:** 개발과 시험에 같은 지역의 유사 사례가 섞이지 않도록 국가나 지역 묶음 전체를 분리합니다.
2. **시간 분리:** 과거 자료로 구성한 문제와 이후 시점의 자료를 사용하는 문제를 분리합니다.
3. **도구 조합 분리:** 개별 도구는 익숙하지만 조합은 새로운 과제를 시험합니다.
4. **동결 자료와 실시간 자료의 병행:** 고정 스냅샷에서는 재현성을, 실시간 자료에서는 변화 대응력을 측정합니다.
5. **불가능한 문제 포함:** 필수 자료가 없는 경우 적절히 중단하는지, 타당한 대체자료를 선택하는지 평가합니다.
6. **템플릿·지역 단위 불확실성 추정:** 같은 템플릿이나 지역에서 나온 문제를 묶어 재표집하고 점수 차이의 신뢰구간을 보고합니다.

> **용어 풀이 — 스냅샷:** 특정 시점의 데이터 상태를 고정해 보관한 것입니다.
>
> **재표집:** 관측된 표본을 다시 뽑는 과정을 반복해 추정의 불확실성을 살펴보는 방법입니다.

소규모 파일럿은 어떤 가설을 더 크게 검증할지 정하는 데 적합합니다. 그 자체를 일반화 성능 향상의 확정적 증거로 제시해서는 안 됩니다.

좋은 임베딩을 보유하는 것과 그 임베딩을 올바른 질문에 적절히 사용하는 것은 다른 능력입니다.

둘째, GRA의 도구 비종속 평가와 Earth-Agent·GeoAgentBench의 **실제 실행·산출물 검증**은 상호 보완적입니다.  
다양한 타당한 분석법을 허용하면서도 단위·좌표계·수치·지도를 검사하는 평가가 필요합니다.

셋째, UnivEARTH 사례는 높은 정답 점수가 자료 분석의 수행을 보증하지 않을 수 있음을 보여줍니다.  
따라서 **최종 답, 사용한 근거, 실행한 계산**을 함께 기록하고 평가하는 방향이 중요합니다. **[원문 pp.22–26; 위 관련 연구에 기반한 해석]**

## 12. 결론 및 시사점

### 12.1. 저자들이 제시한 시사점

**[저자 보고]** 전문 지리공간 도구와 실행 조정 구조를 강한 범용 모델에 결합하면, 모델 단독이나 기본 도구만으로 처리하기 어려운 분석을 상당 부분 수행할 수 있습니다. 특히 전문 기능의 이점은 여러 벤치마크와 두 모델에서 반복 관찰됩니다. **[원문 pp.24–25]**

동시에 실행 조정 구조는 모델에 맞게 설계해야 합니다. Flash에서는 개방형 과제의 점수가 높아졌지만 Pro와 일부 분야에서는 같은 추가 이점이 나타나지 않았습니다. **[원문 pp.20, 25]**

학술적으로는 **전문가가 독립적으로 작성한 분석 절차, 특정 도구에 종속되지 않는 채점, 동일 모델의 구성 비교**를 함께 제시한 점이 중요합니다. 실용적으로는 전문 분석의 초기 자료 수집과 계산을 지원할 가능성이 있지만, 저자들은 결과물을 전문가 검토를 위한 초안으로 봅니다. **[원문 pp.25–26]**

### 12.2. 저자들이 명시한 후속 연구

저자들은 다음을 후속 과제로 제시합니다. **[원문 pp.25–26]**

- 개방 어휘 영상 검색과 앙상블 기상예보를 다단계 분석 속에서 평가하는 전용 벤치마크.
- 대규모 자료 목록에서 관련 데이터를 발견하고 선택하는 능력 향상.
- 다른 LLM 계열과 네트워크 가능한 기본 도구 구성의 비교.
- 사전 계획과 개별 실행 지침의 효과 분리.
- 실제 기업 질의에서의 효용 평가.
- 전문가 벤치마크 제작을 지원하는 에이전트 활용.
- 대체자료와 분석법 변경의 과학적 타당성을 심사하는 세분화된 자동평가자.

### 12.3. 일반화 관점의 최종 판단

**[해석]** 이 논문이 강하게 뒷받침하는 결론은 **전문 자료와 계산 기능을 사용할 수 있게 만드는 것이 지리공간 분석 성능에 큰 차이를 만든다**는 것입니다. 반면, 특정 계획 방식이 모든 모델·분야에 보편적으로 유리하다거나, GRA가 새로운 지리적 환경에서 안정적으로 일반화한다는 결론까지는 뒷받침하지 않습니다.

가장 생산적인 다음 단계는 거대한 새 모델을 먼저 학습하는 것보다, **동일 모델·동일 자료 접근 조건에서 계획과 실패 대응 정책을 분리하고, 새로운 지역·시간에 대해 과정과 결과를 함께 검증하는 것**입니다. 이 접근은 논문이 보여준 성능 향상의 원인을 더 명확하게 하고, 실제 사용에 필요한 정확성과 일반화의 범위를 확인하게 합니다.
