# Scaling Long-Horizon LLM Agent via Context-Folding

---

## 1. Executive Summary (10문장 이내)

LLM 에이전트는 장기(long-horizon) 태스크 수행 시 컨텍스트 길이 한계라는 근본적 제약에 직면한다.  
기존 요약 기반(summarization-based) 방법은 맥락 흐름을 방해하고, 멀티에이전트 시스템은 수작업 설계에 의존해 일반화가 어렵다.  
본 논문은 **Context-Folding**이라는 새로운 메커니즘을 제안하며, 에이전트가 `branch`와 `return` 두 가지 특수 액션으로 컨텍스트를 능동적으로 관리한다.  
에이전트는 서브태스크를 위한 별도 실행 문맥(sub-trajectory)을 분기(branch)하고, 완료 시 중간 단계를 접어(fold) 간결한 요약만 메인 스레드에 남긴다.  
이를 학습 가능하게 하기 위해 **FoldGRPO**라는 엔드-투-엔드 강화학습 프레임워크를 개발했으며, 언폴딩 토큰 패널티, 범위 이탈 패널티 등 프로세스 보상을 도입했다.  
BrowseComp-Plus와 SWE-Bench Verified 두 벤치마크에서 32K 액티브 컨텍스트(최대 10개 브랜치)만으로 각각 62.0%, 58.0%의 pass@1을 달성했다.  
이는 327K 컨텍스트를 사용하는 ReAct 베이스라인과 동등하거나 이를 상회하는 성능이다.  
FoldGRPO는 표준 GRPO 대비 BrowseComp-Plus에서 +7.7%, SWE-Bench에서 +1.6%의 추가 성능 향상을 제공했다.  
태스크 복잡도가 높아질수록 컨텍스트 폴딩의 이점이 더욱 두드러져, 훈련 시 최대 10개 브랜치로 학습했음에도 50개 질문 복합 태스크에서 평균 32.6개 브랜치를 자율적으로 활용했다.  
본 연구는 컨텍스트를 단순히 확장하거나 휴리스틱하게 압축하는 것보다 능동적 관리를 학습하는 것이 확장 가능한 장기 에이전시(long-horizon agency)를 향한 원칙적인 경로임을 시사한다.

### 1-1. 연구의 목적과 필요성

**목적**: LLM 에이전트가 장기 태스크(딥 리서치, 소프트웨어 엔지니어링 등)를 수행할 때 발생하는 컨텍스트 길이 한계 문제를 해결하고, 효율적이고 확장 가능한 에이전트 프레임워크를 구축하는 것.

**필요성**:
- **성능 저하**: LLM은 지나치게 긴 컨텍스트에서 관련 정보를 활용하는 능력이 저하됨 (p.1, [14, 18, 28] 인용)
- **효율성 저하**: Attention 메커니즘의 이차적(quadratic) 연산 비용 증가 및 KV-cache 오버헤드 (p.1, [13] 인용)
- **기존 방법의 한계**: 요약 기반 방법은 맥락 흐름 단절, 멀티에이전트 시스템은 수작업 설계 필요 (p.1)

> 📌 **용어 설명 - KV-cache**: Transformer 모델에서 Key-Value 행렬을 저장해 재계산을 방지하는 캐시. 컨텍스트가 길어질수록 메모리 사용량이 선형적으로 증가하는 문제가 있음.

> 📌 **용어 설명 - Long-horizon task**: 여러 단계의 상호작용과 다양한 도구 사용이 필요한 복잡하고 장기적인 태스크. 예: 심층 웹 검색, 코드베이스 수정 등.

### 2-1. 해결하고자 하는 문제, 제안 방법, 모델 구조, 성능 향상 및 한계

#### 🔴 해결하고자 하는 문제

LLM 에이전트의 상호작용 이력 $\tau := (a_1, o_1, a_2, o_2, \ldots, a_T, o_T)$는 장기 태스크에서 선형적으로 누적되어 컨텍스트 한계를 초과한다. 기존 ReAct 방식:

$$p_\theta^{\text{ReAct}}(\tau \mid q) = \prod_{i \in [T]} \pi_\theta\bigl(a_i \mid q, (a_1, o_1, \ldots, a_{i-1}, o_{i-1})\bigr)$$

여기서:
- $q$: 입력 질문
- $a_i$: 스텝 $i$에서의 LLM 출력 (추론 및 도구 호출 포함)
- $o_i$: 도구 호출 결과 (observation)
- $T$: 총 상호작용 스텝 수
- $\pi_\theta$: 파라미터 $\theta$를 가진 정책 모델

이 방식은 **전체 이력**을 매 스텝 컨텍스트에 추가하므로 $T$가 커질수록 불가능해진다.

---

#### 🟢 제안하는 방법: Context-Folding + FoldGRPO

**Context-Folding 모델링** (p.3, Eq.1):

```math
p_\theta^{\text{Context Fold}}(\tau \mid q) := \prod_{i \in [T]} \pi_\theta\bigl(a_i \mid q, \mathcal{F}(\tau_{ < i})\bigr)
```

여기서:
- $\tau_{<i} = (a_1, o_1, \ldots, a_{i-1}, o_{i-1})$: 스텝 $i$ 이전의 전체 이력
- $\mathcal{F}(\cdot)$: 컨텍스트 매니저 함수 — `branch`와 `return` 사이의 중간 단계를 접어(fold) 제거하고 요약만 남김

**예시** (p.4):

$$\mathcal{F}(a_1, o_1, \underbrace{a_2, o_2, a_3, o_3, a_4}_{\text{branch 1}}, o_4, a_5, \underbrace{o_5, a_6, o_6, a_7, o_7, a_8}_{\text{branch 2}}, o_8, a_9, o_9, a_{10}, o_{10})$$

$$\rightarrow (a_1, o_1, a_2, o_4, a_5, o_8, a_9, o_9, a_{10}, o_{10})$$

---

**FoldGRPO 학습 목표** (p.5):

```math
\mathcal{J}_{\text{FoldGRPO}} = \mathbb{E}_{\substack{q \sim \mathcal{D}, \\ \{\tau_i\}_{i=1}^G \sim \pi_{\text{old}}(\cdot|q)}} \left[ \frac{1}{\sum_{i=1}^G |\tau_i|} \sum_{i=1}^G \sum_{t=1}^{|\tau_i|} \min\left\{ r_{i,t}(\theta)\widehat{A}_{i,t},\ \text{clip}\!\left(r_{i,t}(\theta), 1-\epsilon_{\text{low}}, 1+\epsilon_{\text{high}}\right)\widehat{A}_{i,t} \right\} \right]
```

> 📌 **용어 설명 - GRPO (Group Relative Policy Optimization)**: 동일 질문에서 여러 궤적을 샘플링해 그룹 내 상대적 보상으로 어드밴티지를 추정하는 강화학습 알고리즘. PPO의 변형.

> 📌 **용어 설명 - Importance sampling ratio**: 현재 정책과 구버전 정책의 확률 비율. 오래된 데이터로 현재 정책을 학습할 때 발생하는 분포 차이를 보정.

**중요도 샘플링 비율**:

$$r_{i,t}(\theta) = \frac{\pi_\theta(\tau_{i,t} \mid q, \mathcal{F}(\tau_{i,<t}))}{\pi_{\theta_{\text{old}}}(\tau_{i,t} \mid q, \mathcal{F}(\tau_{i,<t}))} \cdot \mathbf{1}^{\text{LLM}}_{\tau_{i,t}}$$

**그룹 상대 어드밴티지 추정기**:

$$\widehat{A}_{i,t} = \frac{\text{clip}(R_i + Q_{i,t},\ 0,\ 1) - \text{mean}\!\left(\{R_i\}_{i=1}^G\right)}{\text{std}\!\left(\{R_i\}_{i=1}^G\right)}$$

여기서:
- $G$: 그룹 크기 (논문에서 8로 설정)
- $\tau_i$: $i$번째 샘플링된 궤적
- $|\tau_i|$: 궤적 $\tau_i$의 토큰 수
- $R_i \in \{0, 1\}$: 태스크 성공 여부에 따른 최종 이진 보상
- $Q_{i,t}$: 토큰 수준 프로세스 보상 (아래 설명)
- $\mathbf{1}^{\text{LLM}}\_{\tau_{i,t}}$: LLM 생성 토큰에만 최적화 적용 (도구 관찰 토큰 마스킹)
- $\epsilon_{\text{low}}, \epsilon_{\text{high}}$: 클리핑 파라미터 (각각 0.2, 0.28)
- $\pi_{\theta_{\text{old}}}$: 이전(구버전) 정책

**프로세스 보상 $Q_{i,t}$ 설계** (p.5, §2.3.2):

| 패널티 유형 | 조건 | $Q_{i,t}$ 값 |
|---|---|---|
| Unfolded Token Penalty | 메인 스레드 컨텍스트가 한도의 50% 초과 시, 브랜치 생성 턴 제외한 메인 스레드 토큰 | $-1$ |
| Out-of-Scope Penalty | GPT-5-nano 판단 기준 브랜치 내 범위 이탈 행동 시 해당 브랜치 전체 토큰 | $-0.2$ |
| Failure Penalty | 실패한 도구 호출 턴의 모든 토큰 | $-1$ |
| 기타 | 위 조건 외 모든 경우 | $0$ |

> 📌 **용어 설명 - Process reward**: 최종 결과(outcome)뿐 아니라 중간 과정의 각 단계에 보상을 부여하는 방식. Sparse reward의 한계를 극복하고 특정 행동(여기서는 폴딩)을 직접 유도할 수 있음.

#### 🔵 모델 구조

```
메인 스레드 (Planning State)
├── 고수준 추론 및 태스크 분해
├── branch(description, prompt) 호출 → 서브 스레드 생성
│   └── 서브 스레드 (Execution State)
│       ├── 도구 집중 작업 (검색, 코드 탐색 등)
│       ├── 추가 분기(nested branch) 금지
│       └── return(message) 호출 → 메인 스레드 복귀
│           (중간 단계 fold, 요약만 메인 컨텍스트에 추가)
└── 최종 답변 생성
```

- **베이스 모델**: Seed-OSS-36B-Instruct (p.6)
- **훈련 프레임워크**: VeRL 기반 (p.6)
- **최대 컨텍스트**: 32,768 토큰 (브랜치당), 최대 10개 브랜치 → 이론적 최대 327,680 토큰
- **KV-cache 관리**: `return` 호출 시 `branch` 이전 위치로 KV-cache 롤백 → 효율적 추론

#### 🔴 한계

1. **병렬 브랜칭 미완성**: 병렬 브랜치 실험(BC-Plus: 0.6133)이 단일 브랜치(0.620)보다 낮음 (p.10, §4.5.3)
2. **깊이 우선 태스크에 특화**: BrowseComp 등 깊이 우선(depth-first) 특성 태스크에 최적화, 너비 우선(breadth-first) 태스크(WideSearch 등)에서의 효과 불명확
3. **훈련 인프라 비호환성**: 기존 훈련 인프라(VeRL 등)와 직접 호환 불가, 별도 수정 필요 (Appendix A.1)
4. **중첩 브랜치(nested branch) 미지원**: 실행 상태에서 추가 분기 금지로 계층적 태스크 처리 제한
5. **GPT-5-nano 의존성**: Out-of-scope penalty 계산에 외부 모델 사용 (일반화 비용 증가)
6. **평가 도메인 제한**: 두 가지 태스크(딥 리서치, 소프트웨어 엔지니어링)에만 평가

## 4. 저자 보고 결과 vs. 분석자 해석 분리

### 📋 저자가 직접 보고한 결과

**연구 주제**: 저자들은 LLM 에이전트의 컨텍스트 길이 한계를 능동적 컨텍스트 관리(learned cognitive skill)로 해결하는 프레임워크를 제안함을 명시 (p.1, Abstract).

**방법 (직접 보고)**:
- Context-Folding: `branch`/`return` 두 액션으로 컨텍스트 분기 및 접기 (p.2-3)
- FoldGRPO: 동적 컨텍스트 + 토큰 수준 프로세스 보상 (p.4-5)
- 훈련: Seed-OSS-36B, 50 스텝, 32K 컨텍스트, 최대 10 브랜치 (p.6)

**결과 (직접 보고)**:
- Folding Agent (FoldGRPO): BrowseComp-Plus 62.0%, SWE-Bench 58.0% (Table 1, p.7)
- RL에 의한 절대 성능 향상: BrowseComp +20.0%, SWE-Bench +8.8% (p.2, p.8)
- FoldGRPO vs GRPO: +7.7% (BC-Plus), +1.6% (SWE-Bench) (p.8)
- FoldGRPO: 메인 스레드 약 8K 토큰, 전체 100K+ 토큰 처리 → 90% 이상 압축 (p.8, Table 2)
- 훈련 시간: ReAct 327K 대비 롤아웃 1.52배, 스텝 1.43배 빠름 (Figure 8)
- 훈련 10 브랜치 → 추론 시 50문제에서 평균 32.6 브랜치 자율 활용 (p.9)

### 🔍 분석자 해석

1. **RL의 역할 과대 해석 가능성**: 저자들은 RL 없는 Folding Agent(0.420)도 ReAct 32K(0.286)를 이미 상회함을 보여주는데, 이는 **메커니즘 자체의 구조적 이점**이 상당함을 시사한다. RL의 기여가 강조되어 있으나, 프롬프트 엔지니어링(Appendix B.1에서 기본 프롬프트 대비 0.08→0.478로 향상)의 기여도 상당할 수 있다.

2. **GPT-5-nano 판정 신뢰성 문제**: Out-of-scope penalty 계산에 GPT-5-nano를 사용하는데, 이 판정의 정확도와 일관성이 훈련 품질에 직접 영향을 미친다. 저자들은 이에 대한 검증을 별도로 제시하지 않았다.

3. **SWE-Bench 효과 상대적 제한**: BrowseComp-Plus에서 +20%의 큰 향상과 달리, SWE-Bench에서는 +8.8%에 그친다. 이는 코딩 태스크가 검색 태스크보다 폴딩 메커니즘의 이점을 덜 누린다는 것을 시사하며, 태스크 유형별 적합도 차이가 존재한다.

4. **병렬 브랜칭 실험의 한계**: 병렬 브랜치 실험(0.6133 vs 0.620)의 차이가 통계적으로 유의미한지 불명확하며, 저자들도 "비슷한 성능"이라고 기술한다.

## 7. 가장 중요한 그림 5개 해석

### Figure 1 (p.2) — Context-Folding 동작 예시

**해석**: 딥 리서치(좌)와 에이전틱 코딩(우) 두 태스크에서 Context-Folding의 실제 동작을 보여준다.

- **딥 리서치**: "아티스트 이름 찾기"라는 메인 질문에 대해, 웹 검색(`search`)과 페이지 열기(`open`)를 수행하는 토큰 집약적 작업들을 브랜치 내에서 수행하고, 핵심 발견("Gyedu-Blay Ambolley")만을 메인 스레드에 유지한다.
- **에이전틱 코딩**: 코드베이스 탐색과 수정을 브랜치에서 처리하고, 테스트 통과 여부만 메인으로 반환한다.

이 그림은 **"token-intensive operations를 브랜치에서 격리하고 핵심 통찰만 메인 스레드에 보존"** 하는 핵심 원리를 직관적으로 설명한다.

---

### Figure 2 (p.4) — Context-Folding 메커니즘과 FoldGRPO 훈련 파이프라인

**해석**: 논문의 두 핵심 기여를 하나의 그림으로 통합해서 보여준다.

- **(a) Context-Folding**: 메인 스레드에서 두 개의 서브태스크가 브랜치로 분기되고, 각각 `Branch → Observation/Action → Return` 사이클을 완료한다. 이후 메인 스레드는 `Return`의 요약 메시지만 받아 계속 진행한다.
- **(b) FoldGRPO**: ① $\mathcal{F}$를 이용한 롤아웃 → ② Outcome Reward($R_i$)와 Fold Reward($Q_i$)의 합산 → ③ 그룹 정규화로 Advantage($A_i$) 계산 → ④ Gradient Update 사이클을 보여준다. 특히 Outcome Reward와 Fold Reward가 더해져(+) Advantage를 형성하는 구조가 프로세스 보상의 역할을 명확히 한다.

---

### Figure 3 (p.7) — 난이도별 성능 비교

**해석**: Easy/Medium/Hard 세 난이도에서 RL 전후 성능을 비교한다.

- **핵심 발견**: RL 이득이 Easy보다 **Medium/Hard에서 현저히 크다**. BrowseComp Hard 서브셋에서 RL 없는 Folding Agent는 거의 0에 가까운 성능이지만, RL 훈련 후 유의미한 성능을 보인다.
- **ReAct 327K와의 비교**: Medium/Hard에서 Folding Agent(RL)+가 ReAct 327K를 상회하거나 근접한다.
- **실용적 의의**: 이 결과는 FoldGRPO가 단순한 쉬운 태스크 최적화가 아니라 **복잡한 장기 태스크 처리 능력**을 실질적으로 향상시킴을 의미한다.

> 📌 단, Hard 서브셋은 50개에 불과해 통계적 변동이 클 수 있음을 주의해야 한다.

---

### Figure 4 (p.8) — RL 훈련 중 에이전트 행동 변화

**해석**: 훈련 스텝(x축, 0-50)에 따른 4가지 지표 변화를 난이도별로 보여준다.

- **Tool Calls**: Hard 인스턴스에서 약 15회 → 25회 이상으로 증가. 에이전트가 더 철저한 탐색을 학습함.
- **Number of Branch**: Hard에서 약 3개 → 7개로 증가. 폴딩 전략을 더 적극적으로 활용.
- **Response Tokens**: Hard에서 약 100K → 160K 토큰으로 증가. 더 긴 상호작용으로 복잡한 문제 해결.
- **Number of Pages**: 탐색하는 페이지 수가 꾸준히 증가.

**중요**: 이 4가지 지표가 모두 **난이도에 비례하여 다르게 증가**한다는 점이 핵심이다. 에이전트가 태스크 복잡도에 적응적으로 자원을 할당하는 능력을 학습했음을 보여준다.

---

### Figure 5 (p.9) — 컨텍스트 길이 및 태스크 복잡도에 따른 스케일링

**해석**: 두 가지 스케일링 실험을 보여준다.

- **(좌) Pass@1 vs 최대 컨텍스트 길이**: 브랜치 수 0-16 변화에 따라 Folding Agent(RL)는 모든 구간에서 ReAct를 일관되게 상회한다. 320K 이상에서 성능이 포화(plateau)되는데, 이는 대부분의 태스크가 이미 해결되어 추가 컨텍스트의 한계 이득이 없기 때문이다.
- **(우) Pass@1 vs 복합 질문 수 (1-50개)**: **가장 중요한 결과** — 질문 수가 많아질수록(태스크가 복잡해질수록) ReAct는 급격히 성능이 떨어지지만(ReAct 1M 컨텍스트에서도), Folding Agent는 상대적으로 완만하게 하락한다. 50개 질문에서 격차가 가장 크게 벌어진다. 훈련 시 최대 10 브랜치였으나 추론 시 평균 32.6 브랜치를 사용하며 **강력한 길이 일반화(length generalization)** 능력을 보인다.

## 8. 결론 및 후속 연구 방향

### 8-1. 저자 제시 시사점 및 후속 연구 계획

**시사점 (p.3, p.11)**:
- 컨텍스트를 단순 확장하거나 휴리스틱하게 압축하는 것이 아닌, **능동적 관리를 학습**하는 것이 확장 가능한 장기 에이전시의 원칙적 경로
- 컨텍스트 관리는 외부 아키텍처 문제가 아닌 **학습 가능한 인지 기술**로 프레이밍되어야 함
- RL이 에이전트의 탐색 깊이와 전략적 분해 능력을 유의미하게 향상시킴

**저자 제시 후속 연구 (p.11, §6)**:
- **Multi-layer context folding**: 폴드 자체를 다시 폴딩하는 계층적 전략으로 더 깊은 압축 구현

### 8-1. 모델의 일반화 성능 향상 가능성 (중점)

**현재 일반화 근거**:

본 논문의 Figure 5(우)에서 훈련 시 최대 10 브랜치로 학습했으나, 추론 시 50개 복합 질문 태스크에서 **평균 32.6 브랜치를 자율 생성**했다. 이는 Context-Folding이 태스크 규모에 대한 **강력한 길이 일반화(out-of-distribution length generalization)** 능력을 내포함을 보여준다.

> 📌 **용어 설명 - Length generalization**: 훈련 시 본 길이보다 훨씬 긴 입력/출력에 대해 성능이 유지되는 능력. LLM의 대표적 도전 과제 중 하나.

**일반화 성능 향상 가능성 분석**:

| 측면 | 현재 상태 | 향상 가능성 |
|---|---|---|
| 태스크 유형 일반화 | 딥 리서치, 코딩 2개 도메인 | 수학, 데이터 분석, 멀티모달 태스크로 확장 가능 |
| 컨텍스트 길이 일반화 | 훈련 10 브랜치 → 추론 32.6 브랜치 실증 | 계층적 폴딩으로 이론적으로 무한 확장 |
| 베이스 모델 일반화 | Seed-OSS-36B만 평가 | 다른 아키텍처에서의 검증 필요 |
| 언어/문화 일반화 | 영어 중심 | 다국어 태스크에서 검증 필요 |
| 브랜치 전략 일반화 | 깊이 우선 최적화 | 너비 우선 태스크(WideSearch 등) 적응 필요 |

**일반화를 제한하는 요인**:
1. **Out-of-scope penalty의 GPT-5-nano 의존성**: 판정 모델의 품질이 다른 도메인에서 다를 수 있음
2. **태스크별 프롬프트 엔지니어링**: 현재 BrowseComp와 SWE-Bench에 최적화된 시스템 프롬프트 사용 (Appendix B)
3. **단일 모델 평가**: 36B 모델 외 검증 부재

**향상을 위한 제안**:
- **Domain-agnostic process rewards**: 태스크 유형에 관계없이 적용 가능한 보편적 프로세스 보상 설계
- **Meta-learning 접근**: 다양한 태스크에서 FoldGRPO를 사전 훈련 후 소수 샘플로 특화
- **자기 판정(self-critique)**: 외부 모델(GPT-5-nano) 의존 제거 — 동일 모델이 자체 브랜치 범위를 판정

**Context-Folding의 차별점**:

1. **구조화된 경계**: 요약이 서브태스크 완료 시점에 자연스럽게 발생 — 임의 시점의 요약 단절 문제 해결
2. **엔드-투-엔드 학습**: 폴딩 행동 자체를 RL로 학습 — 수작업 워크플로우 불필요
3. **KV-cache 공유**: 모든 브랜치가 동일한 컨텍스트 프리픽스를 공유해 캐시 효율성 유지

---

**해당 논문이 앞으로의 연구에 미치는 영향**:

1. **컨텍스트 관리의 학습 가능성 정립**: 컨텍스트 관리를 외부 시스템 설계가 아닌 **에이전트가 학습하는 인지 기술**로 보는 새로운 패러다임 제시.

2. **프로세스 보상 설계의 중요성**: Sparse reward만으로는 복잡한 에이전트 행동을 학습하기 어렵다는 실증적 증거 제공. 구체적 프로세스 보상 설계가 에이전트 RL의 핵심 과제로 부상할 것.

3. **RL 훈련 인프라 요구**: Context-Folding의 훈련이 기존 VeRL과 직접 호환 불가능하다는 점은, **장기 에이전트 RL을 위한 새로운 훈련 인프라**의 필요성을 제기한다.

---

**앞으로 연구 시 고려할 점**:

1. **통계적 검증 강화**: 평가 세트 크기 증가(현재 N=150)와 반복 실험을 통한 신뢰구간 보고 필요.

2. **태스크 다양화**: 수학적 추론, 과학적 발견, 멀티모달 태스크로 평가 범위 확장.

3. **판정 모델 의존성 제거**: GPT-5-nano 기반 Out-of-scope 판정 대신 학습된 자기 판정 모듈 개발.

4. **계층적 폴딩**: 폴드를 다시 폴딩하는 재귀적 구조로 이론적으로 무한한 컨텍스트 지평 확장.

5. **브랜치 전략 학습**: 언제, 어떤 서브태스크를 브랜치로 분리할지를 더 정교하게 학습하는 메타-플래닝 전략 연구.

6. **효율성 트레이드오프**: 실제 서비스 환경에서 지연 시간(latency), GPU 비용, 사용자 경험 간의 최적 균형점 연구.

7. **병렬 브랜칭**: 너비 우선 태스크에서 병렬 브랜치 전략의 효과를 체계적으로 연구.
