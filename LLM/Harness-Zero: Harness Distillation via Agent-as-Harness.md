# Harness-Zero: Harness Distillation via Agent-as-Harness

분석 대상은 첨부된 **arXiv:2609.24974v1, 총 25쪽**이며, 페이지 번호는 PDF에 표시된 번호를 따릅니다. 관련 연구는 **2026년 10월 2일 기준으로 확인한 원논문과 공식 자료**를 사용했습니다. 아래에서 **‘저자 보고’는 논문에 명시된 내용, ‘해석’은 그 근거에 대한 제 판단, ‘제안’은 추가 연구 방향**을 뜻하며, 성능 실험을 독립적으로 재현한 것은 아닙니다. :chatgpt-content-reference{index="0"}

## 1. Executive summary

이 논문은 에이전트의 실행을 관리하는 외부 시스템인 **하네스(harness)**가 만들어내는 유용한 행동을 모델 가중치에 학습시켜, 배포 시에는 특화 하네스를 제거하는 **하네스 증류(harness distillation)**를 연구합니다.  
연구의 필요성은 작업마다 다른 특화 하네스를 계속 유지·선택해야 하는 운영 부담과, 하네스 개선이 모델 자체의 능력으로 축적되지 않는다는 문제에서 출발합니다.  
핵심 난점은 원래 하네스와 배포용 하네스의 사용 가능한 도구 및 정보가 달라, 원래 실행 기록을 그대로 모방하기 어렵다는 것입니다. :chatgpt-content-reference{index="1"}

제안 방법인 **agent-as-harness**는 별도의 검토 에이전트가 학생 모델의 응답을 실행 전에 검사하고, 필요한 경우 배포 환경에서 실행 가능한 응답으로 최소한 수정하도록 합니다.  
이렇게 실제 실행된 교정 궤적을 지도 미세조정에 사용한 뒤, 배포에서는 검토 에이전트와 특화 하네스를 제거하고 고정된 최소 하네스만 유지합니다.  
저자들은 Qwen3.5-9B의 세 분야 점수의 단순평균을 **23.3%에서 44.3%로 개선**했으며, 이는 기본 모델에 특화 하네스를 붙였을 때의 **41.7%**보다 높다고 보고합니다. :chatgpt-content-reference{index="2"} :chatgpt-content-reference{index="3"}

다만 USPTO 역합성에서는 증류 모델이 **30.0%**로 특화 하네스를 유지한 모델의 **38.0%**에 못 미쳐, 절차적 행동을 배우는 것과 전문지식·도구 기능을 충분히 이전하는 것은 구분해야 합니다.  
별도 추론 실험에서는 agent-as-harness가 code-as-harness보다 평균적으로 높았고 **81.1% 대 78.1%**, 선택된 28개 행동 패턴의 평균 회복률은 **82.3%**였지만, 이들은 각각 추가 검토 연산을 사용하는 비교와 조건부 행동 측정입니다.  
따라서 이 연구는 **고정된 배포 인터페이스에서 특화 하네스의 일부 이점을 모델 행동으로 이전할 가능성**을 보여주지만, 분야별로 따로 학습했으므로 하나의 범용 모델의 다중 분야 일반화나 미지의 하네스로의 전이를 입증한 것은 아닙니다. :chatgpt-content-reference{index="4"} :chatgpt-content-reference{index="5"} :chatgpt-content-reference{index="6"} :chatgpt-content-reference{index="7"}

## 2. 연구 목적과 해결하려는 문제

### 2.1 왜 하네스를 모델에 학습시키려 하는가?

**저자 보고 — pp. 1–3, §1–2.** 에이전트의 성능은 언어모델만으로 결정되지 않습니다. 도구 사용, 작업 상태, 메모리, 실행 순서, 검증 등을 관리하는 하네스도 큰 역할을 합니다. 하지만 하네스를 개선해 얻은 이익은 대체로 그 하네스를 배포 시에도 유지해야만 나타납니다. 범용 에이전트는 결국 모든 작업에 하나의 덜 적합한 하네스를 쓰거나, 여러 특화 하네스를 유지하고 작업에 따라 선택해야 합니다. 저자들은 이러한 외부 개선을 **모델 파라미터에 축적하는 학습 신호**로 바꾸려 합니다. :chatgpt-content-reference{index="8"} :chatgpt-content-reference{index="9"}

> **용어 풀이:**  
> **하네스**는 모델 주변의 실행 시스템입니다. 예를 들어 “파일을 수정하기 전에 검사하고, 저장 후 검증하며, 위험한 실행은 차단한다”는 절차를 구현합니다.  
> **증류**는 다른 시스템이 보여주는 유용한 출력이나 행동을 학습해, 그 시스템의 도움 없이도 비슷한 행동을 수행하도록 만드는 과정입니다.

**해석.** 이 논문의 목표는 단순한 모델 압축이 아닙니다. 압축하거나 이전하려는 대상은 **‘모델 + 도구 + 실행 규칙 + 축적된 경험’이 함께 만들어내는 행동**입니다. 따라서 연구의 핵심은 “좋은 정답을 많이 수집하는가?”보다 **“배포 시 재현 가능한 좋은 행동을 어떻게 학습 데이터로 바꾸는가?”**에 있습니다. 이러한 해석은 논문이 도구·미들웨어·스킬·메모리를 모두 증류 대상으로 설정한 데 근거합니다. :chatgpt-content-reference{index="10"}

### 2.2 직접 모방학습이 실패하는 두 가지 이유

**저자 보고 — p. 2, pp. 4–5.**

첫째는 **행동 공간의 불일치**입니다. 특화 하네스에서 학생이 `verify_answer` 같은 전용 도구를 호출했더라도, 배포용 하네스에는 해당 도구가 없을 수 있습니다.

둘째는 **관측 가능한 정보의 불일치**입니다. 원래 하네스가 비공개 메모리나 실행 상태 검사에 의존했다면, 그 결과만 모방하는 학생은 배포 시 해당 판단을 뒷받침할 정보를 얻지 못할 수 있습니다. Harness-Zero는 필요한 검사를 학생이 실행할 수 있는 행동으로 바꾸고, 검사 결과도 학생의 관측에 들어오게 합니다. :chatgpt-content-reference{index="11"} :chatgpt-content-reference{index="12"}

> **용어 풀이:**  
> **행동 공간**은 에이전트가 실제로 선택할 수 있는 명령과 도구 호출의 집합입니다.  
> **관측**은 파일 내용, 명령 실행 결과처럼 에이전트가 실제로 확인한 정보입니다. 하네스 내부에서만 아는 정보와 구분됩니다.

**해석.** 핵심 아이디어는 전용 도구의 이름이나 교사의 비공개 판단을 복사하는 대신, **그 기능을 학생의 인터페이스로 다시 구현하고 실행하는 방법을 가르치는 것**입니다. 이는 단순한 정답 증류보다 ‘실행 가능한 절차의 이전’에 가깝습니다.

## 4. 제안 방법과 모델 구조: 수식 중심 설명

### 4.1 전체 구조

**저자 보고 — pp. 3–5, Figure 1.** Harness-Zero는 새로운 신경망 구조라기보다 **학습 데이터 생성과 증류를 위한 시스템 구조**입니다. 세 단계로 구성됩니다.

**하네스 진화·변환 → 학생 응답의 실행 전 검토 → 교정 궤적을 이용한 학습과 배포**입니다. :chatgpt-content-reference{index="20"}

| 구성 요소 | 역할 | 배포 시 유지 여부 |
|---|---|---|
| 학생 모델 $\pi_S$ | 작업을 수행할 다음 응답을 제안한다. | 학습된 학생으로 유지 |
| 목표 하네스 $h$ | 실제 도구 실행과 관측 전달을 담당한다. | 유지 |
| 진화된 하네스 $h^\star$ | 분야별 도구·규칙·스킬·메모리를 제공한다. | 제거 |
| 참조 하네스 $K$ | $h^\star$의 지침을 검토자용으로 변환한 자료다. | 제거 |
| 검토 에이전트 $\pi_H$ | 학생 응답을 통과시키거나 교체한다. | 제거 |

이 구분에서 가장 중요한 점은 **‘하네스가 전혀 없는 배포’가 아니라 ‘특화 하네스와 검토자가 없는 배포’**라는 것입니다. 최종 시스템에는 $h$가 남습니다. :chatgpt-content-reference{index="21"}

### 4.2 단계 1: 하네스의 진화와 변환

**논문 Eq. (1), p. 3**

$$
h^\star=\text{Evolve}(D_{\text{train}}),
\qquad
K=\text{Adapt}(h^\star;h).
$$

**기호 설명:** $D_{\text{train}}$은 학습 과제 집합, $h^\star$는 학습 과제의 실패를 분석해 개선한 학생용 하네스, $h$는 고정된 배포용 하네스, $K$는 검토 에이전트가 읽는 비공개 참조 하네스입니다. $\text{Evolve}$는 하네스 개선 절차, $\text{Adapt}$는 그 기능을 $h$에 맞는 검토 지침으로 바꾸는 절차입니다. :chatgpt-content-reference{index="22"}

저자들의 구현은 **분야별 하나의 공유 하네스**를 만들며, 실패한 과제를 분석하는 과정을 세 라운드 수행합니다. 개별 과제의 정답·파일명·특정 셀 주소 같은 내용은 공유 하네스에 넣지 않도록 지침을 둡니다. 이것은 과제 암기보다 재사용 가능한 실패 교정 규칙을 만들려는 설계입니다. :chatgpt-content-reference{index="23"} :chatgpt-content-reference{index="24"}

변환은 다음과 같습니다.

| 원래 하네스 $h^\star$ | 참조 하네스 $K$ | 의미 |
|---|---|---|
| 전용 도구 | 실행 방법을 설명한 **action recipe** | 학생이 Bash/Python으로 동등한 기능을 구성하도록 한다. |
| 실행을 차단·수정하는 미들웨어 | 검토 미들웨어 | 학생에게 보이는 기록에서 문제 징후를 찾아 검토자에게 알린다. |
| 스킬 | 검토 지침 | 현재 단계에 빠진 절차를 찾아 학생 응답으로 구현한다. |
| 메모리 | 실패 패턴 | 반복되는 실수를 인식하고 적절한 개입을 선택한다. |

출처: **p. 18, Table 6**. :chatgpt-content-reference{index="25"}

> **용어 풀이:**  
> **미들웨어**는 모델의 요청이나 도구 실행 사이에 끼어들어 검사·수정·차단을 수행하는 코드입니다.  
> **스킬**은 특정 종류의 작업을 수행하는 재사용 가능한 절차이고, **action recipe**는 그 절차를 실제 명령으로 구현하기 위한 실행 안내입니다.

### 4.3 단계 2: 실행 전에 학생 응답을 교정한다

먼저 비교 대상인 **code-as-harness**는 기본 모델을 특화 하네스에 직접 연결합니다.

**논문 Eq. (2), p. 4**

$$
y_t\sim\pi_{\theta_0}^{h^\star}(\cdot\mid c_t),
\qquad
c_{t+1}=T_{h^\star}(c_t,y_t).
$$

**기호 설명:** $\theta_0$는 기본 모델의 파라미터, $\pi_{\theta_0}^{h^\star}$는 그 모델이 $h^\star$ 아래에서 다음 응답을 생성하는 확률분포, $c_t$는 시점 $t$의 문맥, $y_t$는 생성 응답입니다. $T_{h^\star}$는 응답을 실행하고 다음 문맥을 만드는 전이 함수입니다. :chatgpt-content-reference{index="26"}

Harness-Zero에서는 학생을 처음부터 목표 하네스 $h$에서 실행합니다.

**논문 Eq. (3), p. 4**

```math
\begin{aligned}
y_t &\sim \pi_S(\cdot \mid c_t, \pi_{\theta_0}, h) \\
c_t &\sim \pi_H(\cdot \mid c_t, y_t, K_r, t, \tilde{y}_t) \\
\tilde{y}_t &= \begin{cases} 
y_t & d_t = \text{PASS} \\ 
z_t & d_t = \text{REPLACE} 
\end{cases} \\
c_{t+1} &= T_h(c_t, \tilde{y}_t)
\end{aligned}
```

**기호 설명:** $\pi_S$는 학생 정책, $\pi_H$는 검토 정책입니다. $d_t$는 통과 또는 교체 결정, $z_t$는 교체용 완전한 응답, $\tilde y_t$는 최종 수락된 응답입니다. $r_{<t}$는 이전 검토 내용과 $K$를 읽은 기록 등 검토자의 비공개 이력입니다. $T_h$는 수락된 응답을 목표 하네스에서 실행하는 함수입니다. :chatgpt-content-reference{index="27"} :chatgpt-content-reference{index="28"}

여기에는 중요한 정보 경계가 있습니다. 학생의 기록에 들어가는 것은 **수락된 응답과 그 실행 결과**뿐입니다. 거절된 초안과 비공개 검토는 들어가지 않습니다. 검토자는 학생의 숨겨진 실행 상태나 정답을 직접 볼 수 없으므로, 추가 근거가 필요하면 학생이 실행할 수 있는 검사 명령을 제안해야 합니다. :chatgpt-content-reference{index="29"}

**구체적 예 — pp. 16, 18–19, Code 1–3.** 스프레드시트의 미리 채워진 예시 셀이 변경됐는지 검사한다고 하겠습니다. 원래 하네스는 실행 환경을 직접 검사하고 완료를 차단할 수 있습니다. 하지만 검토자는 비공개로 검사를 수행하지 않고, 학생의 성급한 완료 응답을 **입력·출력 파일을 비교하는 Python 스크립트 실행**으로 바꿉니다. 그러면 비교 결과가 학생의 관측에 나타나고, 학생은 그 결과를 바탕으로 수정하거나 완료합니다. :chatgpt-content-reference{index="30"} :chatgpt-content-reference{index="31"}

**해석.** 이 설계는 “교사가 맞다고 판단했다”는 결론보다 **“학생도 확인할 수 있는 근거를 만드는 행동”**을 학습하게 한다는 점에서 중요합니다. 다만 ‘최소한의 수정’은 검토 프롬프트의 지침이며, 논문이 별도의 수정 거리 최적화나 최소성 보장을 제공하는 것은 아닙니다. :chatgpt-content-reference{index="32"}

### 4.4 단계 3: 수락된 실행 기록으로 학습한다

**논문 Eq. (4), p. 5**

```math
\hat\theta
=
\arg\min_{\theta}
\left[
-\sum_{\tau\in D_{\text{review}}}
\sum_{t=1}^{T_\tau}
\log \pi_\theta^h(\tilde y_t\mid c_t)
\right].
```

**기호 설명:** $D_{\text{review}}$는 학습에 남긴 검토 완료 궤적 집합, $\tau$는 하나의 궤적, $T_\tau$는 그 궤적의 응답 단계 수, $\hat\theta$는 학습 후 파라미터입니다. 이 목적함수는 수락된 응답 $\tilde y_t$의 생성 확률을 높이는 지도학습입니다. :chatgpt-content-reference{index="33"}

통과된 학생 응답과 교체된 응답을 모두 학습합니다. 다만 교체 응답에 “학생의 초안을 검토하니…”처럼 검토자 관점의 추론이 섞이면 해당 추론 토큰을 손실 계산에서 제외합니다. 비공개 경로·검토 도구명 등이 들어간 궤적도 제거합니다. :chatgpt-content-reference{index="34"}

> **용어 풀이:**  
> **궤적(trajectory 또는 rollout)**은 한 작업에서 이어진 응답·도구 실행·관측의 전체 기록입니다.  
> **지도 미세조정(SFT)**은 이러한 예시 응답을 정답 데이터처럼 사용해 모델을 추가 학습하는 방법입니다.  
> **손실 마스킹**은 특정 토큰을 정답으로 모방하지 않도록 학습 점수 계산에서 제외하는 것입니다.

배포는 다음과 같습니다.

**논문 Eq. (5), p. 5**

$$
y_t\sim\pi_{\hat\theta}^{h}(\cdot\mid c_t),
\qquad
c_{t+1}=T_h(c_t,y_t).
$$

**기호 설명:** $\pi_{\hat\theta}^{h}$는 학습된 모델이 목표 하네스 $h$에서 실행되는 정책입니다. 나머지 기호는 앞과 같으며, 이 단계에는 $h^\star$, $K$, $\pi_H$가 없습니다. :chatgpt-content-reference{index="35"}

### 4.5 실제 모델과 학습 구조

**저자 보고 — pp. 6, 23, §E.** 증류 학생은 **Qwen3.5-9B**, 검토자는 **GPT-5.6 Sol**, 하네스 진화에는 **Kimi K3**를 사용합니다. 학생의 신경망을 새로 설계한 것이 아니라 LoRA로 미세조정합니다. 설정은 rank 32, $\alpha=32$, 배치 크기 8, 최대 길이 65,536토큰, 2에포크, 시드 42이며, 최대 학습률은 $2\times10^{-4}$, 마지막 학습률은 $10^{-6}$입니다. **각 분야는 별도로 학습합니다.** :chatgpt-content-reference{index="36"} :chatgpt-content-reference{index="37"}

LoRA를 이해하기 위한 표준 표현은 다음과 같습니다. **이는 Harness-Zero의 새 수식이 아니라 사용된 학습 기법의 설명식입니다.**

$$
W=W_0+\frac{\alpha}{r_L}BA,
\qquad
A\in\mathbb{R}^{r_L\times d_{\text{in}}},
\quad
B\in\mathbb{R}^{d_{\text{out}}\times r_L}.
$$

**기호 설명:** $W_0$는 사전학습된 가중치, $W$는 적응 후 가중치, $A,B$는 학습하는 작은 행렬, $r_L$은 저랭크 차원, $d_{\text{in}},d_{\text{out}}$은 입력·출력 차원, $\alpha$는 변화량의 크기를 조절하는 계수입니다. LoRA는 전체 가중치 대신 작은 행렬을 학습하는 방식입니다. :chatgpt-content-reference{index="38"}

**구조상의 주의점.** 목표 하네스에는 등록된 도구가 `execute` 하나이지만, Bash 안에서 파일·라이브러리를 사용하고 `agent "<task>"` 명령으로 한 단계의 하위 에이전트 위임도 가능합니다. 따라서 **‘도구 하나’는 ‘외부 계산이나 보조 기능이 없다’는 뜻이 아닙니다.** 논문은 하위 에이전트 사용이 드물다고 설명합니다. :chatgpt-content-reference{index="39"}

### 5.4 행동 회복률 82.3%는 무엇을 뜻하는가?

**저자 보고 — p. 8, §4.5; p. 24, §G.1.** 각 행동에 대해 기본 모델이 $h^\star$에서는 그 행동을 보이고 $h$에서는 보이지 않은 테스트 과제만 선택합니다. 그러한 과제가 10개 이상 있는 행동을 남겨 회복률을 계산합니다. :chatgpt-content-reference{index="52"} :chatgpt-content-reference{index="53"}

이를 정리하면 다음과 같습니다. **아래는 논문의 평가 절차를 제가 수식화한 것입니다.**

```math
S_j=
\left\{
x:
b_j(\tau_{\text{base},h^\star}(x))=1,\
b_j(\tau_{\text{base},h}(x))=0
\right\},
```

$$
R_j=
\frac{1}{|S_j|}
\sum_{x\in S_j}b_j(\tau_{\text{HZ},h}(x)),
\qquad
\bar R=\frac{1}{28}\sum_{j=1}^{28}R_j.
$$

**기호 설명:** $j$는 행동 패턴, $b_j$는 궤적에 그 행동이 있는지 판단하는 0/1 검출기, $x$는 평가 과제, $S_j$는 위 조건에 따라 선택된 과제 집합입니다. $\tau$는 각 실행 설정의 궤적, $R_j$는 패턴별 회복률, $\bar R$은 28개 패턴의 단순평균입니다.

**제가 Table 4의 분수로 재계산한 값**은 다음과 같습니다.

| 집계 방식 | 회복률 | 읽는 방법 |
|---|---:|---|
| 스프레드시트 18개 패턴 평균 | 약 85.3% | 전체 패턴의 다수를 차지한다. |
| USPTO 6개 패턴 평균 | 약 89.5% | 형식 검증·정규화 등의 행동 회복이 높다. |
| AppWorld 4개 패턴 평균 | 약 58.3% | 페이지 전체 조회와 수정 후 재확인이 상대적으로 약하다. |
| 28개 패턴 전체 평균 | **82.3%** | 논문의 보고값을 재현한다. |
| 세 분야의 패턴 평균을 다시 동일 비중으로 평균 | 약 77.7% | 분야별 비중을 같게 하면 다른 값이 나온다. |

원자료: **p. 8, Table 4**. :chatgpt-content-reference{index="54"}

**해석.** 82.3%는 의미 있는 행동 변화의 증거지만, 다음의 제한이 있습니다.

기본 모델의 회복률이 0%인 것은 **표본 선택의 정의상 당연한 결과**입니다. 또한 한 번의 기본 실행에서 행동이 나타나지 않았다는 것은 기본 모델이 그 행동을 생성할 능력을 전혀 갖지 않았다는 뜻이 아닙니다. 마지막으로 USPTO는 행동 회복률이 높아도 정답률은 30%이므로, **절차의 외형을 재현하는 것과 올바른 전문적 결정을 내리는 것은 다릅니다.** :chatgpt-content-reference{index="55"} :chatgpt-content-reference{index="56"}

> **용어 풀이:**  
> **SMILES**는 분자 구조를 문자열로 표현하는 표기법이며, **RDKit**은 분자 구조 처리·검증에 쓰이는 소프트웨어입니다. 논문에서 RDKit 사용을 학습했다는 것은 외부 라이브러리를 호출하는 행동을 배웠다는 뜻이지, 라이브러리의 모든 계산을 모델 가중치로 대체했다는 뜻은 아닙니다. **p. 17, Table 5; p. 25, Table 11.** :chatgpt-content-reference{index="57"} :chatgpt-content-reference{index="58"}

## 6. 가장 중요한 그림과 표의 해석

### Figure 1 — p. 4: 가장 중요한 것은 ‘정보가 지나가는 경로’다

왼쪽 위는 특화 하네스를 검토자용 자료로 변환하는 과정, 가운데는 학생과 검토자의 상호작용, 오른쪽은 학습과 배포입니다. 중요한 경계는 **학생에게 보이는 영역과 비공개 검토 영역의 분리**입니다. 그림 하단의 예시는 초기 파일 읽기는 통과시키고, 검증 없는 완료 시도는 입력·출력 재검사로 교체하는 과정을 보여줍니다. :chatgpt-content-reference{index="59"}

**해석:** 교사의 비공개 결론을 학생에게 전달하는 것이 아니라, 학생이 실행할 수 있는 다음 행동을 전달한다는 설계가 핵심입니다. 다만 이 그림만으로 교정이 항상 올바르거나 충분히 학습 가능하다는 사실까지 증명되지는 않습니다.

### Table 2 — p. 7: 평균보다 분야별 방향이 중요하다

스프레드시트와 AppWorld는 특화 하네스 장착 모델을 넘지만 USPTO는 그렇지 않습니다. 따라서 이 표는 성공 사례이면서 동시에 **증류 가능성이 하네스에 담긴 지식·기능의 종류에 따라 달라질 수 있다는 경계**를 보여줍니다. :chatgpt-content-reference{index="60"}

**해석:** “검토 단계를 추가하면 좋아진다”가 아니라 **‘좋은 지침을 현재 상태에 맞게 적용할 능력이 있는 검토자’가 필요하다**는 결과입니다.

## 8. 일반화 성능 향상 가능성: 무엇이 입증됐고 무엇이 남았는가?

### 8.1 확인된 일반화와 미확인 일반화

| 일반화의 종류 | 논문의 근거 | 평가 |
|---|---|---|
| 같은 분야의 학습에 쓰지 않은 과제로의 일반화 | 별도 평가 과제에서 향상. **§4.1, Table 2.** | **제한된 범위에서 지지됨** |
| 하네스 지침의 모델 간 재사용 | Qwen3.5-9B로 진화한 하네스를 두 강한 모델에 재사용. **p. 6, §4.2.** | **일부 지지됨** |
| 하나의 모델이 여러 분야를 함께 수행 | 분야별 별도 학습. **p. 23, §E.3.** | **미검증** |
| 학습하지 않은 새 분야로의 전이 | 분야를 통째로 제외한 평가가 없다. | **미검증** |
| 학습 때 보지 않은 새 하네스로의 전이 | 학습과 배포에서 같은 목표 하네스 $h$를 사용. **Eq. (3)–(5).** | **미검증** |

근거: **pp. 5–6, 23**. :chatgpt-content-reference{index="82"} :chatgpt-content-reference{index="83"} :chatgpt-content-reference{index="84"}

> **용어 풀이:**  
> **분포 밖 일반화, OOD 일반화**는 학습 때와 종류나 구조가 다른 입력·환경에서도 잘 수행하는 능력입니다. 같은 데이터셋에서 일부 문제를 따로 떼어 평가하는 것보다 강한 요구입니다.

### 8.2 일반화에 유리할 수 있는 설계

**해석.** 다음 세 가지가 유망합니다.

**첫째, 학습과 배포의 실행 인터페이스가 같습니다.** 배포 시 없는 도구를 호출하는 문제를 줄일 수 있습니다. Table 3의 실패 분석은 이 중요성을 뒷받침합니다. :chatgpt-content-reference{index="85"}

**둘째, 답보다 재사용 가능한 절차를 가르칩니다.** “수정 전에 상태 확인”, “저장 후 재검증”, “전체 페이지 조회” 같은 행동은 개별 정답보다 여러 과제에 재사용될 가능성이 큽니다. 다만 이러한 재사용 가능성이 미지의 분야에서 실제 성능 향상으로 이어지는지는 별도 평가가 필요합니다. **Table 4, Tables 9–11.** :chatgpt-content-reference{index="86"}

**셋째, 학생이 실제로 제안한 응답에서 교정합니다.** 교사의 완성된 해결 기록만 제공하는 것보다 학생이 마주치는 상태에 맞는 예시를 만들 수 있습니다. 논문은 복구 가능한 실수는 일부 통과시켜 학생의 자기 복구도 학습하도록 지시합니다. **pp. 21–22, Prompt 1.** :chatgpt-content-reference{index="87"} :chatgpt-content-reference{index="88"}

### 8.3 그러나 일반화 보장과는 거리가 있다

**해석.** 이 방법의 데이터는 기본 학생과 검토자가 함께 만든 상태에서 수집됩니다. 학습 후 학생은 다른 실수를 하고 다른 상태에 도달할 수 있습니다. 따라서 학생 기반 수집이라고 해도 **최종 학습 모델의 모든 실행 상태를 포괄하는 것은 아닙니다.**

논문도 ‘on-policy’를 현재 학생의 실행 도중, 학생의 정보와 행동 공간에 맞춰 교정한다는 뜻으로 설명합니다. 수집된 데이터로 2에포크 학습하는 현재 구성은, 학습 중 매번 최신 학생의 실행을 다시 수집하는 완전한 온라인 절차와는 구별해야 합니다. **p. 21, Prompt 1; p. 23, §E.3.** :chatgpt-content-reference{index="89"} :chatgpt-content-reference{index="90"}

> **용어 풀이:**  
> **On-policy**는 원래 현재 정책이 만들어내는 데이터에 기반한 학습을 뜻합니다.  
> **분포 이동**은 학습 때 보던 상태와 실제 배포에서 만나게 되는 상태가 달라지는 현상입니다.

또한 가중치에 절차를 학습시킨다고 해서 실시간 외부 정보나 강제적 안전장치까지 대체할 수 있는 것은 아닙니다. 예를 들어 파일의 현재 상태는 여전히 읽어야 하고, RDKit 검증은 여전히 실제 계산을 수행합니다. 저자들도 문맥 관리 등 일부 하네스 기능은 응답만으로 표현하기 어렵다고 인정합니다. **pp. 8–9, Limitations.** :chatgpt-content-reference{index="91"}

**가장 중요한 운영상 미해결점은 하나의 공유 모델입니다.** 현재 실험에서는 분야별 체크포인트가 다르므로, 여러 하네스를 선택하던 부담을 실제로 없앴는지, 혹은 분야별 모델 선택 문제로 일부 옮겼는지는 검증되지 않았습니다.

### 9.1 GKD·OPHSD와의 수식적 차이

학생이 생성한 출력에 대해 교사와 학생의 다음 토큰 분포를 맞추는 접근은 다음과 같이 표현할 수 있습니다. **이는 비교를 위한 공통 표현이며 Harness-Zero의 목적함수는 아닙니다.**

$$
\mathcal{L}_{\text{token}} = \mathbb{E}_{x,\hat{y} \sim p_\theta(\cdot \mid x)} \left[ \frac{1}{|\hat{y}|} \sum_{j=1}^{|\hat{y}|} D \left( q_H(\cdot \mid x,\hat{y}_{<j}), p_\theta(\cdot \mid x,\hat{y}_{<j}) \right) \right]
$$


**기호 설명:** $x$는 입력 문제, $\hat y$는 학생이 생성한 출력, $j$는 토큰 위치, $\hat y_{<j}$는 앞서 생성한 토큰들입니다. $p_\theta$는 학생의 다음 토큰 분포, $q_H$는 하네스 등의 도움을 받은 교사의 분포, $D$는 두 분포의 차이를 측정하는 함수입니다. OPHSD의 실제 수식은 하네스가 구성한 최종 문맥을 교사에게 제공하는 형태입니다. :chatgpt-content-reference{index="103"}

**차이점에 대한 해석.** Harness-Zero는 Eq. (4)처럼 **실행된 완전한 응답을 모방**합니다. 핵심 감독 신호가 교사의 모든 다음 토큰 확률이 아니라, 학생 인터페이스에서 유효한 교정 응답입니다. 따라서 차별점은 단순히 “하네스를 학습에 쓴다”가 아니라 **‘환경 상호작용 중 발생하는 행동·정보 불일치를 교정 데이터 생성 단계에서 해결한다’**는 데 있습니다.

### 9.2 특히 조심해야 할 선행연구 숫자 비교

**OPHSD의 USPTO 90.81%와 Harness-Zero의 USPTO 30.0%는 직접 비교할 수 없습니다.** OPHSD는 화학 반응식에서 **10개 반응 유형을 분류**하는 과제이고, Harness-Zero는 생성물에서 **반응물 후보를 예측하는 역합성** 과제입니다. 이름이 같은 코퍼스 계열이라는 이유로 같은 벤치마크로 취급하면 안 됩니다. **OPHSD §4.1, Table 2; Harness-Zero §4.1, Table 2.** :chatgpt-content-reference{index="104"} :chatgpt-content-reference{index="105"} :chatgpt-content-reference{index="106"}

마찬가지로 EvoHarness-RL의 ALFWorld 성공률, WHALE의 best mean@8, Harness-Zero의 pass@1·SGC 평균은 **과제·모델·실행 예산·집계 방식이 달라 숫자만으로 우열을 매길 수 없습니다.**

## 11. 결론: 저자의 시사점과 추가 후속 연구

### 11.1 저자들이 제시한 시사점과 후속 계획

**저자 보고 — p. 9, Future work.** 저자들은 검토 에이전트가 학생의 행동을 실행했을 때 환경이 어떻게 바뀔지 예측해야 한다는 점을 강조합니다. 이에 따라 **더 강한 에이전트 세계 모델**, 모든 응답이 아니라 필요한 경우만 검토하는 **선택적 호출**, 응답 전체 교체보다 세밀한 **토큰 삽입·잠재공간 조정**, 거절된 응답과 수락된 응답의 쌍을 이용한 **선호학습**을 후속 방향으로 제시합니다. :chatgpt-content-reference{index="116"}

> **용어 풀이:**  
> **세계 모델**은 행동이 환경에 가져올 변화를 예측하는 모델입니다.  
> **반사실적 예측**은 실제로 하지 않은 다른 행동을 했다면 어떤 결과가 나왔을지 추정하는 것입니다.  
> **잠재공간 조정**은 출력 문장만 바꾸는 대신 모델 내부 표현에 개입하는 방식입니다.  
> **선호학습**은 같은 상황에서 어느 응답이 더 좋은지에 대한 비교를 이용하는 학습입니다.

장기적인 비전은 여러 분야·과제의 하네스에 축적된 행동과 지식을 하나의 공유 모델에 모으고, 더 좋은 모델이 더 좋은 하네스를 만들며 그 이익을 다시 가중치로 되돌리는 순환입니다. **이것은 논문의 전망이지, 현재 실험에서 완성된 시스템은 아닙니다.** :chatgpt-content-reference{index="117"}

### 11.2 추가 제안: 일반화 검증을 중심으로 한 연구 우선순위

**제안 1 — 분야별 증류에서 ‘공유 모델 증류’로 넘어가야 합니다.**

가장 먼저 세 분야의 궤적을 한 모델에 혼합 학습하고, 분야별 모델과 비교해야 합니다. 이어 두 분야만 학습하고 나머지 한 분야를 평가하는 방식으로, **절차가 정말 분야를 넘어 이전되는지** 확인하는 것이 좋습니다. 일반 언어·추론 평가도 함께 수행해 능력 손실 여부를 측정해야 합니다. AgentTuning의 미학습 과제 및 일반 능력 평가가 참고할 만한 선례입니다. :chatgpt-content-reference{index="118"}

**제안 2 — 과제 수가 아니라 과제 구조를 바꾸는 평가가 필요합니다.**

스프레드시트는 새로운 레이아웃·표 구조, AppWorld는 더 어려운 조합과 API 변화, 역합성은 분자 골격이나 반응 유형을 분리한 평가를 설계할 수 있습니다. 파일명·변수명·명령 표현만 바꾸는 실험도 유용합니다. 성능이 유지되면 구체적인 코드 모양을 암기한 것보다 절차를 배웠다는 주장을 강화할 수 있습니다.

**제안 3 — 최신 학생의 실수에 맞춰 데이터를 다시 수집해야 합니다.**

한 번 수집한 기본 학생 궤적으로 끝내지 말고, 학습된 학생을 다시 실행해 새 실패를 수집한 뒤 교정하는 반복 증류를 검증할 필요가 있습니다. 비교 조건은 총 교사 호출 수와 학습 토큰 수를 맞춰야 합니다. GKD의 학생 생성 데이터 활용과 WHALE의 반복적인 모델·하네스 갱신이 결합 가능한 방향입니다. :chatgpt-content-reference{index="119"}

**제안 4 — 교정의 효과를 검증한 뒤 선호학습에 사용해야 합니다.**

같은 환경 상태를 복제해 원래 응답과 교정 응답을 각각 실행하면, 교정이 실제로 더 좋은지 평가할 수 있습니다. 단순히 검토자가 교체했다는 이유만으로 교정 응답을 항상 더 좋은 응답으로 취급해서는 안 됩니다.

검증된 응답 쌍에는 다음과 같은 DPO 목적함수를 적용하는 방안을 생각할 수 있습니다. **이는 추가 제안이며 Harness-Zero가 실험한 방법은 아닙니다.**

```math
\mathcal L_{\text{DPO}}
=
-\mathbb E_{(c,y^+,y^-)}
\log \sigma
\left[
\beta
\left(
\log\frac{\pi_\theta(y^+\mid c)}
{\pi_{\text{ref}}(y^+\mid c)}
-
\log\frac{\pi_\theta(y^-\mid c)}
{\pi_{\text{ref}}(y^-\mid c)}
\right)
\right].
```

**기호 설명:** $c$는 동일한 학생 문맥, $y^+$는 더 낫다고 검증된 응답, $y^-$는 비교 응답, $\pi_\theta$는 학습 모델, $\pi_{\text{ref}}$는 기준 모델, $\beta$는 기준 모델에서 얼마나 달라질지 조절하는 계수입니다. $\sigma$는 값을 0과 1 사이로 변환하는 시그모이드 함수입니다. DPO는 응답의 상대적 선호를 이용해 직접 모델을 학습하는 방법입니다. :chatgpt-content-reference{index="120"}

**제안 5 — 고정 하네스 성능과 하네스 전이성을 별도로 평가해야 합니다.**

현재처럼 알고 있는 $h$에서 학습·배포하는 실험은 유지하되, 도구 이름·호출 형식·문맥 관리가 다른 목표 하네스를 별도로 남겨 평가해야 합니다. 여러 하네스에서 학습했다는 사실만으로 전이성을 주장해서는 안 된다는 점은 2026년 Multi-Harness RL 연구가 특히 잘 보여줍니다. :chatgpt-content-reference{index="121"}

**제안 6 — 확률적인 행동 학습과 강제적인 실행 보장을 구분해야 합니다.**

필수 검사 수행 여부를 모델의 선택에만 맡길 것인지, 외부의 간단한 강제 규칙을 남길 것인지 비교해야 합니다. ‘특화 하네스 전체 제거’보다 **학습 가능한 절차는 모델에, 반드시 지켜야 하는 실행 제약은 작은 외부 장치에 남기는 혼합 구조**가 더 적합할 수 있습니다. 이는 문맥 관리 등 일부 기능은 남아야 한다는 저자의 한계를 확장한 제안입니다. :chatgpt-content-reference{index="122"}

### 11.3 최종 평가

**Harness-Zero의 가장 중요한 기여는 하네스를 없앴다는 데 있지 않습니다. 하네스가 만들어내는 유용한 행동을, 학생이 실제 배포 환경에서 실행하고 학습할 수 있는 데이터로 바꾸는 경로를 제시했다는 데 있습니다.** Figure 1과 Table 3이 이 방법론적 기여를 가장 잘 뒷받침합니다. :chatgpt-content-reference{index="123"} :chatgpt-content-reference{index="124"}

일반화 관점에서 현재 가장 정확한 결론은 **“분야별 고정 인터페이스에서, 학습에 쓰지 않은 과제에 대한 절차적 행동과 성능 향상이 관찰되었다”**입니다. **“다양한 특화 하네스를 하나의 범용 모델로 통합했다”, “새로운 환경에서도 같은 이익이 유지된다”, “외부 도구·검증이 불필요해졌다”**는 결론은 아직 근거가 부족합니다. 다음 연구의 핵심은 더 높은 평균 점수 하나가 아니라, **공유 모델·미학습 분야·미학습 하네스·반복 실험에서도 이익이 유지되는지**를 보여주는 것입니다.
