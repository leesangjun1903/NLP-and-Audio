# Metaⁿ: Recursive Self-Improvement through Emergent Depth

> **⚠️ 중요 고지**: 본 논문은 arXiv:2608.24735v1로 2026년 8월 25일 자 프리프린트입니다. 동료 심사(peer review)를 거치지 않았으며, 일부 참조 연구(예: GPT-5.2, ARC-AGI-2 [2026], CO-Bench [2026])는 아직 공개되지 않았거나 확인이 불가능한 미래 연구입니다. 이 점을 감안하여 모든 수치를 해석하시기 바랍니다.

## 1. Executive Summary (10문장 이내)

Metaⁿ은 단일 고정 메타 연산 $\Omega$를 자신의 출력에 반복 적용하여 계층적 에이전트 스택을 구성하는 재귀적 자기 개선 프레임워크이다.  
기존 자기 개선 LLM 에이전트들은 **답변(output)**을 개선할 뿐, 답변을 생성하는 **과정(process)** 자체는 개선하지 못한다는 근본적 한계를 지닌다.  
선행 시스템들은 메타 메커니즘 자체를 고정하거나, 자기 편집 시 안정성을 위해 일부 드라이버 레이어를 동결해야 하므로 실현 가능한 메타 깊이가 약 2.5 수준에서 제한된다.  
Metaⁿ은 개선자( $\Omega$ )를 고정하되 그 **입력**을 재귀적으로 심화시켜 이 딜레마를 해소한다.  
각 레이어는 하위 스택의 실행 트레이스와 그것을 생성한 코드 모두를 참조하므로, 깊이가 깊어질수록 더 높은 수준의 추론이 가능해진다.  
스택 깊이는 사전에 고정되지 않고 $\Omega$가 더 이상 개선을 발견하지 못할 때 수렴에 의해 결정되며, 진화적 아카이브가 레이어 체인을 탐색한다.  
8개 벤치마크 패밀리에서 두 가지 백본 모델(Gemma 4 31B-IT, GPT-5.2)을 사용해 평가한 결과, Metaⁿ은 모든 벤치마크에서 기존 자기 개선 에이전트를 능가했다.  
특히 ARC-AGI-2에서 유일하게 0점 초과 성능을 달성하였으며, 이는 스킬 암기에 저항하도록 설계된 벤치마크에서의 메타 수준 추론 능력을 시사한다.  
Ablation 연구는 재귀의 이점 대부분이 레이어 간 전달되는 **컨텍스트 조건화(conditioning)** 채널에서 비롯됨을 보여준다.  
또한 어떠한 프롬프트도 역할을 명시하지 않았음에도, 각 레이어가 깊이에 따라 구별되는 역할(전술적 프리미티브 → 전문 라이브러리 → 롤백/수정)을 자발적으로 창발한다는 점이 주목할 만하다.

> 💡 **용어 설명**
> - **메타 레이어(Meta-layer)**: 기존 솔버를 감싸며 전략적 컨텍스트와 코드 라이브러리를 주입하는 상위 레이어
> - **실현 메타 깊이(Realized meta-depth)**: 시스템이 실제로 동작 중에 행동을 변화시키는 최고 레벨의 수
> - **Ablation 연구**: 특정 구성 요소를 제거하며 각 요소의 기여도를 측정하는 실험

### 1-1. 연구의 목적과 필요성

**목적**: LLM 기반 에이전트가 답변뿐 아니라 답변을 생성하는 **과정 자체를 재귀적으로 개선**할 수 있는 안정적이고 확장 가능한 프레임워크를 제시한다.

**필요성**: 기존 자기 개선 시스템들은 다음 두 딜레마 중 하나에 갇혀 있다.

| 딜레마 | 설명 |
|--------|------|
| 안정성을 위한 깊이 포기 | 드라이버 레이어를 동결 → 메타 깊이 ~2.5 이상 불가 |
| 깊이를 위한 안정성 포기 | 자기 편집 → 시스템 불안정화 위험 |

Metaⁿ은 개선자($\Omega$)를 고정하고 **입력을 재귀적으로 심화**시켜 이 딜레마를 근본적으로 우회한다. Hofstadter(1979)의 *Gödel, Escher, Bach*에서 착안한 **스트레인지 루프(strange loop)** 개념, 즉 자기지시적 재귀가 지능을 창발시킨다는 원리를 LLM 에이전트 설계에 처음으로 실용적으로 구현한 시도이다.

> 💡 **스트레인지 루프(Strange Loop)**: 시스템의 규칙이 자신의 산물에 재귀적으로 적용되어 자기지시적 패턴을 생성하는 현상. Hofstadter는 이것이 지능과 자아의식의 근원이라고 주장했다.

## 2-1. 상세 설명

### 해결하고자 하는 문제

1. **메타-자기개선의 깊이 한계**: 기존 시스템들은 드라이버 레이어를 동결해야 하므로 실현 메타 깊이가 ~2.5에서 막힌다.
2. **크로스-태스크 전이 불가**: OpenEvolve 등은 태스크별 독립 진화 루프를 실행하여 한 태스크에서 발견한 패턴("scipy 사용 금지" 등)을 다른 태스크에 공유할 수 없다.
3. **과정이 아닌 답변만 개선**: Self-Refine, Reflexion 등은 동일 메커니즘으로 생성·진단·수정을 수행하는 단일 반사 레이어에 머무른다.

### 제안하는 방법 (수식 포함)

#### 핵심 수식 1: 메타 연산 $\Omega$ (Eq. 1, p.4)

$$\Omega : \left(\{\tau_i^{(d-1)}\}_{i=1}^N,\ [C_2, \ldots, C_{d-1}],\ \mathcal{T},\ d\right) \longmapsto C_d$$

**기호 설명**:

| 기호 | 의미 |
|------|------|
| $\Omega$ | 고정된 메타 연산 (단일 LLM 프롬프트 절차, 깊이·벤치마크 불문 불변) |
| $\tau_i^{(d-1)}$ | 깊이 $d-1$에서 태스크 $i$의 실행 트레이스 (스크립트, stdout/stderr, 종료 코드, 점수, 피드백) |
| $N$ | 전체 태스크 수 |
| $[C_2, \ldots, C_{d-1}]$ | 이전 라운드가 방출한 코드 스택 |
| $\mathcal{T}$ | 태스크 설명 집합 |
| $d$ | 현재 깊이 |
| $C_d = (f_{\text{pre}}^{(d)}, \mathcal{L}^{(d)})$ | $\Omega$의 출력: 전처리 함수 + 코드 라이브러리 |
| $f_{\text{pre}}^{(d)}$ | 각 솔버 호출 전 실행되는 전략적 컨텍스트 주입 함수 |
| $\mathcal{L}^{(d)}$ | 솔버가 호출할 수 있는 재사용 가능한 Python 함수 라이브러리 |

> 💡 **실행 트레이스(Execution trace)**: 솔버가 실행된 결과 기록. 생성된 스크립트, 표준출력/오류, 종료 코드, 평가 점수를 포함한다. $\Omega$가 "무슨 일이 있었는가"를 이해하는 핵심 정보원이다.

#### 핵심 수식 2: 솔버 스택 구성 (Eq. 2, p.5)

$$S_d = M_d(C_d, S_{d-1}) = M_d \circ M_{d-1} \circ \cdots \circ M_2 \circ S_1$$

**기호 설명**:

| 기호 | 의미 |
|------|------|
| $S_d$ | 깊이 $d$의 솔버 (깊이 $d$까지의 메타 레이어를 모두 포함한 합성 함수) |
| $M_d$ | 깊이 $d$의 래퍼 (Wrapper): $C_d$를 $S_{d-1}$ 주변에 비침습적으로 배치 |
| $S_1$ | 기본 솔버 (단일 LLM 호출 또는 8-턴 agentic 루프) |
| $\circ$ | 함수 합성 연산자 |

> 💡 **래퍼(Wrapper)**: 내부 솔버의 상태를 직접 수정하지 않고 외부에서 감싸는 방식. 내부 솔버의 무결성을 보장하면서 상위 레이어의 전략을 주입할 수 있다.

#### 핵심 수식 3: 최적화 목표

$$\bar{S} = \frac{1}{N} \sum_i \text{score}(\tau_i^{(d)})$$

**기호 설명**:

| 기호 | 의미 |
|------|------|
| $\bar{S}$ | 평균 점수 (최대화 목표) |
| $\text{score}(\tau_i^{(d)})$ | 깊이 $d$ 트레이스 기반 평가 점수 $\in [0,1]$ |

#### 핵심 수식 4: 아카이브-best (§2.4, p.6)

$$\bar{S}^\star = \frac{1}{N} \sum_t \max_{c \in \mathcal{A}} \text{score}(t, c)$$

**기호 설명**:

| 기호 | 의미 |
|------|------|
| $\bar{S}^\star$ | 아카이브-best: 각 태스크에서 최고 체인의 점수 평균 |
| $\mathcal{A}$ | 후보 체인들의 단조 증가 아카이브 |
| $c$ | 아카이브 내 개별 후보 체인 |

#### 핵심 수식 5: 진화적 부모 샘플링 가중치 (§2.4, p.6)

$$w(c) \propto \bar{S}(c) + \frac{\alpha}{1 + \text{children}(c)}$$

**기호 설명**:

| 기호 | 의미 |
|------|------|
| $w(c)$ | 부모 체인 $c$의 샘플링 가중치 |
| $\bar{S}(c)$ | 체인 $c$의 평균 점수 (높을수록 선호) |
| $\alpha$ | 탐색 보너스 계수 ($\alpha = 0.3$으로 고정) |
| $\text{children}(c)$ | 체인 $c$에서 이미 파생된 자식 수 (적을수록 탐색 장려) |

> 💡 **탐색 보너스(Exploration bonus)**: 아직 많이 확장되지 않은 체인을 우선 탐색하도록 유도하는 항. 점수가 높지 않더라도 탐색되지 않은 방향을 시도하여 조기 수렴을 방지한다.

#### 핵심 수식 6: 조건화의 표현 가능 구성 수 상한 (§2.3, p.5)

레이어 조건화(conditioning)로 표현 가능한 구성 수의 이론적 상한:

$$\prod_{d=2}^{n} k_d \quad \text{vs.} \quad \sum_{d=2}^{n} k_d \quad (\text{flat architecture})$$

- $n=4$, $k_d=3$일 때: $3^3 = 27$ (조건화) vs. $9$ (flat)
- $k_d$: 깊이 $d$에서의 구별 행동 수

### 모델 구조

```
[Task Input]
     ↓
  M_n (Meta-Layer n: Meta-strategist, Architect)
     ↓
  M_3 (Meta-Layer 3: Algorithm librarian, Task router)
     ↓
  M_2 (Meta-Layer 2: Generic remediator)
     ↓
  S_1 (Base Solver: Single LLM call or 8-turn agentic loop)
     ↓
[Output + Execution Trace]
     ↑
  Ω reads traces + code stack → writes next layer C_d
```

**두 가지 오케스트레이터 모드**:

| 모드 | 특징 | 장점 | 단점 |
|------|------|------|------|
| 선형(Linear) | 그리디하게 한 번에 한 레이어씩 심화 | 단순, 빠름 | 단일 나쁜 $\Omega$ 호출에 취약 |
| 진화적(Evolutionary) | 아카이브 $\mathcal{A}$ 유지, $B$ 부모에서 $K$ 자식 생성 | 강건성, per-task 최적화 | 토큰 비용 증가 |

**두 가지 솔버 변형**:

| 변형 | 설명 | Layer-1 역할 |
|------|------|------|
| Single-shot | 태스크당 LLM 1회 호출 | $\Omega$ 기여 분리 측정용 |
| Agentic | 최대 8턴 관찰-행동 루프 | 더 강한 기본 트레이스 생성 |

## 4. 저자 보고 결과 vs. 나의 해석 분리

### 저자가 직접 보고한 결과

**연구 주제**: 단일 고정 메타 연산 $\Omega$의 재귀 적용으로 계층적 에이전트 스택을 구성하는 Metaⁿ 프레임워크 제시

**방법 (수식)**:

- $\Omega$를 깊이 $d$에서 반복 적용: $\Omega(\{\tau_i^{(d-1)}\}, [C_2,\ldots,C_{d-1}], \mathcal{T}, d) \mapsto C_d$
- 솔버 합성: $S_d = M_d \circ M_{d-1} \circ \cdots \circ M_2 \circ S_1$

**저자 보고 수치**:

| 항목 | 수치 |
|------|------|
| 재귀 제거 효과 (Gemma CO-Bench) | −0.131 (0.845→0.714) |
| 조건화 채널 기여 | ~72% of recursion gain |
| 코드 라이브러리 채널 기여 | ~15% of recursion gain |
| ARC-AGI-2 dev score | Metaⁿ 0.331 vs. OpenEvolve 0.003, GA 0.054 |
| CO-Bench 샘플 효율성 | ~13× 적은 후보 평가 (29 vs. 378) |
| 역할 분류 합의 | Cohen's κ = 0.59 평균 |

---

### 나의 해석

**긍정적 평가**:

1. **설계 원칙의 명확성**: $\Omega$를 고정하고 입력을 심화하는 접근은 안정성-깊이 딜레마를 개념적으로 우아하게 해소한다. 이 설계 원리는 이론적으로 건전하다.

2. **벤치마크 다양성**: 8개 벤치마크 패밀리(NP-hard 최적화, 법률 분류, 수학적 발견, 추상적 추론 등)에 걸친 평가는 프레임워크의 범용성을 지지한다.

3. **Ablation의 통제성**: 재귀만 제거하는 depth-1 ablation이 두 백본 및 두 벤치마크에서 재현되는 것은 통제 수준이 비교적 높다.

**비판적 해석**:

1. **비교 불가능한 수치 존재**: GPT-5.2는 현재 공개된 모델이 아니므로 독립 재현이 불가능하다. Table 2의 모든 수치는 이 모델에 의존한다.

2. **역할 창발의 해석 과잉 가능성**: Cohen's κ=0.59는 중간 수준의 합의로, 특히 추상적 역할(Compositional architectures: κ=0.30)에서 낮다. "창발적 역할"이라는 강한 주장에 비해 측정의 신뢰도가 제한적이다.

3. **ARC-AGI-2의 카테고리 우위**: 0.331 vs. 0.003이라는 수치 차이는 인상적이나, ARC-AGI-2 자체가 2026년 미공개 벤치마크이며, 두 기준선 모두 사실상 바닥 근처라는 점에서 우위의 의미 해석에 신중함이 요구된다.

## 7. 가장 중요한 그림 5개 해석

### Figure 1 (p.1): Metaⁿ 개요

**좌측 - 재귀적 메타 레이어 스택**:
- Base Solver → Layer 1 → Meta-Layer 2 → Meta-Layer 3 → ··· → Meta-Layer n으로 구성되는 계층 구조
- 각 레이어는 하위 스택 전체를 감싸며, 깊이가 증가할수록 더 추상적인 역할이 창발
- 주목할 점: **어떤 프롬프트도 역할을 명시하지 않았음에도** 역할이 자발적으로 분화됨

**우측 - LawBench 수렴 곡선**:
- Metaⁿ agentic(파란 실선)은 4–8 iteration 내에 빠르게 0.85 이상에 도달
- Gödel Agent(삼각형)와 OpenEvolve(사각형)는 더 느리게 수렴하며 낮은 수준에서 정체
- 별표(⋆)는 held-out test 점수; Metaⁿ은 test에서도 validation과 유사한 성능 유지

> 💡 **Held-out test**: 학습/개발 중 전혀 사용하지 않은 별도 테스트 세트. 과적합 여부를 확인하는 핵심 지표

---

### Figure 2 (p.3): 메타 개선의 3가지 패러다임

**패러다임 (1) - Hand-crafted one-layer meta** (FunSearch, AlphaEvolve, ADAS):
- 외부의 고정된 메타 프로세스가 에이전트를 재작성
- 메타 메커니즘 자체는 절대 변하지 않음 → 실현 메타 깊이 = 1

**패러다임 (2) - Self-referential one-layer meta** (Gödel Agent, DGM):
- 에이전트가 자신의 소스 코드를 편집
- 드라이버 레이어는 동결 필수 → 실현 메타 깊이 ≈ 2.5

**패러다임 (3) - Recursive n-layer meta** (Metaⁿ, ours):
- $\Omega$가 자신의 출력에 반복 적용되며 중첩 박스로 표현
- 버전 $v^d$는 $d$개의 중첩 메타 프로세스를 포함
- **핵심**: 깊이는 수렴에 의해 결정되며, 각 레이어가 하위 전체 궤적을 관찰

---

### Figure 3 (p.5): 메타 레이어의 두 단계

**좌측 (a) - Build-step: $\Omega$가 레이어 2–4를 작성**:

| 깊이 | 점수 | $\Omega$의 행동 |
|------|------|----------------|
| $S_1$ base | 0.767 | - |
| $S_2$ | 0.807 | `fuzzy_match_label()` 방출 (+0.040) |
| $S_3$ | 0.773 | `reconcile_labels()` 추가 + "Exhaustive Legal Analysis" 지시 → **회귀** (−0.034) |
| $S_4$ | 0.833 | "Exhaustive Analysis" 롤백, `reconcile_labels` 유지 → 회복 (+0.060) |

**해석**: $\Omega$가 depth 4에서 코드 스택 $[C_2, C_3]$을 읽고 회귀 원인을 **지시문**으로 귀속시켜 라이브러리는 유지하면서 지시문만 롤백하는 **이차 추론**을 수행함. Flat 루프는 이런 귀인(attribution)이 불가능하다.

**우측 (b) - Run-step: $S_4$가 태스크 실행**:
- 외부 레이어($M_4$)가 먼저 실행되어 전략 프레임 설정
- 컨텍스트가 내부로 흐르며 각 레이어가 정제
- 기본 솔버가 병합된 컨텍스트 + 유니온 라이브러리를 받아 실행

> 💡 **귀인(Attribution)**: 관찰된 결과의 원인을 특정 요소에 연결하는 추론. Depth 4 $\Omega$는 점수 회귀의 원인이 helper 코드가 아닌 지시문임을 코드 스택을 읽어 판단한다.

---

### Figure 4 (p.9): 단일-shot vs. agentic 비교 (4개 벤치마크)

**CO-Bench 패널**:
- Gemma seed: 0.56 → Linear-best: 0.73 → Archive-best: **0.85** (+0.29 total)
- Agentic: 0.80 seed → 0.81 linear → **0.86** (+0.07 incremental over linear)
- 아카이브가 선형 최적 체인 대비 0.05–0.07 추가 이득 제공

**AlphaEvolve Math 패널**:
- 씨드가 약할수록(0.22 vs. 0.43) $\Omega$의 추가 이득이 더 큼 (각각 +0.49, +0.43)
- **해석**: 씨드 강도와 $\Omega$ 기여도 사이의 역관계는 §2.3의 "여유(headroom)" 주장을 지지

**AlgoTune 패널**:
- Single-shot이 agentic보다 우수한 유일한 사례 (×18.5 vs. ×15.1)
- **해석**: Agentic 루프의 풍부한 트레이스 신호가 오히려 $\Omega$를 과도 제약으로 유도

**공통 패턴**: Linear-best와 Archive-best의 일관된 격차는 아카이브의 per-task 선택 이득을 실증함

### Figure 6 (p.10): 깊이별 창발 역할 분석

**코드 기판 (a) - CO-Bench, AE Math, SR**:

| 깊이 | 핵심 패턴 |
|------|-----------|
| Depth 2 | Tactical primitives 28%, Task routing 60% — 범용 유틸리티 방출 |
| Depth 3 | Specialized libraries 68%로 급증; **Rollback 55%로 첫 출현** |
| Depth 4 | Rollback 50% 유지; Tactical primitives 26%로 감소 |

**프롬프트 기판 (b) - S2D, LawBench**:

- **해석**: 단일 $\Omega$ 템플릿이 기판 유형에 따라 **자동으로 다른 전략 공간을 탐색**함 → 진정한 범용성 증거

> 💡 **코드 기판 vs. 프롬프트 기판**: 솔버의 행동 표면이 Python 코드인지(코드 기판) 텍스트 프롬프트인지(프롬프트 기판)의 차이. $\Omega$는 기판에 따라 다른 유형의 코드를 방출한다.

## 8. 결론, 시사점, 후속 연구

### 8-1. 저자 제시 시사점 및 후속 연구 계획

**저자 제시 시사점 (§4, p.12)**:

| 시사점 | 내용 |
|--------|------|
| 딜레마 해소 | 개선자를 동결하고 입력을 심화 → 안정성과 깊이 동시 달성 |
| 조건화의 지배적 역할 | 계층 간 전달되는 단순 문자열 컨텍스트가 ~72% 이득 담당 |
| 역할 창발의 보편성 | 단일 $\Omega$ 템플릿으로 8개 이질적 벤치마크에서 기판 적응적 역할 분화 |
| 메타 깊이 >2의 가치 | 구조적으로 구별되는 레이어가 창발 (첫 실증) |

**저자 제시 후속 연구 방향 (§4, Limitations, p.13)**:

1. **이종 모델 조합**: 강한 모델을 $\Omega$에, 약한 모델을 기본 솔버에 배치하는 실험
2. **구조화된 레이어 간 컨텍스트**: 자유형 문자열 대신 타입화된 표현으로 대체
3. **최적 깊이의 상한 탐색**: 현재 3–6 깊이에서 수렴; 모델 추론 능력 또는 컨텍스트 창 포화가 실제 상한인지 검증

---

### 8-1. 모델의 일반화 성능 향상 가능성 (중점)

**현재 일반화 증거**:

| 측면 | 근거 |
|------|------|
| 도메인 간 일반화 | 8개 이질적 벤치마크 + 2개 백본에서 일관된 성능 우위 |
| 백본 불가지론성 | Gemma와 GPT-5.2 모두에서 동일한 시스템 순서 유지 |
| 기판 적응성 | 코드 vs. 프롬프트 기판에서 자동으로 다른 전략 채택 |
| 크로스-태스크 전이 | `simulated_annealing` 함수가 4개 태스크 패밀리에 전파 |

**일반화 제한 요인**:

1. **Dev→Test 성능 저하의 이질성**: CO-Bench (dev 0.886 → test 0.870, −1.8%)는 양호하나, S2D (dev 0.887 → test 0.725, −18.2%)는 심각한 저하를 보임. 이는 프롬프트 재작성 계약이 단일 분포로 붕괴할 때 메타 레이어가 분포 외 태스크에 일반화하지 못할 가능성을 시사한다.

2. **행동 표면 의존성**: 성능 이득은 실패 모드의 다양성과 직결됨. S2D처럼 행동 표면이 좁은(단일 프롬프트, 22 레이블) 태스크에서는 $\Omega$가 추가할 수 있는 전략 공간이 본질적으로 제한된다.

3. **씨드 강도 의존성**: "씨드와 천장 간의 여유(headroom above seed)"가 충분해야 메타 레이어가 이득을 제공한다. SWE-Bench 실패 사례가 이를 명확히 보여준다.

**일반화 향상을 위한 제언**:

```
현재 아키텍처의 일반화 경로:

① 구조화된 실패 패턴 표현 → Ω의 귀인 능력 강화
   (자유형 문자열 컨텍스트 → 타입화된 실패 분류 트리)

② 메타-학습 통합 → 태스크 분포에 대한 사전 지식 활용
   (MAML 류의 few-shot 적응과 결합)

③ 도메인 적응적 깊이 선택 → 행동 표면 복잡도에 비례한 자동 깊이 결정

④ 크로스-도메인 코드 라이브러리 → 여러 도메인의 유용한 프리미티브 누적
   (태스크 패밀리 간 범용 알고리즘 라이브러리 구축)
```

### 8-2. 2020년 이후 관련 최신 연구 비교 분석

#### 자기 개선 LLM 에이전트 연구 계보

| 연구 | 연도 | 방법 | 메타 깊이 | Metaⁿ 대비 관계 |
|------|------|------|-----------|----------------|
| Self-Refine [Madaan et al.] | 2023 | 자기 피드백 반복 개선 | 1 | 단일 반사 루프; 과정 개선 불가 |
| Reflexion [Shinn et al.] | 2023 | 언어 강화학습 반영 | 1 | 누적 언어 기억 사용; 코드 수정 불가 |
| FunSearch [Romera-Paredes et al.] | 2024 | 집단 프로그램 탐색 | 1 | 메타 루프 고정; 태스크별 독립 탐색 |
| STOP [Zelikman et al.] | 2024 | 재귀적 스캐폴딩 개선 | 1–1.5 | 단일 메타 스텝만 실현 |
| PromptBreeder [Fernando et al.] | 2024 | 프롬프트 진화 | 2 | 프롬프트 공간에 국한; 코드 불가 |
| Gödel Agent [Yin et al.] | 2024 | 소스 코드 자기 편집 | ~2.5 | 드라이버 동결 필요 |
| ADAS [Hu et al.] | 2025 | 자동 에이전트 설계 | 1 | 메타 메커니즘 고정 |
| AlphaEvolve [Novikov et al.] | 2025 | 코드 진화 에이전트 | 1 | 태스크별 독립; 크로스-태스크 전이 없음 |
| DGM [Zhang et al.] | 2025 | 진화 + 자기 수정 | ~2.5 | 아카이브 유지 레이어 동결 |
| OpenEvolve [Sharma] | 2025 | 오픈소스 AlphaEvolve | 1 | MAP-Elites 기반; 단일 태스크 수준 |
| HyperAgents [Zhang et al.] | 2026 | 태스크+메타 에이전트 통합 | ~2.5 | 외부 평가 루프 동결 |
| **Metaⁿ (본 논문)** | **2026** | **재귀적 메타 연산** | **3–6** | **최초 메타 깊이 >2 실증** |

> 💡 **MAP-Elites**: 행동 다양성을 보존하는 진화 알고리즘. 특성 공간을 격자로 분할하고 각 셀에서 최고 성능 개체를 유지한다.

#### Metaⁿ이 앞으로의 연구에 미치는 영향

**긍정적 영향**:

1. **메타-깊이 벤치마킹의 필요성 환기**: 논문이 제안한 "실현 메타 깊이" 분류 체계는 향후 자기 개선 연구의 공통 평가 기준으로 채택될 가능성이 있다.

2. **크로스-태스크 전이 패러다임**: 태스크별 독립 최적화에서 공유 라이브러리 기반 전이 학습으로의 방향 전환을 제시한다.

3. **$\Omega$ 고정 원칙의 보편화**: 개선자를 고정하고 입력을 심화하는 원칙은 다양한 도메인(로보틱스, 과학적 발견, 교육 시스템)에 적용될 수 있다.

4. **역할 창발 연구의 동기 제공**: 계층적 에이전트에서 역할이 자발적으로 창발한다는 발견은 LLM의 내재적 구조 형성 능력에 대한 새로운 연구 질문을 제기한다.

#### 앞으로 연구 시 고려할 점

| 고려 사항 | 세부 내용 |
|-----------|-----------|
| **재현 가능성** | GPT-5.2 등 미공개 모델 의존 실험의 독립 검증이 우선 필요. 공개 모델(Llama 3, Qwen 등)에서의 재현 실험 설계 |
| **계산 비용 정당화** | Agentic 모드 36.1M 토큰 사용은 상당한 비용. 비용-성능 파레토 분석 및 최소 유효 깊이 연구 필요 |
| **이론적 근거 강화** | 조건화의 $\prod k_d$ 이득은 상한선에 불과. 실제 이득의 정보 이론적 분석 필요 |
| **프롬프트 민감도** | 단일 $\Omega$ 프롬프트에 대한 민감도 분석 없음. 프롬프트 변형에 대한 강건성 검증 필요 |
| **장기 동작** | 실행 중 누적 코드가 컨텍스트 창을 채울 때의 성능 저하 및 대응 전략 연구 |
| **안전성** | 자동 생성 코드의 샌드박스 탈출 가능성. AST 기반 정적 분석의 한계(adversarial 코드 등) 탐색 |
| **인간 제어 가능성** | 깊이가 증가함에 따라 메타 레이어의 의사결정이 불투명해질 가능성. 해석 가능성 연구 병행 필요 |
