# ReplaySSM: Cache SSM Inputs, Not State

**분석 기준:** 첨부된 *ReplaySSM: Cache SSM Inputs, Not State*, arXiv:2610.13778v1, 총 35쪽을 기준으로 합니다. 아래 페이지 번호는 첨부 PDF의 번호이며, 외부 연구는 해당 연구의 페이지·절·그림 번호를 별도로 표시했습니다. 실험 수치는 **저자가 보고한 결과**이며, 제가 코드를 실행하여 독립적으로 재현한 결과는 아닙니다. 2610.13778v1

## 1. Executive summary — 8문장

ReplaySSM은 새로운 언어모델을 학습시키는 연구가 아니라, 기존 상태공간모델의 추론 과정에서 **상태를 언제, 어떤 형태로 저장할지**를 바꾸어 처리 속도와 수치적 안정성을 개선하는 연구입니다.  
기존 방식은 토큰마다 전체 상태를 읽고 다시 저장하므로 메모리 이동량이 크고, 추측한 토큰을 거부했을 때 이전 상태로 돌아가기 어려우며, 저정밀 상태의 반올림 오차가 이후 계산에 반복적으로 유입됩니다.  
저자들은 현재 상태를 **이전 시점의 체크포인트와 최근 입력 버퍼의 조합**으로 표현하여, 대부분의 단계에서는 작은 입력만 저장하고 버퍼가 찼을 때 전체 상태를 갱신하도록 제안합니다.  
이 표현은 추측 디코딩에서 거부된 토큰을 버퍼 포인터 조정으로 제외하고, 중간 상태들을 만들지 않고도 검증에 필요한 출력을 계산할 수 있게 합니다. 2610.13778v1

또한 출력 계산에는 저정밀 체크포인트를, 장기적인 상태 갱신에는 상대적으로 고정밀인 체크포인트를 사용하여, **읽기용 저정밀 사본의 반올림 오차가 해당 상태 갱신 경로로 재유입되는 것을 차단**합니다.  
배치 크기 256에서 네 하이브리드 모델의 표준 디코딩 단계는 튜닝된 vLLM 대비 **1.20–1.47배**, 두 120B급 모델의 추측 디코딩 처리량은 약 **1.8배** 향상됐습니다. 2610.13778v1  
Qwen3.5-4B의 128K 토큰 실험에서는 NVFP4 읽기와 FP32 갱신을 분리했을 때, 공유 NVFP4 체크포인트 대비 출력 KL divergence가 **0.136에서 0.0038로 약 36배 감소**했습니다. 2610.13778v1  
따라서 제 판단은 **“기존 모델의 능력을 더 저렴하고 안정적으로 유지하는 중요한 추론 시스템 연구”**이며, 학습하지 않은 과제나 분포에 대한 모델의 일반화 능력이 새롭게 향상됐다고 해석할 근거는 아직 부족합니다. 2610.13778v1 2610.13778v1

> **용어풀이**
> - **상태공간모델, SSM:** 과거 입력을 고정 크기의 내부 상태에 요약하면서 순차적으로 계산하는 모델.
> - **체크포인트:** 여기서는 이전 시점의 *추론 상태 사본*이며, 학습된 가중치 파일을 뜻하지 않음.
> - **버퍼:** 최근 입력의 계산용 벡터를 잠시 보관하는 공간.
> - **추측 디코딩:** 여러 후보 토큰을 먼저 제안하고, 본 모델이 한꺼번에 검증하는 생성 방식.
> - **KL divergence:** 두 확률분포의 차이를 측정하는 값으로, 정확도 자체와는 다른 지표.

## 3. 연구 목적·필요성·모델 구조·제안 방법

### 3.1 해결하려는 문제: 고정 크기 상태도 충분히 비싸다

**저자 보고.** SSM은 문맥이 길어져도 상태 크기가 일정하지만, 각 요청과 각 SSM 층은 별도의 상태를 필요로 합니다. Nemotron-3-Super의 경우 층당·요청당 FP32 상태가 4MiB이며, SSM 층 40개와 Attention 층 8개를 가집니다. 저자들의 계산에서는 SSM 상태 이동량과 Attention 캐시 이동량이 약 81,920토큰에서 같아지고, 실제 지연시간의 교차점은 약 100K토큰에 나타납니다. 이는 **특정 모델·정밀도·하드웨어 설정의 결과**입니다. [pp. 4, 21; Figure 1; Appendix C.2] 2610.13778v1 2610.13778v1

**해석.** “문맥 길이에 대해 메모리가 일정하다”와 “메모리 비용이 작다”는 다른 명제입니다. 특히 요청을 많이 동시에 처리하면, 각 요청의 상태를 읽고 쓰는 비용이 커져 이론적인 선형 시간 복잡도만으로는 실제 속도를 설명하기 어렵습니다.

> **용어풀이:** **HBM**은 GPU의 고대역폭 메모리입니다. **메모리 병목**은 산술 계산보다 데이터를 읽고 쓰는 속도가 전체 실행시간을 제한하는 상황입니다. **KV 캐시**는 Attention이 재사용하는 과거 key·value 벡터들의 저장 공간입니다.

두 번째 문제는 **상태 되돌리기**입니다. 기존 방식은 후보 토큰들을 이미 하나의 상태에 반영했으므로, 일부를 거부하면 수락된 지점의 상태가 필요합니다. 논문에서 비교한 vLLM 방식은 검증 토큰마다 상태 스냅샷을 저장합니다. 세 번째 문제는 **양자화 오차의 재유입**으로, 반올림된 상태가 다음 상태 갱신의 입력이 됩니다. [p. 4, §§3.2–3.3] 2610.13778v1

### 3.3 기본 재귀식과 입력 버퍼

#### A. Mamba-2

논문의 출발점은 다음 식입니다. [p. 3, 식 (1)]

$$
S_t=\alpha_t S_{t-1}+v_tk_t^\top,
\qquad
o_t=S_tq_t.
$$

**기호:** $t$는 토큰 단계, $S_t\in\mathbb R^{d_v\times d_k}$는 상태, $v_t,o_t\in\mathbb R^{d_v}$는 값 벡터와 출력, $k_t,q_t\in\mathbb R^{d_k}$는 키와 질의 벡터입니다. $d_v,d_k$는 각 벡터의 차원이며, $\alpha_t\in(0,1)$는 해당 단계에서 과거 상태를 얼마나 남길지 결정하는 감쇠 계수입니다. $\top$는 전치입니다. 2610.13778v1

> **용어풀이:** $v_tk_t^\top$ 같은 **외적**은 두 벡터로 행렬을 만드는 연산입니다. 이를 이용한 **rank-1 갱신**은 큰 상태 행렬을 비교적 작은 두 벡터로 수정하는 방식입니다. 직관적으로 key는 정보의 주소, value는 내용, query는 현재 꺼내려는 정보를 지정합니다.

#### B. Gated DeltaNet

GDN은 단순히 정보를 추가하는 것에 더해, 기존 기억이 반환하는 내용과 새 내용의 차이를 반영합니다. [p. 3, 식 (2)–(3)]

```math
S_t
=
\alpha_tS_{t-1}(I-\beta_tk_tk_t^\top)
+
\beta_tv_tk_t^\top.
```

이를 다음처럼 쓸 수 있습니다.

$$
u_t=\beta_t(v_t-\alpha_tS_{t-1}k_t),
\qquad
S_t=\alpha_tS_{t-1}+u_tk_t^\top.
$$

**기호:** $I$는 $d_k\times d_k$ 단위행렬, $\beta_t\in(0,1)$는 쓰기 강도, $u_t\in\mathbb R^{d_v}$는 새로 반영할 보정 벡터입니다. 나머지 기호는 앞 식과 같습니다. 즉 Mamba-2의 $v_t$를 GDN에서는 상태 의존적인 $u_t$로 바꾸면 같은 외적 형태가 됩니다. 2610.13778v1

> **용어풀이:** **델타 규칙**은 현재 기억의 응답과 원하는 응답의 차이를 이용해 기억을 수정하는 방식입니다. 따라서 GDN의 버퍼에는 단순한 원시 입력만이 아니라 계산된 보정 벡터도 들어갑니다.

#### C. 재귀식을 전개해 체크포인트와 최근 입력으로 표현

창 내부의 토큰을 $1,\ldots,h$로 번호 매기고, 창 시작 상태를 $S_{\text{ckpt}}$라고 하면 다음과 같습니다. [pp. 4–5, 식 (4)–(5)]

$$
\gamma_{i:j}=\prod_{\ell=i}^{j}\alpha_\ell,
\qquad
\gamma_h=\gamma_{1:h},
$$

```math
\text{Replay}(S_{\text{ckpt}},\mathcal B_{1:h})
=
\gamma_hS_{\text{ckpt}}
+
\sum_{j=1}^{h}
\gamma_{j+1:h}v_jk_j^\top.
```

**기호:** $\mathcal B_{1:h}$는 최근 $h$개의 버퍼 기록, $\gamma_{i:j}$는 $i$부터 $j$까지 누적된 감쇠입니다. $i>j$인 빈 곱은 1로 정의합니다. GDN에서는 $v_j$ 대신 $u_j$를 사용합니다. 2610.13778v1 2610.13778v1

**저자 제안.** 표준 디코딩에서는 입력을 버퍼에 추가하고 출력을 계산하되, 길이가 $L$에 도달했을 때만 버퍼 내용을 체크포인트에 합쳐 저장합니다. [p. 5, Algorithm 1]

**중요한 구별.** Algorithm 1은 GPU 내부에서 작업용 상태를 재구성할 수 있습니다. 따라서 논문의 모든 실행 경로가 “상태를 전혀 만들지 않는다”는 뜻은 아닙니다. 핵심은 **대부분의 단계에서 전체 상태를 HBM에 다시 쓰지 않는다**는 것이고, 다음 절의 출력 전용 방식은 중간 상태의 생성까지 피합니다. 2610.13778v1 2610.13778v1

> **용어풀이:** **flush**는 버퍼의 정보를 체크포인트에 반영하고 버퍼를 비우는 동작입니다. **누적 감쇠**는 과거 기억이 현재까지 얼마나 남아 있는지를 나타냅니다.

### 3.4 메모리 이동량과 창 크기의 절충

FP32 상태, BF16 값·키, FP32 감쇠를 가정한 Mamba-2의 창당 이동량은 다음과 같습니다. [p. 22, 식 (13)]

$$
r=2d_v+2d_k+4,
$$

$$
M_{\text{conv}}=8Ld_vd_k,
$$

```math
M_{\text{replay}}
=
4(L+1)d_vd_k
+
\frac{(L-1)(L+2)}{2}r.
```

**기호:** $r$은 버퍼 기록 하나의 바이트 수, $M_{\text{conv}}$와 $M_{\text{replay}}$는 각각 기존 방식과 ReplaySSM이 한 창에서 이동시키는 바이트 수, $L$은 창 길이입니다. 공통으로 발생하는 작은 입력·출력 이동량은 양쪽에서 제외한 식입니다. 2610.13778v1

상태 이동만 비교하면 비율은 $(L+1)/(2L)$입니다. 그러나 버퍼도 읽고 써야 하므로 실제 총량은 더 큽니다. 저자가 제시한 $d_v=64,d_k=128,L=16$에서는 약 **0.58배**, 즉 약 **42% 감소**입니다.

창을 무조건 크게 만들 수도 없습니다. 저자는 메모리 병목만 고려한 근사 최적값을 다음처럼 도출합니다. [p. 23, 식 (16)]

$$
L^*
\approx
\sqrt{
2\bar a
\left(
\frac{M_S}{r}-T
\right)
}.
$$

**기호:** $M_S$는 상태 하나의 바이트 수, $T$는 단계당 검증 토큰 수, $\bar a$는 단계당 평균 확정 토큰 수입니다. $r$은 기록 크기입니다. 이 식은 실제 flush가 발생하는 시점, 계산량, GPU 내부 저장 공간의 제약을 단순화합니다. 2610.13778v1

**해석.** 논문의 $L=16$은 시험한 설정에서 좋은 선택이지 보편적인 상수가 아닙니다. 특히 실제 탐색은 $L\in\{8,16,32\}$이며, 배치 256에서 수행됐습니다. [p. 27, Figure 9] 2610.13778v1

### 3.5 추측 디코딩: 포인터 기반 복구와 출력 전용 검증

#### A. 버퍼를 상태 표현 자체로 사용

저자들은 크기 $L+T$의 원형 버퍼를 사용합니다. 검증할 입력들을 일단 추가하되, 수락 여부가 결정되기 전에는 확정 길이 $h$를 늘리지 않습니다. 검증 후 수락된 길이 $a$만큼만 포인터를 전진시키고 나머지는 다음 단계에서 덮어씁니다. $h+T>L$이면 **이미 확정된 기록만** 체크포인트에 반영합니다. [pp. 5–6, Algorithm 2; pp. 24–25, Appendix D.1] 2610.13778v1 2610.13778v1

여기서 $1\le a\le T$라는 논문의 계수 규약에 주의해야 합니다. 그림에서 후보가 모두 거부된 경우도 $a=1$로 표시되며, 이를 “수락된 초안이 항상 하나 있다”는 뜻으로 읽어서는 안 됩니다. [p. 8, §7.1; p. 20, Table 4] 2610.13778v1 2610.13778v1

#### B. 중간 상태 대신 출력만 계산

핵심 대수적 관찰은 다음과 같습니다.

$$
(vk^\top)q=v(k^\top q).
$$

왼쪽은 큰 행렬을 먼저 만들지만 오른쪽은 스칼라 내적 $k^\top q$를 먼저 계산합니다. 이를 여러 검증 토큰에 적용하면 다음 식이 됩니다. [p. 6, 식 (6)]

```math
O
=
S_{\text{ckpt}}QD
+
V\left(W\odot(K^\top Q)\right),
```

```math
D_{ss}=\gamma_{h+s},
\qquad
W_{js}
=
\begin{cases}
\gamma_{j+1:h+s}, & j\le h+s,\\
0, & j>h+s.
\end{cases}
```

**기호:** $Q\in\mathbb R^{d_k\times T}$는 검증 질의들, $K\in\mathbb R^{d_k\times(h+T)}$와 $V\in\mathbb R^{d_v\times(h+T)}$는 확정 기록과 검증 기록의 키·값 행렬입니다. $O\in\mathbb R^{d_v\times T}$는 출력, $D$는 대각 감쇠 행렬, $W$는 위치별 감쇠와 미래 차단을 결합한 행렬, $\odot$는 원소별 곱입니다. 2610.13778v1

> **용어풀이:** **인과 마스크**는 현재 토큰이 자신보다 미래에 있는 후보를 참조하지 못하게 하는 장치입니다. **출력 전용 계산**은 이후에 사용하지 않을 중간 상태 행렬을 굳이 만들지 않고 최종 출력만 계산하는 방식입니다.

#### C. GDN에는 보정 벡터 계산이 추가된다

GDN의 새 보정 벡터는 앞선 후보들의 영향을 받으므로 다음 연립방정식을 풉니다. [p. 18, 식 (10)]

$$
U_d(I+AB_d)=RB_d,
$$

```math
R=
V_d-S_{\text{ckpt}}K_dD
-
U_c\left(W_c\odot(K_c^\top K_d)\right).
```

**기호:** $U_c,K_c$는 확정된 보정·키 행렬, $U_d$는 구하려는 후보 보정 행렬, $V_d,K_d$는 후보 값·키 행렬입니다. $B_d=\text{diag}(\beta_{h+1},\ldots,\beta_{h+T})$이며, $W_c$는 $W$의 확정 기록 부분입니다. $A$는 $j<s$일 때 $A_{js}=\gamma_{h+j+1:h+s}k_{h+j}^{\top}k_{h+s}$이고 나머지는 0인 행렬입니다. $I+AB_d$는 대각 원소가 1인 상삼각행렬입니다. 2610.13778v1

> **용어풀이:** **삼각 연립방정식 풀이**는 대각선 한쪽이 0인 행렬의 구조를 이용해 미지수를 효율적으로 구하는 방법입니다. 여기서는 큰 중간 상태들을 모두 만들지 않고 후보 보정값들을 계산하는 데 사용합니다.

### 3.6 이중 정밀도: 출력용 상태와 갱신용 상태 분리

저자들의 두 정밀도 구성은 개념적으로 다음과 같습니다. [pp. 5, 7; Algorithm 3]

```math
\widetilde S_{\text{new}}
=
\text{Replay}
\left(
S_{\text{ckpt}}^{\text{HP}},
\mathcal B_{\text{committed}}
\right),
```

```math
S_{\text{new}}^{\text{HP}}
=
Q_{\text{HP}}(\widetilde S_{\text{new}}),
\qquad
S_{\text{new}}^{\text{LP}}
=
Q_{\text{LP}}(\widetilde S_{\text{new}}).
```

**기호:** HP와 LP는 각각 상대적으로 높은 정밀도와 낮은 정밀도, $\mathcal B_{\text{committed}}$는 확정된 기록, $\widetilde S_{\text{new}}$는 누산 정밀도에서 계산한 새 상태입니다. $Q_{\text{HP}},Q_{\text{LP}}$는 각 저장 형식으로 변환하는 연산입니다. 두 사본은 한쪽을 다른 쪽으로 변환하는 것이 아니라, 같은 계산 결과에서 각각 만듭니다. 2610.13778v1 2610.13778v1

**GDN의 중요한 예외.** 낮은 정밀도에서 계산해 캐시한 $u_j$를 그대로 고정밀 상태에 합치면 오차가 다시 유입됩니다. 따라서 두 정밀도 GDN은 원래 값 $v_j$도 보관하고, flush 때 고정밀 경로에서 $u_j$를 다시 계산합니다. 이 단계가 있어야 논문의 오차 차단 논리가 성립합니다. [p. 19, Appendix B.4, Algorithm 6] 2610.13778v1

#### 오차가 누적되는 이유

Mamba-2에서 실제 저장 상태와 이상적인 상태의 차이를 $D_t$라고 하면 다음과 같습니다. [p. 24, 식 (17)]

```math
D_t=\alpha_tD_{t-1}+e_t
=
\sum_{j\le t}\gamma_{j+1:t}e_j.
```

**기호:** $D_t=\widehat S_t-S_t$는 누적 상태 오차, $\widehat S_t$는 반올림해 저장한 상태, $e_t$는 현재 단계의 새 반올림 오차입니다. 초기 상태 차이는 0으로 둡니다. 과거 오차가 이후 감쇠를 거치며 남는 구조입니다. 2610.13778v1

저자가 가정한 단순화된 경우, 즉 감쇠가 상수 $\alpha$이고 각 원소의 오차가 단계 간 독립이며 평균 $\mu$, 분산 $\sigma^2$일 때는 다음과 같습니다.

```math
\lim_{t\to\infty}\mathbb E[D_t]
=
\frac{\mu}{1-\alpha},
\qquad
\lim_{t\to\infty}\text{Var}(D_t)
=
\frac{\sigma^2}{1-\alpha^2}.
```

**기호:** $\mathbb E$는 평균, $\text{Var}$는 분산입니다. 식은 상태의 개별 원소에 적용한 분석이며, $\mu$는 원문의 편향 기호를 구별하기 위해 바꿔 쓴 것입니다. $\alpha<1$이면 이 단순 모형의 한계값은 유한하지만, $\alpha$가 1에 가까울수록 커집니다. 2610.13778v1

> **용어풀이:** **확률적 반올림, SR**은 가까운 두 표현값 중 하나를 확률적으로 선택해 이상적인 조건에서 평균 편향을 없애는 방식입니다. **최근접 반올림, RTN**은 가장 가까운 값을 고릅니다. SR도 오차의 분산까지 없애지는 못합니다.

**해석상의 제한.** 분리되는 것은 특정 저정밀 사본의 **직접적인 상태 갱신 피드백 경로**입니다. 고정밀 경로의 자체 오차, 출력의 근사 오차, 다른 층으로 전달되는 오차, 생성 토큰이 달라지면서 생기는 이후의 경로 변화까지 모두 없어지는 것은 아닙니다. 실제로 부록은 일부 Nemotron 모델에서 분리 구성의 KL도 길이에 따라 상승한다고 명시합니다. [pp. 24, 30] 2610.13778v1 2610.13778v1

## 6. 모델의 일반화 성능 향상 가능성

### 6.1 현재 증거가 뒷받침하는 것과 그렇지 않은 것

**가장 중요한 구분은 다음과 같습니다.**

| 구분 | 이 논문의 증거 |
|---|---|
| 저정밀 상태에서 장기 생성 정확도를 보존하는가? | 네 모델과 세 정확도 벤치마크에서 상당한 회복을 보고 |
| 기존 FP32 모델보다 새로운 지식·추론 능력이 생기는가? | 입증하지 않음 |
| 학습 길이보다 긴 길이로 일반화하는 능력이 향상되는가? | 학습 길이와의 관계를 통제한 전용 실험이 없어 확정하기 어려움 |
| 새로운 언어·분야·과제 분포에서도 같은 효과인가? | 별도 분포 이동 평가가 충분히 제시되지 않음 |
| 다양한 SSM에 같은 시스템 설계가 적용되는가? | 본문 실험은 Mamba-2와 GDN이며, 모델 일반화와는 다른 의미의 적용 범위 |

근거: 평가 설정, 정확도 결과, 장문 입력 평가의 범위. [pp. 8–9, 25–26, 30–34] 2610.13778v1 2610.13778v1 2610.13778v1

> **용어풀이:** **분포 외 일반화**는 학습·조정 때와 다른 유형의 데이터에서도 잘 작동하는 능력입니다. **길이 외삽**은 학습 때 경험한 길이보다 긴 입력·계산 과정으로 능력을 확장하는 것입니다. **수치적 강건성**은 낮은 정밀도나 연산 오차 때문에 원래 능력이 무너지지 않는 성질입니다.

### 6.2 정확한 연산에서는 일반화 능력을 바꾸지 않는다는 점

**분석적 귀결.** 재학습이나 근사적 생략 없이 같은 재귀식을 정확하게 계산한다면, 모든 동일한 입력 $x$에 대해 다음 토큰 분포도 같습니다.

```math
p_{\theta}^{\text{Replay}}(\,\cdot\mid x)
=
p_{\theta}^{\text{base}}(\,\cdot\mid x).
```

**기호:** $\theta$는 같은 학습 가중치, $x$는 같은 입력 토큰열, $p_\theta$는 다음 토큰의 확률분포입니다. 이는 논문의 재귀식 동등성에서 도출되는 해석이며, 실제 부동소수점 실행이 비트 단위로 동일하다는 뜻은 아닙니다. [근거: p. 4, 식 (4)] 2610.13778v1

따라서 정확한 연산을 기준으로 하면 **저장 방식만 바꿔서 새로운 함수나 추론 능력을 얻는 것은 아닙니다.** 가능한 개선은 유한 정밀도에서 생기던 왜곡을 줄여 원래 함수에 가까워지는 것입니다.

이 구분은 *Repeat After Me: Transformers are Better than State Space Models at Copying*이 다룬 정확한 복사 능력의 구조적 문제와도 연결됩니다. ReplaySSM은 그러한 기억·검색 능력을 새로 학습시키는 방법이 아니므로, 해당 격차를 해결했다고 볼 증거는 없습니다. [비교 연구 p. 1; ReplaySSM p. 1] [arXiv](https://arxiv.org/pdf/2402.01032) 2610.13778v1

### 6.3 RULER-128K 결과를 과대 해석하면 안 된다

**저자 보고.** RULER-128K에서 모든 구성이 FP32 대비 0.3pp 이내입니다. 그러나 입력은 약 130K토큰인 반면 출력은 18–81토큰이고, prefill은 고정밀입니다. 따라서 긴 추론 벤치마크처럼 수백~수천 번의 상태 갱신·양자화를 거치는 평가가 아닙니다. [pp. 33–34, Table 13] 2610.13778v1 2610.13778v1

**해석.** 이 결과는 “긴 입력 이후 짧은 응답을 만들 때 성능이 보존된다”는 근거이지, “128K에 걸친 새로운 장기 추론 일반화가 개선됐다”는 근거는 아닙니다.

#### 최신 방법과의 수식 수준 비교

**DAMP의 위험도.** 기호를 간략히 쓰면, DAMP는 다음 형태의 점수로 보호할 채널을 정합니다. [DAMP p. 6, 식 (8)–(10)]

```math
C_c
=
\frac{E_c}
{\max(1-a_{\text{eff},c}^2,\tau)}.
```

**기호:** $c$는 채널, $E_c$는 교정 데이터에서 측정한 양자화 오차 에너지, $a_{\text{eff},c}$는 감쇠의 기하평균, $\tau>0$는 지속시간 추정의 발산을 막는 하한, $C_c$는 위험 점수입니다. **큰 오차가 오래 남는 채널**을 보호하는 접근입니다. [arXiv](https://arxiv.org/pdf/2608.27513v1)

**LeapQuant의 보정 분해.** 원문의 행렬 방향을 위의 ReplaySSM 표기에 맞추고 평활화 이전 형태만 쓰면 다음과 같습니다. [LeapQuant p. 5, 식 (6)]

```math
\widetilde S
=
Q_{\text{dq}}(S-UK^\top)+UK^\top.
```

**기호:** $S$는 상태, $U\in\mathbb R^{d_v\times r}$와 $K\in\mathbb R^{d_k\times r}$는 고정밀 보정 성분, $r$은 보정 성분의 수, $Q_{\text{dq}}$는 양자화 후 복원하는 연산, $\widetilde S$는 재구성 상태입니다. 여기의 $U,K$는 앞 절의 입력 행렬이 아니라 **보정용 행렬**입니다. 큰 성분을 저정밀 잔차에서 빼내는 방식이며, 전체 고정밀 체크포인트를 별도로 유지하는 ReplaySSM과 저장 비용의 성격이 다릅니다. [arXiv](https://arxiv.org/pdf/2609.38166v1)

**비교 시 특히 중요한 사실:** LeapQuant는 공개된 **BF16 ReplaySSM 커널**을 비교 대상으로 사용했다고 명시합니다. 따라서 관련 직접 비교가 전혀 없다고 말하면 틀립니다. 다만 그것을 첨부 ReplaySSM의 **이중 정밀도 전체 구성에 대한 동일 조건 비교**로 확대할 수는 없습니다. [LeapQuant p. 9, §4.4, Table 2] [arXiv](https://arxiv.org/pdf/2609.38166v1)

**종합 해석.** 앞으로의 경쟁 축은 단순한 “몇 비트인가?”가 아니라, **오차를 얼마나 작게 만들고, 얼마나 오래 남게 하며, 어떤 경로로 다시 상태에 넣는가?**입니다. ReplaySSM은 경로 분리에 강점이 있고, DAMP·STEPQuant는 중요한 부분의 선별 보호, LeapQuant는 작은 고정밀 보정 성분을 통한 압축에 강점이 있는 설계로 비교할 수 있습니다.

## 9. 결론: 저자의 시사점과 추가 후속 연구

### 9.1 저자들이 제시한 시사점

저자들의 핵심 메시지는 **재귀식의 수학적 형태가 “매 단계 전체 상태를 저장하라”는 실행 정책을 강제하지 않는다**는 것입니다. 체크포인트와 최근 입력을 상태 표현으로 사용하면 표준 디코딩의 쓰기를 줄이고, 추측 디코딩의 복구를 단순화하며, 저정밀 출력 계산을 장기 상태 갱신에서 분리할 수 있습니다. [p. 11, §9] 2610.13778v1

Appendix G와 NVIDIA 공식 기술 글은 실제 모델 및 추론 소프트웨어에의 도입을 보고합니다. 이는 실용성을 뒷받침하는 정보이지만, 공동 개발 측의 보고이며 **독립적인 정확도·성능 재현과는 다른 증거**입니다. [p. 35, Appendix G] 2610.13778v1 [NVIDIA Developer](https://developer.nvidia.com/blog/replayssm-rethinking-state-storage-for-faster-hybrid-model-decoding/)

### 9.2 저자의 명시적 후속 연구: 체크포인트 읽기까지 줄이기

현재 방법은 대부분의 쓰기를 없애지만 체크포인트 읽기는 계속 수행합니다. 저자는 누적 감쇠가 충분히 작은 head에서는 과거 체크포인트의 기여를 생략하거나 더 거친 정밀도로 읽는 방향을 제안합니다. [pp. 11, 35; Appendix F, 식 (18)] 2610.13778v1 2610.13778v1

**제 분석: 감쇠만 작다고 안전한 것은 아닙니다.** Mamba-2에서 생략하는 출력 성분은 $\gamma_hS_{\text{ckpt}}q_h$이므로, 국소 출력 오차에는 다음 상한을 사용할 수 있습니다.

$$
\|\Delta o_h\|_2
\le
|\gamma_h|
\,
\|S_{\text{ckpt}}\|_2
\,
\|q_h\|_2.
$$

**기호:** $\Delta o_h$는 체크포인트 항을 생략해 생기는 출력 차이, $\|\cdot\|_2$는 벡터에서는 유클리드 길이, 행렬에서는 최대 증폭률에 해당하는 노름입니다. 이는 논문 식 (18)에 노름 부등식을 적용한 **제 분석식**이지, 저자가 제시한 추가 정리는 아닙니다.

따라서 후속 방법은 $\gamma_h$뿐 아니라 상태와 질의의 크기도 고려해야 합니다. 또한 이 상한이 작아도 이후 층과 생성 과정 전체의 정확도가 보장되는 것은 아니므로 별도의 실험이 필요합니다.

### 9.3 일반화 성능을 중심으로 한 추가 연구 방향

**첫째, 능력 향상과 능력 보존을 분리한 실험이 필요합니다.** 동일한 FP32 모델, ReplaySSM-FP32, 공유 저정밀, 분리 저정밀을 같은 입력과 생성 예산에서 비교해야 합니다. 학습 길이를 명시하고, 긴 입력·긴 출력·낯선 언어·새로운 과제를 독립적인 축으로 바꾸면 길이 외삽과 수치 강건성을 구분할 수 있습니다.

**둘째, 장기 기억을 가진 head를 우선 보호하는 정밀도 정책을 연구할 가치가 있습니다.** 저자의 오차 분석에서는 감쇠가 느린 head가 오차를 오래 보존합니다. DAMP·STEPQuant의 위험도 기반 배분을 읽기용 또는 갱신용 체크포인트에 결합하는 것은 타당한 연구 가설이지만, 교정 데이터와 평가 데이터의 분포가 달라져도 위험도 순위가 유지되는지 검증해야 합니다. 2610.13778v1 [arXiv](https://arxiv.org/pdf/2608.27513v1)

**셋째, 실제 저장량을 맞춘 비교가 중요합니다.** 두 체크포인트, 버퍼, 스케일, 보정 성분을 모두 포함한 동일 메모리 예산에서 정확도와 처리량을 비교해야 합니다. 특히 “읽기 4비트”와 “상태 평균 6비트”는 같은 조건이 아닙니다.

**넷째, 절약한 추론 비용이 실제 과제 성능으로 이어지는지 검증해야 합니다.** 같은 GPU 시간 안에서 더 많은 후보 답안이나 검증 단계를 수행할 수 있다는 가능성은 있지만, 속도가 빨라졌다는 사실만으로 답의 정확도가 올라가지는 않습니다. 고정 토큰 수 비교와 고정 시간·비용 비교를 분리해야 합니다.

**다섯째, 재현성과 불확실성 보고를 강화해야 합니다.** PG-19는 더 많은 책과 여러 SR 시드로, 정확도는 질문 단위의 쌍별 재표집으로, 서비스 성능은 실제 요청 길이 분포와 전력 조건까지 포함해 평가하는 것이 바람직합니다. 작은 정확도 상승보다 큰 손실이 사라지는지, 특정 모델·언어·길이에서 실패가 집중되는지를 우선 확인해야 합니다.

### 최종 판단

**ReplaySSM의 가장 중요한 기여는 모델의 일반화 능력을 새로 만드는 것이 아니라, 그 능력을 손상시키는 추론 시스템의 비용과 수치 오차를 줄이는 데 있습니다.** 특히 긴 생성에서 저정밀 상태의 오차가 재귀적으로 되먹임되는 문제를 실행 구조의 분리로 다룬 점이 강합니다. 다만 일반화 향상을 주장하려면, 앞으로 **학습 분포 밖의 평가·동일 메모리 예산 비교·실제 저비트 통합 실행·여러 시드의 불확실성 분석**이 추가되어야 합니다.
