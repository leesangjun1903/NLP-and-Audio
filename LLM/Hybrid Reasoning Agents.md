# Hybrid Reasoning Agents

보고서에서 **[저자 보고]**는 원문에 직접 제시된 내용, **[분석]**은 그 근거가 허용하는 범위의 해석, **[후속 제안]**은 아직 검증되지 않은 실험 계획을 뜻한다.  후속 제안의 예상 성과를 논문의 결과처럼 서술하지 않는다.

## 1. Executive summary, 연구 배경 및 목표

### 1.1. Executive summary — 10문장

1. 이 논문은 단어를 출력하지 않고 연속 벡터로 계산하는 **잠재 추론**과 텍스트를 통한 도구 사용을 하나의 생성 과정에 통합하는 **HybridAgent**를 제안한다. **[pp.1–5, Figure 1]**
2. 핵심 모듈인 **HybridLink**는 모델의 마지막 층 은닉상태를 다음 입력에 적합한 벡터로 변환하고, 연속적인 KV 메모리는 텍스트·잠재 상태·도구 결과를 여러 턴에 걸쳐 유지한다. **[pp.4–5, 식 (4)–(6), Figure 3]**
3. 학습은 모델이 자신의 잠재 입력에 적응하도록 하는 **HybridSFT**와, 텍스트·잠재 추론의 사용 방식을 보상으로 개선하는 **HybridRL**로 구성된다. **[pp.6–8, Figure 4, Algorithm 1]**
4. 평가는 Qwen3-Base의 4B·8B·14B에서 이루어졌지만, 11개 벤치마크 전체 평가는 8B·14B에 해당하며 4B는 4개 과제에서 평가되었다. **[pp.8–10, 35, Tables 1·2·8]**
5. 14B HybridAgent는 GAIA에서 52.4, WebWalker에서 49.5를 기록하여 같은 크기의 ARPO 결과인 43.7과 40.5를 웃돌았다. **[p.9, Table 1]**
6. 수학·지식 과제에서도 동급 강화학습 비교군보다 높은 점수를 보였으나, MATH500의 88.2 대 87.4처럼 차이가 작은 경우에는 개별 비교의 통계적 유의성을 확인할 정보가 부족하다. **[p.10, Table 2]**
7. 효율성 측면에서는 텍스트 토큰과 전체 생성 단계가 감소했고, Figure 7의 통합 측정에서는 추론 시간이 134초에서 63초로 줄었으며, 2.7–3.7배 비용 절감은 별도의 가정에 따른 생성 연산비 추정치이다. **[pp.10–11, Figures 6·7; pp.35–36, Table 9]**
8. 잠재 상태를 교란하면 정확도가 하락하고 최근접 토큰으로 읽어 낸 문자열이 질문과 관련성을 보이지만, 이것만으로 내부 계산 전체의 의미가 충실하게 설명된다고 결론 내릴 수는 없다. **[pp.13, 34–35, Table 5, Appendix F]**
9. 일반화에 관한 가장 중요한 제약은 수학용과 검색·에이전트용으로 서로 다른 강화학습 체크포인트를 사용했다는 점이며, 새로운 모델 계열·미학습 도구·명시적인 분포 밖 환경으로의 일반화는 입증되지 않았다. **[p.38, Appendix H.3]**
10. 따라서 이 연구의 가장 설득력 있는 기여는 **잠재 추론을 실제 도구 사용 에이전트로 연결하는 구조와 학습 절차**이며, 초록의 평균 10.4% 향상이나 광범위한 일반화 주장은 공개된 집계 방식과 평가 범위를 함께 고려해야 한다. **[pp.3–10, Tables 1·2]**

### 1.2. 연구가 해결하려는 문제

**[저자 보고]** 논문의 문제의식은 내부 추론에 적합한 표현 방식과 외부 환경에 적합한 표현 방식이 다르다는 데서 출발한다. **[p.2, Introduction]**

- **텍스트 중심 에이전트의 부담:** 중간 추론을 모두 토큰으로 생성하면 출력 길이와 생성 시간이 늘어난다.
- **잠재 추론의 연결 문제:** 연속 벡터만으로 추론하면 검색·Python 실행 같은 외부 도구 호출을 자연스럽게 수행하기 어렵다.
- **감사와 학습의 어려움:** 잠재 상태는 사람이 직접 읽기 어렵고, 텍스트 토큰의 확률을 전제로 하는 학습 방법을 그대로 적용하기도 어렵다.
- **다중 턴 문맥 보존 문제:** 잠재 상태가 섞인 추론 이력은 텍스트 로그를 다시 토큰화하는 방식만으로 복원할 수 없다. **[pp.2, 5, 7]**

> **용어 풀이 — 에이전트:** 답변 생성 외에 도구 호출, 결과 관찰, 다음 행동 선택을 반복하는 시스템.  
> **잠재 상태:** 모델 내부에서 계산되는 수치 벡터로, 반드시 하나의 단어나 문장에 대응하지는 않는다.  
> **다중 턴:** 추론과 도구 실행이 한 번으로 끝나지 않고 여러 차례 이어지는 과정.

### 1.3. 연구 목적과 필요성

**[저자 보고]** 목표는 내부 계산에는 잠재 공간을 활용하고, 도구 호출·중요한 결정·최종 답변에는 텍스트를 사용하면서 두 모드를 동적으로 오가는 에이전트를 만드는 것이다.  
이를 위해 구조, 학습, 추론 실행 환경을 함께 설계한다. **[pp.2–8]**

**[분석]** 이 연구에서 필요한 것은 잠재 벡터를 생성하는 기능만이 아니다.  
실제 도구 사용 중에도 문맥을 유지하고, 모델이 자신이 생성한 연속 입력을 안정적으로 처리하며, 외부에서 확인할 정보가 남도록 해야 한다.  
논문의 가치는 이러한 요구를 하나의 실행 가능한 학습·생성 체계로 묶었다는 데 있다. **[Figures 1·3·4·12]**

### 2.3. 모델 구조: 공유 Transformer와 두 가지 입력 경로

**[저자 보고]** HybridAgent는 하나의 Transformer를 공유하면서 다음 입력을 만드는 방식만 모드에 따라 바꾼다. 원문 식 (1)–(2)는 배경이 되는 일반적 하이브리드 생성을 설명하며, 제안 방식은 잠재 입력에 식 (4)의 HybridLink를 적용한다. **[pp.3–4]**

이를 제안 모델 기준으로 함께 쓰면 다음과 같다.

$$
y_{t+1}\sim \text{Softmax}(W_{\text{out}}h_t),
$$

$$
e_{t+1}=
\begin{cases}
\text{Emb}(y_{t+1}), & \text{텍스트 모드},\\
\mathcal R(h_t), & \text{잠재 모드},
\end{cases}
\qquad
h_{t+1}=f_\theta([E_{\leq t};e_{t+1}]).
$$

**기호 설명**

- $t$: 생성 위치.
- $h_t$: 마지막 Transformer 층의 은닉상태.
- $y_{t+1}$: 다음 텍스트 토큰.
- $e_{t+1}$: 다음 위치의 입력 벡터.
- $W_{\text{out}}$: 은닉상태를 어휘별 출력 점수로 바꾸는 행렬.
- $\text{Emb}$: 토큰을 입력 임베딩으로 바꾸는 함수.
- $\text{Softmax}$: 출력 점수를 토큰 확률로 변환하는 함수.
- $E_{\leq t}$: 지금까지의 입력 벡터 목록.
- $f_\theta$: 파라미터 $\theta$를 가진 기반 Transformer.
- $\mathcal R$: HybridLink.

**출처: 원문 식 (1)·(2)·(4)를 제안 모델 기준으로 통합한 표기, pp.3–4.**

> **용어 풀이 — 임베딩과 은닉상태:** 임베딩은 모델에 넣는 입력 표현이고, 은닉상태는 모델 내부 계산의 결과이다. 차원이 같더라도 값의 분포와 역할은 다를 수 있다.

#### HybridLink: 은닉공간과 입력공간의 정렬

$$
\boxed{
e_{t+1}=\mathcal R(h_t)
=h_t+W_2\sigma(W_1h_t)
}
$$

여기서 $W_1,W_2$는 학습 가능한 선형변환, $\sigma$는 GELU 같은 비선형 활성화 함수이다. $h_t$를 그대로 더하는 경로가 **잔차 연결**이다. 저자는 추가 파라미터를 약 $2d_h^2$로 설명하며, $d_h$는 은닉 차원이고 4B 모델에서는 약 1천만 개 수준이라고 제시한다. **[p.4, 식 (4), Figure 1]**

> **용어 풀이 — 잔차 연결:** 원래 입력을 변환 결과에 더하여, 모델이 전체 표현을 새로 만드는 대신 필요한 차이를 학습하도록 하는 구조.

**[분석]** 이 설계의 근거는 “은닉 벡터를 그대로 입력해도 된다”는 가정을 완화하는 데 있다. Table 6에서 직접 재사용보다 학습된 정렬 모듈이 높은 성능을 보인다. 다만 잔차 연결이 의미를 완벽하게 보존한다는 수학적 보장이 제시된 것은 아니다. **[p.14, Table 6]**

#### 모드 진입과 종료

텍스트 모드에서 `<latent>`가 생성되면 잠재 모드로 들어간다. 잠재 모드에서는 토큰을 샘플링해 재입력하지 않고 $\mathcal R(h_t)$를 연속적으로 사용한다. 종료 조건은 다음과 같다.

$$
\text{argmax}_{v\in\mathcal V}
\cos\!\left(\mathcal R(h_t),\text{Emb}(v)\right)
=\texttt{</latent>}.
$$

- $\mathcal V$: 어휘 집합.
- $v$: 어휘에 속한 토큰.
- $\cos(a,b)$: 두 벡터 방향의 유사도.
- `</latent>`: 잠재 모드를 종료하는 경계 토큰.

**출처: p.5, 식 (5); 종료 신호의 학습은 p.28, Appendix B.2.**

이 최근접 토큰 대응을 각 잠재 단계에 적용하면 읽기용 **pseudo-text**를 얻는다.

> **용어 풀이 — pseudo-text:** 연속 벡터를 가까운 토큰에 대응시켜 얻은 문자열. 잠재 모드가 실제로 생성해 다시 입력한 텍스트와는 구별된다.

**[분석상 주의]**

- 전환은 **16–256단계의 길이 제한 안에서 적응적**이다.
- “토큰 디코딩을 생략한다”는 설명은 토큰 샘플링과 재임베딩 경로를 생략한다는 의미이다.
- 종료 판정에는 어휘 임베딩과의 비교가 있으므로, 잠재 모드에서 어휘 관련 계산이 전혀 없다고 설명하면 부정확하다. **[식 (5), p.39]**

### 2.4. 다중 턴 working memory

**[저자 보고]** 텍스트, 잠재 입력, 도구 관측을 처리하면서 생성되는 모든 층의 key–value 항목을 보존하고 다음 턴에서 이어 사용한다. **[p.5, Figure 3]**

원문 식 (6)을 단계별 갱신 형태로 정리하면 다음과 같다.

$$
\mathcal M^{(0)}
=[K_{\leq |x|},V_{\leq |x|}],
\qquad
\mathcal M_{t+1}
=\mathcal M_t\oplus[K_{t+1},V_{t+1}].
$$

- $\mathcal M^{(0)}$: 최초 입력 $x$를 처리한 뒤의 메모리.
- $|x|$: 최초 입력 길이.
- $\mathcal M_t$: 위치 $t$까지 누적한 모든 층의 KV 메모리.
- $K,V$: attention에서 과거 정보를 참조하는 key와 value.
- $\oplus$: 순서를 유지하는 이어 붙이기.

> **용어 풀이 — KV cache:** 과거 입력을 매번 재계산하지 않도록 저장하는 attention 중간값. 이 논문에서는 잠재 상태가 포함된 문맥을 다음 턴으로 전달하는 역할도 한다.

부록의 Theorem A.1은 다음 동등성을 보인다.

$$
h_{t+1}^{\text{cached}}
=f_\theta([E_{\leq t};e_{t+1}]).
$$

왼쪽은 저장된 KV로 이어 계산한 은닉상태이고, 오른쪽은 동일한 전체 하이브리드 입력을 다시 처리한 은닉상태이다. **[pp.25–26, 식 (12)]**

**[분석]** 여기서 “무손실”은 **후속 계산의 동등성**을 뜻한다. 동일한 모델, 위치 인코딩, 마스크, 계산 조건과 모든 기존 KV의 보존이 필요하다. KV 압축·삭제·양자화 이후의 동등성이나, 원래 입력을 KV에서 완전히 역복원할 수 있다는 성질까지 증명한 것은 아니다.

### 2.5. HybridSFT: 데이터 구성과 자기 조건화

#### ① 텍스트 시연에 잠재·텍스트 모드 지정

**[저자 보고]** 외부 LLM 전문가의 판단과 기반 모델의 예측 엔트로피를 결합한다. 낮은 엔트로피의 추론 단계는 잠재 후보로, 도구 호출과 감사에 중요한 단계는 텍스트로 남긴다. 이후 별도의 비평 모델이 잠재 구간을 가린 기록을 검사하고, 중요한 정보가 사라졌으면 해당 단계를 텍스트로 복구한다. **[pp.33–34, Figure 12]**

추론 단계 $s$의 엔트로피는 다음과 같다.

$$
H_s=
-\frac{1}{|\mathcal I_s|}
\sum_{t\in\mathcal I_s}
\sum_{v\in\mathcal V}
p_\theta(v\mid x,\tau_{ < t})
\log p_\theta(v\mid x,\tau_{ < t}).
$$

- $\mathcal I_s$: 단계 $s$에 속한 토큰 위치들의 집합.
- $\tau_{<t}$: 이전 추론과 도구 관측.
- $p_\theta$: 고정된 기반 모델의 다음 토큰 확률로, 원문 식 (18)의 $f_\theta(v\mid\cdot)$와 같다.
- $x,\mathcal V,t,v$: 각각 입력, 어휘, 위치, 토큰.

**출처: p.33, 식 (18).**

> **용어 풀이 — 엔트로피:** 예측 확률이 여러 후보에 얼마나 퍼져 있는지 나타내는 값. 낮은 엔트로피는 높은 확신을 뜻하지만 정답임을 보장하지 않는다.

**[분석]** 실제 엔트로피 임곗값과 LLM 판단이 엔트로피 판단과 충돌할 때의 결합 규칙은 충분히 구체화되어 있지 않다.

#### ② 형식과 HybridLink 활성화

먼저 기반 모델에 모드 경계가 포함된 형식을 학습시킨다. 이후 기반 모델을 고정하고 HybridLink를 정답 토큰 임베딩에 맞춘다.

$$
\mathcal L_{\text{Backbone}}
=\text{CE}(f_\theta(x),y),
$$

```math
\mathcal L_{\text{HybridLink}}
=
\lambda_{\cos}
\left[
1-\cos\!\left(
\mathcal R(h_{\text{lat}}),
\text{Emb}(y_{\text{lat}})
\right)
\right]
+
\lambda_{\text{mse}}
\left\|
\mathcal R(h_{\text{lat}})
-\text{Emb}(y_{\text{lat}})
\right\|_2^2.
```

- $\text{CE}$: 정답 토큰의 확률을 높이는 교차엔트로피 손실.
- $y$: 정답 출력 시퀀스.
- $h_{\text{lat}}$: 잠재 위치의 은닉상태.
- $y_{\text{lat}}$: 해당 위치의 원래 텍스트 정답 토큰.
- $\lambda_{\cos},\lambda_{\text{mse}}$: 방향 정렬과 벡터 차이의 가중치이며 각각 1.0, 0.2.
- $\|\cdot\|_2^2$: 벡터 차이의 제곱합.

**출처: p.6, 식 (7); p.39, Table 10.**

#### ③ 두 번의 forward pass를 이용한 자기 조건화

첫 번째 pass에서는 정답 입력으로 모델을 실행하고, HybridLink가 다음 잠재 입력을 예측한다. 두 번째 pass에서는 정답 임베딩 대신 그 예측값을 잠재 위치에 넣고 기반 모델과 HybridLink를 함께 학습한다.

```math
\mathcal L_{\text{HybridSFT}}
=
\mathcal L_{\text{Backbone}}
+
\mathcal L_{\text{HybridLink}}.
```

여기서 두 손실은 위에서 정의한 손실이며, 기본적으로 텍스트 위치에는 교차엔트로피, 잠재 위치에는 벡터 회귀 손실을 적용한다.  
종료 경계에는 별도의 교차엔트로피·임베딩 정렬 감독이 함께 사용된다. **[pp.6–7, 식 (8), Figure 4; p.28]**

> **용어 풀이 — teacher forcing:** 학습 중 이전 위치에 모델 예측 대신 정답을 제공하는 방식.  
> **훈련·추론 불일치:** 학습에서는 정답 입력을 보지만 실제 생성에서는 자신의 예측을 입력으로 받아 생기는 차이.

**[분석]** 자기 조건화는 이 불일치를 줄이는 장치로 해석할 수 있다. 다만 첫 번째 pass는 여전히 정답에 조건화되어 있으므로, 임의 길이의 자유 생성에서 오류 누적이 사라진다는 보장은 아니다. **[pp.27–28, Figure 11]**

### 2.6. HybridRL: 잠재 입력을 기록하고 텍스트 확률을 최적화

#### 정책 인수분해

**[저자 보고]** 잠재 전이는 결정론적이며 샘플링은 텍스트 위치에서 이루어지므로, 정책을 다음과 같이 기술한다.

```math
\pi_\theta(\tau\mid x)
=
\prod_{t\in\mathcal T}
\pi_\theta(y_t\mid x,\tau_{ < t}).
```

- $\tau=(z,y,o)$: 잠재 입력 $z$, 생성 텍스트 $y$, 도구 관측 $o$를 포함한 궤적.
- $\mathcal T$: 샘플링한 텍스트 위치들의 집합.
- $\pi_\theta$: 현재 모델의 생성 정책.
- $\tau_{<t}$: 텍스트와 잠재 입력, 도구 관측을 모두 포함한 이전 문맥.

도구 결과는 정책이 생성하는 토큰의 확률로 최적화하지 않고, 이후 결정을 위한 관측 문맥으로 취급한다. **[p.7, 식 (10); p.29, 식 (13)]**

#### Exact rollout replay와 목적함수

생성 당시의 잠재 입력과 도구 관측을 저장하고, 업데이트할 때 같은 입력을 재생하여 텍스트 토큰 확률을 계산한다.

```math
\rho_{i,t}(\theta)
=
\frac{
\pi_\theta(y_{i,t}\mid x,\tau_{i, < t})
}{
\pi_{\theta_{\text{old}}}(y_{i,t}\mid x,\tau_{i, < t})
}.
```

- $i$: 생성한 궤적의 인덱스.
- $\theta_{\text{old}}$: 해당 궤적을 생성했던 정책의 파라미터.
- $\rho_{i,t}$: 같은 기록 문맥에서 현재 정책과 이전 정책의 토큰 확률 비율.

**출처: p.29, 식 (14).**

```math
\mathcal L_{\text{RL}}(\theta)
=
-\frac{1}{\sum_i|\mathcal T_i|}
\sum_i\sum_{t\in\mathcal T_i}
\min
\left[
\rho_{i,t}(\theta)A_i,\,
\text{clip}\!\left(
\rho_{i,t}(\theta),1-\epsilon,1+\epsilon
\right)A_i
\right].
```

- $A_i$: 같은 질문의 여러 생성 결과에서 보상을 정규화한 advantage.
- $\epsilon$: 정책 변화량을 제한하는 범위.
- $\text{clip}$: 값을 지정한 상·하한 안으로 제한하는 함수.
- $\mathcal T_i$: 궤적 $i$의 샘플링된 텍스트 위치 집합.

**출처: p.29, 식 (15); 구현은 GRPO 기반, p.38.**

> **용어 풀이 — rollout:** 현재 정책으로 실제 답변·도구 사용 궤적을 생성하는 과정.  
> **advantage:** 같은 문제의 다른 시도와 비교해 해당 시도가 얼마나 좋은지 나타내는 학습 신호.  
> **GRPO:** 같은 질문에서 생성한 여러 결과의 보상을 상대적으로 비교하여 정책을 학습하는 방법.

#### 보상 설계

```math
r(\tau)
=
r_{\text{correct}}
+r_{\text{format}}
+r_{\text{tool}}.
```

- $r_{\text{correct}}$: 수학에서는 정답 검증의 0/1, 검색에서는 토큰 단위 F1.
- $r_{\text{format}}$: 정상 형식 0, 잘못된 형식 −1.
- $r_{\text{tool}}$: Python과 검색을 모두 사용한 궤적에 +0.1.
- $r(\tau)$: 전체 궤적의 합산 보상.

**출처: p.8, 식 (11); p.12; pp.39–40, Tables 11·12.**

텍스트 또는 잠재 모드를 얼마나 사용했는지에 대한 직접 보상은 없다. 다만 도구 사용에는 명시적인 보상이 있으므로 도구 사용 증가까지 모두 자발적으로 생긴 현상이라고 설명해서는 안 된다.

#### 이론적 보장의 정확한 범위

**[저자 보고]** 부록 C는 초기 정책 지점에서 다음 등가성을 제시한다.

```math
-\nabla_\theta\mathcal L_{\text{RL}}(\theta_{\text{old}})
=
\frac{1}{\sum_i|\mathcal T_i|}
\sum_i A_i
\left.
\nabla_\theta\log\pi_\theta(\tau_i\mid x)
\right|_{\theta=\theta_{\text{old}}}.
```

$\nabla_\theta$는 모델 파라미터에 대한 기울기이고, 나머지 기호는 위의 RL 목적함수와 같다.  
중요한 전제는 **기록한 잠재 입력을 재생 중 고정하여** $\partial z_{i,t}/\partial\theta=0$으로 둔다는 것이다. **[pp.30–31, Theorem C.3, 식 (16)]**

**[분석]** 이는 **기록된 잠재 문맥을 고정한 목적함수에서의 국소적 기울기 등가성**이다.  
HybridLink를 고정해도 새로 생성할 잠재 상태는 기반 모델의 파라미터에 영향을 받는다.  
따라서 현재 정책이 새로 생성할 모든 잠재 상태와 종료 시점까지 고려한 전체 기대보상의 정확한 기울기를 증명했다고 확대해서는 안 된다.

## 4. 저자 보고와 해석의 분리: 일반화 성능을 중심으로

### 4.1. 현재 실험이 보여 주는 일반화의 범위

| 관점 | 저자가 직접 보여 준 것 | 아직 입증되지 않은 것 |
|---|---|---|
| 모델 크기 | Qwen3 계열 4B·8B·14B에서 효과 관찰 | 다른 모델 계열·구조에서 같은 효과 |
| 과제 범위 | 수학·과학·의료 지식·검색·에이전트 벤치마크 결과 | 한 체크포인트의 전 영역 일반화 |

| 문맥 유지 | 완전한 KV 보존 아래 계산적 연속성 | 매우 긴 문맥, KV 압축·삭제 이후의 정확성 |
| 잠재 표현 | 특정 교란에 대한 민감도와 읽기용 문자열의 관련성 | 모든 잠재 계산에 대한 충실한 의미 설명 |

**근거: pp.8–10, 25–26, 35, 38–40.**

> **용어 풀이 — 일반화:** 학습에서 익힌 방식이 새로운 문제나 조건에서도 작동하는 능력.  
> **분포 밖 평가, OOD:** 학습 자료와 문제 형태·언어·도구·환경 등이 체계적으로 다른 조건에서 평가하는 것.  
> **pass@k:** 여러 시도 중 정답이 포함될 가능성을 평가하는 지표로, 시스템이 그 정답을 자동으로 찾아 선택했다는 뜻은 아니다.

### 4.2. 일반화 향상 가능성을 시사하는 세 가지 설계

#### A. 입력 표현을 정렬하는 HybridLink

#### B. 자신의 예측을 경험하는 자기 조건화

**[저자 보고]** 활성화만 수행한 모델보다 성능과 잠재 readout 지표가 개선된다. **[Table 3, Figure 8]**

### 4.3. 일반화에 대한 최종 평가

**이 논문은 여러 벤치마크와 동일 모델 계열의 여러 크기에서 방법의 유효성을 보여 주지만, 광범위한 분포 밖 일반화를 입증한 연구로 분류하기는 어렵다.**

“반복 실험이나 오차 보고가 전혀 없다”는 비판은 맞지 않는다. 논문은 다음을 보고한다.

> **paired bootstrap:** 같은 문제에서 두 방법의 결과를 짝지어 재표집하며 성능 차이의 불확실성을 추정하는 방법.

### 5.2. 평균 10.4% 향상은 어떻게 읽어야 하는가?

**[저자 보고]** 본문은 SFT 단계 18.5%, RL 단계 10.4%, 강한 에이전트 비교군 대비 17.4%의 평균 향상을 제시한다. **[pp.9–10]**

**[분석]** 어느 비교군을 분모로 삼았는지, 어떤 모델 크기와 열을 포함했는지, 과제 가중치가 무엇인지가 명확하지 않아 **유일한 집계값으로 재현하기 어렵다**.

예를 들어 Table 2의 8B·14B, 6개 벤치마크를 동일하게 가중하여 HybridRL과 ARPO를 비교하면 다음과 같다.

- 12개 셀의 **상대 향상률 단순평균:** 약 **4.32%**.
- 12개 셀의 **점수 차이 단순평균:** 약 **1.81%p**.

이는 10.4%가 반드시 틀렸다는 반증은 아니다. **집계 정의가 달라지면 다른 값이 나온다는 뜻**이며, 10.4%를 10.4%p로 바꾸어 쓰면 안 된다.

### 5.3. 직접 비교하면 안 되는 수치

1. **[직접 비교 불가] 텍스트 토큰 감소와 전체 계산량 감소**  
   잠재 단계도 기반 모델을 실행한다. Figure 6의 텍스트 토큰과 전체 단계는 다른 분모이다.

2. **[직접 비교 불가] pass@64와 단일 응답 정확도**  
   64개 후보 중 정답의 존재 여부와 실제로 선택한 한 답변의 정답률은 다르다.

3. **[직접 비교 불가] 비용 추정과 실제 서비스 청구액**  
   Table 9에는 입력 처리·문맥별 attention·외부 도구 비용 등이 빠져 있다.

4. **[인과 비교 제한] 14B 시스템과 외부 대형 모델의 점수**  
   기반 모델·사전학습·후속 학습·서비스 구성이 다르다. 또한 HybridAgent의 검색 환경에는 외부 대형 모델의 페이지 요약이 포함된다. 작은 기반 모델만의 독립 능력으로 해석하면 안 된다. **[pp.38–40]**

5. **[재현성 주의] 실시간 검색 결과**  
   검색 시점과 반환 문서가 달라질 수 있어 정적인 데이터셋 평가와 재현 조건이 다르다.

### 5.4. 원문 내부의 명확한 불일치

**첫째, AUROC 차이 설명이다.** p.15는 텍스트 에이전트와의 차이가 0.022 이내라고 서술하지만 Table 7에서는 다음 차이가 나온다.

- 8B 약한 모니터: $0.840-0.772=0.068$.
- 14B 약한 모니터: $0.860-0.818=0.042$.
- 8B 강한 모니터: $0.961-0.935=0.026$.

이는 본문 문구와 표의 수치가 맞지 않는 사례이다. 차이가 대체로 HybridAgent에 유리하므로 감시 성능이 나쁘다는 뜻은 아니다.

> **용어 풀이 — AUROC:** 정답·오답 같은 두 부류를 점수로 얼마나 잘 구분하는지 나타내는 지표.

**둘째, SFT 데이터 원천의 인용이 다르다.** 부록 E의 ARPO·DAPO와 H.3의 Tool-Star·ARPO를 동일한 데이터 구성이라고 단정할 수 없다. **[pp.33, 38]**

### 7.2. Figures 2·8의 “가독성”은 무엇을 측정하는가?

**[저자 보고]** 가독성은 잠재 벡터와 가장 가까운 토큰 임베딩의 평균 코사인 유사도이다.

```math
\text{Read}(b)
=
\frac{1}{L_b}
\sum_{t=1}^{L_b}
\max_{v\in\mathcal V}
\cos\!\left(z_{b,t},\text{Emb}(v)\right).
```

- $b$: 하나의 연속 잠재 구간.
- $L_b$: 구간 길이.
- $z_{b,t}$: 해당 구간의 잠재 입력 벡터.
- $\mathcal V,\text{Emb}$: 어휘와 토큰 임베딩 함수.

**출처: p.34, 식 (19).**

문맥 특이성은 다음과 같이 정의된다.

```math
\text{Spec}(b)
=
\frac{
J\!\left(W(P_b),W(q_{i(b)})\right)
}{
\frac{1}{M-1}
\sum_{j\neq i(b)}
J\!\left(W(P_b),W(q_j)\right)
},
\qquad
J(A,B)=\frac{|A\cap B|}{|A\cup B|}.
```

- $P_b$: 잠재 구간의 pseudo-text.
- $W$: 문자열에서 불용어 등을 제거하고 내용어를 추출하는 함수.
- $q_{i(b)}$: 해당 잠재 구간을 생성한 원래 질문.
- $q_j$: 같은 과제의 다른 질문.
- $M$: 비교 질문 수.
- $J(A,B)$: 두 단어 집합의 Jaccard 유사도.

**출처: p.34, 식 (20).**

> **용어 풀이 — Jaccard 유사도:** 두 집합이 공유하는 원소 수를 전체 서로 다른 원소 수로 나눈 값.

**[분석]** 두 축은 각각 **토큰 임베딩에 얼마나 가까운가**, **원래 질문의 단어와 얼마나 더 관련되는가**를 측정한다. 논리의 정확성이나 설명 충실성을 직접 측정하지는 않는다.

또한 다음 조건이 있다.

- $n=200$은 질문 수이고, 점 하나는 잠재 구간이다.
- 같은 질문에서 나온 여러 구간은 독립 표본으로 보기 어렵다.
- 내용어가 없는 readout은 제외한다.
- 양수 문맥 특이성만 로그 축에 표시한다.
- 임베딩 정렬은 이미 HybridLink의 학습 목표이므로, 높은 정렬 점수만으로 독립적인 의미 이해 검증을 대체할 수 없다. **[pp.34–35]**

도구 실행 성공률 **99.7%**는 **유효한 도구 호출에 조건화된 값**이다.

## 8. 결론, 시사점, 한계 및 후속 연구

### 8.1. 학계·실용 분야에 대한 시사점과 저자의 후속 계획

**[저자 보고]** 이 논문은 효율적인 잠재 추론, 텍스트 기반 도구 사용, 외부 점검을 결합한 에이전트 구조를 제안하며 다음 방향을 제시한다. **[pp.16–17, Sections 8–9]**

- KV 기반 잠재 메모리를 중심으로 하는 새로운 에이전트 실행 체계.
- 텍스트와 잠재 모드에 따라 작업 단계를 배치하는 방식.
- 한 에이전트의 하이브리드 궤적을 다른 에이전트에 전달하는 통신.
- 잠재 readout을 비평 모델이 검사하여 단계별 보상, 유망 경로 분기, 잘못된 경로의 조기 종료에 활용하는 학습.

> **용어 풀이 — 에이전트 실행 체계, harness:** 모델 호출, 도구 실행, 메모리 유지, 오류 처리 등을 관리하는 주변 소프트웨어.  
> **단계별 보상 귀속:** 전체 답의 성공·실패를 중간의 어떤 선택에 연결할지 결정하는 과정.

**[분석: 학술적 시사점]** 기여의 중심은 추론 표현, 문맥 보존, 후속 학습을 함께 설계했다는 점이다. 후속 연구는 연속 표현 자체의 효과와 정렬·훈련·캐시 관리의 효과를 분리해야 한다.

**[분석: 실용적 시사점]** 검색·코드 실행 에이전트의 생성량과 시간을 줄일 수 있다는 실증 근거가 있다. 다만 은닉상태와 KV에 접근하고 생성 엔진을 수정해야 하므로, 기존 텍스트 API에 프롬프트만 추가하는 방식으로 그대로 적용되는 기술은 아니다. **[pp.39–40]**

저자들은 잠재 상태를 제공자 측에서 유지하는 방식의 보안·감사상 이점도 논의한다. 그러나 이 부분은 배포 시사점이며, 별도의 공격·정보 유출 평가로 입증된 보안 보장으로 읽어서는 안 된다. **[p.16]**

### 8.2. 일반화 성능 향상을 위해 우선 검증할 방향

다음은 **[후속 제안]**이며, 성능 향상이 이미 확인되었다는 뜻은 아니다.

| 우선순위 | 후속 실험 | 답할 수 있는 질문 |
|---|---|---|
| 1 | **하나의 체크포인트**로 모든 영역 평가 | 현재 결과가 전문화된 체크포인트 선택에 얼마나 의존하는가? |
| 2 | 한 도메인 또는 도구 유형을 학습에서 제외한 평가 | 실제로 새로운 작업·도구로 전이하는가? |
| 3 | 다른 기반 모델 계열에서 동일 조건 재현 | Qwen3의 특정 표현 공간에 의존하는가? |

| 5 | 잠재 길이·도구 호출 수·관측 오류를 늘리는 평가 | 학습 범위를 벗어난 긴 추론에서도 안정적인가? |

이 가운데 **단일 체크포인트 평가와 명시적 미학습 도메인·도구 평가**가 일반화 주장에 가장 직접적인 근거를 추가한다.

### 8.3. 제한사항: 저자가 명시한 제약과 분석에서 확인한 한계

이 논문에는 독립된 **Limitations** 절이 없다. 따라서 아래 항목을 모두 “저자가 인정한 한계”로 묶는 것은 부정확하다.

**저자가 직접 설명한 설계·구현상 제약**

- 잠재 문맥은 일반적인 텍스트 재토큰화만으로 복원할 수 없어 KV 유지가 필요하다. **[p.5]**
- 정답 임베딩만으로 학습하면 실제 잠재 입력과 차이가 생겨 자기 조건화가 필요하다. **[pp.27–28]**
- 기존 serving engine이 다중 턴 하이브리드 생성을 직접 지원하지 않아 verl·vLLM 관련 인프라를 확장했다. **[pp.8, 40]**
- 실제 실험에는 잠재 길이, 생성 예산, 도구 호출 수 제한이 적용된다. **[pp.39–40]**

**분석에서 확인한 평가·보고상의 한계**

- 한 모델 계열, 제한된 도구 환경, 과제별 체크포인트.
- 일반화와 데이터 오염을 분리하는 평가의 부족.
- 개별 성능 차이의 불확실성 및 평균 향상률 집계의 불명확성.
- 기하학적 가독성 지표와 실제 설명 충실성 사이의 차이.
- 전체 운영 비용을 포함하지 않는 비용 추정.
- 잠재 입력을 고정한 RL 목적함수와 자유 생성 정책의 관계에 대한 제한된 이론적 설명.

### 8.4. 가장 유망한 접근법과 빠른 검증 방법

복잡한 에이전트와 대규모 RL을 바로 재구현하기보다 다음 순서가 합리적이다. 이는 **논문의 결과를 바탕으로 한 검증 우선순위 제안**이다.

| 우선 접근법 | 선택 근거 | 최소한의 검증 실험 | 먼저 확인할 지표 |
|---|---|---|---|
| **잔차 HybridLink** | 직접 은닉상태 재사용보다 큰 개선, Table 6 | 같은 기반 모델·자료에서 직접 입력, 1층, 2층+잔차 비교 | 정답률, 비정상 생성, 입력 표현의 변동 |

| **ARPO — Dong 외, 2025** | 도구 응답 후의 불확실성을 활용한 적응적 샘플링과 단계별 보상 귀속 | HRA의 핵심 텍스트 에이전트 비교군이다. 추론 매체 변경의 효과를 평가할 때 도구 탐색·보상 방식의 효과를 함께 통제해야 한다. [arxiv.org](https://arxiv.org/abs/2507.19849?utm_source=chatgpt.com) |

| **SWITCH — Yang 외, 2026** | 이산 경계 토큰과 Switch-GRPO를 사용하고, 잠재 재귀 계산을 통과하는 기울기 및 인과 개입을 연구한다 | HRA의 잠재 입력 고정 재생과 다른 학습 방식이다. 두 방식의 안정성·비용·일반화 차이는 HRA에서 직접 검증되지 않았다. [ACL Anthology](https://aclanthology.org/2026.findings-emnlp.457/?utm_source=chatgpt.com) |
| **ALAR — Jung 외, 2026** | 턴별로 고정 길이 잠재 블록과 명시적 CoT를 선택하며, 검색과 도구 호출을 평가한다 | 이미 잠재 추론과 다중 턴 도구 사용을 결합했다. HRA의 차이는 생성 과정 내부의 전환, 길이 제어, 연속 KV 문맥, readout·학습의 통합에 두어야 한다. **[ALAR §§3.2–3.3]** [arxiv.org](https://arxiv.org/abs/2606.02871?utm_source=chatgpt.com) |

**[분석: 문헌 비교의 결론]** HybridAgent를 “잠재 추론과 도구를 처음 결합한 연구”라고 설명하는 것은 부정확하다. 특히 ALAR와 SWITCH를 고려하면, 차별점은 **HybridLink·턴 간 메모리·자기 조건화·기록 문맥 재생 RL·잠재 readout을 하나의 세부적인 시스템으로 결합한 방식**에 있다. ALAR·SWITCH와 같은 가까운 방법에 대한 직접 비교가 없어, 이들보다 우수한지는 아직 판단할 수 없다.

### 8.6. 최종 결론

**HybridAgent는 잠재 추론을 도구 사용 에이전트의 실제 생성 과정에 통합하는 설계로서 유망하다.** 가장 강한 근거는 동급 Qwen3 비교군에서 나타난 에이전트 과제 개선, 표현 공간 정렬과 자기 조건화의 효과, 짧아진 생성 과정이다. **[Tables 1–3·6, Figures 6·7]**

일반화 성능에 대해서는 평가 범위를 좁혀 읽어야 한다. 현재 근거는 **동일 모델 계열과 여러 벤치마크에서의 유효성**이며, 단일 모델의 범용성이나 새로운 도구·도메인으로의 전이를 확정하지 않는다. 후속 연구에서 가장 필요한 것은 **단일 체크포인트, 명시적인 미학습 환경, 동일한 전체 계산·도구 예산**을 적용한 비교이다.
