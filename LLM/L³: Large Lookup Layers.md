## 1. Executive Summary (10문장 이내)

$\text{L}^3$ (Large Lookup Layer)는 토크나이저 임베딩 테이블의 개념을 트랜스포머 디코더 레이어 내부로 일반화한 새로운 희소(sparse) 아키텍처이다.  
기존 Mixture-of-Experts(MoE)가 동적 라우팅으로 희소성을 달성하는 것과 달리, $\text{L}^3$는 **토큰 ID 기반의 정적 라우팅**으로 하드웨어 친화적 희소성을 구현한다.  
각 토큰은 사전에 결정된 임베딩 집합을 선택하고, 히든 스테이트(hidden state)를 쿼리로 한 어텐션(attention)을 통해 문맥 의존적으로 이를 집계한다.  
임베딩 할당은 LZW 압축 알고리즘에서 파생된 정보이론적 알고리즘으로 결정되며, 이는 균일 할당 대비 2배의 퍼플렉시티(perplexity) 개선 효과를 낸다.  
정적 라우팅 덕분에 $\text{L}^3$ 파라미터는 토큰 생성 즉시 알 수 있어, CPU 오프로딩 및 프리페칭이 추가 오버헤드 없이 가능하다.  
저자들은 800M, 1.5B, 2.6B 활성 파라미터 모델을 사전학습하여 iso-FLOP 밀집(dense) 모델과 iso-sparse MoE 모두를 언어 모델링 및 다운스트림 태스크에서 유의미하게 능가함을 실증하였다.  
훈련 처리량은 동등 밀집 모델의 약 87%를 달성하며, 추론 시 CPU 오프로딩 후에도 속도 저하가 미미하다.  
$\text{L}^3$는 MoE의 대체재가 아닌 **보완적 희소 스케일링 축**으로 제안되며, 두 아키텍처의 결합은 향후 연구 과제로 남겨졌다.  
본 연구는 훈련 안정성, 하드웨어 효율성, 성능 향상을 동시에 달성하는 새로운 희소 아키텍처 설계 원칙을 제시한다.

### 1-1. 연구의 목적과 필요성

**배경:** 언어 모델에서 희소성(sparsity) — 총 파라미터 수 대비 활성 파라미터 비율을 높이는 것 — 은 다운스트림 성능을 크게 향상시킨다 (Shazeer et al., 2017; Dai et al., 2024). 현재 주류 방법인 MoE는 다음과 같은 시스템적 문제를 내포한다:

| 문제 | 설명 |
|------|------|
| 동적 라우팅 불안정성 | 라우터 붕괴(collapse) 방지를 위한 보조 손실(auxiliary loss) 필요 |
| 오프로딩 불가 | 어떤 전문가(expert)가 활성화될지 라우터 도달 전까지 알 수 없음 |
| 부하 불균형 | 전문가 과부하 시 장치 활용률 저하 및 토큰 드롭 발생 |
| 샤딩 복잡성 | 수조 개 파라미터를 다수 장치에 분산해야 함 |

**목적:** MoE의 시스템적 부담 없이, 문맥 의존적 집계를 통해 토크나이저 임베딩 테이블의 네이티브 희소성을 디코더 레이어 전반으로 확장하는 $\text{L}^3$ 아키텍처를 제안한다 (p.1).

> 💡 **희소성(Sparsity)이란?** 모델의 전체 파라미터 중 하나의 입력 토큰을 처리할 때 실제로 사용되는 파라미터의 비율이 낮은 것. 예: 총 7B 파라미터 중 2.6B만 활성화 → 희소율 약 2.7×

#### 제안하는 방법 및 수식

**$\text{L}^3$ 레이어의 핵심 수식 (p.4):**

$$\text{L}^3(x, t;\, W_{\text{mix}}, W_{\text{up}}, K, V) \in \mathbb{R}^{d_{\text{out}}} = W_{\text{mix}} \begin{bmatrix} \text{LayerNorm}(W_{\text{up}}(V_t^T \,\text{Softmax}(K_t x))) \\ x \end{bmatrix}$$

**각 기호 설명:**

| 기호 | 설명 |
|------|------|
| $x \in \mathbb{R}^{d_{\text{in}}}$ | 토큰의 히든 스테이트 (문맥 정보를 담은 벡터) |
| $t \in \{1, \ldots, \|\tau\|\}$ | 토큰 ID, $\|\tau\|$는 어휘 크기 |
| $K_t \in \mathbb{R}^{d_t \times d_{\text{in}}}$ | 토큰 $t$에 할당된 키 행렬 집합 (어텐션 키) |
| $V_t \in \mathbb{R}^{d_t \times d_{\text{emb}}}$ | 토큰 $t$에 할당된 값 행렬 집합 (저장된 임베딩) |
| $d_t$ | 토큰 $t$에 할당된 임베딩 수 |
| $\text{Softmax}(K_t x) \in \mathbb{R}^{d_t}$ | 히든 스테이트로 임베딩 중요도 계산 (어텐션 스코어) |
| $V_t^T \,\text{Softmax}(K_t x) \in \mathbb{R}^{d_{\text{emb}}}$ | 가중 집계된 임베딩 출력 |
| $W_{\text{up}} \in \mathbb{R}^{d_{\text{up}} \times d_{\text{emb}}}$ | 임베딩 업프로젝션 행렬 |
| $W_{\text{mix}} \in \mathbb{R}^{d_{\text{out}} \times (d_{\text{in}} + d_{\text{up}})}$ | 임베딩 출력과 잔류 스트림(residual stream)을 혼합 |
| $\text{LayerNorm}(\cdot)$ | 레이어 정규화 (RMS Norm) |

> 💡 **잔류 스트림(Residual Stream)이란?** 트랜스포머에서 레이어를 통과하면서 정보가 누적되는 메인 벡터 흐름. 각 레이어는 이 스트림에 정보를 더하는 방식으로 동작한다.

> 💡 **어텐션(Attention)이란?** 쿼리(Q), 키(K), 값(V)을 이용해 중요한 정보에 가중치를 두어 집계하는 메커니즘. 여기서는 히든 스테이트 $x$가 쿼리 역할을 하고, 임베딩 테이블에서 관련 정보를 선택적으로 가져온다.

**임베딩 총 예산:**

$$v = \sum_i d_i \quad \text{(전체 임베딩 수, 하이퍼파라미터)}$$

**MoE 라우터 출력 (비교용, p.2):**

$$y = \sum_{e \in E^*_x} r(x,e) \cdot e(x)$$

여기서 $r(x,e)$는 토큰 $x$와 전문가 $e$의 라우터 스코어, $E^*_x$는 활성 전문가 집합.

> 💡 **MoE (Mixture of Experts)란?** 여러 개의 "전문가" 신경망을 두고, 각 입력 토큰마다 동적으로 일부 전문가만 선택하여 연산하는 아키텍처.

**LZW 기반 임베딩 할당 알고리즘 (Algorithm 1, p.4-5):**

핵심 아이디어: 코퍼스를 스캔하며 아직 등장하지 않은 가장 긴 토큰 접미사(suffix)를 코드워드로 등록하고, 빈도수 기반으로 임베딩 수를 할당.

$$\text{임베딩 수} \propto \text{코드워드 등장 빈도} \quad \text{(단, } 1 \leq d_t \leq k \text{)}$$

- $k$: 토큰당 최대 임베딩 수 (기본 $k=512$)
- $v = 710{,}000$: 총 임베딩 예산 (실험 기본값)

> 💡 **LZW 알고리즘이란?** Lempel-Ziv-Welch, 반복 패턴을 코드워드로 대체하여 데이터를 압축하는 무손실 압축 알고리즘. 여기서는 압축의 "코드워드"를 임베딩 할당의 기준으로 역용(dual problem)한다.

> 💡 **Zipf 법칙이란?** 자연어에서 단어 빈도는 순위(rank)에 반비례하는 멱함수(power law) 분포를 따른다는 법칙. 흔한 단어는 매우 자주, 드문 단어는 거의 등장하지 않는다.

#### 모델 구조

```
입력 토큰 t, 히든 스테이트 x
        ↓
[정적 라우팅] 토큰 ID t로 K_t, V_t 선택
        ↓
[어텐션] Softmax(K_t · x) → 어텐션 스코어
        ↓
[집계] V_t^T · score → 집계된 임베딩
        ↓
[업프로젝션] W_up → LayerNorm
        ↓
[혼합] W_mix([집계 결과; x]) → L³ 출력
```

전체 모델에서는 Llama 기반 디코더 레이어 **사이에** $\text{L}^3$ 레이어를 삽입 (MLP 레이어를 대체하지 않음). 기본 설정: 1~3개의 $\text{L}^3$ 레이어, 위치는 중간 디코더 레이어 이후.

> 💡 **Llama 아키텍처란?** Meta의 오픈소스 대형 언어 모델 아키텍처. RMS Norm, RoPE 위치 인코딩, SwiGLU 활성화 함수 등을 특징으로 하며, 현재 많은 연구의 기반 모델로 사용된다.

#### 성능 향상 및 한계

**성능 향상 (저자 보고):**
- WikiText2 퍼플렉시티: 800M 기준 22.02 → 19.59 (Triple $\text{L}^3$, 5.2B total)

## 4. 저자 보고 결과 vs. 해석 분리

### 연구 주제

| 구분 | 내용 |
|------|------|
| **저자 직접 기술** | "We introduce the Large Lookup Layer (L³), which generalizes embedding tables to model decoder layers as a means of further scaling sparsity." (p.1) |
| **검토자 해석** | 이 연구는 단순히 MoE의 대안을 제안하는 것이 아니라, 임베딩 테이블이라는 기존 구조를 재활용하여 시스템 친화적 희소성을 달성하는 새로운 설계 철학을 제시한다. |

### 방법

| 구분 | 내용 |
|------|------|
| **저자 직접 기술** | "L³ layers use static token-based routing to aggregate a set of learned embeddings per token in a context-dependent way." (p.1 Abstract) |
| **저자 직접 수식** | $\text{L}^3(x, t) = W_{\text{mix}}[\text{LayerNorm}(W_{\text{up}}(V_t^T \text{Softmax}(K_t x))); x]$ (p.4) |
| **검토자 해석** | 정적 라우팅과 동적 집계의 분리가 핵심 혁신이다. 라우팅은 토큰 ID만으로 결정되어 예측 가능하지만, 집계는 히든 스테이트로 문맥 의존성을 유지한다. 이는 "어떤 정보를 볼지"(정적)와 "어떻게 해석할지"(동적)를 분리한 것이다. |

### 결과

| 구분 | 내용 |
|------|------|
| **저자 직접 보고** | "L³ strongly outperforms both dense models and iso-sparse MoEs in both language modeling and downstream tasks." (p.1 Abstract); WikiText2 퍼플렉시티 800M 기준 22.02→19.59, 2.6B 기준 15.43→14.51 (Table 1) |
| **저자 직접 보고** | "our training setup... achieves 135K toks/s for an 800M parameter model on an 8×A100 node, or roughly 87% the 155K toks/s we achieved for an equivalent dense model." (p.8) |
| **검토자 해석** | 성능 개선의 원인이 단순히 파라미터 수 증가 때문인지, $\text{L}^3$ 구조 자체의 귀납적 편향(inductive bias) 덕분인지는 충분히 분리 검증되지 않았다. 특히 총 파라미터 수가 더 많은 $\text{L}^3$ 모델과 활성 파라미터 수만 같은 밀집 모델의 비교는 공정하지 않을 수 있다. |
| **검토자 해석** | Tuned Lens 분석(Fig. 10)에서 $\text{L}^3$ 레이어 위치에서 KL 발산이 급감하는 현상은, $\text{L}^3$가 정보를 캐싱하여 후속 레이어의 계산을 단축(shortcut)한다는 저자의 주장을 간접적으로 지지하나, 인과적 증거는 아니다. |

> 💡 **귀납적 편향(Inductive Bias)이란?** 모델이 훈련 데이터 외의 패턴도 잘 일반화하도록 아키텍처 설계에 내재된 가정이나 구조적 제약. 예: CNN의 지역성(locality) 가정.

## 7. 가장 중요한 그림 5개 해석

### Figure 1 (p.1): L³ 파라미터 스케일링

**해석:** x축은 총 파라미터 수(B), y축은 WikiText2 퍼플렉시티(낮을수록 좋음). 세 종류의 마커: $+$ (L³), $\star$ (iso-FLOP 밀집), $\times$ (iso-sparse MoE). 800M, 1.5B, 2.6B 활성 파라미터 각각의 궤적을 보면, L³를 추가할수록 퍼플렉시티가 지속적으로 감소하며, 같은 총 파라미터 수에서 L³가 MoE와 밀집 모델 모두를 능가한다. 이는 L³ 스케일링이 "더 많은 파라미터를 추가할수록 밀집 모델 대비 지속적 이득"이라는 새로운 스케일링 축을 제공함을 시각적으로 보여준다. 다만, 총 파라미터가 많아질수록 메모리 요구량도 증가하므로 순수 성능 비교로만 보아야 한다.

---

### Figure 6 (p.6): 훈련 퍼플렉시티 곡선

**해석:** 800M, 1B, 2.5B 활성 파라미터 세 패널에서 각각 L³ 레이어 수를 늘릴수록 훈련 초기부터 퍼플렉시티가 낮다. **특히 중요한 관찰:** MoE와 달리 훈련 초기에 밀집 모델보다 성능이 나빠지는 구간이 없다. 이는 정적 라우팅의 훈련 안정성 이점을 직접 보여준다. $\text{L}^3$ 레이어 수가 늘어날수록 (Single→Dual→Triple) 개선폭도 증가하나, 레이어 수에 비례하지는 않아 수확 체감(diminishing returns)도 확인된다.

> 💡 **퍼플렉시티(Perplexity)란?** 언어 모델이 텍스트를 얼마나 잘 예측하는지를 나타내는 지표. 값이 낮을수록 좋다. "모델이 다음 단어를 얼마나 확신하는가"의 역수적 개념.

---

### Figure 7 (p.6): 세 가지 절제 연구(Ablation)

**해석 (3개 패널):**

**(L) 레이어 수 vs. 임베딩 수:** 2×710K, 4×355K, 1×1420K는 유사한 총 임베딩 수에도 비슷한 성능을 보여, **총 임베딩 예산이 핵심**임을 시사. 단, 1×1420K는 오프로딩 프리페칭 시간이 부족해질 수 있다.

**(C) 할당 알고리즘 비교:** LZW Cap 512 > LZW Cap 256 > LZW Uncapped(보증 없음) 순이 아니라, Uncapped LZW가 성능 최고지만 최빈 토큰이 20K+ 임베딩을 독점하는 최악의 경우를 만든다. **균일 할당은 현저히 낮은 성능**으로, LZW 할당의 중요성을 입증. ⚠️ 단, Uncapped의 장기 훈련 안정성과 실용성은 미검증.

**(R) 가중치 공유:** $W_K, W_V$ 공유 시 성능 차이 거의 없음. 이는 스파스율을 절반으로 줄이면서 동일 성능을 내므로, **실용적 추론 효율화의 핵심 테크닉**으로 주목할 만하다.

---

### Figure 8 (p.7): L³ vs. MoE 퍼플렉시티 격차

**해석:** 800M(좌)과 1.5B(우) 모델에서 밀집 모델 대비 퍼플렉시티 개선폭을 훈련 토큰 수에 따라 비교. **핵심 관찰:**
- 800M: MoE 2-layer 등가 모델이 오히려 밀집 모델보다 낮은 성능 구간 존재 (음수 구간)
- 1.5B: MoE 1-layer 등가가 밀집 모델 하회
- $\text{L}^3$: 훈련 처음부터 양의 개선폭 유지

이는 MoE의 동적 라우터 학습 불안정성과 $\text{L}^3$의 정적 라우팅 안정성의 극명한 대비를 보여준다. ⚠️ 단, MoE 설정이 최적화되지 않았을 가능성은 남아 있다 (저자는 OLMoE 추천 설정 사용).

---

### Figure 10 (p.7): Tuned Lens 분석

**해석:** 2.6B 모델에서 각 디코더 레이어 이후 출력의 최종 모델 출력 대비 KL 발산을 시각화. **$\text{L}^3$ 모델(실선):** 레이어 4와 16 ($\text{L}^3$ 배치 위치)에서 KL이 급격히 감소. **밀집 모델(점선):** 부드럽게 단조 감소. 이는 $\text{L}^3$ 레이어가 모델의 예측 분포를 급격히 개선하는 "정보 캐시" 역할을 한다는 저자의 가설을 지지한다. 즉, $\text{L}^3$는 후속 디코더 레이어들이 반복 계산해야 할 정보를 미리 제공하여 계산 단축(shortcut)을 가능하게 한다. ⚠️ 인과 관계는 아니며, 상관 관계 수준의 증거임.

> 💡 **KL 발산(KL Divergence)이란?** 두 확률 분포 간의 차이를 측정하는 지표. 값이 0에 가까울수록 두 분포가 유사함. 여기서는 각 레이어의 중간 예측과 최종 예측 간의 차이를 측정.

> 💡 **Tuned Lens란?** 각 중간 레이어의 히든 스테이트를 직접 최종 로짓(logit)으로 변환하는 보조 선형 함수를 학습하여, 각 레이어가 "얼마나 이미 최종 답에 가까운지"를 측정하는 해석 가능성 도구.

## 8. 결론 및 후속 연구

### 8-1. 연구자 제시 시사점 및 후속 연구 계획

**저자 제시 시사점 (p.8-9):**
- $\text{L}^3$는 "새롭고 더 효율적인 희소 스케일링 축"을 제공
- MoE의 대체재가 아닌 보완적 아키텍처
- CPU 오프로딩으로 모바일/엣지 환경에서도 대용량 모델 활용 가능성

**저자 명시 후속 연구 (p.3, 5):**
1. $\text{L}^3$ + MoE 결합 모델 실험
2. Engrams와의 전면 비교 분석
3. $\text{L}^3$ 레이어의 "태스크 간 교체(swapping)" 가능성 탐구 (Cartridges 개념 연계)

---

### 8-1. 모델 일반화 성능 향상 가능성 (중점 분석)

**일반화 관련 긍정적 증거:**
- $\text{L}^3$ 레이어는 문맥 의존적 집계( $\text{Softmax}(K_t x)$ )를 수행하므로, 동일 토큰도 다른 문맥에서 다르게 처리됨
- 여러 임베딩의 가중 집계는 "희귀 컨텍스트"에도 대응 가능한 유연성 제공
- 훈련 초기부터 안정적 학습으로 일반화에 도움이 되는 충분한 훈련 가능

**일반화 관련 우려 사항:**
- **도메인 특이성:** LZW 할당이 FineWeb-Edu 기반이므로, 코드, 수학, 다국어 등 이질적 도메인에서 빈도 분포가 달라 임베딩 할당이 비효율적일 수 있음
- **정적 라우팅의 한계:** 새로운 어휘나 OOV(Out-of-Vocabulary) 토큰에 대한 임베딩 할당이 없음
- **과적합 위험:** 특정 코퍼스의 n-gram 패턴에 과도하게 특화될 가능성

**일반화 향상을 위한 제언:**
1. **다중 도메인 LZW 학습:** 코드, 수학, 다국어 코퍼스를 혼합하여 임베딩 할당 학습
2. **동적 임베딩 확장:** 새로운 도메인 파인튜닝 시 $\text{L}^3$ 임베딩 테이블만 선택적 업데이트 (파라미터 효율적 파인튜닝)
3. **계층적 임베딩 할당:** 토큰 단위가 아닌 의미론적 클러스터 단위 할당으로 희귀 토큰의 일반화 지원

---

### 8-2. 2020년 이후 관련 최신 연구 비교 분석

| 연구 | 연도 | 방법 | L³와의 관계 | 한계 대비 |
|------|------|------|-------------|----------|
| **MoE (Shazeer et al.)** | 2017 | 동적 라우팅 + 밀집 MLP 전문가 | L³가 명시적으로 능가 목표 | 라우팅 불안정, 오프로딩 불가 |
| **DeepSeekMoE (Dai et al.)** | 2024 | 세밀한 전문가 특화 MoE | L³와 보완적 | 여전히 동적 라우팅 문제 존재 |
| **SCONE (Yu et al.)** | 2025 | f-gram 임베딩, 모델 시작 부분에만 적용 | L³의 선행 연구, 더 제한적 | 문맥 전체를 활용하지 못함 |
| **Product Key Networks (Lample et al.)** | 2019 | 히든 스테이트 기반 키 선택 | L³의 선행 연구, 동적 라우팅 | 오프로딩 불가 |
| **Engrams (Cheng et al.)** | 2026 | n-gram 해싱 + 모델 전체 임베딩 테이블 | 동시 발표 concurrent work | 더 복잡한 구현, L³와 유사 성능 |
| **Cartridges (Eyuboglu et al.)** | 2025 | 학습된 KV 캐시, 태스크별 교체 | 개념적 연계, 다른 목적 | 리트리벌 태스크 특화 |
| **OLMoE (Muennighoff et al.)** | 2025 | 오픈소스 MoE, 로드 밸런싱 개선 | L³ 비교 기준선으로 사용 | 동적 라우팅 한계 유지 |
| **SuperBPE (Liu et al.)** | 2025 | 향상된 BPE 토크나이저 | L³의 토크나이저로 활용 | L³와 직접 경쟁 관계 아님 |

**L³가 앞으로의 연구에 미치는 영향:**
1. **"정적 라우팅 + 동적 집계" 패러다임** 제시 — 향후 희소 아키텍처 설계의 새로운 선택지
2. **정보이론적 하이퍼파라미터 설계** — LZW 기반 할당처럼 데이터 통계를 아키텍처 설계에 활용하는 접근법 확산 가능
3. **CPU 오프로딩 추론** — 엣지 AI, 온디바이스 LLM 배포에 실용적 시사점
4. **임베딩 캐시 패러다임** — Cartridges, SCONE 등과 연계하여 "학습된 컨텍스트 캐시" 연구 방향 강화

**앞으로 연구 시 고려할 점:**

| 고려사항 | 구체적 방향 |
|----------|------------|
| **다중 도메인 검증** | 코드, 수학, 의학 등 전문 도메인에서 LZW 할당의 효과 검증 |
| **초대형 모델 스케일링** | 10B, 100B+ 활성 파라미터에서의 스케일링 법칙 확인 |
| **L³ + MoE 결합** | 두 희소 메커니즘의 시너지 탐구 |
