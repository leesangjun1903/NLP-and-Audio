### 3.2 분기별 목적함수: 무엇을 최적화하는가?

**[저자 보고: 원문 식 (1), p.4]**

```math
J_b^t(H)
=
\frac{1}{|\mathcal X_b^t|}
\sum_{x\in\mathcal X_b^t}
\mathbb E\left[r\left(f_M(H,x),x\right)\right].
```

**기호 설명:** $b$는 분기, $t$는 탐색 반복, $H$는 후보 하네스, $M$은 실행 모델, $\mathcal X_b^t$는 해당 시점에 분기 $b$가 사용하는 개발 문제 집합입니다. $f_M(H,x)$는 하네스와 모델이 문제 $x$에서 생성하는 실행 경로이며, $r$은 그 실행의 과제 점수입니다. $\mathbb E$는 실행의 확률적 변동에 대한 기댓값입니다. 실제 구현은 관측된 평균 보상으로 이를 추정하고, 가장 높은 후보를 분기 대표로 선택합니다. 2609.37834v1

> **용어:** 실행 경로 또는 trajectory — 모델의 추론, 도구 호출, 도구 응답과 같은 실행 과정의 기록; 기댓값 — 같은 조건을 반복했을 때의 평균적인 결과

중요한 점은 **과제의 채점 규칙 $r$을 바꾸는 것이 아니라, 평균에 포함되는 문제 집합 $\mathcal X_b^t$를 바꾼다**는 것입니다. 따라서 코드가 그대로여도 개발 문제의 구성이 바뀌면 후보의 순위가 달라질 수 있습니다〔pp.3–4〕. 2609.37834v1 2609.37834v1

### 3.3 개발 문제의 소유권: 어떻게 전문화시키는가?

각 분기의 현재 개발 점수 상위 $q$개 하네스를 프런티어 $\mathcal F_b^t$로 정의합니다. **여기서 프런티어는 단순한 상위 후보 집합**이며, 여러 목적에서 비지배적인 해를 뜻하는 파레토 프런티어와는 다릅니다〔p.4〕. 2609.37834v1

> **용어:** 프런티어(frontier) — 이 논문에서는 분기별 성적 상위 $q$개 후보; 파레토 프런티어 — 한 기준을 개선하려면 다른 기준을 희생해야 하는 비지배적 후보들의 집합

**[저자 보고: 원문 식 (2), p.4]**

```math
c_b^t(x)
=
\sum_{H\in\mathcal F_b^t}
\mathbf 1\{H\ \text{solves}\ x\}.
```

**기호 설명:** $c_b^t(x)$는 분기 $b$의 상위 후보 중 문제 $x$를 해결한 후보 수입니다. $\mathbf 1\{\cdot\}$는 조건이 참이면 1, 거짓이면 0인 지시함수입니다. 2609.37834v1

문제 배정 규칙은 다음과 같습니다.

- 모든 분기의 모든 프런티어 하네스가 해결한 문제는 모든 분기에서 제거합니다.
- 나머지 문제에서 다음 조건을 만족하는 분기 $b$가 있으면 그 분기에 소유권을 주고, 다른 분기의 개발 집합에서는 제거합니다.
- 어느 분기도 충분히 우세하지 않으면 기존 소속을 유지합니다.

```math
c_b^t(x)
-
\max_{b'\ne b}c_{b'}^t(x)
\ge \Delta.
```

**기호 설명:** $b'$는 다른 분기, $\Delta$는 소유권을 부여하기 위해 필요한 최소 성공 후보 수의 차이입니다. 실험에서는 $q=5$, $\Delta=2$를 사용합니다〔pp.4, 6〕. 2609.37834v1 2609.37834v1

예를 들어, 두 분기의 성공 후보 수가 각각 4와 2이면 첫 번째 분기가 문제를 맡습니다. 둘 다 5이면 이미 모든 상위 후보가 해결하므로 제거합니다. 3과 2이면 차이가 충분하지 않아 기존 배정을 유지합니다. 이는 위 규칙을 적용한 설명용 예시입니다.

**[해석]** 이 방법은 약한 분기에게 문제를 맡겨 약점을 보완시키기보다, **상대적으로 잘하는 분기가 그 강점을 더 발전시키도록 유도**합니다. 또한 5개 후보는 같은 조상 코드와 모델을 공유할 수 있으므로, 5표를 독립적인 통계적 증거 5개로 해석해서는 안 됩니다.

### 3.4 제안 지침의 적응: 어떻게 “개선 방법”을 개선하는가?

**[저자 보고]** 제안 모델은 최근 탐색 기록을 읽고 `SKILL.md`를 수정합니다. 업데이트 프롬프트는 같은 개발 단계 안에서 점수를 비교하고, 한 구현의 실패를 전체 접근법의 실패로 일반화하지 않으며, 문제 내용·정답·문항 ID를 지침에 넣지 않도록 요구합니다〔pp.4, 14–15〕. 2609.37834v1 2609.37834v1

이를 **설명용으로 재표현**하면 다음과 같습니다.

```math
S_b^{\text{new}}
=
U_P\left(
S_b^{\text{old}},
\text{Recent}_{C_s}(D_b)
\right).
```

**기호 설명:** $S_b^{\text{old}}$와 $S_b^{\text{new}}$는 수정 전후의 지침, $U_P$는 제안 모델 $P$가 수행하는 문서 수정 연산, $D_b$는 분기 이력, $C_s$는 참조하는 최근 반복 구간입니다. 이것은 원문의 별도 수식이 아니라 지침 수정 절차를 요약한 표현입니다.

기본 설정은 분기 수 $B=2$, 탐색 반복 $N=20$, 개발 집합 업데이트 간격 $C_p=1$, 지침 업데이트 간격 $C_s=5$입니다. 두 업데이트가 동시에 예정되면 개발 집합을 먼저 바꾸고 지침을 수정합니다〔pp.5–6〕. 2609.37834v1 2609.37834v1

**[해석]** 부록에서 사용하는 “gradient”라는 표현은 여기서 미분으로 계산한 기울기를 뜻하지 않습니다. **실행 경험을 자연어 수정 지침으로 바꾸는 과정**입니다.

> **용어:** 기울기(gradient) — 일반적인 신경망 학습에서는 매개변수를 어느 방향으로 바꿀지 알려주는 미분값; 이 논문의 지침 수정은 그러한 수치 미분이 아닌 텍스트 편집

### 3.5 라우터: 시험 정답 없이 어떤 전문가를 선택하는가?

**[저자 보고]** 탐색 종료 후 각 분기의 최종 개발 집합에서 가장 높은 점수를 받은 대표 $\widehat H_b^N$를 남깁니다. 이어서 **최종 대표 중 정확히 하나만 해결한 개발 문제**를 라우터 학습 사례로 사용합니다〔p.5〕. 2609.37834v1

이를 **설명용으로 재표현**하면 다음과 같습니다.

```math
s_b(x)
=
\mathbf 1\{\widehat H_b^N\ \text{solves}\ x\},
```

```math
\mathcal D_R
=
\left\{
(x,b):
x\in\mathcal X,\;
s_b(x)=1,\;
\sum_{j=1}^{B}s_j(x)=1
\right\}.
```

**기호 설명:** $s_b(x)$는 최종 대표의 성공 여부, $\mathcal X$는 전체 개발 문제 집합, $B$는 분기 수, $\mathcal D_R$는 “이 문제에는 어떤 전문가가 적합한가”라는 라우터용 학습 사례입니다. 이 식은 p.5의 절차를 수학적으로 풀어 쓴 것입니다.

여기서 **프런티어 투표로 정한 개발 문제의 소유권**과 **최종 대표 하나만 성공한 라우터 학습 사례**는 서로 다른 개념입니다.

라우터는 전문가 코드, 해당 개발 사례, 개발 사례에 대한 두 전문가의 출력을 참고하고, GEPA로 최적화한 지침에 따라 새 문제의 전문가를 선택합니다. 하지만 **새 시험 문제에 대한 전문가 출력은 선택 전에 제공되지 않습니다**〔pp.5, 15, 18〕. 2609.37834v1 2609.37834v1 2609.37834v1

> **용어:** GEPA — 실행 기록을 자연어로 분석하고 프롬프트 후보를 진화시키는 최적화 방법; 이 논문에서는 주로 라우팅 지침을 최적화하는 데 사용

## 7. 일반화 성능 향상 가능성: 입증된 것과 아직 가설인 것

### 7.1 “일반화”를 네 수준으로 나눠야 한다

| 일반화의 수준 | 이 논문이 제공하는 증거 |
|---|---|
| 탐색에 쓰지 않은 시험 문제에서의 성능 | **있음:** 개발 데이터로 선택한 시스템을 별도 시험 집합에서 평가 |
| 같은 탐색 절차가 여러 모델·분야에서도 작동하는가 | **부분적으로 있음:** 네 설정에 각각 적용해 성능 상승 |
| 한 설정에서 얻은 하네스를 고정한 채 다른 모델·분야로 옮겨도 좋은가 | **보고되지 않음:** 설정마다 별도 탐색 |
| 기반 모델의 가중치 자체가 더 일반적인 능력을 획득했는가 | **이 연구의 평가 대상이 아님:** 모델 가중치 변경이 아닌 하네스·지침 최적화 |

이 구분은 실험 설정과 최적화 대상에 대한 제 해석입니다〔pp.6, 9〕. 2609.37834v1 2609.37834v1

> **용어:** 전이(transfer) — 한 환경에서 얻은 하네스나 전략을 다른 환경에서도 재사용하는 것; 분포 밖 일반화(OOD) — 학습·탐색 환경과 성격이 다른 문제에서의 성능

따라서 “두 모델에서 각각 개선됐다”와 “한 모델에서 발견한 전략이 다른 모델로 일반화됐다”는 서로 다른 주장입니다.

### 7.2 왜 상보성이 일반화에 도움이 될 수 있는가?

**[해석: 관측 성공표에 대한 설명용 분해]** 두 하네스의 성공 여부를 고정해 놓으면 라우터 정확도는 다음과 같이 표현할 수 있습니다.

```math
A_R
=
a+\rho_1u_1+\rho_2u_2,
\qquad
A_{\cup}
=
a+u_1+u_2.
```

**기호 설명:** $a$는 두 하네스가 모두 해결하는 문제의 비율, $u_1,u_2$는 각각 한 하네스만 해결하는 비율, $\rho_1,\rho_2$는 해당 고유 성공 문제에서 라우터가 성공하는 전문가를 고르는 비율입니다. $A_R$은 라우터 성능, $A_{\cup}$는 해결 합집합 비율입니다.

Math–Gemini의 보고값을 대입하면 다음과 같습니다.

```math
A_R
=
0.47
+
\frac{12}{18}\times0.09
+
\frac{18}{22}\times0.11
=
0.62.
```

여기서 $0.47,0.09,0.11$은 Figure 2(b), 선택 성공률은 p.8의 보고값입니다. 2609.37834v1 2609.37834v1

**[해석]** 일반화 향상에는 두 조건이 동시에 필요합니다. 새로운 문제에서도 전문가의 강점이 서로 달라야 하고, 라우터가 그 차이를 알아볼 수 있어야 합니다. 전문가만 다양하고 라우터가 잘못 고르면 이득이 사라집니다.

또한 현재 전문가를 그대로 둔 채 라우터만 개선한다면, 이 관측 성공표에서 가능한 Math–Gemini의 추가 여지는 최대 5%p입니다. **두 전문가 모두 실패한 33%는 선택만 잘한다고 해결되지 않습니다.** 그 부분에는 새로운 하네스 능력이나 실행 모델·도구의 개선이 필요합니다〔Figure 2(b)〕. 2609.37834v1

### 7.3 전문화가 일반화를 해칠 수 있는 경로

**[해석]** 강한 전문화에는 반대 방향의 위험도 있습니다. 두 분기가 이미 푼 문제를 탐색에서 제거하면, 후속 변경이 그 문제들을 다시 실패하게 만드는 회귀를 놓칠 수 있습니다. 상대적으로 잘하는 문제만 남기는 방식은 실제 배포에서 자주 등장하는 공통 문제보다 작은 특수 집합을 과도하게 중시할 수도 있습니다.

이 위험이 실제로 얼마나 발생했는지는 논문이 측정하지 않습니다. 따라서 “개발 집합을 줄이면 일반화가 좋아진다”보다는 **“이 실험에서 개발 집합 조정과 지침 적응의 결합이 시험 성능 상승과 연결됐다”**가 더 정확한 결론입니다〔Table 3, Conclusion〕. 2609.37834v1 2609.37834v1

> **용어:** 회귀(regression) — 수정 후 이전에 잘하던 문제를 다시 실패하게 되는 성능 저하

### 8.2 일반화 관점에서 중요한 비교 세 가지

**첫째, Meta-Harness가 모든 설정에서 미사용 시험 평가를 하지 않았던 것은 아닙니다.** 원 논문의 수학 실험은 별도 문제 평가와 다른 모델로의 하네스 전이를 포함합니다. 반면 TerminalBench 실험은 탐색과 최종 평가에 같은 과제를 사용했다고 명시합니다. 따라서 본 논문의 평가상 개선을 “처음으로 일반화를 평가했다”라고 표현하는 것은 부정확합니다〔Meta-Harness, Table 6 및 §4.3〕. [arXiv](https://arxiv.org/html/2603.28052v1)

**둘째, SkillOpt의 전이 실험과 현재 논문의 네 설정 결과는 증거의 종류가 다릅니다.** SkillOpt는 최적화한 스킬을 다른 모델·실행 환경·수학 벤치마크로 옮깁니다. 본 논문은 각 설정에서 다시 탐색합니다. 따라서 “한 번 얻은 산출물의 재사용 가능성”은 별도로 검증해야 합니다〔SkillOpt, Table 4; 본 논문 p.6〕. [arXiv](https://arxiv.org/html/2605.23904v1) 2609.37834v1

**셋째, 최신 Harness Learning 연구와 결합할 여지가 있습니다.** 해당 연구가 제시한 상위 학습 목표는 다음과 같습니다〔해당 논문 식 (5)〕.

$$
\max_{\theta}
\mathbb E\left[
J\left(h_T;Q^{\text{eval}}\right)
\right].
$$

**기호 설명:** $\theta$는 제안 모델의 학습 가능한 가중치, $h_T$는 $T$번 수정 후의 하네스, $Q^{\text{eval}}$은 수정 피드백·선택에 사용하지 않는 평가 문제, $J$는 하네스의 평균 점수입니다. 기댓값은 과제와 생성·실행의 변동을 포함합니다. 원문은 실제 훈련에서 최종 목표의 대리값으로 개별 수정의 즉시 성과를 사용한다고 설명합니다. [arXiv](https://arxiv.org/html/2609.35738v1)

> **용어:** 메타학습 — 여러 과제의 경험을 통해 새로운 과제에 적응하는 방법을 학습하는 접근; 대리 목표 — 직접 최적화하기 어려운 최종 목표 대신 사용하는 학습 기준

**[해석·제안]** “학습된 제안 모델”과 “분기별 적응형 목표·지침”을 결합하는 것은 유망합니다. 그러나 이것은 두 논문의 결과로 입증된 조합이 아니라 새로운 연구 가설입니다. 또한 *Harness Learning* 역시 일부 비교에서 제안 수는 맞추지만 총 계산량과 피드백은 맞추지 않았다고 명시하므로, 최신 연구라고 해서 평가 문제가 해결된 것은 아닙니다〔해당 논문 §5.3〕. [arXiv](https://arxiv.org/html/2609.35738v1)

### 8.3 논문 간 수치를 직접 비교할 수 없는 이유

*Rethinking…*의 Terminal-Bench **2.1** 결과와 현재 논문의 **2.0** 결과는 벤치마크 버전, 실행 모델, 데이터 분할과 예산이 다릅니다. 해당 연구의 낮은 일반화 이득이 현재 논문의 결과를 곧바로 반박하지도 않고, 현재 논문의 50%가 그 연구의 방법보다 높거나 낮다고 순위를 정해 주지도 않습니다. 비교해야 하는 것은 **실험 설계의 원칙과 실패 가능성**입니다. [arXiv](https://arxiv.org/html/2607.12227v1) 2609.37834v1

## 10. 결론과 후속 연구 방향

### 10.1 저자들이 제시한 시사점과 후속 계획

**[저자 보고]** 결론의 중심은 **개발 문제 배정과 분기별 제안 지침을 함께 적응시키고, 개발 데이터 기반 라우팅으로 상보적인 하네스를 배포하는 것이 유효했다**는 것입니다. 동시에 저자들은 계산량 불일치, 제한적인 반복 평가, 일부 설정에서의 라우팅 손실, 개별 탐색 변화와 성능 향상 사이의 인과성 미확인을 명시합니다〔pp.9–10〕. 2609.37834v1

**구체적인 후속 실험 일정이나 연구 계획은 결론에 명시되어 있지 않습니다.** 따라서 아래 방향은 저자의 약속이 아니라 **이 검토에서 제안하는 후속 연구**입니다.

### 10.2 추가 후속 연구의 우선순위

| 우선 방향 | 제안 실험 | 확인하려는 것 |
|---|---|---|
| **1. 동일 자원·반복 평가** | 동일 총 비용과 배포 예산 아래 단일 Meta-Harness, 독립 분기 탐색, 제안법, 단순 재시도 비교; 여러 분할·탐색 시드 반복 | 구조적 개선과 추가 계산 효과의 분리 |
| **2. 고정 산출물의 전이** | 한 설정에서 얻은 하네스·라우터를 수정 없이 다른 모델, 새 저장소, 시간적으로 나중의 과제에 적용 | “다시 탐색하면 된다”를 넘어선 실제 일반화 |
| **3. 회귀를 막는 전문화** | 제거된 쉬운 문제의 일부를 고정 회귀 집합으로 유지하고 주기적으로 재검사 | 전문화가 공통 능력을 손상시키는지 확인 |
| **4. 불확실성을 고려한 라우팅** | 라우터의 선택 신뢰도를 검증하고, 불확실할 때 범용 하네스로 되돌리는 방식과 비교 | 상보성 손실을 줄이면서 새로운 문제에 대한 안정성 확보 |
| **5. 분기 수와 다양성의 관계** | 분기 수를 늘리되 예산을 고정하고 고유 해결 비율·중복률·라우팅 손실 측정 | 분기 증가가 유용한 다양성을 만드는지, 비용만 늘리는지 확인 |
| **6. 학습된 제안 모델과의 결합** | 범용 수정 능력을 학습한 제안 모델에 분기별 목표·지침 적응을 결합 | “하네스의 일반화”와 “개선 절차의 일반화”를 함께 높일 수 있는지 검증 |

여기서 첫 두 방향이 가장 중요합니다. **동일 자원에서 재현되는가**, 그리고 **발견된 하네스를 고정한 채 새로운 환경으로 옮겨도 이득이 남는가**가 확인되어야 일반화에 대한 주장을 한 단계 강화할 수 있습니다.

### 10.3 일반화를 위한 구체적 방법 제안

**[제안: 논문에 없는 확장]** 전문화 과정에서 공통 능력의 손상을 줄이는 한 방법은, 분기별 개발 점수에 고정된 공통 회귀 집합의 성능을 섞는 것입니다.

```math
\widetilde J_b^t(H)
=
(1-\lambda)J_b^t(H)
+
\lambda
\frac{1}{|\mathcal A|}
\sum_{x\in\mathcal A}
\mathbb E\left[
r\left(f_M(H,x),x\right)
\right].
```

**기호 설명:** $\widetilde J_b^t$는 제안하는 수정 목적함수, $J_b^t$는 원 논문의 분기별 목적함수, $\mathcal A$는 고정된 공통 **개발용** 회귀 문제 집합, $\lambda\in[0,1]$는 전문화와 공통 능력 유지 사이의 비중입니다. 나머지 기호는 식 (1)과 같습니다.

$\mathcal A$도 최적화에 사용하므로 독립적인 최종 시험 집합으로 간주하면 안 됩니다. 별도의 미사용 평가 집합이 필요합니다. 또한 이 혼합 목적이 실제로 성능을 높인다는 증거는 아직 없으며, 전문화가 약해지는 부작용도 함께 실험해야 합니다.

### 최종 평가

**이 논문의 가장 설득력 있는 기여는 “모델을 더 똑똑하게 재학습했다”가 아니라, “서로 다른 강점을 가진 실행 프로그램을 발견하도록 탐색의 평가 대상과 설계 지침을 바꾸고, 그 강점을 시험 정답 없이 일부 결합했다”는 것입니다.** Math–Gemini의 큰 상승은 유망한 결과이지만, 다른 설정의 작은 증가와 계산 예산·반복 평가 한계를 함께 보아야 합니다〔Tables 1–3, Conclusion〕. 2609.37834v1 2609.37834v1 2609.37834v1

일반화 연구에 미칠 중요한 영향은 **“최고 점수의 하네스 하나를 찾는 문제”를 “이동 가능한 전문가 집합과 신뢰할 수 있는 선택 규칙을 찾는 문제”로 확장한다는 데** 있습니다. 다음 단계의 핵심은 더 높은 단일 벤치마크 점수보다, **고정된 하네스·라우터의 전이성, 자원 일치 비교, 회귀 방지, 그리고 개선 과정 자체의 재현성**입니다.
