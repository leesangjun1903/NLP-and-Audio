# LoGRA: Scaling LLM Reinforcement Learning with Low-Rank Gradient Sketches

**핵심 판단:** 이 논문의 가장 강한 기여는 **평가한 추론 과제에서 성능을 대체로 유지하면서 학습 메모리를 줄이고, 같은 하드웨어에서 Dense Adam으로 실행하지 못한 27B 모델의 강화학습을 가능하게 했다는 것**입니다.  
일반화에 관해서는 별도 평가 문제에서의 성능 유지·개선을 보여 주지만, **그래디언트 압축 자체가 일반화를 향상시킨다는 인과적·이론적 증거는 제시하지 않습니다.** [원문 pp. 5–10, Tables 1–2, Figures 2–6]

보고서에서 **[저자 보고]**는 원문에 직접 제시된 내용, **[분석자 해석]**은 그 증거에 대한 평가, **[후속 연구 제안]**은 아직 검증되지 않은 실험 방향을 뜻합니다. 관련 연구 비교는 별도 절에서 다루며, 다른 논문의 결과를 LoGRA의 결과로 취급하지 않습니다.

---

## 1. Executive summary — 8문장

1. **LoGRA는 대규모 언어모델의 강화학습 후훈련에서 그래디언트와 최적화 상태가 차지하는 메모리를 줄이기 위해, 큰 그래디언트를 작은 저랭크 스케치로 표현하는 방법입니다.** [pp. 1–3]

2. **선택된 가중치 행렬에 대해 전체 그래디언트를 먼저 저장하지 않고 역전파 중 스케치를 직접 누적하며, 이를 원래 가중치에 병합하므로 기존 모델의 순전파 구조를 유지합니다.** [p. 3, 식 (2)–(4)]

3. **예측 KL 제어는 업데이트 전에 다음 토큰 확률분포가 얼마나 달라질지 추정하고, 정해진 변화 예산에 맞춰 업데이트 크기를 조절합니다.** [pp. 4–5, 식 (5)–(7)]

4. **주실험에서 평균 학습 메모리는 1.5B 모델에서 9.18→7.18 GiB/GPU로 21.8%, 7B에서 31.82→17.29 GiB/GPU로 45.7% 감소했습니다.** [pp. 6–7, Table 1]

5. **첫 200회 업데이트 구간의 최고 MATH-500 Pass@1은 1.5B에서 Dense Adam의 63.77%보다 높은 67.87%였고, 7B에서는 72.48%와 72.33%로 비슷했습니다.** [pp. 5–7, Figure 2, Table 1]

6. **27B 모델은 H100 80GB GPU 8개로 구성된 단일 노드에서 학습할 수 있었으며, 같은 자원 배분의 Dense Adam은 첫 최적화 상태 할당에서 메모리 부족으로 실패했습니다.** [pp. 5–7, 16]

7. **별도의 27B 장기 실험에서는 1,100회 이상의 기록된 학습 단계 동안 동일한 8개 과제의 보류 문제 점수가 39.69%에서 62.94%로 상승했지만, 이는 한 번의 학습 궤적에서 얻은 결과입니다.** [p. 7, Figure 4; pp. 15–16]

8. **따라서 논문은 메모리 효율과 학습 실행 가능성에 대한 근거를 제공하지만, 새로운 도메인으로의 일반화 향상, LoRA 대비 정확도·속도 우위, KL 제어의 필수성까지 확립하지는 않습니다.** [pp. 8–10, 15–17]

> **용어 풀이**
>
> - **강화학습 후훈련:** 이미 사전학습된 모델이 자신이 생성한 답변에 대한 보상을 이용해 추가로 학습하는 과정입니다.
> - **그래디언트:** 손실을 줄이려면 각 가중치를 어느 방향으로 얼마나 바꿔야 하는지 나타내는 미분값입니다.
> - **저랭크 스케치:** 큰 행렬의 정보를 적은 수의 독립적인 방향으로 압축한 작은 행렬입니다.
> - **KL 발산:** 두 확률분포의 차이를 측정하는 값으로, 여기서는 업데이트 전후의 다음 토큰 확률 변화를 측정합니다.
> - **보류 문제:** 학습에 사용하지 않고 평가를 위해 따로 둔 문제입니다.

## 2. 연구 배경·목표·필요성

### 2.1. 해결하려는 문제

**[저자 보고]** LLM의 강화학습에는 모델 가중치 외에도 그래디언트, 최적화 상태, 중간 활성값, 응답 생성용 모델 등이 필요합니다.  
따라서 **추론은 가능한 하드웨어라도 강화학습은 불가능할 수 있습니다.** 저자는 7B 모델의 BF16 가중치가 약 14 GB인 데 비해, Adam의 FP32 모멘트 버퍼 두 개만으로 약 56 GB가 추가된다는 예를 제시합니다. [pp. 1–2]

> **용어 풀이**
>
> - **BF16·FP32:** 각각 16비트와 32비트 부동소수점 수 표현입니다.
> - **최적화 상태:** 다음 가중치 업데이트를 계산하기 위해 저장하는 과거 학습 정보입니다.
> - **모멘트:** Adam에서는 과거 그래디언트의 이동평균과 제곱값의 이동평균을 뜻합니다.
> - **활성값:** 모델의 순전파 과정에서 만들어지는 중간 계산 결과입니다.

기존 접근에는 학습 상태를 GPU 여러 개에 나누는 FSDP, 일부 계산을 다시 수행해 활성값 저장을 줄이는 체크포인팅, CPU 메모리로 데이터를 옮기는 오프로딩, 작은 어댑터만 학습하는 LoRA 등이 있습니다. LoGRA는 이와 함께 사용할 수 있는 **그래디언트 표현 자체의 압축**에 초점을 맞춥니다. [p. 2; p. 10, §4]

### 2.2. 연구 목적

논문의 목적은 다음 세 가지로 정리할 수 있습니다.

| 목적 | 연구가 시도하는 해결책 | 근거 |
|---|---|---|
| 학습 메모리 감소 | 전체 크기 그래디언트 버퍼 대신 작은 스케치를 직접 누적 | pp. 2–3 |
| 압축된 업데이트의 안정성 확보 | 업데이트가 정책에 미치는 영향을 예측 KL로 추정하여 크기 조절 | pp. 4–5 |
| 학습 모델과 생성 모델의 동기화 비용 감소 | 작은 업데이트 인자와 무작위 시드로 동일한 갱신을 재현하는 절차 제안 | pp. 3–4, Algorithm 1 |

**[분석자 해석]** 세 번째 목적은 첫 번째와 증거 수준이 다릅니다. **주실험은 실제로 전체 가중치를 동기화했습니다.**  
따라서 압축 동기화는 제안된 기능이지만, 주실험의 처리량으로 그 통신 효과가 검증되었다고 해석할 수는 없습니다. [p. 16, Appendix D.1]

### 2.3. 왜 저랭크 압축을 시도하는가?

**[저자 보고]** 정답 여부처럼 응답 하나당 제한적인 보상이 주어지는 RL에서는, 학습에 필요한 유용한 신호를 전체 그래디언트보다 작은 표현에 담을 수 있다는 직관이 출발점입니다. [p. 2]

**[분석자 해석]** 이는 연구의 동기입니다. 논문은 **“보상이 이진값이면 그래디언트가 반드시 저랭크가 된다”는 정리**를 증명하지 않습니다. 압축 후에도 충분한 학습 성능을 유지하는지는 실험으로 확인합니다.

## 4. 제안 방법과 모델 구조 — 수식 중심 설명

### 4.1. 모델 구조에서 바뀌는 부분

**[저자 보고]** LoGRA는 새로운 Transformer 구조를 제안하지 않습니다. 기존 모델의 **Attention과 MLP 투영 가중치**에 압축 업데이트를 적용하고, 다른 파라미터는 고정합니다. 가중치는 원래 크기로 유지되고, 별도의 지속적인 어댑터 분기는 없습니다. [p. 3, §2.2]

| 구성 요소 | LoGRA의 처리 |
|---|---|
| 순전파 | 기존 전체 크기 가중치로 계산 |
| 선택된 가중치의 역전파 | 입력을 먼저 투영하여 작은 그래디언트 스케치를 직접 누적 |
| 최적화 | SGD 또는 RowAdam 등으로 스케치 조정 |
| 업데이트 크기 | 모든 선택 행렬에 공통 배율 $\alpha$ 적용 |
| 가중치 반영 | 저랭크 업데이트를 원래 가중치에 병합 |
| 다음 단계 | 새로운 투영행렬을 표본화하여 다른 부분공간에서 학습 가능 |

> **용어 풀이**
>
> - **Attention:** 문맥의 어떤 토큰 정보를 참고할지 조절하는 모듈입니다.
> - **MLP:** 각 토큰의 내부 표현을 변환하는 신경망 모듈입니다.
> - **부분공간:** 전체 가능한 변화 방향 중 일부 방향으로 이루어진 공간입니다.
> - **SGD:** 현재 그래디언트에 비례해 가중치를 갱신하는 기본적인 최적화 방법입니다.

### 4.2. 전체 그래디언트와 저랭크 스케치

#### ① 일반적인 업데이트 — 원문 식 (1)

$$
G=\nabla_W\mathcal L\in\mathbb R^{d\times k},
\qquad
W\leftarrow W-\eta G.
$$

**기호:** $W$는 출력 차원 $d$, 입력 차원 $k$를 가진 가중치 행렬이고, $\mathcal L$은 미분 가능한 RL 손실, $G$는 그 그래디언트, $\eta$는 학습률입니다. [p. 2]

일반적인 그래디언트 누적은 $dk$개의 값을 저장합니다. 배치를 여러 마이크로배치로 나눠도 최종 누적 버퍼의 크기는 그대로입니다.

> **마이크로배치:** 큰 학습 배치를 메모리에 들어갈 만큼 작게 나눈 처리 단위입니다.

#### ② 스케치 생성 — 원문 식 (2)

$$
A\in\mathbb R^{r\times k},
\qquad
S=GA^\top\in\mathbb R^{d\times r},
\qquad
r\ll\min(d,k).
$$

**기호:** $A$는 학습하지 않는 무작위 투영행렬, $r$은 압축 차원, $S$는 그래디언트 스케치이며, $A^\top$는 전치행렬입니다. [p. 3]

기본 설정에서 $A$의 각 원소는 독립적으로 $+1/\sqrt r$ 또는 $-1/\sqrt r$을 취합니다. $A$는 현재 배치와 독립적으로 표본화하고, **한 업데이트의 마이크로배치 누적 동안에는 고정**합니다.

> **Rademacher 투영:** 양수와 음수를 같은 확률로 선택하는 무작위 부호 행렬을 이용한 투영입니다.

#### ③ 전체 그래디언트를 만들지 않는 계산

다음 식은 **p. 3의 구현 설명을 이해하기 쉽게 재표현한 것으로, 원문에 별도로 번호가 붙은 식은 아닙니다.**

$$
G=EX^\top
\quad\Longrightarrow\quad
S=GA^\top=E(AX)^\top.
$$

**기호:** $X\in\mathbb R^{k\times N}$는 입력 활성값, $E\in\mathbb R^{d\times N}$는 출력에 대한 역전파 미분값, $N$은 묶어서 처리한 입력 위치 수입니다.

계산 순서를 보면, 큰 $G$를 만든 뒤 압축하는 대신 **입력 $X$를 먼저 $AX$로 줄이고 이를 역전파 미분값과 곱해 $S$를 직접 계산**할 수 있습니다. 실제 구현은 이 스케치를 FP32로 누적합니다. [p. 3]

### 4.3. 스케치에서 가중치 업데이트로

#### ④ 기본 복원과 업데이트 — 원문 식 (3)

$$
\widehat G=SA,
\qquad
W\leftarrow W-\eta SA.
$$

**기호:** $\widehat G$는 원래 그래디언트의 저랭크 근사이며, $S$, $A$, $\eta$는 앞서 정의한 스케치·투영행렬·학습률입니다. [p. 3]

$SA$의 크기는 원래 그래디언트와 같지만 랭크는 최대 $r$입니다. 이것은 **근사값**이며 정확한 그래디언트 복원을 주장하는 식은 아닙니다.

#### ⑤ 최적화와 KL 제어를 포함한 업데이트 — 원문 식 (4)

$$
W\leftarrow W-\alpha\eta UA.
$$

**기호:** $U\in\mathbb R^{d\times r}$는 최적화기가 조정한 스케치, $\alpha$는 업데이트 크기를 조절하는 공통 배율입니다. 기본 SGD에서는 $U=S$입니다. [p. 3]

각 단계의 업데이트는 저랭크이지만, $A$를 단계마다 바꾸면 여러 업데이트의 합은 하나의 고정된 랭크- $r$ 부분공간에 제한되지 않습니다. 다만 **누적 변화가 반드시 전체 랭크가 된다거나, 이것만으로 일반화가 좋아진다는 보장은 없습니다.** [p. 3]

### 4.4. 메모리와 동기화 비용

**[저자 보고]** 그래디언트 누적 버퍼는 $dk$개 값에서 $dr$개 값으로 줄어듭니다. 예를 들어 $d=k=4096$, $r=64$일 때 FP32 버퍼는 **64 MiB에서 1 MiB**로 감소합니다. [p. 3]

그러나 가중치, 활성값, 투영행렬, 다른 버퍼는 남습니다. 따라서 위 예의 **64배 감소는 특정 그래디언트 버퍼에 대한 값**이며, 전체 GPU 메모리의 감소율이 아닙니다.

제안된 동기화에서는 생성 엔진이 시드로 $A$를 재생성하고, 전달받은 $\alpha\eta U$를 적용합니다. 전송할 값은 전체 $dk$개 대신 대략 $dr$개와 시드·메타데이터가 됩니다. **이 압축 동기화는 Algorithm 1에 제시되지만, Table 1 주실험에는 사용되지 않았습니다.** [pp. 3–4; p. 16]

> **정책 동기화:** 학습 중인 모델의 변경 사항을 응답 생성용 모델에 반영하는 과정입니다.  
> **GiB·MiB:** 각각 $2^{30}$바이트와 $2^{20}$바이트 단위입니다.

### 4.5. RowAdam — 주실험의 최적화기

RowAdam은 스케치의 **행마다 하나의 제곱 크기 통계**를 유지합니다. 원문 식 (15)는 다음과 같습니다. [pp. 14–15]

```math
v_{t,i}
=
\beta_2v_{t-1,i}
+
(1-\beta_2)\frac1r
\sum_{j=1}^{r}(S_t)_{ij}^{2},
```

```math
\widehat v_{t,i}
=
\frac{v_{t,i}}{1-\beta_2^t},
\qquad
(\widetilde U_t)_{i,:}
=
\frac{(S_t)_{i,:}}
{\sqrt{\widehat v_{t,i}}+\epsilon_t}.
```

**기호:** $t$는 업데이트 번호, $i$는 행, $j$는 스케치 열, $v_{t,i}$는 행별 제곱 크기의 이동평균, $\widehat v_{t,i}$는 초기값 편향을 보정한 값, $\beta_2=0.95$는 과거 정보의 유지 정도, $\epsilon_t$는 수치 안정화 항, $\widetilde U_t$는 행별 크기를 조정한 스케치입니다.

그다음 원래 스케치와 전체 크기가 같도록 다시 조정합니다. 원문의 설명을 수식으로 표현하면 다음과 같습니다.

$$
U_t=
\frac{\|S_t\|_F}{\|\widetilde U_t\|_F}\widetilde U_t.
$$

**기호:** $\|\cdot\|_F$는 행렬 원소 제곱합의 제곱근인 Frobenius 노름이고, $U_t$는 최종 업데이트 인자입니다. 영 스케치는 영 업데이트로 처리합니다. [p. 15]

> **편향 보정:** 이동평균을 0에서 시작할 때 초기 추정값이 작아지는 효과를 보정하는 절차입니다.  
> **노름:** 벡터나 행렬의 전체 크기를 나타내는 값입니다.

RowAdam은 **1차 모멘텀을 저장하지 않으며**, 선택된 행렬마다 $d$개의 2차 모멘트 값만 필요합니다. 따라서 Dense Adam과 비교할 때는 그래디언트 압축뿐 아니라 **최적화기의 상태와 동작도 함께 달라진다**는 점을 고려해야 합니다. [pp. 14–16]

### 4.6. 예측 KL을 이용한 업데이트 크기 조절

#### ⑥ 제어하려는 정책 변화 — 원문 식 (5)

$$
\frac1{|\mathcal P|}
\sum_{s\in\mathcal P}
D_{\text{KL}}
\left(
\pi_\theta(\cdot\mid s)
\;\|\;
\pi_{\theta+\alpha D}(\cdot\mid s)
\right)
\approx
\alpha^2q(D).
$$

**기호:** $\theta$는 현재 모델 파라미터, $\pi_\theta$는 현재 정책, $D$는 전체 파라미터의 업데이트 제안, $\alpha$는 적용 배율, $\mathcal P$는 선택한 문맥 집합, $s$는 프롬프트와 이미 생성된 응답 접두부, $q(D)$는 배율 1인 제안의 예측 KL입니다. 각 선택 행렬의 업데이트 제안은 $D_W=-\eta UA$입니다. [p. 4]

여기서 비교하는 것은 **같은 문맥에서의 업데이트 전후 정책**입니다. 사전학습 모델을 기준으로 한 장기적인 지식 보존을 직접 측정하는 식은 아닙니다.

#### ⑦ 로짓 변화로 예측 KL 계산 — 원문 식 (6)

$$
p(s)=\text{softmax}\left(\frac{z(s)}{T}\right),
\qquad
\dot z_v(s)=
\left.
\frac{d\,z_v(\theta+aD;s)}{da}
\right|_{a=0},
$$

$$
q(D)=
\frac1{2|\mathcal P|T^2}
\sum_{s\in\mathcal P}
\text{Var}_{v\sim p(s)}
\left[\dot z_v(s)\right].
$$

**기호:** $z_v(s)$는 토큰 $v$의 로짓, $z(s)$는 전체 어휘의 로짓 벡터, $T>0$는 양쪽 정책에 동일하게 사용하는 온도, $p(s)$는 현재 토큰 확률분포, $a$는 미분을 위한 스칼라 배율, $\dot z_v(s)$는 업데이트 방향에서의 로짓 변화율입니다. 분산은 현재 토큰 확률로 가중합니다. [p. 5; pp. 13–14]

직관적으로, 모든 토큰 점수가 같은 양만큼 바뀌면 상대적인 확률은 그대로입니다. 반대로 토큰별 점수가 서로 다르게 바뀌면 확률분포가 변합니다. 이 차이를 확률가중 분산으로 측정합니다.

> **용어 풀이**
>
> - **로짓:** 확률로 변환하기 전의 토큰 점수입니다.
> - **Softmax:** 여러 점수를 합이 1인 확률로 바꾸는 함수입니다.
> - **온도:** 확률분포를 더 날카롭거나 평평하게 조절하는 값입니다.
> - **JVP:** 파라미터를 특정 방향으로 움직일 때 모델 출력이 얼마나 변하는지 계산하는 미분 연산입니다.

부록은 문맥만 일부 선택하고, 선택된 각 문맥에서는 **전체 어휘**에 대한 분산을 계산한다고 설명합니다. 이 분산은 보상 분산이나 시드 간 성능 분산과 다릅니다. [p. 14]

#### ⑧ 예산에 맞춰 배율 결정 — 원문 식 (7)

```math
\alpha=
\min\left\{
\alpha_{\max},
\sqrt{\frac{\delta}{q(D)}}
\right\},
\qquad 0 < q(D) < \infty.
```

**기호:** $\delta>0$는 허용할 예측 KL 예산, $\alpha_{\max}>0$는 배율 상한, $q(D)$는 조절 전 업데이트의 예측 KL입니다. [p. 5]

예를 들어 $q(D)=4\delta$이면 배율은 최대 $1/2$가 됩니다. 반대로 예측 KL이 작고 상한이 허용하면 업데이트를 키울 수도 있습니다.

### 4.7. 이론적으로 유도한 것과 유도하지 않은 것

부록의 핵심은 다음과 같은 **국소 Taylor 전개**입니다. [p. 13, 식 (11)–(12)]

```math
K_s(\alpha)
=
\frac{\alpha^2}{2}K_s''(0)
+
O(\alpha^3),
```

```math
\frac1{|\mathcal P|}
\sum_{s\in\mathcal P}K_s(\alpha)
=
\alpha^2q(D)+O(\alpha^3).
```

**기호:** $K_s(\alpha)$는 문맥 $s$에서 업데이트 전후 정책의 KL, $K_s''(0)$는 배율 0에서의 2차 미분, $O(\alpha^3)$는 작은 배율 근처에서 남는 고차 오차항입니다.

가정은 업데이트 제안 $D$와 문맥 집합이 고정되어 있고, 해당 방향에서 로짓의 3차 미분이 연속이고 유계이며, 같은 온도를 사용하는 것입니다.

> **국소 근사:** 현재 상태와 가까운 작은 변화에 대해 성립하는 근사입니다.  
> **Taylor 전개:** 함수의 주변 값을 미분값들의 합으로 표현하는 방법입니다.

**[분석자 해석]** 이 유도는 예측 KL의 계산을 뒷받침합니다. 그러나 다음을 보장하지는 않습니다.

- 실제 KL이 언제나 예산 이하라는 보장
- 모든 프롬프트에서 동일한 정책 변화 제한
- 기대 보상의 단조 증가나 학습 수렴
- 새로운 도메인에 대한 일반화 향상
- 기존 능력의 망각 방지

### 4.8. KL 예산 감소와 불일치 보정

주실험은 다음의 코사인 감소 일정을 사용합니다. [p. 16, 식 (16)]

```math
\delta_u
=
\delta_{\min}
+
\frac{\delta_{\max}-\delta_{\min}}2
\left[
1+\cos\left(\pi\frac{u-1}{H-1}\right)
\right].
```

**기호:** $u$는 실제 업데이트 번호, $H=300$은 감소 일정의 길이, $\delta_{\max}=2\times10^{-4}$, $\delta_{\min}=2\times10^{-5}$입니다.

생성 엔진과 학습 엔진의 확률 계산 불일치를 고려하여 다음 유효 예산도 사용합니다. [p. 16, 식 (17)]

```math
\delta_u^{\text{eff}}
=
\max\left(\delta_u-\kappa_u,\;0.5\delta_u\right).
```

**기호:** $\delta_u^{\text{eff}}$는 보정 후 예산, $\kappa_u$는 같은 명목 가중치에서 생성 엔진과 학습 엔진의 로그확률 차이를 평활화한 추정값입니다.

저자는 이 보정을 **예산을 조절하는 경험적 규칙이며, KL의 정확한 분해가 아니라고 명시**합니다. [p. 16]

> **Annealing:** 학습이 진행되면서 학습률이나 허용 변화량을 점차 줄이는 절차입니다.  
> **평활화:** 최근 관측값을 평균내어 일시적인 변동을 줄이는 처리입니다.

> **Advantage:** 어떤 응답의 보상이 기준보다 얼마나 좋은지 나타내는 학습 신호입니다.

**DAPO-Math-7.5K:** DAPO-Math-17k 학습 자료를 원래 순서대로 읽으며, 첫 프롬프트 메시지 내용이 중복되지 않는 최초 7,500개를 선택합니다.

학습 중복과 학습·평가 문제의 겹침을 제거하지만, 학습과 평가가 **서로 다른 과제 종류로 분리된 것은 아닙니다.**

### 5.3. 평가 지표의 의미

- **MATH-500 Pass@1:** 이 논문에서는 문제당 생성한 4개 응답, 총 2,000개 응답의 정오 판정 평균입니다. 탐욕적 생성 한 번의 정확도와 동일한 지표로 취급하면 안 됩니다. [p. 15]
- **Pass@4:** 네 번의 시도에 대한 성공 지표로 보고되지만, 원문은 Pass@1처럼 별도의 계산식을 자세히 제시하지 않습니다.
- **Reasoning-Gym 점수:** 각 과제의 검증기 점수가 $[0,1]$ 범위이며, 8개 과제별 평균을 동일 가중치로 평균합니다. [p. 15]

> **검증기:** 생성된 답변이 정답이나 과제 조건을 충족하는지 자동 판정하는 프로그램입니다.  
> **Macro 평균:** 각 과제의 문제 수와 관계없이 과제마다 같은 비중을 주는 평균입니다.

> **Gaussian 투영:** 정규분포에서 뽑은 값으로 구성한 투영행렬입니다.  
> **코사인 유사도:** 두 행렬을 긴 벡터처럼 보았을 때 방향이 얼마나 일치하는지 측정한 값입니다.

## 8. 모델 일반화 성능 향상 가능성에 대한 집중 분석

### 8.1. 직접 확인한 일반화 증거

**[저자 보고]** 학습에 사용한 DAPO-Math-7.5K와 별도의 MATH-500에서 성능을 평가했고, Reasoning-Gym에서는 학습에서 제외한 문제들로 평가했습니다. 따라서 학습 문제의 보상만 보고한 연구는 아닙니다. [pp. 5–7, 15]

그러나 증거는 다음 범위에 머뭅니다.

| 일반화의 종류 | 이 논문이 제공하는 증거 |
|---|---|
| 같은 과제의 새로운 문제 | Reasoning-Gym 보류 문제 평가 |
| 별도 수학 벤치마크에서의 성능 | DAPO 학습 후 MATH-500 평가 |
| 새로운 과제 종류로의 전이 | 직접 평가 없음 |
| 새로운 언어·도메인·난이도로의 전이 | 체계적인 평가 없음 |
| 사전학습 능력 보존 | 별도의 광범위한 평가 없음 |
| 압축 자체가 일반화를 향상시키는가 | 원인을 분리한 실험 없음 |

> **분포 내 일반화:** 학습과 비슷한 종류의 새로운 문제를 잘 푸는 능력입니다.  
> **분포 밖 일반화, OOD:** 학습과 다른 도메인·조건·문제 유형에서도 성능을 유지하는 능력입니다.

### 8.2. 세 가지 가능성과 각각의 증거 한계

#### A. 누적 업데이트의 표현 범위

**[저자 보고]** 투영을 갱신하면 누적 업데이트가 고정된 저랭크 부분공간에 묶이지 않습니다. [p. 3]

**[분석자 해석]** 이는 업데이트가 사용할 수 있는 방향에 관한 구조적 성질입니다. Figure 5에서는 갱신 방식이 고정 방식보다 일관되게 좋지 않았으므로, 이를 일반화 향상의 근거로 삼을 수 없습니다.

#### B. 작은 정책 변화와 학습 안정성

**[저자 보고]** 보수적인 KL 예산은 후반 평가 성능을 유지하는 데 유용했습니다. [pp. 9–10]

**[분석자 해석]** 안정적으로 학습을 계속할 수 있다는 결과는 중요하지만, 이것이 새로운 도메인으로의 전이나 기존 지식 보존을 의미하지는 않습니다. 해당 능력은 별도로 평가해야 합니다.

#### C. 메모리 절감으로 확보되는 연구 자원

**[저자 보고]** 같은 하드웨어에서 더 큰 모델의 학습을 실행할 수 있었습니다. [pp. 6–7]

**[분석자 해석]** 이는 일반화 연구를 수행할 수 있는 자원상의 이점입니다. 그러나 같은 총 GPU 시간이나 같은 생성 토큰 예산에서 더 높은 일반화 성능을 얻는지는 비교하지 않았습니다.

### 8.3. 가장 중요한 해석

**LoGRA에서 “작게 저장되는 것”은 각 단계의 그래디언트 스케치입니다. 최종 학습 모델의 전체 변화가 작은 복잡도로 표현된다는 보장은 없습니다.**

따라서 다음 연결은 이 논문만으로 성립하지 않습니다.

> 스케치가 작음 → 최종 모델이 단순함 → 과적합이 줄어듦 → 일반화가 향상됨

각 연결을 확인하려면 최종 가중치 변화의 복잡도, 학습·평가 성능 차이, 독립적인 평가 분포를 추가로 분석해야 합니다. 이는 **후속 연구 과제**입니다.

> **과적합:** 학습 자료에는 잘 맞지만 새로운 자료에서는 성능이 떨어지는 현상입니다.

### 9.3. 원문에서 해석이 불명확한 지점

본문은 1.5B·7B 주실험을 **20,000회 업데이트**했다고 쓰고, Table 1의 정확도는 **0–200회**에서 집계하며, 부록의 KL 감소 일정은 **300회**로 정의합니다. 이들은 서로 다른 범위를 가리킬 수 있지만, **300회 이후 예산 처리와 전체 기간의 정확도 추이는 충분히 설명되지 않습니다.** [p. 5; p. 7, Table 1; p. 16]

따라서 이 보고서는 해당 수치를 임의로 “200회”나 “300회”로 수정하지 않았습니다.

## 11. 2020년 이후 관련 연구 비교

다음은 **2026년 10월 29일 기준 확인한 관련 1차 자료**입니다. 방법의 위치와 검증 범위를 비교하며, 서로 다른 실험의 정확도·메모리 수치를 순위화하지 않습니다.

### 11.1. 방법론 비교

| 연구 | 핵심 접근 | LoGRA와의 차이·관계 | 후속 연구에서 고려할 점 |
|---|---|---|---|
| **LoRA, 2021** | 사전학습 가중치를 고정하고 작은 저랭크 행렬을 학습 | LoGRA의 투영행렬은 학습 대상이 아니며, 갱신을 원래 가중치에 누적 | LoRA가 항상 성능이 낮다는 전제는 부적절; LoGRA의 직접 비교에서도 정확도 우위 없음 |
| **Flora, 2024** | 무작위 투영으로 그래디언트 누적·모멘텀을 압축하고 투영을 재표본화 | LoGRA와 가장 가까운 개념적 선행연구 | 저랭크 누적과 투영 갱신 자체를 LoGRA의 최초 발명으로 서술하면 안 됨 |
| **GaLore, 2024** | 그래디언트의 저랭크 부분공간에서 최적화 상태를 유지 | 대표 방식은 그래디언트의 SVD로 방향을 선택; LoGRA는 배치 독립 무작위 투영 | 정보에 맞춰 고른 방향과 단순 무작위 방향의 RL 성능·비용 비교 필요 |
| **GaLore 2, 2025** | 빠른 randomized SVD와 FSDP 결합 등으로 대규모 사전학습 확장 | LoGRA보다 장기 사전학습·분산 확장에 초점 | 사전학습에서의 결과를 RL에서의 우열로 옮길 수 없음 |
| **APOLLO, 2024 공개·2025 발표** | 저랭크 상태로 적응적 크기 조절을 추정하여 전체 그래디언트에 적용 | LoGRA는 업데이트 방향 자체를 저랭크 인자로 구성 | “상태 압축”과 “그래디언트·업데이트 압축”을 구분해야 함 |
| **Fira, 2024 공개·2025 개정** | 저랭크 최적화의 크기 조절을 활용해 전체 랭크 갱신을 구성하고 크기 급증을 제한 | 압축에서 빠지는 방향을 보완하는 접근 | RL에서도 버린 방향을 복구하는 이득이 추가 메모리·계산 비용보다 큰지 검증 가능 |
| **DeepSeekMath / GRPO, 2024** | 여러 응답의 상대적 보상을 이용하는 정책 최적화 | RL 목적함수·advantage 계산을 다루며, LoGRA는 그 결과의 그래디언트 표현을 다룸 | 경쟁 관계로만 볼 수 없고, 결합 효과는 별도 실험 필요 |
| **LoRA Without Regret, 2025** | 특정 RL 설정에서 작은 랭크 LoRA도 전체 미세조정과 비슷한 성능을 보고 | LoGRA의 “RL 신호는 작은 표현으로 충분할 수 있다”는 동기와 연결 | 연구자 기술 보고이며, 모든 RL 과제에 적용되는 정리는 아님 |

각 행의 1차 출처는 다음과 같습니다.

- LoRA는 원래 가중치를 고정하고 저랭크 행렬을 학습하는 구조와 여러 NLP 평가를 제시합니다. [arxiv.org](https://arxiv.org/abs/2106.09685?utm_source=chatgpt.com)
- Flora의 §2.4와 Algorithms 1–2는 이미 압축된 그래디언트 누적과 투영 재표본화, 모멘텀 압축을 다룹니다. [arxiv.org](https://arxiv.org/html/2402.03293v2?utm_source=chatgpt.com)
- GaLore는 사전학습과 미세조정에서 저랭크 그래디언트 투영을 평가하고, GaLore 2는 빠른 SVD와 FSDP 통합을 확장합니다. [arxiv.org](https://arxiv.org/abs/2403.03507?utm_source=chatgpt.com)
- APOLLO는 저랭크 보조 상태를 이용한 크기 조절, Fira는 전체 랭크 학습을 유지하기 위한 크기 조절과 제한 장치를 제안합니다. [arxiv.org](https://arxiv.org/html/2412.05270v4?utm_source=chatgpt.com)
- DeepSeekMath는 GRPO를 도입했고, *LoRA Without Regret*은 특정 수학 RL 실험에서 매우 작은 랭크의 유효성을 보고합니다. [arxiv.org](https://arxiv.org/abs/2402.03300?utm_source=chatgpt.com)

> **용어 풀이**
>
> - **SVD, 특잇값 분해:** 행렬에서 중요한 변화 방향과 그 크기를 분리하는 방법입니다.
> - **Randomized SVD:** 무작위 샘플링을 활용해 주요 방향을 효율적으로 근사하는 SVD이며, LoGRA의 배치 독립 무작위 투영과 동일한 방식은 아닙니다.
> - **모멘텀:** 과거 그래디언트 방향을 누적하여 업데이트의 변동을 줄이는 방법입니다.
> - **GRPO:** 같은 문제에 대해 생성한 여러 응답의 보상을 비교해 학습 신호를 만드는 정책 최적화 방법입니다.

### 11.2. 일반화와 가장 직접적으로 연결되는 2026년 연구

**Zhu, Alur, Kang의 *Non-vacuous Generalization Bounds for Reinforcement Learning with Verifiable Rewards*는 LoGRA와 다른 질문을 다룹니다.** 이 연구는 RLVR, 학생 모델이 생성한 문맥에서의 증류, TinyLoRA, 양자화를 결합하여 **최종 모델 변화를 기술하는 정보량**과 일반화 보장을 연결합니다. [arxiv.org](https://arxiv.org/html/2607.14506v1?utm_source=chatgpt.com)

| 구분 | LoGRA | 해당 2026년 연구 |
|---|---|---|
| 압축 대상 | 각 학습 단계의 그래디언트 표현 | 최종 학습 모델의 가중치 변화 |
| 중심 목적 | 학습 메모리·실행 가능성 | 새로운 데이터에 대한 성능의 이론적 하한 |
| 핵심 근거 | RL 실험, 메모리 측정, 국소 KL 유도 | 압축 기반 PAC-Bayes 분석과 실험 |
| 연결할 때의 주의 | 작은 스케치가 작은 최종 모델 복잡도를 보장하지 않음 | 그 일반화 보장을 LoGRA에 자동 적용할 수 없음 |

해당 연구도 기본 보장은 학습과 배포 분포가 맞는 조건에 적용되며, 분포가 달라질 때는 별도 조건과 자료가 필요하다고 명시합니다. [arxiv.org](https://arxiv.org/html/2607.14506v1?utm_source=chatgpt.com)

> **용어 풀이**
>
> - **RLVR:** 정답 판정 등으로 보상을 검증할 수 있는 강화학습입니다.
> - **증류:** 더 강한 모델의 출력을 이용해 다른 모델을 학습시키는 방법입니다.
> - **양자화:** 수치를 더 적은 비트로 표현하여 저장량을 줄이는 방법입니다.
> - **PAC-Bayes 일반화 경계:** 정해진 가정과 확률하에서 학습 성능과 새로운 데이터 성능의 차이를 제한하는 이론입니다.
> - **Non-vacuous:** 최악의 경우만 말하는 자명한 한계보다 엄격하여 실제 정보가 있는 보장이라는 뜻입니다.

**[분석자 해석]** LoGRA의 후속 연구가 일반화 이론으로 발전하려면, 단계별 스케치 크기뿐 아니라 **최종 가중치 변화의 복잡도와 독립적인 평가 분포**까지 다뤄야 합니다.

### 12.2. 일반화 질문에 답하기 위한 최소한의 실험 설계

**첫째, 압축과 제어의 효과를 분리해야 합니다.** 같은 모델·학습 가능 파라미터·최적화기를 사용하고, 전체 그래디언트/스케치와 KL 제어 없음/있음을 교차 비교하면 각각의 기여를 더 명확히 볼 수 있습니다.

**둘째, 최고 점수보다 사전에 정한 평가 시점을 중심으로 비교해야 합니다.** 동일한 실제 업데이트 수, 생성 토큰 수 또는 GPU 시간 중 하나를 기준으로 맞추고, 마지막 구간 평균과 고정 체크포인트 성능을 함께 보고하는 편이 좋습니다.

**셋째, 일반화 평가를 단계적으로 넓혀야 합니다.** 같은 과제의 새 문제에서 시작해 새로운 난이도, 학습하지 않은 과제 종류, 다른 도메인 순서로 확장하면 어디까지 효과가 유지되는지 구분할 수 있습니다.

**넷째, 추론 능력과 출력 예산 사용을 분리해야 합니다.** Figure 4처럼 응답 잘림이 크게 줄어드는 경우, 동일한 출력 예산과 잘리지 않은 응답의 성능도 함께 분석해야 점수 상승의 원인을 좁힐 수 있습니다.

**다섯째, 투영 갱신은 성능 향상을 전제하지 말고 검증해야 합니다.** Figure 5에서 일관된 우위가 없었으므로, 고정 투영과 갱신 투영을 더 긴 학습 구간과 새로운 평가 과제에서 비교하는 것이 타당합니다.

## 13. 결론 및 시사점

### 13.1. 저자가 제시한 시사점

**[저자 보고]** 그래디언트의 표현을 압축하는 것은 RL 후훈련의 하드웨어 장벽을 낮추는 실용적인 방법입니다.  
압축된 업데이트와 보수적인 정책 변화 제어를 결합하면, 평가한 추론 과제에서 성능을 유지하면서 메모리를 줄이고 27B 모델의 장기 학습을 실행할 수 있습니다. [p. 10, §5]

논문의 결론에는 **구체적인 후속 연구 로드맵이 제시되어 있지 않습니다.** 따라서 새로운 과제·적응형 랭크·일반화 이론 등의 방향은 저자의 계획으로 귀속하면 안 됩니다.

### 13.2. 학계와 실무에 대한 의미

**[분석자 해석]**

- **학술적으로**, 이 논문은 RL에서 반드시 전체 크기의 그래디언트 표현을 유지해야 하는지 실험적으로 묻고, 압축 표현과 정책 변화 제어를 함께 연구할 근거를 제공합니다.
- **실무적으로**, 가장 분명한 활용 조건은 학습 속도보다 GPU 메모리가 실행 여부를 결정하는 상황입니다.
- **방법 비교 측면에서는**, LoGRA를 하나의 완성된 학습 설정으로 평가한 결과와, 스케치·RowAdam·KL 제어 각각의 독립적 효과를 구분해야 합니다.
- **일반화 연구 측면에서는**, 보류 평가의 성능 유지·개선은 출발점이지만, 압축이 일반화 향상의 원인인지 확인하려면 통제 실험과 더 넓은 평가가 필요합니다.

**최종 평가:** LoGRA는 **메모리 효율적인 LLM 강화학습의 실행 가능성을 보여 준 연구**로 평가할 근거가 충분합니다.  
일반화 성능에 대한 가장 정확한 표현은 **“평가한 보류 문제에서 성능을 유지하거나 개선했다”**이며, 광범위한 일반화 향상이나 그 원인까지 증명했다고 확대해서는 안 됩니다.
