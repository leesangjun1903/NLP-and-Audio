## 1. Executive summary — 9문장

① 이 연구의 목적은 대형 토큰 언어모델의 지식을 작은 바이트 언어모델로 증류할 때, 토큰화 방식이 장기 학습의 성능·데이터 효율·저장 비용에 어떤 영향을 미치는지 밝히는 것입니다.  
② 이를 위해 저자는 토큰 예측분포를 바이트 예측분포로 변환하는 근사 방법 **Marginalize-It**과, 토큰 종료 기호 `<eot>`를 추가하여 확률을 보존하는 **End-Of-Token**을 제안합니다.  
③ 실험은 약 12.8억 개의 Transformer 내부 파라미터를 맞춘 모델에서 세 가지 입력 표현과 두 가지 학습 목적을 교차한 여섯 조건을 비교합니다. **[pp. 3–6, Table 1]** 2609.12303v1 2609.12303v1

> **용어:** 토큰은 모델이 처리하는 단어·단어 조각 등의 단위, 바이트는 256가지 값을 갖는 8비트 단위, 지식증류는 큰 모델의 예측분포를 작은 모델이 학습하는 방식

④ 실제 학습 구간에서는 토큰 모델이 적은 계산량에서 강하지만, 바이트 모델은 계산량이 증가하면서 성능 격차를 줄이는 경향을 보입니다.  
⑤ 그러나 최대 학습 지점의 여섯 평가 평균은 End-Of-Token 증류 모델 **44.6%**, 토큰 증류 모델 **44.4%**로, 표에 기재된 실측 평균 차이는 **0.2%포인트**입니다.

> **용어:** 외삽은 관측한 범위 밖으로 추세를 연장하는 예측, 점근치는 계산량 등이 한없이 증가한다고 가정했을 때 수식이 접근하는 값, %포인트는 두 백분율의 산술적 차이

⑦ 학습 데이터 약 **1/6**, 로짓 저장량 약 **1/5**이라는 효율 주장도 외삽한 성능 도달 지점과 계산량·데이터 단위 환산에 근거하므로, 동일 정확도를 실제 달성한 두 모델의 직접 비교로 읽어서는 안 됩니다.

## 2. 연구의 목적·필요성과 핵심 주장

### 2.1 무엇을 해결하려는가?

**[저자 설명] 첫 번째 문제는 교사와 학생의 출력 공간이 다르다는 것입니다.** 교사 모델은 하나의 BPE 토큰에 확률을 부여하지만, 학생 모델은 다음 바이트에 확률을 부여합니다. 하나의 토큰이 여러 바이트로 구성되므로, 교사의 토큰 확률을 바이트별 조건부확률로 옮기는 과정이 필요합니다. 특히 같은 바이트 접두사를 공유하면서 길이가 다른 토큰들이 존재하면, 단순한 변환은 일부 가능한 경로의 확률을 놓칩니다. **[p. 4, §2; p. 5, Figure 2]** 2609.12303v1

> **용어:** BPE는 자주 함께 등장하는 작은 문자열 단위를 합쳐 어휘를 만드는 토큰화 방식이며, 접두사는 문자열의 앞부분입니다. 예를 들어 `is`, `isu`, `isk`는 `is`라는 접두사를 공유합니다.

**[저자 설명] 두 번째 문제는 오프라인 증류의 저장 비용입니다.** Llama 3 계열 교사의 어휘는 128,256개여서 모든 위치의 전체 예측분포를 저장하기 어렵습니다. 이 논문은 토큰 증류에서는 상위 600개 로짓을 저장하고, 바이트 증류에서는 약 260개 출력값 전체를 저장하는 비교를 구성합니다. **[pp. 25–26, §A.6, Table 10]** 2609.12303v1

> **용어:** 로짓은 확률로 변환하기 전 모델의 출력 점수입니다. 오프라인 증류는 교사의 출력을 미리 저장한 뒤 학생을 학습하는 방식이며, top- $k$ 절단은 점수가 높은 $k$개 항목만 남기는 방법입니다.

**[저자 설명] 세 번째 문제는 무엇을 ‘더 좋은 작은 모델’이라고 판단할 것인가입니다.** 저자는 모델 크기를 거의 고정한 채 더 오래 학습하는 상황에서 토큰과 바이트의 성능 증가 양상이 달라지는지, 검증 손실의 개선이 실제 과제 성능으로 이어지는지를 조사합니다. **[pp. 1–3, Introduction, §1.1]** 2609.12303v1 2609.12303v1

> **용어:** 이 논문의 *overtraining*은 작은 모델을 계산 최적 학습점보다 더 오래 학습하는 전략을 뜻하며, 시험 성능이 악화되는 *과적합*과 동의어가 아닙니다.

### 3.2 Marginalize-It: 왜 근사인가?

아래 변환 수식은 **원문 §2와 Appendix F의 알고리즘을 설명하기 위해 제가 재표기한 것**입니다. 논문에 같은 형태의 번호 달린 수식으로 제시된 것은 아닙니다.

교사의 토큰 확률을 다음과 같이 둡니다.

```math
p_T(v\mid h)
=
\frac{\exp(\ell_v(h))}
{\sum_{v'\in V}\exp(\ell_{v'}(h))}
```

여기서 $V$는 교사의 토큰 어휘, $v$는 후보 토큰, $h$는 앞선 토큰 문맥, $\ell_v(h)$는 교사의 로짓, $p_T$는 확률입니다. 중요한 점은 **로짓 자체를 더하는 것이 아니라 확률로 변환한 뒤 합산한다**는 것입니다. 원문의 의사코드도 입력을 토큰 확률 `probs`로 정의합니다. **[p. 46, §F.1]** 2609.12303v1

토큰 $v$의 바이트열을 $s(v)$, 지금까지 확인된 해당 토큰 내부의 바이트 접두사를 $u$, 그 길이를 $j=|u|$라고 하겠습니다. 아직 바이트가 남아 있는 후보 집합은

```math
\mathcal V_u^{+}
=
\left\{
v\in V:
s(v)_{1:j}=u,\quad |s(v)|>j
\right\}
```

이고, Marginalize-It의 다음 바이트 분포는

```math
q_M(b\mid h,u)
=
\frac{
\sum_{v\in\mathcal V_u^{+}}
p_T(v\mid h)\,
\mathbf 1\!\left[s(v)_{j+1}=b\right]
}{
\sum_{v\in\mathcal V_u^{+}}p_T(v\mid h)
}
```

입니다.

여기서 $b$는 다음 바이트, $\mathbf 1[\cdot]$는 조건이 참이면 1인 지시함수입니다. 분자는 다음 바이트가 $b$인 후보들의 확률 합, 분모는 살아남은 후보들의 전체 확률입니다.

**근사의 원인:** $s(v)=u$인 짧은 토큰, 즉 이미 끝난 토큰은 $\mathcal V_u^{+}$에서 제외됩니다. 하지만 그 토큰 다음에 새 토큰이 이어지는 경로도 원래 언어모델에서는 가능합니다. Marginalize-It은 그 후속 분포를 추가로 계산하지 않고 남은 후보들에 확률을 재분배합니다. **[p. 4, §2.1; p. 48, Figure 29]** 2609.12303v1 2609.12303v1

> **용어:** 주변화는 여러 세부 경우의 확률을 더해 관심 있는 사건의 확률을 구하는 연산입니다. 재정규화는 남은 확률의 합이 다시 1이 되도록 나누는 연산입니다.

### 3.3 End-Of-Token: 무엇을 정확하게 보존하는가?

End-Of-Token은 각 교사 토큰의 끝에 별도 종료 기호를 붙입니다.

```math
\widetilde{s}(v)
=
s(v)\,\Vert\,\langle\text{eot}\rangle
```

여기서 $\Vert$는 이어 붙이기입니다. 확장된 문자열에서 접두사 $u$와 일치하며 다음 기호가 남아 있는 후보 집합을

```math
\widetilde{\mathcal V}_u^{+}
=
\left\{
v\in V:
\widetilde{s}(v)_{1:j}=u,\quad
|\widetilde{s}(v)|>j
\right\}
```

라고 하면, 같은 확률 합산 방식으로

```math
q_E(b\mid h,u)
=
\frac{
\sum_{v\in\widetilde{\mathcal V}_u^{+}}
p_T(v\mid h)\,
\mathbf 1\!\left[\widetilde{s}(v)_{j+1}=b\right]
}{
\sum_{v\in\widetilde{\mathcal V}_u^{+}}
p_T(v\mid h)
}
```

를 얻습니다.

여기서 $b$는 일반 바이트뿐 아니라 $\langle\text{eot}\rangle$도 될 수 있습니다. 나머지 기호는 앞 절과 같습니다. 짧은 토큰은 사라지는 대신 **다음 기호가 `<eot>`인 후보**로 남으므로 종료 확률이 보존됩니다. **[p. 4, §2.2; p. 5, Figure 2]** 2609.12303v1 2609.12303v1

Figure 2의 예에서는 `is`까지 관찰했을 때 관련 확률 질량이 `isu`에 0.5, `isk`에 0.125, `is`에 0.125 있습니다.

$$
q_M(u)=\frac{0.5}{0.625}=0.8,
\qquad
q_M(k)=\frac{0.125}{0.625}=0.2
$$

반면 End-Of-Token은

$$
q_E(u)=\frac{0.5}{0.75}=\frac23,
\qquad
q_E(k)=\frac{0.125}{0.75}=\frac16,
\qquad
q_E(\langle\text{eot}\rangle)=\frac{0.125}{0.75}=\frac16
$$

로 종료 경로를 남깁니다. 여기서 $u$와 $k$는 이 예의 문자에 해당하는 바이트값입니다. **[pp. 4–5, Figure 2]** 2609.12303v1

**[해석] ‘정확하다’의 범위는 제한해서 읽어야 합니다.**

- 정확한 것은 **교사 토큰 분포를 경계 기호를 포함한 바이트 표현으로 변환하는 과정**이지, 유한하게 학습한 학생이 교사를 완벽히 복제한다는 보장이 아닙니다.
- “한 번의 forward pass”는 주어진 학습 시퀀스에서 얻은 교사 출력으로 변환하고, 대체 토큰 경로마다 교사를 추가 실행하지 않는다는 뜻입니다.
- 학생의 어휘는 작아지지만, `<eot>` 위치에는 교사의 BPE 경계 정보가 남으므로 완전히 토큰화 편향에서 자유로운 설정은 아닙니다.

이 구분은 원문의 `<eot>` 삽입 절차와 분포 보존 설명에서 도출됩니다. **[pp. 3–4; pp. 48–49, Figures 29–30]** 2609.12303v1 2609.12303v1 2609.12303v1

### 3.4 학습 목적함수

저자는 다음 지식증류 목적함수를 제시합니다. 아래는 원문 Eqs. (3)–(5)를 기호 충돌 없이 재표기한 것입니다.

```math
\mathcal L_{\text{KD}}
=
\alpha\mathcal L_{\text{KL}}
+
(1-\alpha)\mathcal L_{\text{CE}}
```

```math
\mathcal L_{\text{KL}}
=
\frac1n
\sum_{t=1}^{n}
\sum_{a\in\mathcal A}
q_T(a\mid x_{ < t})
\log
\frac{q_T(a\mid x_{ < t})}
{p_S(a\mid x_{ < t})}
```

```math
\mathcal L_{\text{CE}}
=
-\frac1n
\sum_{t=1}^{n}
\sum_{a\in\mathcal A}
Y_{t,a}
\log p_S(a\mid x_{ < t})
```

$n$은 시퀀스 길이, $t$는 위치, $\mathcal A$는 학생의 출력 어휘, $a$는 출력 항목, $x_{<t}$는 이전 문맥입니다. $q_T$는 학생 출력 공간에 맞게 준비한 교사 분포, $p_S$는 학생 분포, $Y_{t,a}$는 정답 항목에만 1인 표시입니다. $\alpha$는 두 손실의 혼합 계수이며, 저자는 $\alpha=0$을 지도학습, $\alpha=1$을 순수 증류로 설명합니다. **[pp. 24–25, Eqs. (3)–(5)]** 2609.12303v1

> **용어:** 교차엔트로피는 정답에 높은 확률을 주도록 하는 손실입니다. KL 발산은 두 확률분포가 얼마나 다른지를 나타내며, 여기서는 학생의 예측분포를 교사에 가깝게 만드는 데 사용됩니다.

**[해석] 일반화 측면에서 중요한 차이는 정답만 배우느냐, 정답 외 대안들의 상대적 가능성도 배우느냐입니다.** 다만 교사의 전체 분포를 보존하는 것이 새로운 도메인에서의 정확성까지 보장하지는 않으며, 교사의 잘못된 예측도 함께 전달될 수 있습니다.

## 4. 스케일링 법칙과 실제 성능: 반드시 분리해서 읽어야 할 부분

### 4.1 BPB는 무엇을 측정하는가?

원문의 Eq. (6)을 합산 손실 기준으로 명확히 쓰면 다음과 같습니다.

```math
\text{BPB}
=
\frac{
-\sum_{t=1}^{n}
\ln p_S(x_t\mid x_{ < t})
}{
B_{\text{raw}}\ln 2
}
```

$B_{\text{raw}}$는 평가 텍스트의 바이트 수, $n$은 해당 모델 표현에서의 예측 위치 수입니다. 분자는 **평균이 아닌 합산 음의 로그확률**입니다. 원문 Eq. (5)의 평균 교차엔트로피를 사용한다면 합산값으로 환산해야 합니다. **[p. 25, §A.5, Eq. (6)]** 2609.12303v1

> **용어:** BPB, 즉 bits per byte는 원문 1바이트를 예측하는 데 필요한 평균 정보량으로, 낮을수록 평가 텍스트에 더 높은 확률을 부여한 것입니다.

**[저자 보고] 그러나 BPB가 낮다고 반드시 과제를 더 잘 푸는 것은 아닙니다.** 약 $1.8\times10^{21}$ FLOPs에서 바이트 모델들은 토큰 지도학습 모델보다 BPB가 낮아도 과제 성능은 더 낮습니다. **[p. 11, §5.4; p. 16, §6.6]** 2609.12303v1 2609.12303v1

Appendix G의 설명은 직관적입니다. 정답 확률이 두 모델 모두 0.4여도, 다른 후보 확률이 각각 $(0.35,0.25)$와 $(0.5,0.1)$이면 정답의 순위는 달라집니다. 정답 확률에 기반한 손실은 같지만 가장 높은 확률의 답을 고르는 결과는 다를 수 있습니다. 다만 이 예는 **손실과 순위가 다를 수 있다는 반례**이지, 논문의 모든 성능 차이에 대한 인과적 설명은 아닙니다. **[pp. 49–50, §G.1, Table 24]** 2609.12303v1

### 4.2 두 단계 예측식

먼저 계산량 $F$와 검증 BPB $y$의 관계를 적합합니다.

$$
y(F)=bF^a+c
\qquad(a<0,\ b>0)
$$

$F$는 학습 FLOPs, $a$는 감소 지수, $b$는 크기 계수, $c$는 계산량을 무한히 늘렸을 때 예측되는 BPB입니다. **[p. 7, Eq. (1); p. 8, Table 2]** 2609.12303v1 2609.12303v1

그다음 BPB와 평균 과제 오류율 $z$의 관계를 적합합니다.

$$
z(y)=\epsilon-ke^{-\gamma y}
$$

$\epsilon$, $k$, $\gamma$는 데이터로 추정하는 계수입니다. $z$는 객관식 네 과제와 생성 두 과제의 평균 오류율이며, 정확도를 0과 1 사이 값으로 나타내면

$$
z=1-\frac16\sum_{i=1}^{6}A_i
$$

입니다. 여기서 $A_i$는 $i$번째 과제의 성능입니다. **번역 BLEU 두 방향은 이 여섯 과제 평균과 점근 정확도 예측에 포함되지 않습니다.** **[p. 14, §6.4, Eq. (2)]** 2609.12303v1

> **용어:** BLEU는 생성한 번역과 참조 번역의 표현 중첩을 이용하는 평가 점수로, 정답률과 같은 단위가 아닙니다.

두 식을 결합하면 예측 점근 정확도는

```math
\widehat A_{\infty}(\%)
=
100\left[1-z(c)\right]
=
100\left[1-\epsilon+ke^{-\gamma c}\right]
```

입니다. $\widehat A_{\infty}$는 **예측치**이며, 실제 학습된 모델 점수가 아닙니다. **[pp. 15–16, §6.5, Table 5]** 2609.12303v1

**[해석] 제목의 ‘ceiling’은 보편적 한계로 증명된 것이 아닙니다.** 여기서는 특정 모델 크기·데이터·학습 설정에서 선택한 함수가 예측한 끝값입니다. 수식의 높은 적합도가 그 끝값의 실현 가능성까지 보장하지는 않습니다.

### 4.4 교차점과 ‘데이터 1/6’ 주장의 정확한 의미

Table 6의 질문은 “동일 계산량에서 두 성능 곡선이 처음 만나는가?”가 아니라, **“바이트 모델이 토큰 증류 모델의 예측 점근 성능 48.4%에 언제 도달하는가?”**입니다. 결과는 Marginalize-It $2.04\times10^{23}$ FLOPs, End-Of-Token $6.33\times10^{22}$ FLOPs입니다. **[p. 18, Table 6]** 2609.12303v1

이를 대수적으로 재표기하면, 토큰 모델의 점근 오류율을 $r_T^\star=z_T(c_T)$라 할 때 바이트 방법 $m$의 목표 BPB와 계산량은

```math
y_m^\star
=
-\frac1{\gamma_m}
\ln\left(
\frac{\epsilon_m-r_T^\star}{k_m}
\right)
```

```math
F_m^\star
=
\left(
\frac{y_m^\star-c_m}{b_m}
\right)^{1/a_m}
```

입니다. 아래첨자 $m$은 바이트 방법별 적합 계수이며, 유한한 도달점에는 로그의 정의역과 $y_m^\star>c_m$ 등의 조건이 필요합니다. 이는 저자의 역산 절차를 수식으로 정리한 것입니다. **[p. 18, Table 6 설명]** 2609.12303v1

데이터 절감 비율은 같은 계산량에서 처리하는 원문량을 비교하면 이해할 수 있습니다.

$$
D_T(F)=4.5\,\frac{F}{f_T},
\qquad
D_E(F)=\frac{4.5}{5.5}\,\frac{F}{f_E}
$$

```math
\frac{D_T(F)}{D_E(F)}
=
5.5\frac{f_E}{f_T}
\approx
5.5\frac{9.44}{8.18}
\approx 6.35
```

$D_T,D_E$는 처리한 원문 바이트량, $f_T,f_E$는 각각 토큰 한 개와 End-Of-Token 처리 단위 한 개의 학습 FLOPs입니다. 4.5는 평균 바이트/토큰, 5.5는 여기에 `<eot>` 한 개가 추가된 값입니다. **[p. 18, Table 7]** 2609.12303v1

**[해석] 이 비율에서 계산량 $F$가 소거된다는 점이 중요합니다.** 6.35배는 아키텍처별 처리 비용과 단위 정의에서 나오는 비율이고, 성능 동등성 주장은 별도의 외삽에 의존합니다. 마찬가지로 저장량 5.19배 절감은 데이터량·처리 단위 환산까지 결합한 결과입니다. 논문은 애초 동일 원문량에서 토큰 top- $k$와 바이트 전체 분포의 저장 비용을 비슷하게 맞춰 $k\approx600$을 선택했으므로, **작은 어휘 자체가 동일 원문 저장량을 곧바로 1/5로 만든다는 설명은 부정확합니다.** **[pp. 18, 25–26, Tables 7, 10]** 2609.12303v1 2609.12303v1

## 7. 일반화 성능 향상 가능성: 근거와 가설의 구분

### 7.1 논문이 실제로 보여준 일반화의 범위

**[실측]** 이 논문은 객관식 질문, 코드 생성, 사실 질문 응답, 영어↔독일어 번역을 평가합니다. 따라서 학습 손실만이 아니라 여러 종류의 과제 성능을 조사했다는 장점이 있습니다. 그러나 명시적인 미관측 언어 전이, 철자 교란, 새로운 전문 도메인, 장문 길이 외삽 실험은 제시하지 않습니다. **[p. 6, §3.3; p. 21, §10.1]** 2609.12303v1 2609.12303v1

> **용어:** 분포 밖 일반화는 학습 때와 다른 언어·도메인·입력 조건에서도 성능을 유지하는 능력입니다. 일반적인 벤치마크 점수가 높다는 사실만으로 모든 분포 밖 조건에 강하다고 결론 내릴 수는 없습니다.

### 7.2 향상을 기대할 수 있는 경로 — 모두 검증할 가설

**가설 A: 희귀 표현을 구성 요소 수준에서 공유할 수 있다.**  
작은 바이트 어휘를 반복적으로 학습하면 드문 문자열도 이미 학습한 작은 단위의 조합으로 처리할 수 있습니다. 이는 철자·형태 변화와 세밀한 문자열 조작에 유리할 가능성이 있습니다. 관련 연구인 ByT5와 BLT는 노이즈 및 문자 수준 처리의 이점을 직접 보고하지만, 그 결과를 이 논문의 End-Of-Token 모델이 자동으로 계승한다고 볼 수는 없습니다. [ACL Anthology](https://aclanthology.org/2022.tacl-1.17/)

> **용어:** 장꼬리 표현은 매우 드물게 등장하는 이름·단어·패턴 등입니다. 조합적 일반화는 학습한 구성 요소를 새로운 조합에서도 올바르게 사용하는 능력입니다.

**가설 B: 전체 교사 분포가 더 풍부한 학습 신호를 제공한다.**  
정답 외 후보들의 확률까지 학습하면 단일 정답만 사용하는 학습보다 덜 경직된 표현을 얻을 가능성이 있습니다. 그러나 본 논문에서는 이것이 실제로 확률 보정이나 분포 밖 일반화를 개선하는지 측정하지 않았습니다. 이는 목적함수와 전체 분포 저장 설계에서 제기되는 가설입니다. **[pp. 24–26, Eqs. (3)–(5), Table 10]** 2609.12303v1 2609.12303v1

> **용어:** 확률 보정은 모델이 “80% 확신한다”고 한 예측들이 실제로도 대략 80% 맞는지에 관한 성질입니다.

**가설 C: `<eot>`가 학습에 유용한 경계 신호를 제공한다.**  
지도학습만 사용하는 `<eot>` 모델도 주된 설정에서 더 나은 점근 성능을 예측한다는 사실은, 경계 기호가 단순히 증류 오류를 고치는 것 이상의 영향을 줄 가능성을 시사합니다. 그러나 같은 길이의 무의미한 기호나 임의 경계와 비교하지 않았으므로, 언어적으로 유용한 경계 신호의 효과인지 추가 계산의 효과인지 아직 알 수 없습니다. **[p. 16, Table 5; p. 21, Discussion]** 2609.12303v1 2609.12303v1

> **용어:** 귀납 편향은 모델이 어떤 패턴을 더 쉽게 학습하도록 만드는 구조적 경향입니다. 토큰 경계 역시 하나의 귀납 편향이 될 수 있습니다.

### 7.3 일반화를 제한할 수 있는 경로

**[해석]** 확률 변환이 정확하다는 사실은 교사의 지식이 정확하다는 사실과 다릅니다. 교사의 편향·지식 부족·오류가 남을 수 있고, `<eot>`가 교사의 토큰 경계를 유지하기 때문에 특정 언어나 데이터에 맞춰진 경계 선택도 전달될 수 있습니다.

또한 바이트 시퀀스가 길어지므로, 같은 위치 수만 허용하는 환경에서는 실제로 볼 수 있는 원문 길이가 짧아질 수 있습니다. 본 논문은 학습 시퀀스 길이를 늘려 이를 조정하지만, 배포 시 메모리·지연 제약에서도 같은 보상이 가능한지는 별도 검증이 필요합니다. **[p. 25, §A.4; p. 21, Inference Costs]** 2609.12303v1 2609.12303v1

BLT와의 결합 가능성을 보여주는 핵심 수식은 다음과 같습니다.

```math
H_i
=
-\sum_{b\in\mathcal B}
p_e(b\mid x_{ < i})
\log p_e(b\mid x_{ < i})
```

$$
H_i > \theta_g
\quad\text{또는}\quad
H_i-H_{i-1}>\theta_r
$$

$\mathcal B$는 바이트 어휘, $p_e$는 작은 엔트로피 추정 모델의 다음 바이트 분포, $H_i$는 위치 $i$의 불확실성, $\theta_g,\theta_r$는 경계 선택 임계값입니다. BLT는 이러한 조건을 이용해 패치 경계를 결정합니다. **[BLT PDF p. 3, §2.3]** [ACL Anthology](https://aclanthology.org/2025.acl-long.453.pdf)

> **용어:** 엔트로피는 예측분포가 얼마나 불확실한지를 나타냅니다. 여러 후보가 비슷한 확률이면 높고, 한 후보가 거의 확실하면 낮습니다.

**[해석] 두 연구는 해결하는 층위가 다릅니다.** End-Of-Token은 “학생에게 어떤 확률분포를 가르칠 것인가”를, BLT·H-Net은 “어느 위치에 얼마나 계산을 쓸 것인가”를 다룹니다. 따라서 장기적으로 유망한 방향은 바이트를 무조건 많이 계산하는 것이 아니라, **정보를 보존하는 증류와 적응적 계산 배분을 결합하는 것**입니다.

## 10. 결론과 후속 연구 방향

### 10.1 저자가 제시한 시사점과 후속 연구

**[저자 시사점]** 입력 표현과 학습 목적은 검증 BPB의 스케일링뿐 아니라 BPB와 과제 성능 사이의 관계도 바꿉니다. End-Of-Token은 교사 분포를 보존하면서 작은 어휘의 학생을 학습할 수 있게 하고, 특정 설정의 외삽에서는 토큰 증류보다 높은 평균 성능을 예측합니다. 동시에 저자는 바이트 모델의 높은 추론 비용을 인정하며, BPB만으로 모델 품질을 판단하지 말아야 한다고 강조합니다. **[pp. 20–21, Discussion]** 2609.12303v1

**[저자 후속 계획]** 명시된 방향은 Mixture-of-Experts를 통한 희소성 축 추가, 더 큰 모델과 더 많은 데이터, 더 다양한 벤치마크, 큰 바이트 교사에서 작은 바이트 학생으로의 증류입니다. 추론 비용을 맞춘 토큰·바이트 비교도 중요한 미해결 과제로 제시합니다. **[p. 21, §10.1 및 Inference Costs]** 2609.12303v1

> **용어:** Mixture-of-Experts는 여러 전문가 신경망 중 일부를 입력에 따라 선택하는 구조입니다. 희소성은 전체 계산 요소 중 일부만 활성화하는 성질입니다.

### 10.2 추가로 우선할 연구 — 제안

**첫째, 외삽을 검증 가능한 예측 문제로 바꾸어야 합니다.**  
낮은 계산량 결과만으로 미리 곡선과 예측구간을 확정한 뒤, 더 큰 학습 실행을 새로운 시험 데이터처럼 사용해야 합니다. 여러 seed와 데이터셋을 포함하고, BPB→과제 성능의 두 단계 불확실성을 함께 전달하면 “52.4%라는 점 예측”보다 연구·투자 판단에 유용한 결과를 얻을 수 있습니다.

**둘째, 일반화 이득의 원인을 분리해야 합니다.**  
동일 원문량·총 FLOPs·총 파라미터 조건을 각각 따로 맞추고, 전체 토큰 분포 증류, 실제 BPE 경계, 임의 경계, 길이만 늘린 보조 기호를 비교하는 대조 실험이 필요합니다. 이를 통해 바이트 표현, 정확한 확률 보존, 경계 신호, 추가 계산의 기여를 구분할 수 있습니다.

**셋째, ‘평균 벤치마크 향상’ 대신 일반화의 여러 측면을 따로 평가해야 합니다.**  
한국어를 포함한 다언어, 희귀 이름·새 단어, 오탈자·유니코드 변형, 코드 식별자 조작, 새로운 도메인, 긴 문맥을 별도 축으로 평가하는 설계를 제안합니다. 깨끗한 입력의 정확도뿐 아니라 교란 후 성능 하락, 최악 조건 성능, 확률 보정, 학습 데이터 중복을 함께 보고해야 합니다.

**넷째, 추론 효율을 갖춘 구조와 증류를 결합해야 합니다.**  
BLT·H-Net 같은 적응적 묶음 처리와 Fast BLT 계열 생성 기법은 본 논문의 높은 바이트 처리 비용을 줄일 후보입니다. 다만 `<eot>`를 없애거나 경계를 새로 학습하도록 바꾸면 원래의 확률 보존 논거가 그대로 유지되는지 다시 확인해야 합니다. 관련 연구는 결합 가능성의 근거이지, 해당 조합의 성공을 입증한 결과는 아닙니다. [ACL Anthology](https://aclanthology.org/2025.acl-long.453.pdf)

### 최종 판단

**이 논문의 가장 확실한 기여는 작은 바이트 모델의 보편적 우월성을 증명한 것이 아니라, 토큰→바이트 증류에서 확률을 보존하는 실용적 변환을 제안하고, 토큰화·학습 목적에 따라 손실과 과제 성능의 관계가 달라짐을 보여준 데 있습니다.**

**일반화 성능 향상의 가능성은 충분히 연구할 가치가 있지만, 대표 수치인 4.0%포인트 우위와 데이터·저장 절감은 외삽 및 비용 환산에 의존합니다. 따라서 다음 단계의 핵심은 더 큰 예측값을 제시하는 것보다, 외삽의 실측 검증·원인 분리·분포 밖 평가·동일 추론 비용 비교를 통해 그 가능성이 실제 능력으로 이어지는지 확인하는 것입니다.**
