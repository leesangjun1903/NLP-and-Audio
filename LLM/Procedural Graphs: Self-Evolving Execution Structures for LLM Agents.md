# Procedural Graphs: Self-Evolving Execution Structures for LLM Agents

**기준 문서:** Yuxing Lu, Yicheng Chen, Shanchan Wu, Sercan Ö. Arık의 arXiv v1, 2026년 9월 8일 공개본이며, 아래 페이지 번호는 첨부된 36쪽 PDF를 기준으로 합니다. 외부 연구 비교에는 2026년 10월 6일 확인한 논문 원문을 사용했습니다. [arXiv](https://arxiv.org/abs/2609.09153)

## 1. Executive summary — 9문장

이 연구의 목적은 장기 과제를 수행하는 LLM 에이전트가 목표를 잊거나, 도구 호출 순서를 어기거나, 실패 행동을 반복하는 문제를 줄이는 것이다[pp.1–2].  
저자들은 이를 위해 “무엇을 아는가”가 아니라 “어떤 조건에서 무엇을 다음에 해야 하는가”를 모델 가중치 외부의 **Procedural Graph, 이하 PG**로 표현한다[Figure 1, p.2].  
실행 중에는 현재 절차에 연결된 **2-hop 부분그래프**를 읽어 상황별 지침을 생성하되, 다음 행동을 강제하지 않고 해결 모델의 판단을 유도한다[Figure 2, p.4]. 2609.09153v1 2609.09153v1

> **용어:** *LLM 에이전트*는 언어모델이 도구를 사용하며 여러 단계의 과제를 수행하는 시스템이며, *2-hop*은 그래프의 화살표를 최대 두 번 따라가 도달하는 범위입니다.

학습 배치 사이에는 성공·실패 실행 기록을 바탕으로 그래프를 수정하고, 별도 검증 집합의 점수가 유지되거나 개선되는 후보만 채택하면서 거절된 수정 이력도 보관한다[pp.5–6, Algorithm 1].  
주요 비교에서 PG는 6개 벤치마크와 4개 모델의 24개 조합 중 21개에서 단독 또는 공동 1위를 기록했으며, 각 조합의 최강 기준선에 대해 19승·2무·3패를 보였다[Table 1, p.7].  
별도 구성 실험에서는 최소 그래프에서 시작한 자기진화가 HotpotQA의 F1을 71.21에서 78.79로 높였고, 잘못된 전문가 그래프에서 출발한 반복 수정은 MultiChallenge 성공률을 58.93%에서 92.86%로 회복시켰다[Table 2, p.9]. 2609.09153v1 2609.09153v1 2609.09153v1

> **용어:** *검증 집합*은 수정안을 선택하는 데 쓰는 별도 문제 집합이고, *테스트 집합*은 선택이 끝난 방법의 성능을 평가하는 집합이며, *F1*은 여기서 예측 답변과 정답의 단어 중첩을 평가하는 지표입니다.

EnterpriseArena의 별도 자기진화 실험에서 최종 반환 그래프의 테스트 생존율은 0%에서 85%로 상승했지만, 이는 테스트 에피소드 20개에 대한 결과이며 탐색 중 관찰된 최고값 95%와 구분해야 한다[p.10, Table 11].  
또한 부분그래프 사용은 전체 그래프 기반 지침 생성보다 토큰을 절약하지만, 그래프가 없는 기준선보다 총 토큰 사용량이 늘어나는 경우가 있어 “더 적은 단계”를 곧바로 “더 저렴한 실행”으로 해석할 수 없다[Table 3, p.10].  
**제 판단으로 이 논문은 외부 절차 지식의 학습 가능성을 설득력 있게 보여주지만, 동일한 그래프가 새로운 모델·도구·도메인으로 이전되는 일반화까지 입증한 연구는 아니다**[p.11]. 2609.09153v1 2609.09153v1

## 3. 연구의 목적·필요성과 해결하려는 문제

### 3.1 저자의 문제 설정

저자가 지적하는 문제는 단순한 사실 지식 부족이 아닙니다. 에이전트가 필요한 도구를 알고 있어도, 긴 실행 이력에서 **지금 무엇이 완료되었고, 어떤 조건이 충족되었으며, 무엇을 먼저 해야 하는지**를 매번 복원해야 한다는 점입니다. 그 결과 목표 이탈, 부적절한 순서, 불필요한 재시도가 발생할 수 있다는 것이 출발점입니다[pp.1–2]. 2609.09153v1

기존 접근에 대한 저자의 구분은 다음과 같습니다.

| 기존 접근 | 보존하는 것 | 저자가 지적한 부족한 점 |
|---|---|---|
| 텍스트 메모리·자기반성 | 과거 경험과 교훈 | 현재 단계에서 어떤 순서로 적용할지 다시 추론해야 함 |
| 상태별 조건부 지침 | “이 상황이면 이 행동”이라는 조언 | 여러 절차 사이의 연결과 의존관계가 명시적이지 않을 수 있음 |
| 워크플로·상태기계 | 실행 단계와 전이 순서 | 수작업 설계 부담 또는 실행 유연성의 제약 |
| PG | 연결된 절차, 적용 조건, 수행 지침, 실패 방지 조언 | 구조와 유연성을 결합하고 실행 피드백으로 수정하려는 접근 |

이 구분과 PG의 위치는 본문 및 확장 관련 연구에서 설명됩니다[pp.1–3, pp.17–19, Table 4]. 2609.09153v1 2609.09153v1

> **용어:** *워크플로*는 작업 단계들의 실행 흐름이고, *상태기계*는 현재 상태와 정해진 전이 규칙에 따라 다음 행동을 결정하는 구조입니다.

### 3.2 제 해석: “더 많이 기억하기”보다 “기억을 실행에 연결하기”

PG의 연구 질문은 다음처럼 정리하는 것이 적절합니다.

> **과거 실행에서 얻은 교훈을, 현재 상태에 맞는 다음 행동과 그 이후의 절차까지 연결하는 외부 구조로 바꾸면 성능이 개선되는가?**

예컨대 “자금 조달은 일찍 요청해야 한다”는 문장만 저장하는 것과, **현금 확인 → 현금흐름 예측 → 시장 확인 → 자금 조달 판단 → 대기·다음 달 재평가**를 연결하는 것은 다릅니다. 후자는 조언이 필요한 시점과 선행 절차를 함께 드러냅니다. 다만 이러한 연결이 항상 정확한 인과관계를 학습했다는 뜻은 아닙니다[Figure 5, p.34]. 2609.09153v1

## 4. 제안 방법과 모델 구조: 수식 중심 설명

### 4.1 PG는 새로운 신경망 구조가 아니라 외부 실행 지식 계층이다

**저자 보고.** 시스템에는 세 가지 LLM 역할이 있습니다.

| 구성 요소 | 입력과 역할 | 작동 시점 |
|---|---|---|
| **Solver** | 질문·전체 실행 이력·생성된 지침으로 다음 행동 선택 | 과제 실행 중 |
| **Guidance model** | 현재 부분그래프·질문·최근 실행 이력으로 상황별 지침 생성 | 각 의사결정 단계 |
| **Refiner** | 실행 기록·현재 그래프·거절 이력을 보고 그래프 수정 제안 | 학습 배치 사이 |

각 실험에서 세 역할은 **같은 기반 LLM**을 사용합니다. 서로 다른 역할을 위한 호출과 프롬프트를 분리한 것이며, 별도의 그래프 신경망을 학습하는 구조는 제시되지 않습니다. 기본 설정은 검색 깊이 $h=2$, 최근 이력 길이 $w=3$, temperature 0입니다[p.6; Figure 2]. 2609.09153v1 2609.09153v1

> **용어:** *기반 LLM*은 각 역할의 바탕이 되는 언어모델입니다. *Temperature 0*은 출력 선택의 무작위성을 줄이는 설정이지만, 외부 환경까지 완전히 결정적으로 만드는 조건은 아닙니다.

**중요한 구분.** 논문 일부의 “Online Evolution”은 **학습 배치 사이의 점진적 갱신**을 뜻합니다. 개별 에피소드 내부와 테스트 평가 중에는 그래프를 고정합니다[p.30, Appendix D.2]. 2609.09153v1

### 4.2 절차 그래프의 정의 — 원문 식 (1)

```math
\mathcal G
=
(\mathcal V,\mathcal R,\mathcal E,\Phi),
\qquad
\mathcal E
\subseteq
\mathcal V\times\mathcal R\times\mathcal V.
```

기호의 의미는 다음과 같습니다.

| 기호 | 의미 |
|---|---|
| $\mathcal G$ | 전체 절차 그래프 |
| $\mathcal V$ | 도구 호출, 기술, 내부 추론 단계, 작업 상태 등을 나타내는 노드 집합 |
| $\mathcal R$ | 절차 사이 관계 유형의 집합 |
| $\mathcal E$ | 방향성 간선 집합 |
| $e=(u,r,v)$ | 노드 $u$ 이후 관계 $r$에 따라 노드 $v$로 진행할 수 있다는 전이 |
| $\Phi(e)$ | 간선 $e$에 부착된 속성 |

구현에서 $\Phi(e)$는 세 가지 텍스트 필드를 사용합니다. `condition`은 적용 조건, `guidance`는 수행 방법, `pitfalls`는 피해야 할 오류입니다[pp.3–4, 식 (1)]. 2609.09153v1 2609.09153v1

> **용어:** *방향성 그래프*는 연결에 방향이 있는 그래프이고, *토폴로지*는 어떤 노드가 어떤 노드와 연결되어 있는지를 뜻합니다. *속성*은 연결에 붙인 부가 정보입니다.

**제 해석.** PG의 차별점은 행동 목록이 아니라 **조건이 붙은 행동 간 연결**입니다. 그러나 조건은 자연어이므로, 이를 프로그램의 엄격한 실행 전제조건과 동일하게 보아서는 안 됩니다.

### 4.3 현재 위치 파악 → 부분그래프 추출 → 지침 생성 — 원문 식 (2)

실행 이력을 다음과 같이 둡니다.

```math
\mathcal T_t
=
(a_1,o_1,\ldots,a_{t-1},o_{t-1}).
```

각 단계의 지침 생성은 다음과 같습니다.

```math
u_t
=
\text{Match}(a_{t-1},\mathcal V),
```

```math
\mathcal G_t
=
\begin{cases}
\mathcal N_h(u_t), & u_t\neq\varnothing,\\
\mathcal G, & \text{그 외}.
\end{cases}
```

```math
g_t
=
\Psi\!\left(
\mathcal G_t,q,\mathcal T_{t-w:t}
\right).
```

| 기호 | 의미 |
|---|---|
| $t$ | 현재 의사결정 단계 |
| $a_{t-1}$ | 직전 행동 또는 절차 |
| $o_i$ | 행동 후 얻은 관찰 |
| $u_t$ | 현재 활성 노드 |
| $\text{Match}$ | 직전 절차와 노드를 정확히 일치시키는 함수 |
| $\mathcal N_h(u_t)$ | $u_t$에서 나가는 간선을 최대 $h$단계 확장한 부분그래프 |
| $q$ | 사용자 질문 |
| $\mathcal T_{t-w:t}$ | 최근 $w$단계의 실행 이력 |
| $\Psi$ | 지침 생성 LLM |
| $g_t$ | 생성된 상황별 지침 |

첫 단계는 $a_0=\text{Start}$, $u_1=\text{Start}$로 초기화합니다. 노드 매칭에 실패하면 전체 그래프를 사용합니다[p.4, 식 (2)]. 2609.09153v1

**제 해석과 한계.** 이 방식은 현재 위치 주변의 정보를 선택한다는 장점이 있지만, 직전 행동이 현재 상태 전체를 완전히 표현하지는 않습니다. 같은 도구를 다른 목적으로 호출한 경우, 오래전의 제약이 중요한 경우, 필요한 연결이 2-hop 밖에 있는 경우에는 추가 판단이 필요합니다. 따라서 **지역 검색이 모든 선행 조건의 확보를 보장하는 것은 아닙니다.**

### 4.4 Solver는 지침을 참고하지만 강제받지 않는다 — 원문 식 (3)

$$
a_t
\sim
P_{\text{solver}}
\!\left(
\cdot\mid q,\mathcal T_t,g_t
\right).
$$

여기서 $P_{\text{solver}}$는 해결 모델의 다음 행동 분포이고, $a_t$는 선택된 행동입니다. 지침 생성에는 최근 이력 창을 사용하지만, 이 식에서 Solver는 전체 실행 이력 $\mathcal T_t$를 받습니다[p.5]. 2609.09153v1

> **용어:** *연성 유도, soft guidance*는 조언으로 행동 선택을 유도하는 방식입니다. 반대로 *강제 제약, hard constraint*은 허용하지 않은 행동을 시스템 수준에서 차단합니다.

**제 해석.** 이것은 유연성과 안전성 사이의 교환관계입니다. 그래프에 없는 대응도 가능하지만, 그래프에 적힌 주의사항을 무시하는 행동이 원천적으로 차단되지는 않습니다.

### 4.5 실행 피드백으로 그래프 수정

**저자 보고.** 현재 보존 그래프 $\mathcal G_{k-1}$로 학습 배치 $\mathcal B_k$를 실행한 뒤, 고득점·저득점 기록을 비교해 수정안 $\Delta\mathcal G_k$를 생성합니다.

```math
\mathcal G_k^{\text{cand}}
=
\mathcal G_{k-1}\oplus\Delta\mathcal G_k.
```

$k$는 진화 라운드, $\mathcal G_k^{\text{cand}}$는 후보 그래프, $\oplus$는 그래프 사본에 수정안을 적용하는 연산입니다. 노드·간선을 추가하거나 삭제할 수 있으며, 간선 속성 변경은 기존 간선을 삭제한 뒤 수정된 속성으로 다시 추가하는 방식입니다[p.5]. 2609.09153v1

> **용어:** *롤아웃, rollout*은 에이전트를 환경에서 실제로 실행해 행동·관찰·결과를 모으는 과정입니다. 여기서 “진화”는 생물학적 진화나 모델 가중치 학습이 아니라 그래프 수정안의 반복 생성·선택을 뜻합니다.

구조 검사는 잘못된 간선 끝점, 허용되지 않는 유형, 종료 노드까지의 경로 등을 확인합니다. 그러나 **종료 노드에 도달할 경로가 존재한다는 것과 실제 실행이 반드시 종료된다는 것은 다릅니다.** 또한 행동 노드가 실제 도구 목록에 속하는지는 Refiner 프롬프트의 요구사항일 뿐, 일반 구조 검사기가 독립적으로 강제하지는 않습니다[p.24, Algorithm 1 설명]. 2609.09153v1

### 4.6 검증 점수와 후보 채택 — 원문 식 (4), (5)

```math
S_{\text{val}}(\mathcal G)
=
\frac{1}{|\mathcal D_{\text{val}}|}
\sum_{(q,y)\in\mathcal D_{\text{val}}}
S\!\left(
f_{\text{solver}}(q\mid\mathcal G),y
\right).
```

| 기호 | 의미 |
|---|---|
| $\mathcal D_{\text{val}}$ | 별도 검증 집합 |
| $y$ | 정답 또는 평가 기준 |
| $f_{\text{solver}}(q\mid\mathcal G)$ | 그래프 $\mathcal G$를 사용한 전체 과제 해결 결과 |
| $S(\cdot,y)$ | 과제별 평가 함수 |
| $S_{\text{val}}(\mathcal G)$ | 검증 집합의 평균 점수 |

구조 검사를 통과한 후보에 대해 다음 규칙을 적용합니다.

```math
\mathcal G_k
=
\begin{cases}
\mathcal G_k^{\text{cand}},
&
S_{\text{val}}(\mathcal G_k^{\text{cand}})
\ge
S_{\text{val}}(\mathcal G_{k-1}),\\
\mathcal G_{k-1},
&
\text{그 외}.
\end{cases}
```

초기 그래프를 한 번 평가하고, 보존 그래프의 검증 점수는 캐시해 비교합니다. **동점도 채택**합니다[p.5, 식 (4)–(5)]. 2609.09153v1

**제 해석.** 이 규칙이 보장하는 것은 **기록된 검증 점수의 비감소**입니다. 새로운 문제에서의 기대 성능이 단조롭게 좋아진다는 이론적 보장은 아닙니다. 동일한 검증 집합을 반복 사용하면 그 집합에 유리한 수정이 선택될 가능성도 있습니다.

### 4.7 거절 이력의 활용 — 원문 식 (6)

$$
\Delta\mathcal G_{k+1}
\sim
P_{\text{refiner}}
\!\left(
\cdot\mid
\mathcal G_k,
\mathcal C_{k+1},
\mathcal H_{\text{rejected}}
\right).
$$

$\mathcal H_{\text{rejected}}$는 거절된 후보와 수정안·평가 결과 등의 기록이고, $\mathcal C_{k+1}$는 다음 수정에 제공되는 실행 문맥입니다. 실행 기록이 길이 제한 $L_{\max}$를 넘으면 앞부분을 버리고 마지막 토큰들을 보존합니다[p.6]. 2609.09153v1

**제 해석.** 거절 이력은 같은 실수를 반복하지 않도록 돕는 장치이지만, 독립적인 제거 실험이 없으므로 성능 향상 중 얼마가 이 장치 덕분인지는 분리되어 있지 않습니다. 또한 과거에 실패한 수정이 환경 변화 후에는 유효해질 수 있다는 문제도 남습니다.

### 8.2 일반화가 좋아질 수 있는 이유 — 제 해석

**첫째, 사례의 표면적 세부사항보다 재사용 가능한 절차를 저장할 수 있습니다.** Refiner 프롬프트도 특정 실행의 세부사항에 과적합하지 말고 고수준 개념을 사용하도록 요구합니다. 이것은 개별 답을 외우는 대신 “검증 후 제출”, “대기 요청 확인 후 추가 요청” 같은 규칙을 재사용하게 할 가능성이 있습니다. 다만 프롬프트 요구사항 자체가 일반화의 보장은 아닙니다[p.23]. 2609.09153v1

> **용어:** *과적합*은 학습·검증에서 본 사례에는 잘 맞지만 새 사례에는 잘 맞지 않는 상태입니다.

**둘째, 공통 하위 절차를 새로운 순서로 결합할 가능성이 있습니다.** 다만 이 논문은 알려진 하위 절차를 처음 보는 조합으로 연결해야 하는 별도의 **조합적 일반화** 실험을 제시하지 않습니다. 현재 결과는 그 가능성에 부합할 뿐, 직접 검증은 아닙니다[그래프 정의: pp.3–4; 평가 구성: pp.19–20]. 2609.09153v1 2609.09153v1

> **용어:** *조합적 일반화*는 이미 배운 구성 요소를 처음 보는 조합으로 결합해 문제를 해결하는 능력입니다.

**셋째, 모델을 재학습하지 않고도 외부 절차를 수정할 수 있습니다.** 이는 모델 교체 시 절차 지식을 재사용할 가능성을 열어주지만, 실제 재사용성은 모델별 지침 해석 능력과 도구 인터페이스의 차이에 달려 있습니다[p.11]. 2609.09153v1

### 8.3 일반화를 방해할 수 있는 요인 — 제 해석

가장 큰 위험은 **추상적 절차와 환경 특화 요령이 같은 그래프 안에 섞이는 것**입니다. “현금 상태를 확인하고 예측하라”는 넓게 재사용할 수 있지만, “자금 요청 뒤에는 월 마감을 하지 말라”는 특정 환경의 자동 월 진행 기능에 의존합니다[Figure 5]. 2609.09153v1

또한 EnterpriseArena의 위기는 32·59·112개월에 배치되어 있습니다. 에이전트에게 미리 알려주지 않았다는 것과, 학습 중 반복 경험한 위기 구조와 다른 상황에서도 견딘다는 것은 다릅니다. 위기 시점·강도·자금 유입 지연을 바꾼 실험이 필요합니다[p.25]. 2609.09153v1

> **용어:** *분포 변화*는 새 문제의 조건이 학습 때와 달라지는 현상이고, *부정적 전이*는 이전 환경에서 유익한 지식이 새 환경에서는 오히려 성능을 떨어뜨리는 현상입니다.

### 9.2 일반화 관점에서 특히 중요한 비교 세 가지

**① AutoGuide는 이미 도메인 전이를 시험했다.**  
원 논문은 WebShop에서 추출한 지침을 WebArena-Shopping에 적용하는 실험을 포함합니다. 다만 관찰 공간의 차이를 맞추는 별도 grounding 모듈을 사용하므로, 이를 “아무 조정 없는 전이”로 해석하면 안 됩니다[AutoGuide §4.3, Table 5]. [arXiv](https://arxiv.org/html/2403.08978v2)

> **용어:** 여기서 *grounding*은 추상적인 지침을 현재 환경의 실제 화면·도구·상태와 대응시키는 과정입니다.

**② AWM과 MemP는 PG가 추가해야 할 평가 축을 보여준다.**  
AWM은 교차 웹사이트·도메인을 나누어 평가하고, MemP는 한 모델이 만든 절차 메모리를 다른 모델에 제공하는 실험을 포함합니다. 따라서 PG의 “4개 모델에서 개선”을 이러한 전이 실험보다 더 강한 일반화 증거라고 주장할 수는 없습니다[AWM p.8, Table 4; MemP p.8, Figure 5(a)]. [arXiv](https://arxiv.org/pdf/2409.07429)

**③ 2026년 연구들은 기억의 표현뿐 아니라 유효성 유지에 초점을 넓힌다.**  
Live-Evo는 연속 피드백과 오래된 경험의 활용도 조정을, Grounding Agent Memory는 기록된 실행 밖의 환경을 확인하는 과정을 다룹니다. 제 해석으로는 PG의 다음 과제 역시 “더 좋은 그래프 만들기”에 그치지 않고 **언제 기존 그래프를 의심하고 수정해야 하는가**로 확장되어야 합니다. [arXiv](https://arxiv.org/abs/2602.02369)

**비교상의 결론:** 이들 논문의 점수는 모델·도구·적응 허용 범위·평가 단위가 다르므로 직접 순위를 매길 수 없습니다. PG의 기여는 저자 스스로 설명하듯 **속성 있는 전이, 지역적 지침 생성, 구조 수정의 결합**이지, 그래프나 조건부 지식 또는 자기개선 개념의 최초 제안은 아닙니다[p.18]. 2609.09153v1

## 11. 결론과 후속 연구 방향

### 11.1 저자들이 직접 제시한 시사점과 향후 방향

저자의 핵심 시사점은 **모델 가중치를 갱신하지 않고도 실행 피드백으로 절차 지식을 학습·수정할 수 있다**는 것입니다. 최소 초기화에서 유용한 그래프를 만들 수 있고, 성능을 해치는 전문가 사전 지식도 복구할 수 있다는 결과를 제시합니다[p.11]. 2609.09153v1

저자가 직접 언급한 후속 방향은 **단계 간 지침 재사용 또는 선택적 생성으로 토큰 비용을 줄이는 것**, 그리고 **Solver와 도구 인터페이스를 바꾸어 학습된 절차의 재사용 범위를 평가하는 것**입니다. 이는 확정된 구현 계획이라기보다 결론에서 제안한 연구 방향입니다[p.11]. 2609.09153v1

### 11.2 추가 제안 1: “여러 모델에서 효과”가 아니라 “같은 그래프의 이전”을 측정해야 한다

다음은 **논문에 없는, 제가 제안하는 전이 평가식**입니다.

```math
\Delta_{\text{transfer}}(A\rightarrow B)
=
\mathbb E_{(q,y)\sim\mathcal D_B}
\left[
S\!\left(f_B(q\mid\mathcal G_A),y\right)
-
S\!\left(f_B(q\mid\varnothing),y\right)
\right].
```

$A$는 그래프를 학습한 원래 설정, $B$는 새로운 모델 또는 환경 설정, $\mathcal G_A$는 $A$에서 학습한 뒤 고정한 그래프, $\mathcal D_B$는 목표 문제 분포, $f_B$는 목표 Solver, $\varnothing$는 그래프 미사용을 뜻합니다.

이 평가에서는 **그래프 완전 고정**, **도구 이름만 대응**, **소량의 목표 환경 데이터로 수정**을 별도 조건으로 두어야 합니다. 그래야 절차 자체가 일반적인지, 도구 대응만 필요한지, 사실상 다시 학습해야 하는지를 구분할 수 있습니다.

### 11.3 추가 제안 2: 구조적 일반화와 환경 변화에 대한 강건성을 분리해야 한다

알려진 하위 절차를 처음 보는 순서로 결합하는 문제와, 기존 행동의 효과 자체가 바뀌는 문제는 다릅니다. 전자에는 절차 조합 평가가, 후자에는 도구 규약·위기 시점·지연 분포를 바꾸는 평가가 필요합니다.

특히 Figure 5의 어댑터 특화 수정은 좋은 시험 대상입니다. 동일 그래프를 **자금 요청이 월을 진행시키는 환경과 진행시키지 않는 환경**에 적용하면, PG가 추상적 원리와 환경 특화 규칙을 구분하는지 확인할 수 있습니다[Figure 5의 관찰에서 도출한 제안]. 2609.09153v1

### 11.4 추가 제안 3: 채택 기준을 불확실성과 비용까지 고려하도록 확장해야 한다

다음 역시 **제가 제안하는 기준**입니다.

$$
\text{LCB}_{1-\alpha}
\!\left(\Delta S_k\right) > \epsilon.
$$

$\Delta S_k$는 같은 평가 조건에서 후보 그래프와 현재 그래프의 성능 차이, $\text{LCB}_{1-\alpha}$는 그 차이의 신뢰 하한, $\alpha$는 허용하는 오류 수준, $\epsilon$은 최소한의 실질적 개선폭입니다.

> **용어:** *신뢰 하한*은 불확실성을 고려했을 때 개선폭이 적어도 어느 정도라고 볼 수 있는지를 나타내는 값입니다.

단순히 관측 점수가 같거나 높으면 채택하는 대신, 반복 실행·대응 평가·새 검증 표본을 활용할 수 있습니다. 다만 이러한 엄격한 기준은 유용한 중립적 수정도 거절할 수 있으므로, **탐색용 후보 보관과 실제 배포용 채택을 분리**하는 설계가 적절합니다. 여러 번 검사할 때의 오류 누적도 별도로 다루어야 합니다.

### 11.5 추가 제안 4: 그래프 구조의 기여와 안전성을 별도로 검증해야 한다

지역 원문 주입, 동일 토큰 길이의 텍스트 지침, 간선을 섞은 그래프, 속성만 유지한 그래프, 거절 메모리를 제거한 루프 등을 비교하면 개선 원인을 더 분명히 할 수 있습니다. 동시에 자연어 조건을 검사 가능한 도구 규약과 연결하고, 실제 도구 목록 포함 여부·권한·부작용을 실행 계층에서 검증해야 합니다. 이는 현재의 연성 지침과 구조 검사만으로 보장되지 않는 부분입니다[p.24]. 2609.09153v1

### 최종 판단

**이 논문의 가장 중요한 성과는 “LLM의 행동 경험을 수정 가능한 외부 절차 구조로 축적할 수 있다”는 실증입니다.** 반면 가장 중요한 미해결 과제는 **그 구조가 학습한 환경을 넘어 얼마나 재사용되는가**입니다.

따라서 후속 연구에서 우선해야 할 것은 더 많은 동일 분포 벤치마크의 최고점보다, **고정 그래프의 모델 간 이전, 도구 변화에 대한 적응, 처음 보는 절차 조합, 시간에 따라 바뀌는 환경, 계산 예산을 맞춘 비교**입니다. 이 평가들을 통과한다면 PG는 특정 벤치마크용 지침 최적화를 넘어, 재사용 가능한 에이전트 절차 지식의 기반으로 발전할 가능성이 있습니다. 현재 문서만으로는 그 단계에 도달했다고 단정할 수 없습니다.
