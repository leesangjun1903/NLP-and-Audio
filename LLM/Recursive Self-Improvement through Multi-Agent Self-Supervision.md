## 2. 연구의 목적·필요성과 핵심 주장

### 2.1 무엇을 해결하려는가?

**저자가 제시한 문제는 ‘감독의 병목’과 ‘개선 방법의 병목’입니다.** 개방형 연구에서는 정답을 즉시 확인하기 어렵고, 결과가 전문적인 수준에 도달할수록 사람의 평가도 느리거나 불완전해집니다. 동시에 좋은 연구 수행 데이터를 생성하려면 작업 분해, 도구 사용, 검증, 결과 통합 등의 절차를 개선해야 하는데, 이를 과제마다 사람이 설계하는 데 많은 비용이 듭니다〔p.2, Introduction〕. 2610.12176v1

> **용어:** 개방형·비검증 과제는 단일 정답이나 간단한 자동 채점기만으로 전체 품질을 판정하기 어려운 과제; 감독 신호는 무엇이 더 좋은 행동인지 모델에 알려주는 학습 정보

동일한 모델이 생성·평가·수정을 모두 수행하면 같은 사전 지식과 편향을 공유하므로, 잘못된 결과를 서로 승인할 위험이 있습니다. 저자는 이를 해결하기 위해 모델 자체를 즉시 더 크게 만드는 대신, **같은 모델이 서로 다른 역할과 문맥에서 일하도록 조직하는 방식**을 바꿉니다〔p.2〕. 2610.12176v1

**제 해석:** 이 연구는 “같은 답을 여러 번 생각하면 좋아진다”보다, “문제를 나누고 중간 결과를 전달하는 절차를 학습하면 좋아질 수 있다”에 가깝습니다. 다만 역할을 나눈다고 모델들의 오류가 통계적으로 독립적이 되는 것은 아닙니다. 따라서 MASS는 자기평가의 한계를 제거한 방법이라기보다, 그 한계 안에서 더 유용한 실행 경험을 얻는 방법으로 읽는 것이 적절합니다.

관련 선행 연구인 Huang 외의 *Large Language Models Cannot Self-Correct Reasoning Yet*도 외부 피드백 없이 이루어지는 내재적 자기수정의 어려움을 보고했습니다. MASS는 도구 실행 결과와 다중 에이전트 작업 구조를 활용하므로, 그 선행 연구와 정확히 같은 조건의 실험은 아닙니다. [arXiv](https://arxiv.org/abs/2310.01798)

## 3. 제안 방법과 모델 구조: 수식 중심 설명

아래에서 원문에 있는 수식과, 원문의 절차를 이해하기 쉽게 다시 쓴 수식을 구별합니다.

### 3.1 구조: 서로 다른 전문가 모델이 아니라 하나의 공유 모델

**저자 보고:** MASS의 실행자, 평가자, 워크플로 최적화자는 같은 모델을 사용합니다. 실행자 내부의 조정자와 하위 에이전트도 같은 가중치를 공유합니다〔p.4〕. 2610.12176v1 2610.12176v1

```math
L_{\text{agent}}^{(g)}
=
L_{\text{eval}}^{(g)}
=
L_{\text{opt}}^{(g)}
=
L_{\theta^{(g)}}.
```

**기호:** $g$는 자기개선 세대, $\theta^{(g)}$는 해당 세대의 모델 가중치, $L_{\text{agent}}$는 실행 모델, $L_{\text{eval}}$은 평가 모델, $L_{\text{opt}}$는 워크플로 제안 모델입니다.

실행 구조는 다음과 같습니다.

| 구성 요소 | 수행하는 일 |
|---|---|
| 조정자 | 과제를 분해하고 하위 에이전트를 호출하며, 결과를 검증·통합합니다. |
| 하위 에이전트 | 제한된 작업과 파일을 받아 구현·분석·검증을 수행합니다. |
| 자기평가자 | 완성된 작업 디렉터리 두 개를 비교하고 선호 및 이유를 제공합니다. |
| 워크플로 최적화자 | 이전 설계와 평가 이력을 보고 역할·정보 전달·호출 순서를 수정합니다. |

> **용어:** 조정자(orchestrator)는 팀의 작업을 배분하는 역할; 하위 에이전트(subagent)는 특정 작업을 맡는 모델 실행 단위; 작업 디렉터리(workspace)는 코드·결과 파일·보고서 등 실제 산출물의 집합

**중요한 구조적 구분:** 이 논문은 새로운 신경망 층이나 어텐션 구조를 제안하지 않습니다. 주요 변화는 **모델 바깥의 실행 절차**와 **그 절차로 생성한 기록을 이용한 가중치 학습**에 있습니다. 또한 추론 시 최적화된 워크플로를 제공하지 않더라도, 하위 에이전트 호출 도구 자체는 계속 사용할 수 있습니다〔p.20, Appendix C.5〕. 2610.12176v1

### 3.2 워크플로 표현

**원문의 정의〔p.4〕:**

```math
w_t
=
\left\{
h_t,\,
(r_{t,j},u_{t,j},c_{t,j})_{j=1}^{m_t}
\right\}.
```

**기호:** $t$는 과제, $w_t$는 과제별 워크플로, $m_t$는 하위 에이전트 수, $r_{t,j}$는 역할, $u_{t,j}$는 작업 지시, $c_{t,j}$는 반환할 정보의 규약, $h_t$는 하위 에이전트 호출 순서입니다. 2610.12176v1

> **용어:** 출력 계약(output contract)은 “결과를 잘 설명하라”는 추상적 지시가 아니라, 반환할 파일 경로·지표·오류 내용·검증 결과 등을 명시한 정보 규약; hop은 여기서 하위 에이전트를 호출하는 순서

과제 프롬프트에 워크플로를 붙여 실행합니다.

$$
(\tau_t,y_t)
\sim
A(x_t\oplus w_t;L_{\theta}).
$$

**기호:** $A$는 도구와 실행 환경을 포함한 코딩 에이전트, $x_t$는 과제 프롬프트, $\oplus$는 텍스트 연결, $\tau_t$는 실행기록, $y_t$는 최종 산출물입니다.

예를 들어 금융 연구에서는 데이터 수집→특징 생성→모델링→백테스트→감사→보고서 작성으로 연결하며, 감사에서 문제가 발견되면 해당 작업자에게 구체적인 수정 요청을 되돌려 보내도록 설계합니다〔pp.32–36, Appendix I.1〕. 다만 저자는 이 워크플로에 포함된 임계값과 검증 규칙이 **최적화자가 제안한 내용이지 검증된 과학적 기준은 아니라고 명시**합니다. 2610.12176v1

### 3.3 내부 반복: 워크플로 탐색

다음은 **Algorithm 2를 수식으로 재표현한 것**입니다.

$$
w_t^{(i+1)}
\sim
L_{\text{opt}}
\left(
w_t^{(i)},w_t^\star,D_{t,i};x_{\text{opt}}
\right).
$$

$$
(\tau_t^{(i+1)},y_t^{(i+1)})
\sim
A(x_t\oplus w_t^{(i+1)};L_{\text{agent}}).
$$

$$
(w_t^\star,y_t^\star)
\leftarrow
(w_t^{(i+1)},y_t^{(i+1)})
\quad
\text{if }
y_t^{(i+1)}\succ y_t^\star.
$$

**기호:** $i$는 내부 탐색 단계, $w_t^\star$는 현재까지 보존한 최선의 워크플로, $y_t^\star$는 그 워크플로의 산출물, $D_{t,i}$는 평가 이력, $x_{\text{opt}}$는 최적화 지시문, $\succ$는 자기평가자가 더 선호한다는 관계입니다〔pp.5,15〕. 2610.12176v1 2610.12176v1

**해석상 핵심:** $w_t^\star$는 전역 최적해가 아닙니다. 한 번씩 실행한 결과를 순차적으로 비교하여 남겨 둔 **자기평가 기준의 현재 최선**입니다. 따라서 실행 운이 좋았던 후보를 보존하거나, 좋은 설계를 잘못 버릴 가능성이 있습니다.

> **용어:** 전역 최적해는 가능한 모든 후보 중 가장 좋은 해; 엘리트 보존은 현재 가장 좋은 후보를 남겨 다음 탐색의 기준으로 삼는 방식

### 3.4 외부 반복: 자기선별 데이터와 지도 미세조정

**저자 보고:** 과제별로 최적화된 워크플로를 18회 실행하고, 자기평가자가 산출물을 쌍별 비교합니다. Bradley–Terry 모형으로 순위를 만든 뒤 상위 15개를 학습에, 16위를 검증에 사용합니다〔pp.5–6,15–16〕. 2610.12176v1 2610.12176v1

Bradley–Terry의 의미를 설명하는 **표준형 수식**은 다음과 같습니다. 논문은 이 모형의 사용을 명시하지만 아래 식 자체를 제시하지는 않습니다.

```math
\mathbb{P}(y_a\succ y_b)
=
\frac{\exp(\beta_a)}
{\exp(\beta_a)+\exp(\beta_b)}.
```

**기호:** $\beta_a,\beta_b$는 두 산출물의 잠재적 선호 점수, $\mathbb{P}$는 선호 확률입니다.

> **용어:** Bradley–Terry 모형은 여러 쌍의 승패를 종합하여 각 후보의 상대적 강도를 추정하는 순위 모형; 이 점수는 과학적 진실성의 절대 척도가 아님

학습 데이터를 만들 때 조정자의 초기 입력에서는 워크플로와 실행 지시를 제거하고, 과제만 남깁니다. 그러나 하위 에이전트가 받은 구체적 작업 지시는 유지합니다. 이는 **팀을 어떻게 구성할지**와 **맡은 작업을 어떻게 실행할지**를 같은 가중치에 함께 학습시키려는 설계입니다〔p.15, Algorithm 3; p.16〕. 2610.12176v1 2610.12176v1

**원문의 지도 미세조정 목적함수〔p.5〕:**

```math
\ell_{\text{SFT}}(\theta)
=
-
\mathbb{E}_{z\sim q}
\left[
\frac{
\sum_{\ell=1}^{|z|}
\mu_\ell\log p_\theta(z_\ell\mid z_{<\ell})
}{
\sum_{\ell=1}^{|z|}\mu_\ell
}
\right].
```

**기호:** $\theta$는 학습할 가중치, $z$는 학습용 토큰 구간, $|z|$는 구간 길이, $z_\ell$은 현재 토큰, $z_{<\ell}$은 앞선 토큰, $p_\theta$는 다음 토큰 확률, $\mu_\ell$은 학습 대상이면 1인 마스크, $q$는 구간을 뽑는 분포입니다. 프롬프트·도구 출력·겹치는 문맥은 손실에서 제외됩니다. 2610.12176v1

> **용어:** 지도 미세조정(SFT)은 선택된 실행 예시를 모방하도록 학습하는 방식; 손실 마스킹은 입력으로는 보여 주되 정답처럼 따라 배우게 하지는 않는 처리

**제 해석:** MASS의 가중치 업데이트는 강화학습이 아니라 **선별된 행동 기록을 모방하는 학습**입니다. 산출물 수준의 선호가 좋다고 해서 그 안의 모든 중간 행동이 옳다는 보장은 없으며, 잘못된 검증 절차도 함께 학습될 수 있습니다.

### 3.6 정보 흐름 가설의 분석 수식

이 수식들은 **학습 목적함수가 아니라, 최적화된 워크플로를 사후 분석하는 지표**입니다.

**원문의 과제 정보량 추정치〔p.26〕:**

```math
\widehat I(Z_c;T)
=
-\frac{1}{2}
\sum_j
\log(1-\kappa_{c,j}^{2}).
```

**기호:** $Z_c$는 구성 요소 $c$의 텍스트 임베딩, $T$는 과제 설명을 임베딩한 표현, $\kappa_{c,j}$는 두 표현 사이의 $j$번째 정준상관입니다. $c$는 역할·지시·출력 계약·호출 순서 중 하나입니다. 2610.12176v1

> **용어:** 임베딩은 텍스트의 의미를 숫자 벡터로 나타낸 것; 정준상관은 두 벡터 집합 사이에서 가장 강하게 함께 변하는 방향을 찾는 통계; 여기서의 정보량은 가우시안 가정에 기반한 대리지표

**원문의 구성 요소 중복도 추정치:**

```math
\widehat{\text{TC}}(Z)
=
\frac{1}{2}
\left[
\sum_{c\in C}\log\det\Sigma_c
-
\log\det\Sigma
\right].
```

**기호:** $C$는 네 구성 요소의 집합, $Z$는 이들을 연결한 벡터, $\Sigma_c$는 각 구성 요소의 공분산 행렬, $\Sigma$는 전체 공분산 행렬, $\det$는 행렬식입니다. 저자는 과제별 평균을 뺀 표현에도 같은 추정식을 적용하지만, 이것이 정확한 조건부 총상관 추정치는 아니라고 명시합니다〔p.26〕. 2610.12176v1

> **용어:** 총상관(TC)은 여러 변수 사이에 중복되는 정보의 정도; 공분산은 여러 값이 함께 변하는 정도

**저자 보고:** 탐색 초기와 마지막을 비교하면 출력 계약과 호출 순서는 더 과제 특화되고, 역할과 지시문은 덜 과제 특화됩니다. 전체 중복도는 네 설정 모두 감소하지만, 과제 평균을 제거한 중복도는 한 설정에서 증가합니다〔p.27, Tables 12–13〕. 2610.12176v1

**제 해석:** “전문가처럼 행동하라”는 역할 문구보다 “어떤 결과를 누구에게 언제 전달할지”가 중요해진다는 설명과 부합합니다. 그러나 이것으로 일반화 오차가 줄어드는 이론적 보장이나 인과관계가 성립하지는 않습니다.

미완료 결과가 0점인 평가에서는 다음 관계가 성립합니다. 이는 저자의 채점 정의로부터 얻는 **설명용 항등식**입니다.

```math
\mathbb{E}[S]
=
\mathbb{P}(\text{완료})
\cdot
\mathbb{E}[S\mid\text{완료}].
```

**기호:** $S$는 실행 하나의 점수, $\mathbb{E}[S]$는 전체 평균, $\mathbb{P}(\text{완료})$는 완료 확률, $\mathbb{E}[S\mid\text{완료}]$는 완료된 실행의 평균 점수입니다.

**제 해석:** 현재 결과는 “연구를 끝까지 수행하여 산출물을 제출하는 능력이 향상되었다”는 주장에 특히 잘 부합합니다. 다만 조건부 평균이 낮아졌다고 연구 품질이 악화되었다고 단정하는 것도 잘못입니다. 새 모델이 이전에는 실패하던 어려운 과제를 추가로 완료했을 수 있기 때문입니다. 필요한 것은 **두 모델이 모두 완료한 동일 과제 집합에서의 품질 비교**입니다.

더 중요한 점은 MLR-Bench의 전체 180개 실행에서 **하위 에이전트 위임 도구 호출이 한 번도 없었다는 사실**입니다. 따라서 이 벤치마크의 성능 향상을 “추론 시 다중 에이전트 협업이 직접 일으켰다”고 설명할 수 없습니다〔p.21〕. 2610.12176v1

### 4.4 일반화는 어느 수준까지 관찰되었는가?

**첫째, 같은 분야의 새로운 과제로의 전이입니다.** 합성 테스트 과제 세 개는 금융·약학·로봇공학에서 하나씩 선택되며, 학습 과제와 같은 큰 분야에 속합니다. 또한 이 분할은 미세조정·검증·체크포인트 선택에 대한 분할이고, 워크플로 탐색 실험은 테스트 과제에도 수행됩니다〔p.16, Table 3〕. 2610.12176v1

**제 해석:** 이는 과제 간 전이의 증거이지만, 완전히 새로운 분야에 대한 일반화 실험은 아닙니다. 테스트 과제가 세 개뿐이라는 점도 일반화 범위 추정을 제한합니다.

**둘째, 외부 벤치마크로의 전이입니다.** 최적화된 워크플로 없이 네 연구 벤치마크에서 개선을 보인 것은 긍정적입니다. 하지만 일반 코딩 두 벤치마크의 하락 때문에 **전반적인 범용 능력 상승**으로 확대할 수 없습니다〔p.20, Table 7〕. 2610.12176v1

**셋째, 역할 간 전이입니다.** 수행 기록만으로 평가와 워크플로 생성이 개선된 결과는 흥미롭지만, 같은 기반 모델 계열 내부의 전이입니다. 다른 모델 구조·크기·도구 환경으로의 전이는 입증하지 않았습니다〔p.7, Table 1〕. 2610.12176v1

> **용어:** 분포 외 일반화는 학습 환경과 다른 분야·조건에서도 성능을 유지하는 능력; 여기서는 과제 이름이 다르다는 것과 학습 분포 자체가 다르다는 것을 구별해야 함

## 9. 결론: 저자의 시사점과 추가 후속 연구 방향

### 9.1 저자가 직접 제시한 결론과 후속 방향

저자는 같은 모델의 여러 복제본을 조직하고 집단 수행 경험을 공유 가중치에 학습시키면, 동질적인 자기개선 과정에서도 유용한 감독 신호를 얻을 수 있다고 결론짓습니다. 논문 결론에서 명시한 후속 방향은 **각 자기개선 주기에서 성능이 향상되는 속도를 높이는 것**입니다〔p.10, Conclusion〕. 2610.12176v1

논문과 별개인 저자 공식 해설 *MASS: Recursive Self-Improvement through Multi-Agent Self-Supervision*의 Conclusion은 공유된 맹점이 생성·평가·교정을 동시에 훼손할 위험을 강조하고, 독립적인 점검, 자율 행동의 제약, 효과적인 개입 조건을 연구해야 한다고 논의합니다. 이는 **공식 해설의 추가 논의**이지 본문 결론에 모두 열거된 연구 계획은 아닙니다. [사카나 AI 출판물](https://pub.sakana.ai/mass/)

### 9.2 제가 제안하는 우선순위 높은 후속 연구

**첫째, 일반화를 평가하기 전에 데이터 구조의 인과적 기여부터 분리해야 합니다.** 동일 과제·동일 생성 예산·동일 처리 토큰·동일 샘플러·동일 모델 선택 규칙 아래에서 단일 에이전트, 일반 팀 지시, 최적화된 팀 워크플로를 비교하는 실험을 제안합니다. 여기에 조정자만 학습, 작업자만 학습, 공동 학습을 추가하면 Figure 6의 이점이 데이터 품질·다양성·역할 분해 중 어디서 나오는지 구별할 수 있습니다.

**둘째, 과제 단위가 아니라 분야·환경 단위로 보류하는 일반화 실험이 필요합니다.** 예를 들어 금융과 로봇공학으로 학습한 뒤 약학 전체를 보류하고, 새로운 도구·다른 실행 환경·다른 기반 모델에서도 평가하는 방식입니다. 평가 과제는 워크플로 탐색과 모델 선택에도 노출되지 않도록 분리해야 합니다. 평균 향상뿐 아니라 분야별 하락과 기존 능력 유지도 함께 보아야 합니다.

> **용어:** 분야 보류 평가는 특정 분야 전체를 학습에서 제외하는 평가; 능력 유지는 새 능력을 배우면서 기존에 잘하던 과제 성능을 보존하는 것

**셋째, 완료율·실질 품질·과학적 유효성을 별도 지표로 평가해야 합니다.** 보고서가 존재하는지, 동일 과제에서 결과가 더 좋은지, 원래 실험의 의미를 보존했는지는 서로 다른 질문입니다. 숨겨진 실행 검사와 일부 전문가의 눈가림 평가를 병행하고, 시뮬레이터·채점 기준·정답 파일 등은 실행자가 임의로 바꿀 수 없도록 보호하는 설계를 제안합니다. 이는 p.29의 반례를 직접 겨냥합니다.

**넷째, 길어진 자기개선 과정에서 성능 유지와 오류 누적을 추적해야 합니다.** 여러 세대를 반복하면서 새 과제 성능, 기존 코딩 성능, 출력 다양성, 자기평가와 독립 평가의 불일치를 함께 기록해야 합니다. 쉬운 성공 사례만 남기는 방식과 실패·반례·기존 데이터도 보존하는 방식을 비교하면, 좁은 성공 패턴으로의 편향을 줄일 수 있는지 시험할 수 있습니다.

**다섯째, 워크플로의 기대 성능과 안정성을 평가해야 합니다.** 후보마다 한 번만 실행하기보다 일부 후보를 반복 실행하고, 평균과 변동성을 함께 고려하여 보존하는 방법을 제안합니다. 통계 분석은 판정 수가 아니라 과제를 상위 단위로 삼아야 하며, 동일 과제의 모델 간 차이를 유지하는 재표집이 적절한 출발점입니다.

> **용어:** 과제 단위 재표집은 개별 평가자 판정을 흩어 뽑는 대신 과제와 그에 속한 반복 결과를 함께 뽑아 불확실성을 추정하는 방식

**여섯째, 일반화를 높이는 ‘선택적 협업’을 연구할 가치가 있습니다.** 모든 문제에서 팀을 구성하도록 만드는 것보다, 단독 수행으로 충분한 문제와 검증·분업이 필요한 문제를 구분하도록 학습하는 접근입니다. 다중 에이전트 생성 비용과 일반 코딩 성능 하락을 함께 고려하면, 후속 목표는 단순히 위임 횟수를 늘리는 것이 아니라 **협업이 유익한 상황을 정확히 선택하는 것**이어야 합니다.

### 최종 평가

**MASS는 “더 나은 협업 절차를 찾고, 그 경험을 모델에 학습시킨 뒤, 개선된 모델로 다시 절차를 찾는다”는 연결을 실제로 시험했다는 점에서 가치가 있습니다.** 그러나 일반화에 관한 현재의 가장 강한 결론은 **일부 연구형 과제에서 수행·완료 능력과 역할 간 전이가 개선되었다**는 것이며, 연구 내용의 타당성·범용 능력·장기 자기개선의 안정성까지 확장되지는 않습니다.

따라서 앞으로 가장 중요한 연구 질문은 **“몇 세대를 더 반복하면 얼마나 높아지는가”뿐 아니라, “어떤 구조의 자기 생성 경험이 새로운 분야에서도 재사용되며, 그 과정에서 오류와 기존 능력 저하를 어떻게 통제할 것인가”**입니다.
