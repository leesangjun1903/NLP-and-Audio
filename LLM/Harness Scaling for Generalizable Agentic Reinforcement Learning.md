# Harness Scaling for Generalizable Agentic Reinforcement Learning

**핵심 평가:** 이 논문의 가장 중요한 기여는 **에이전트의 실행 방식을 구성요소별로 나누고, 균형 있게 선택한 실행 구성으로 학습하여 새로운 구성과 외부 실행 시스템으로의 전이를 개선한 것**입니다.  
제시된 실험에서는 개선 방향이 일관되지만, 통계적 유의성이나 임의의 실행 환경에 대한 일반화까지 입증한 것은 아닙니다.  
**근거:** 원문 pp. 3–10, Figure 1, Tables 1–4.

> **용어 — 하네스(harness):** 모델에 지시를 전달하고, 도구를 연결하며, 대화 이력과 실행 순서를 관리하는 실행 소프트웨어 계층입니다.  
> **용어 — 에이전트 강화학습(agentic RL):** 모델이 도구를 사용하며 여러 단계의 작업을 수행하고, 그 결과에 대한 보상을 통해 행동 방식을 학습하는 방법입니다.  
> **용어 — 일반화(generalization):** 학습에서 직접 경험하지 않은 조건에서도 성능을 유지하는 능력입니다. 이 논문에서는 특히 **실행 구성의 변화에 대한 일반화**를 다룹니다.

4. 각 과제에는 기준 구성과 구조적으로 가까운 구성을 배정하고, 하나의 공유 모델을 기존 강화학습 알고리즘으로 학습시킵니다. **[pp. 5–6; Figure 1]**
5. 실험은 Qwen3 계열 두 모델, 두 강화학습 알고리즘, 세 평가 과제집을 사용하며, 학습하지 않은 내부 조합과 외부 실행 시스템에서 성능을 측정합니다. **[p. 6]**
6. 내부 미학습 조합에서 세 평가 과제집의 평균 개선은 4B 모델의 GRPO/PPO에서 각각 **+9.80/+3.57점**, 30B-A3B 모델에서 **+5.21/+4.90점**입니다. **[p. 7; Table 1]**
7. 외부 Claude Code로의 전이에서는 구조화된 하네스 학습이 단일 OpenClaw 하네스로 강화학습한 비교군보다 평균 **+3.84점과 +4.92점** 높습니다. **[p. 8; Table 2, 표 수치 차이 계산]**
8. 구성 선택과 과제별 배정 방식이 중요하여, 동일한 학습 예산에서는 구조화된 18개 구성이 전체 243개 구성보다 좋았고, 과제당 하네스 수도 시험한 조건 중 두 개가 가장 좋았습니다. **[pp. 8–9; Figure 3]**
9. 다만 평가 반복의 분산·신뢰구간과 독립 재학습 결과가 제시되지 않았으므로, 이 결과는 **시험한 조건에서 관찰된 평균 전이 성능의 개선**으로 해석하는 것이 정확합니다. **[pp. 6–10, 17–20]**

> **용어 — GRPO/PPO:** 정책의 행동 확률을 보상에 따라 갱신하는 강화학습 알고리즘이며, 구체적인 차이는 4.5절에서 설명합니다.

## 2. 연구 배경·목표·필요성

### 2.1 해결하려는 문제

**[저자 보고]** 에이전트 성능은 기반 언어모델뿐 아니라, 모델이 사용하는 하네스에도 영향을 받습니다.  
같은 문제라도 도구 이름, 도구 결과의 표현, 이전 대화의 보존 방식, 계획·검증 절차가 달라지면 모델이 수행해야 하는 상호작용이 달라집니다.  
따라서 하나의 하네스에서만 강화학습하면 그 실행 관례에 특화될 수 있습니다. **[pp. 1–2]**

저자들은 기존 에이전트 학습의 확장 축을 다음과 같이 구분합니다. **[pp. 1–3; Figure 1]**

| 확장 축 | 바꾸는 대상 | 연구 질문 |
|---|---|---|
| 과제 확장 | 풀어야 하는 문제 | 더 다양한 문제를 학습하면 능력이 넓어지는가? |
| 환경 확장 | 작업 공간과 외부 상호작용 환경 | 더 다양한 환경에서 학습하면 다른 환경에도 적응하는가? |
| **하네스 확장** | 동일 과제·환경에 접근하고 실행하는 방식 | 실행 구성이 달라져도 잘 작동하는 정책을 학습할 수 있는가? |

> **용어 — 정책(policy):** 현재 입력과 상호작용 이력을 보고 다음 행동이나 토큰을 선택하는 모델의 확률적 행동 규칙입니다.

### 2.2 연구 목적

이 논문의 목적은 다음 세 가지입니다. **[pp. 2–5]**

1. 하네스 다양성을 **명시적인 조합 공간**으로 표현합니다.
2. 제한된 학습 예산으로 그 공간을 다룰 수 있도록 **대표 훈련 구성을 선택**합니다.
3. 선택한 구성들을 과제에 배정하는 방식을 설계하여 **미학습 조합과 외부 하네스로의 일반화**를 평가합니다.

### 2.3 연구가 필요한 이유

**[해석]** 배포 시 프롬프트나 도구 연결 방식이 바뀔 때마다 성능이 크게 변한다면, 특정 환경에서 얻은 강화학습 성과의 활용 범위가 좁아집니다.  
이 연구는 실행 방식의 변화를 학습 과정에 포함시키는 것이 그러한 의존성을 줄이는 데 도움이 되는지를 통제된 실험으로 조사합니다. **근거: pp. 1–5, Tables 1–4.**

다만 하네스 다양화 자체는 선행연구에도 있습니다. 이 논문의 차별성은 **다양성의 구성·선택·배정 방식을 명시적으로 설계하고 분리하여 검증한 점**에 두는 것이 적절합니다.  
관련 연구와의 구체적인 비교는 9절에 제시합니다.

## 4. 제안 방법과 모델·시스템 구조

### 4.1 무엇을 학습하고, 무엇을 바꾸는가?

**[저자 보고]** 학습 대상은 과제를 수행하는 **공유 Qwen 정책 모델**입니다. Harness Scaling은 이 모델이 경험하는 **과제–하네스 조합의 분포**를 설계합니다.  
정책 업데이트에는 PPO 또는 GRPO를 사용합니다. **[pp. 5–6]**

연구에 등장하는 모델의 역할을 구분하면 다음과 같습니다.

| 모델 | 역할 | 근거 |
|---|---|---|
| Qwen3-4B-Instruct | 학습·평가 대상 정책 | p. 6 |
| Qwen3-30B-A3B-Instruct | 학습·평가 대상 정책 | p. 6 |
| Opus-4.7 | 하네스 구성요소의 대안 구현 생성 | p. 15, Appendix A |
| GPT-5.4 | 기준표 기반 과제 평가와 행동 궤적 평가 | pp. 19–20 |

**[해석]** 논문이 새로 제안하는 구조는 신경망 내부 층의 변경보다 **훈련 시스템의 구성 방식**에 있습니다. Figure 1도 이 훈련 절차를 설명합니다. **[p. 3, Figure 1; p. 6, 식 (7)]**

기반 모델의 구조를 보충하면, Qwen3-4B는 밀집 모델이고 Qwen3-30B-A3B는 MoE 모델입니다. 따라서 두 실험을 동일한 밀집 구조의 크기만 변화시킨 비교로 보기는 어렵습니다. [arxiv.org](https://arxiv.org/html/2505.09388v1?utm_source=chatgpt.com)

> **용어 — 밀집 모델(dense model):** 일반적으로 각 토큰을 처리할 때 해당 층의 전체 신경망 경로를 사용하는 모델입니다.  
> **용어 — MoE, Mixture of Experts:** 여러 전문가 모듈 중 일부를 선택하여 토큰을 처리하는 구조입니다. 총 파라미터 수와 실제 활성화되는 파라미터 수가 다릅니다.

### 4.2 다섯 하네스 구성요소

저자들이 실제로 사용한 변형은 다음과 같습니다. **[pp. 15–16, Table 5]**

| 기호·요소 | 기본 구현: 수준 0 | 변형 I: 수준 1 | 변형 II: 수준 2 |
|---|---|---|---|
| $S$: 시스템 프롬프트 | 역할과 실행 규칙을 직접 지시 | 동일 요구사항을 제품·플랫폼 설명 속에 배치 | 이야기와 역할 설정으로 재표현 |
| $T$: 도구 인터페이스 | 원래 도구 이름·형식 사용 | 의미가 비슷한 별칭과 방해 도구 추가 | 기능을 추측하기 어려운 식별자와 방해 도구 추가 |
| $O$: 관측 | 원래 도구 출력 | 가상 인프라 메타데이터 추가 | 도구명·종료 코드·실행 시간 등의 XML형 메타데이터 추가 |
| $C$: 문맥 관리 | 전체 상호작용 이력 유지 | 이전 내용을 요약하고 최근 5턴 유지 | 최근 3턴 유지, 요약 이력을 보조 파일에 저장 |
| $W$: 워크플로 | 자유로운 실행 | 실행 전 계획 작성 요구 | 계획 작성과 함께 3단계마다 진행 상황 검증 |

> **용어 — 관측(observation):** 도구 실행 결과처럼 환경이 모델에 돌려주는 정보입니다.  
> **용어 — 메타데이터:** 실제 작업 결과에 덧붙는 실행 위치·시간·상태 등의 부가 정보입니다.  
> **용어 — 문맥 압축(compaction):** 긴 상호작용 이력을 요약하거나 외부에 저장하여 현재 모델 입력을 줄이는 처리입니다.  
> **용어 — 방해 도구(distractor tool):** 여기서는 실제 과제 수행 기능이 없는 추가 도구로, 모델이 적절한 도구를 구별하도록 만드는 요소입니다.

기본 도구는 파일 읽기·쓰기·편집, Bash 실행, 코드 해석, 검색, 웹 가져오기의 다섯 계열입니다. 저자는 변형 과정에서 과제의 의미와 실제 도구 기능을 보존하도록 제약했다고 설명합니다. **[p. 15]**

**[해석]** 이러한 의미·기능 보존은 연구 설계의 중요한 전제입니다. 다만 변형 전후의 등가성을 독립적으로 검증한 정량 결과는 본문·부록에 제시되지 않습니다.

### 4.3 구성요소 변형과 전체 조합 공간

#### 원문 식 (1): 구성요소별 변형

```math
F^{(\ell)}
=
\tau_F^{(\ell)}\!\left(F^{(0)}\right)
```

**기호 설명**

- $F\in\{S,T,O,C,W\}$: 변형할 구성요소입니다.
- $F^{(0)}$: 해당 요소의 기본 구현입니다.
- $\tau_F^{(\ell)}$: 해당 요소에 적용하는 $\ell$번째 변환입니다.
- $F^{(\ell)}$: 변환 후 구현입니다.

이 식은 요소별 변형을 표현합니다. 실제 훈련에서 함께 사용하는 두 하네스가 반드시 한 요소에서만 달라진다는 뜻은 아닙니다. **[p. 3, 식 (1)]**

#### 원문 식 (2): 전체 하네스 공간

```math
\mathcal H
=
\mathcal S
\times
\mathcal T
\times
\mathcal O
\times
\mathcal C
\times
\mathcal W
```

**기호 설명**

- $\mathcal S,\mathcal T,\mathcal O,\mathcal C,\mathcal W$: 각 요소의 구현 집합입니다.
- $\times$: 각 집합에서 하나씩 선택하는 모든 조합을 뜻합니다.
- $\mathcal H$: 완전한 하네스 구성 전체입니다.
- $h\in\mathcal H$: 개별 하네스 구성입니다.

각 요소에 세 가지 구현이 있으므로 다음과 같습니다.

$$
|\mathcal H|=3^5=243
$$

여기서 $|\mathcal H|$는 집합에 포함된 구성의 개수입니다. **[p. 4, 식 (2); p. 6]**

#### 일반화의 두 유형

| 유형 | 평가 대상 | 무엇이 새로운가? |
|---|---|---|
| **In-Space** | $\mathcal H\setminus\mathcal H_{\text{tr}}$의 일부 | 구성요소 자체는 학습했지만, 다섯 요소의 전체 조합은 새로움 |
| **Out-of-Space** | Claude Code, OpenClaw | 직접 만든 조합 공간에 포함되지 않은 외부 실행 시스템 |

$\mathcal H_{\text{tr}}$는 훈련에 사용한 하네스 집합입니다. **[p. 4, §3.1.2]**

> **용어 — 화이트박스·블랙박스:** 이 논문에서는 직접 구성하고 통제하는 하네스와 외부의 복잡한 실행 시스템을 구분하는 표현입니다. 모델 가중치의 공개 여부를 뜻하지 않습니다.

### 4.4 243개 중 18개를 선택하는 원리

#### 원문 식 (3): 두 구성요소의 조합을 균등하게 포함

$$
N_{ij}(\ell,\ell')=\lambda
$$

**기호 설명**

- $i,j$: 서로 다른 구성요소의 인덱스입니다.
- $\ell,\ell'$: 각 요소에서 선택한 구현 수준입니다.
- $N_{ij}(\ell,\ell')$: 훈련 집합에서 해당 수준쌍을 포함하는 구성의 수입니다.
- $\lambda$: 모든 수준쌍에 공통으로 적용되는 등장 횟수입니다.

예를 들어 도구 인터페이스와 문맥 관리의 수준쌍이 총 아홉 가지라면, 그 아홉 가지가 모두 같은 횟수로 나타나도록 합니다. **[pp. 4–5, 식 (3)]**

> **용어 — 요인·수준:** 바꿀 설계 항목이 요인이고, 그 항목에 준비한 선택지가 수준입니다.  
> **용어 — 강도 2 직교설계(strength-2 orthogonal design):** 임의의 두 요인을 골랐을 때 가능한 수준쌍이 모두 같은 횟수로 등장하도록 만든 실험 설계입니다. 세 요인 이상의 모든 조합까지 균등하다는 뜻은 아닙니다.

#### 원문 식 (4)·(5): 필요한 구성 수

$$
N=\lambda L^2
$$

$$
N\ge 1+M(L-1)
$$

**기호 설명**

- $N$: 선택하는 훈련 하네스 수입니다.
- $M$: 구성요소 수입니다.
- $L$: 각 요소의 수준 수입니다.
- $\lambda$: 각 두 요소의 수준쌍이 등장하는 횟수입니다.

첫 식은 두 요소의 $L^2$개 수준쌍을 각각 $\lambda$번 포함한다는 관계입니다. 둘째 식은 직교설계의 크기에 대한 **Rao 하한**입니다. **[p. 5, 식 (4)–(5)]**

> **용어 — 하한(lower bound):** 어떤 조건을 만족하려면 최소한 넘어야 하는 값입니다. 여기서는 설계에 필요한 구성 수의 제한이며, 모델 성능의 최소 보장값이 아닙니다.

이 연구에서는 $M=5$, $L=3$이므로 다음을 만족해야 합니다.

$$
N=9\lambda,\qquad N\ge11
$$

두 조건을 만족하는 가장 작은 후보 크기는 $N=18$이며, 저자들은 실제로 $\lambda=2$인 18개 구성을 제시합니다. 그 결과 각 요소의 개별 수준은 6회, 임의의 두 요소의 수준쌍은 2회 등장합니다. **[pp. 16–17, 식 (8)–(11), Table 6]**

**[검산]** Table 6의 18개 구성을 직접 계산한 결과, 위의 단일 수준 균형과 모든 두 요소 조합의 균형이 일치했습니다. Table 8의 평가 구성과 중복도 없었습니다.

**[해석]** 이 수학적 근거는 **조합을 균형 있게 포함한다는 보장**입니다. 학습한 정책의 일반화 오차나 성능 향상을 보장하는 정리는 아닙니다.

### 4.5 과제마다 가까운 하네스를 배정하는 방법

저자는 두 하네스에서 서로 다른 구성요소의 개수를 **Hamming 거리**로 정의합니다. 원문 p. 4의 정의를 수식으로 표현하면 다음과 같습니다.

```math
d_H(h_i,h_j)
=
\sum_{f\in\{S,T,O,C,W\}}
\mathbf 1\!\left[h_i^{(f)}\ne h_j^{(f)}\right]
```

**기호 설명**

- $h_i^{(f)}$: 하네스 $h_i$에서 요소 $f$에 선택한 수준입니다.
- $\mathbf 1[\cdot]$: 조건이 참이면 1, 거짓이면 0입니다.
- $d_H(h_i,h_j)$: 두 하네스에서 다른 요소의 개수입니다.

> **용어 — Hamming 거리:** 두 구성의 항목을 나란히 비교했을 때 서로 다른 항목 수입니다. 변화의 개수를 세지만, 각 변화가 실제로 얼마나 어려운지는 구분하지 않습니다.

과제 $x$에 대해 먼저 기준 하네스를 균등하게 뽑습니다.

$$
h_x\sim\text{Unif}(\mathcal H_{\text{tr}})
$$

여기서 $\text{Unif}$는 각 훈련 하네스를 같은 확률로 선택한다는 뜻입니다.

#### 원문 식 (6): 과제별 하네스 집합

```math
\mathcal H_x
=
\left\{
h_x,
h_x^{(1)},
\ldots,
h_x^{(K-1)}
\right\}
```

**기호 설명**

- $x$: 과제입니다.
- $K$: 해당 과제에 배정하는 하네스 수입니다.
- $h_x$: 무작위로 선택한 기준 하네스입니다.
- $h_x^{(1)},\ldots,h_x^{(K-1)}$: 기준과 Hamming 거리가 가장 가까운 나머지 하네스입니다.
- $\mathcal H_x$: 과제 $x$에 배정한 하네스 집합입니다.

주 설정은 $K=2$입니다. 서로 다른 과제는 훈련 공간의 여러 위치를 경험하고, 같은 과제에는 비교적 가까운 실행 구성의 변화를 제공합니다. **[pp. 5–6]**

**중요한 구현 사항:** 같은 과제의 $K$개 하네스는 **$K$개의 연속 훈련 단계에 걸쳐 사용**합니다. 서로 다른 하네스의 보상을 하나의 새로운 대조 손실로 묶는 방법은 제안하지 않습니다. **[p. 6, §3.3.2]**

**[검산]** 실제 Table 6의 훈련 집합에서 각 기준 하네스의 최근접 이웃까지 거리는 모두 **2**입니다. 예를 들어 기본 구성 `S0T0O0C0W0`의 최근접 구성 `S0T1O0C0W2`는 $T$와 $W$가 바뀝니다. 따라서 이 실험을 “한 번에 한 요소만 바꿔 같은 과제를 학습한다”고 설명하면 부정확합니다.

### 4.6 정책 최적화: 원문 식 (7)

```math
\mathcal L(\theta)
=
\frac{1}{N_{\mathcal B}}
\sum_{(x,h,\tau)\in\mathcal B}
\sum_{t=1}^{|\tau|}
M_t
\min\!\left(
\rho_t(\theta)A_t,\,
\text{clip}\!\left(
\rho_t(\theta),1-\epsilon,1+\epsilon
\right)A_t
\right)
```

보조 정의는 다음과 같습니다.

```math
N_{\mathcal B}
=
\sum_{(x,h,\tau)\in\mathcal B}
\sum_{t=1}^{|\tau|}
M_t
```

```math
\rho_t(\theta)
=
\frac{
\pi_\theta(\tau_t\mid x,h,\tau_{ < t})
}{
\pi_{\theta_{\text{old}}}(\tau_t\mid x,h,\tau_{ < t})
}
```

**기호 설명**

| 기호 | 의미 |
|---|---|
| $\theta$ | 갱신할 정책 모델의 파라미터 |
| $\theta_{\text{old}}$ | 비교 기준인 이전 정책의 파라미터 |
| $\pi_\theta$ | 현재 정책이 토큰을 생성할 확률 |
| $\mathcal B$ | 과제·하네스·실행 궤적으로 구성된 학습 배치 |
| $x,h$ | 과제와 배정된 하네스 |
| $\tau$ | 실행 궤적 |
| $\tau_t,\tau_{ < t}$ | 현재 토큰과 그 이전 이력 |
| $\mid \tau \mid$ | 궤적의 토큰 길이 |
| $M_t\in\{0,1\}$ | 유효한 정책 생성 토큰만 포함시키는 마스크 |
| $N_{\mathcal B}$ | 배치 안의 유효 정책 생성 토큰 총수 |
| $\rho_t(\theta)$ | 이전 정책 대비 현재 정책의 토큰 확률비 |
| $A_t$ | 해당 행동이 기준보다 얼마나 좋은지 나타내는 학습 신호 |
| $\epsilon$ | 확률비 변화의 제한 범위 |
| $\text{clip}$ | 값을 정해진 하한·상한 사이로 제한하는 함수 |

**[저자 보고]** Harness Scaling은 이 목적함수에 들어가는 **과제–하네스 표본의 구성**을 바꾸며, $A_t$의 계산은 PPO 또는 GRPO를 따릅니다. **[p. 6, 식 (7)]**

> **용어 — 궤적(trajectory), rollout:** 한 번의 과제 실행에서 생성된 행동·도구 호출·관측 등의 기록입니다.  
> **용어 — advantage:** 행동의 결과가 기준 기대값보다 얼마나 좋거나 나쁜지를 나타내는 값입니다.  
> **용어 — PPO:** 행동을 선택하는 정책과 기대 보상을 추정하는 가치 모델을 이용하고, 정책 변화 폭을 제한하여 학습하는 방법입니다.  
> **용어 — GRPO:** 같은 입력에 대해 생성한 여러 결과의 상대적인 보상을 이용하여 학습 신호를 계산하는 방법입니다. 별도의 가치 모델을 사용하는 PPO와 차이가 있습니다. GRPO의 원 출처는 *DeepSeekMath*입니다. [arxiv.org](https://arxiv.org/html/2402.03300v3?utm_source=chatgpt.com)

**수식과 실제 설정의 차이:** 식 (7)은 하나의 $\epsilon$을 쓰는 대칭 표기이지만, 실제 구현은 하한·상한 clipping 비율을 **0.20/0.28**로 설정합니다. 또한 KL·엔트로피 정규화는 사용하지 않습니다. **[pp. 17–18, Table 7]**

> **용어 — 정규화(regularization):** 학습이 특정 방향으로 지나치게 치우치지 않도록 추가하는 제약입니다. KL은 기준 정책과의 차이를, 엔트로피는 행동 분포의 다양성을 다루는 데 사용됩니다.

### 4.7 문맥 압축으로 궤적이 나뉠 때의 처리

**[저자 보고]** 문맥 압축은 하나의 rollout을 여러 훈련 구간으로 나눌 수 있습니다. 저자는 이때 다음을 유지합니다. **[p. 17, Appendix C.1]**

- 같은 rollout에서 나온 구간들은 같은 rollout 보상을 공유합니다.
- GRPO의 보상 평균·표준편차는 **원래 8개 rollout**을 기준으로 계산합니다.
- 분할 구간을 추가 rollout으로 세지 않습니다.
- 모든 유효 정책 생성 토큰에 대해 손실을 평균합니다.

**[해석]** 문맥 압축이 많다는 이유만으로 하나의 실행이 여러 독립 표본으로 중복 계산되는 문제를 피하는 설계입니다. 다만 실제 토큰 수와 실행 비용까지 모든 하네스에서 같게 만드는 것은 아닙니다.

### 5.2 실행 예산과 비교군

**[저자 보고]** 학습은 veRL과 비동기 vLLM rollout을 사용하며, 4B에는 NVIDIA H20 16개, 30B-A3B에는 32개를 사용합니다.  
최대 prompt/response 길이는 각각 **8K/32K**, **4K/60K**입니다. **[pp. 17–18, Table 7]**

**[검산]** 두 알고리즘 모두 단계당 128 rollout이므로, 300단계에서 **38,400 rollout 수준의 학습 노출**에 해당합니다.  
그러나 GRPO와 PPO가 한 단계에서 사용하는 서로 다른 과제 수는 다릅니다.

주요 비교군은 다음과 같습니다. **[pp. 6–8, 17–18]**

| 비교군 | 학습 방식 |
|---|---|
| Base | 추가 학습하지 않은 기반 모델 |
| Single-Harness RL | 고정된 하나의 하네스로 강화학습 |
| Black-Box SFT | OpenClaw에서 수집한 12,800개 궤적으로 3 epoch 학습 |
| Black-Box RL | OpenClaw에서 온라인 강화학습 |
| Harness Scaling | 구조화한 18개 하네스에서 학습 |

> **용어 — SFT, 지도 미세조정:** 주어진 예시 출력이나 행동 기록을 모방하도록 모델을 학습시키는 방법입니다.  
> **용어 — epoch:** 준비된 학습 데이터를 한 차례 순회하는 단위입니다.  
> **용어 — 온라인 강화학습:** 갱신되는 정책으로 새로운 실행 경험을 수집하며 학습하는 방식입니다.

Black-box 학습에는 **OpenClaw v2026.4.5**, 미학습 외부 평가에는 **Claude Code v2.1.205**를 사용합니다. 여기서 Claude Code는 **Qwen 정책을 실행하는 하네스**입니다. 이 결과를 Claude 기반 모델 자체의 성능으로 읽어서는 안 됩니다. **[pp. 17–18]**

### 6.3 어떤 설계가 효과에 기여했는가?

#### 구조화 선택과 가까운 구성 배정

다음은 4B에서의 결과이며, 각 셀은 **내부 평가 / Claude Code**입니다. **[p. 8, Table 3]**

| 설정 | ClawGym-Bench | PinchBench |
|---|---:|---:|
| 무작위 18개 구성 | 47.90 / 42.78 | 51.28 / 48.74 |
| 구조화된 18개 + 무작위 배정 | 50.46 / 43.17 | 53.20 / 50.23 |
| **제안법** | **52.78 / 45.37** | **56.24 / 51.47** |

**[해석]** 구성의 균형 있는 선택과 가까운 구성의 배정이 각각 결과에 기여한다는 대조 근거입니다. 다만 다른 무작위 집합이나 학습 초기값에서도 같은 차이가 유지되는지는 보고되지 않습니다.

#### 과제 반복의 효과를 분리한 실험

| 설정 | ClawGym-Bench | PinchBench |
|---|---:|---:|
| $K=1$ | 48.21 / 43.17 | 54.23 / 49.26 |
| Repeat-2: 같은 하네스로 같은 과제 반복 | 49.76 / 43.60 | 50.34 / 48.64 |

| $K=4$ | 49.56 / 41.99 | 53.90 / 50.04 |

**근거:** p. 19, Table 10.

**[해석]** $K=2$가 Repeat-2보다 모든 제시 조건에서 높으므로, 단순히 같은 문제를 두 번 보여주는 것만으로 개선을 설명하기 어렵습니다. 그러나 $K=2$가 다른 예산·데이터에서도 항상 최적이라는 결론은 얻을 수 없습니다.

### 6.4 더 강한 단일 하네스와 비교하면?

저자들은 기본 구성 외에 세 가지 단일 하네스를 추가로 시험했습니다. 4B·GRPO에서 그중 가장 높은 관찰 평균은 내부 평가 **35.79**, Claude Code **36.11**입니다. Scaling은 각각 **40.86**, **37.22**입니다. **[pp. 19–20, Table 11]**

**[검산]** 이 비교에서 차이는 **+5.07점, +1.11점**입니다.

**[해석]** 제안법이 기본 하네스의 약점만 이용한 것은 아니라는 근거가 됩니다. 동시에 외부 전이의 이득 크기는 어떤 단일 하네스를 기준으로 삼느냐에 따라 달라집니다.

### 6.5 일반화 성능에 대해 어디까지 확인했는가?

| 일반화의 범위 | 확인 상태 |
|---|---|
| 훈련과 분리된 평가 과제에서의 성능 | 저자가 과제 분리를 명시 |
| 이미 본 구성요소들의 새로운 조합 | 고정된 18개 조합에서 평가 |
| 조합 공간 밖의 외부 하네스 | Claude Code·OpenClaw에서 평가 |
| 훈련에서 보지 않은 개별 구성요소 수준 | 별도 평가 없음 |
| 새로운 실제 도구 기능·모델 계열·언어 | 별도 결과 없음 |
| 모든 미학습 조합의 평균·최악 성능 | 결과 없음 |

**근거:** pp. 4, 6, 18–19.

**[검산]** 미학습 구성은 $243-18=225$개이며, 내부 평가는 그중 18개, 즉 **8%**를 사용합니다. 평가 구성에서 훈련 집합까지의 최소 Hamming 거리는 1인 것이 8개, 2인 것이 10개입니다. **[Tables 6·8 기반 계산]**

**[해석]** 따라서 내부 결과의 가장 정확한 표현은 **학습한 구성요소를 새로운 방식으로 조합했을 때의 일반화**입니다. 더 강한 외삽을 시험하려면 새로운 요소 수준이나 새로운 도구 기능을 별도로 보류해야 합니다.

## 7. 중요한 그림의 선정과 해석

### 7.1 Figure 1 — 연구의 전체 구조, p. 3

**[해석]** 이 그림의 핵심은 실행 방식을 독립적인 학습 설계 변수로 다룬다는 점입니다. 신경망 내부 구조도보다 **실험 설계도**로 읽는 것이 적절합니다.

**주의:** 그림의 “거리 1인 연결”은 전체 조합 공간의 인접 관계입니다. 실제 선택된 훈련 18개 사이의 최근접 거리가 1이라는 뜻은 아닙니다.

### 7.2 Figure 3 — 구성 수보다 선택·배정 방식이 중요함, p. 9

**그림이 보여주는 것**

- 훈련 구성 수 1·3·18·243의 비교.
- 과제당 하네스 수 $K=1,2,4$의 비교.
- 내부 평가와 외부 Claude Code 평가의 변화.

**[저자 보고]** 시험한 고정 예산에서는 구조화된 18개 구성과 $K=2$가 가장 좋습니다. **[pp. 8–9]**

**[해석]** 하네스 수의 증가만으로 성능이 계속 높아지는 관계는 관찰되지 않습니다. 따라서 이 그림은 일반적인 규모–성능 법칙보다 **주어진 예산에서 다양성을 어떻게 배분할 것인가**에 관한 근거입니다.

**비교상 주의:** 243개 조건에는 내부 평가 구성도 학습에 포함됩니다. 저자도 이를 미학습 일반화 실험이 아닌 고정 예산 스트레스 테스트로 명시합니다. 또한 243개 조건의 정확한 수치를 그래프에서 소수점 단위로 역추정해 제시할 근거는 없습니다.

> **용어 — 스케일링 법칙:** 자원이나 규모의 증가와 성능 사이에 반복적으로 성립하는 정량 관계입니다. 이 논문은 하네스 다양성을 확장 축으로 연구하지만, 그러한 보편적 함수 관계를 추정하지는 않습니다.

**(a–b): 행동 평가**

지시 준수, 인터페이스 처리, 관측 읽기, 상태 추적, 절차 준수, 오류 복구를 평가합니다. 저자는 특히 상태 추적·절차 준수·오류 복구에서 큰 개선을 보고합니다. **[pp. 9–10]**

**(c–d): 두 하네스의 동일 과제 보상**

두 고정 하네스는 서로 네 요소에서 다릅니다. 점 하나는 같은 과제를 두 하네스에서 실행했을 때의 보상쌍입니다. 오른쪽 위로 이동하면 두 하네스 모두에서 보상이 높다는 뜻입니다. **[p. 10]**

**통계적 주의**

- 타원은 **$1.5\sigma$ 공분산 영역**이며 95% 신뢰구간이 아닙니다.
- 상관계수나 하네스 간 보상 차이의 통계 검정은 제시하지 않습니다.
- 행동 점수 개선이 성능 향상의 원인인지, 성공적인 실행에 함께 나타나는 특성인지는 분리하지 않습니다.

> **용어 — 공분산:** 두 값이 함께 움직이는 정도입니다. 공분산 타원은 관측값의 분포 모양을 나타내며, 평균 추정의 불확실성을 나타내는 신뢰구간과 다릅니다.

ClawGym 내부 평가에서 학습이 진행될수록 Scaling과 Single의 성능 차이가 벌어지는 모습을 보여줍니다.

## 8. 통계적 취약점·비교 불가능한 수치·미해결 질문

### 8.1 통계적으로 취약한 부분

> **용어 — 신뢰구간:** 반복 표본 추출을 고려할 때 추정값의 불확실성이 어느 정도인지를 나타내는 구간입니다.

### 8.2 직접 비교하면 안 되는 수치

### 8.3 저자가 직접 명시한 한계와 분석자가 도출한 한계

첨부 논문에는 **별도의 Limitations 절이 없습니다**. 따라서 위 비판을 모두 저자가 인정한 한계로 귀속하면 부정확합니다.

**저자가 직접 명시한 주의사항**

- 전체 243개 구성 실험은 내부 평가 구성을 학습에 포함합니다. **[pp. 8–9, 18]**
- SFT와 RL의 학습 노출 횟수가 비슷해도 고정 데이터 재사용과 온라인 수집은 다릅니다. **[p. 18]**
- 구성 수의 증가가 동일 예산에서 단조로운 개선으로 이어지지는 않습니다. **[pp. 8–9]**

**분석자가 도출한 제한**

- 일반화의 근거는 Qwen3 두 모델과 제한된 하네스·과제 범위에 묶여 있습니다.

### 8.4 문서가 답하지 않는 질문

1. **새로운 수준에도 일반화하는가?**

5. **평균보다 약한 경우도 개선되는가?**

## 11. 결론 및 시사점

### 저자들이 제시한 결론

**[저자 보고]** 하네스 다양성은 과제·환경 다양성에 추가되는 에이전트 강화학습의 확장 축이며, 그 효과는 다양성의 양뿐 아니라 **어떤 구성을 선택하고 학습에 어떻게 배치하는지**에 달려 있습니다. 구조화된 학습은 미학습 조합과 외부 하네스에서 개선을 보였습니다. **[p. 10, §6]**

논문은 구체적인 후속 연구 계획을 열거하지 않습니다. 따라서 앞 절의 실험 제안은 저자의 예정된 연구가 아니라 본 보고서의 검증 제안입니다.

### 학술적 시사점

**[해석]** 이 논문은 에이전트 일반화 연구에서 실행 구성을 명시적인 실험 변수로 취급할 수 있는 방법을 제공합니다. 특히 “다양한 하네스로 학습했다”라는 설명을 **구성 공간·조합 균형·배정 규칙**으로 분해하여 비교할 수 있게 한 점이 중요합니다.

직교설계의 수학적 보장은 훈련 구성의 균형에 한정됩니다. 정책 일반화의 보장은 실험으로 더 확인해야 하며, 이 둘을 구분하는 것이 후속 연구의 출발점입니다.

### 실용적 시사점과 일반화 향상 가능성

**[해석]** 같은 모델을 여러 실행 시스템에서 활용하려는 경우, 단일 하네스에서의 최고 성능뿐 아니라 **실행 구성이 바뀌었을 때의 성능 유지**를 학습 목표와 평가 항목에 포함할 근거가 됩니다. 외부 하네스 전이 결과와 기본 하네스 성능 보존 결과는 이 방향을 지지합니다. **[Tables 2·4·9]**

다만 현재 확인된 것은 제한된 모델·과제·하네스에서의 평균 개선입니다. **새로운 구성요소 수준, 다른 모델 계열, 실제 비용을 맞춘 조건, 최악 하네스 성능**까지 확인되어야 일반화 성능 향상의 범위를 더 넓게 주장할 수 있습니다.
