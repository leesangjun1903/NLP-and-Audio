# Diagnostic Analysis for Large Language Model Reasoning

**핵심 판단:** 이 논문은 **LLM이 생성한 추론 그래프를 어떻게 검증해야 하는지**를 제안한 진단 연구입니다.  
그래프를 이용한 계산이 특정 조건에서 신뢰도 평가를 개선한다는 결과는 있지만, **모델의 일반화 성능을 전반적으로 향상했다는 근거는 없습니다.**  
다른 모델·데이터셋에서는 비교 우위가 사라지거나 역전된다는 부록 결과까지 함께 읽어야 합니다.

## 1. Executive summary — 10문장

1. 이 연구는 LLM이 생성한 추론 그래프가 후속 계산에 사용할 만큼 신뢰할 수 있는지를, 그래프 구성과 활용을 분리한 2단계 진단 체계로 평가한다. **[pp.1–3]**
2. 그래프의 각 노드는 하위 질문·중간 답·근거 문단을 나타내며, 간선은 다음 단계를 풀기 위해 앞 단계의 답이 직접 필요하다는 의존관계를 나타낸다. **[p.3, §3.1]**
3. Stage 1은 정답 노드가 주어진 간선 생성, 정답 질문 분해가 주어진 답·근거·간선 생성, 전체 그래프 생성이라는 세 조건을 비교한다. **[p.3, Table 1]**
4. 실험은 MuSiQue 개발 세트 2,417개와 2WikiMultiHopQA의 층화 표본 498개를 사용하며, 그래프 연결 능력과 중간 답 생성 능력이 모델 크기에 따라 함께 향상하지 않음을 보여준다. **[pp.4–5, Table 2; p.22, Table 19]**
5. 그래프 신뢰성은 모델 계열, 출력 형식 예시, 추론 단계 수, 의존관계 구조에 민감하다. **[p.5, Table 3; p.18, Table 10]**
6. Stage 2에서 그래프를 프롬프트 정보로 제공하는 방식은 일반적인 CoT 기반 반복 샘플링보다 신뢰도 순위 판별력을 뚜렷하게 개선하지 못했다. **[p.7, Table 6; p.24, Table 26]**
7. 그래프를 확률 계산 구조로 사용하는 Sampled BN은 Llama-3.1-70B·MuSiQue 조건에서 AUROC를 0.766에서 0.795로 높였지만, 전체 답변 F1 차이는 통계적으로 유의하지 않았고 기본 설정의 확률 보정 지표는 악화됐다. **[p.7, Table 6; p.24, Table 26]**
8. 같은 446개 문제에서 정답 간선을 생성 간선으로 교체하면 Sampled BN의 F1이 0.657에서 0.599로 떨어져, 구조 오류가 후속 계산에 전달됨을 확인했다. **[p.8, Table 7]**
9. Sampled BN의 신뢰도 순위 개선은 Qwen3-32B와 2WikiMultiHopQA에서는 재현되지 않아, 보편적인 일반화 향상으로 해석할 수 없다. **[pp.25–26, Tables 29–30]**
10. 실용적인 기여는 그래프 오류의 단계별 진단이며, 빠르게 검증할 만한 접근은 출력 형식 예시 수정과 조건부 확률 평활화이고, 저자가 제시한 후속 방향은 그래프 기반·비그래프 기반 신뢰도 신호의 결합이다. **[p.9, §6; p.18, Table 10; p.24, Table 25]**

> **용어**
>
> - **다중 홉 추론·multi-hop reasoning:** 여러 사실이나 중간 답을 연결해 최종 답을 얻는 과정입니다.
> - **정답 그래프·gold graph:** 평가 기준으로 제공되는 참조 그래프입니다. 가능한 모든 올바른 풀이를 포괄한다는 뜻은 아닙니다.
> - **CoT·Chain of Thought:** 중간 풀이 과정을 텍스트로 생성하는 방식입니다.
> - **AUROC:** 정답에 오답보다 높은 신뢰도를 부여하는 능력을 측정하는 순위 지표입니다. 높을수록 좋지만, 신뢰도 0.8이 실제 정답률 80%를 의미하는지는 별개입니다.
> - **확률 보정·calibration:** 예측한 신뢰도와 실제 정답률이 얼마나 일치하는지를 뜻합니다.

## 2. 연구 배경·목표·필요성

### 2.1 해결하려는 문제

**[저자 보고]** 기존 연구는 추론을 사슬이나 그래프로 표현한 뒤, 이를 확률 추론·사실 검증·불확실성 추정에 활용합니다.  
그러나 그 계산의 바탕인 **그래프 자체가 올바르게 구성되었는지**는 충분히 분리해서 평가하지 않았다는 것이 출발점입니다. **[pp.1–2, §§1–2]**

논문이 구분하는 오류는 다음과 같습니다.

| 오류가 생기는 위치 | 문제 | 후속 계산에 미칠 수 있는 영향 |
|---|---|---|
| 질문 분해 | 필요한 중간 단계 누락 또는 불필요한 단계 추가 | 수행해야 할 추론 자체가 달라짐 |
| 의존관계 | 간선 누락·잘못된 연결·지름길 연결 | 잘못된 부모 정보를 조건으로 계산 |
| 중간 답 | 특정 단계의 답이 틀림 | 이후 단계에 잘못된 전제가 전달됨 |
| 근거 연결 | 답과 무관하거나 불충분한 문단을 근거로 지정 | 겉보기에는 근거가 있지만 실제 뒷받침은 부족 |

**근거:** pp.1–3, §3.1; p.19, Figure 2.

> **용어 — 지름길 간선·shortcut edge:** 앞 단계의 정보가 중간 단계를 통해서만 최종 답에 영향을 주는데도, 앞 단계와 최종 답을 직접 연결한 간선입니다.

### 2.2 연구 목적

연구 질문은 두 가지입니다.

1. **구성 능력:** LLM은 단계·중간 답·근거·의존관계가 올바른 추론 그래프를 만들 수 있는가?
2. **활용 효과:** 그래프가 주어졌을 때, 이를 프롬프트에 넣는 것과 실제 계산 구조로 사용하는 것 중 어느 방식이 신뢰도 평가에 도움이 되는가?

첫 질문은 Stage 1, 둘째 질문은 Stage 2가 담당합니다. **[p.3, §3.2]**

### 2.3 왜 필요한가

**[분석]** 최종 답이 맞았다는 사실만으로 중간 구조가 정확했다고 판단할 수 없습니다.  
반대로 그래프가 보기 좋게 연결되었다고 해서 각 노드의 답과 근거까지 옳은 것도 아닙니다.  
따라서 이 연구의 필요성은 **최종 정답률 하나로 합쳐졌던 실패 원인을 분리한다는 점**에 있습니다.

다만 진단 대상은 **모델이 외부로 출력한 그래프**입니다. 저자는 이것이 모델 내부의 숨겨진 추론 과정을 직접 관찰하거나 검증하는 연구는 아니라고 명시합니다. **[p.3, §3.1]**

> **용어**
>
> - **Edge F1:** 예측한 간선의 정확성과 정답 간선의 복원 정도를 함께 측정합니다.
> - **Ans F1:** 예측 답과 정답 사이의 단어·토큰 중첩을 측정합니다.
> - **평활화·smoothing:** 관측 횟수에 작은 값을 더해, 적은 표본에서 확률이 지나치게 0이나 1에 가까워지는 것을 완화합니다.
> - **$p$값:** 차이가 없다는 가정 아래 관측 결과가 얼마나 드문지를 나타내는 검정 값입니다. 효과의 크기나 재현 가능성 자체를 뜻하지 않습니다.

### 3.2 그래프 표현

논문의 그래프를 다음과 같이 표현할 수 있습니다.

$$
G=(V,E), \qquad v_i=(q_i,a_i,\mathcal E_i).
$$

- $G$: 추론 그래프.
- $V$: 추론 단계의 노드 집합.
- $E$: 방향이 있는 의존 간선 집합.
- $v_i$: $i$번째 노드.
- $q_i$: 해당 단계의 하위 질문.
- $a_i$: 해당 질문의 중간 답.
- $\mathcal E_i$: 답을 지지하는 문단 ID 집합입니다. 원문의 $E_i$와 간선 집합 $E$를 구별하기 위해 표기만 바꾸었습니다.

최종 노드 $v_{\text{final}}$은 원래 질문과 최종 답을 나타냅니다. 간선 $v_i\rightarrow v_j$는 **$j$를 답하는 데 $i$의 답이 직접 필요하다**는 뜻입니다. **[p.3, §3.1]**

예를 들어 $v_1\rightarrow v_2\rightarrow v_{\text{final}}$이라면, $v_1$이 최종 단계에 별도로 직접 필요하지 않는 한 $v_1\rightarrow v_{\text{final}}$을 추가하지 않습니다.

> **용어**
>
> - **DAG·유향 비순환 그래프:** 방향을 따라 이동해도 출발점으로 되돌아오는 순환이 없는 그래프입니다.
> - **위상 정렬:** 모든 선행 단계를 후속 단계보다 앞에 배치하는 순서입니다.
> - **주의:** 순환이 없다는 형식적 조건만으로 의존관계의 의미까지 올바르다고 보장되지는 않습니다.

### 3.3 Stage 1: 세 가지 통제 조건

| 설정 | 모델에 주는 정보 | 모델이 생성하는 정보 | 분리해서 평가하는 능력 |
|---|---|---|---|
| **A** | 원 질문, 후보 문단, 정답 하위 질문·답·근거 ID | 간선과 위상 순서 | 의존관계 연결 |
| **B** | 원 질문, 후보 문단, 정답 하위 질문 | 중간 답, 근거 ID, 간선 등 | 고정된 질문 분해 안에서 답과 근거 생성 |
| **C** | 원 질문과 후보 문단 | 질문 분해를 포함한 전체 그래프 | 전체 구성 능력 |

**근거:** p.3, Table 1; pp.11–12, Appendix A.1.

**[분석]** A→B→C는 주어지는 정답 정보가 줄어드는 설계입니다. 다만 평가 지표도 달라지므로, 서로 다른 열의 점수를 단순히 빼서 동일 척도상의 성능 하락으로 해석하면 안 됩니다.

#### ① 고정된 노드에서의 간선 평가

원문의 set F1 정의를 풀어 쓰면 다음과 같습니다.

```math
\text{Edge F1}
=
\frac{2|\widehat E\cap E|}{|\widehat E|+|E|},
\qquad
\text{Exact Edge}
=
\mathbf 1[\widehat E=E].
```

- $\widehat E$: 예측 간선 집합.
- $E$: 정답 간선 집합.
- $|\cdot|$: 집합의 원소 수.
- $\cap$: 두 집합에 공통으로 포함된 간선.
- $\mathbf 1[\cdot]$: 조건이 참이면 1, 거짓이면 0인 지시함수.

Edge F1은 일부 간선이 맞아도 점수를 주지만, Exact Edge는 전체 간선 집합이 정확히 같아야 1입니다. **[p.4, §4.1]**

#### ② 자유 생성된 노드의 의미 정렬

Setting C에서는 예측 하위 질문을 정답 하위 질문에 먼저 대응시킵니다. e5-large-v2 문장 임베딩과 코사인 유사도 임곗값 $\tau=0.85$를 사용합니다. 정의를 풀어 쓰면 다음과 같습니다.

```math
s(q_i,\widehat q_j)
=
\frac{\phi(q_i)^\top\phi(\widehat q_j)}
{\|\phi(q_i)\|\,\|\phi(\widehat q_j)\|},
\qquad s(q_i,\widehat q_j)\ge \tau.
```

- $\widehat q_j$: 예측한 하위 질문.
- $\phi(\cdot)$: 질문을 벡터로 바꾸는 임베딩 함수.
- $s$: 두 질문 벡터의 코사인 유사도.
- $\|\cdot\|$: 벡터의 크기.
- $\tau$: 대응을 허용하는 유사도 기준입니다.

**근거:** p.4, §4.1; p.17, Appendix B.

> **용어 — 임베딩·의미 정렬:** 문장을 숫자 벡터로 표현하고, 문구가 달라도 비슷한 질문을 묻는지 비교하는 절차입니다. 벡터 유사도가 높다고 논리적 동등성이 보장되는 것은 아닙니다.

원문은 임베딩과 임곗값을 명시하지만, 여러 노드가 같은 노드에 대응하려 할 때 충돌을 해소하는 세부 알고리즘은 명확히 설명하지 않습니다.

#### ③ 단계 복원: HPS와 Step F1

최종 노드를 제외한 정답·예측 중간 노드 집합을 각각 $V^{-}$, $\widehat V^{-}$, 정렬된 중간 단계 쌍을 $M$이라고 두면 다음과 같습니다.

$$
\text{HPS}=\frac{|M|}{|V^{-}|},
\qquad
P_{\text{step}}=\frac{|M|}{|\widehat V^{-}|}.
$$

```math
\text{Step F1}
=
\frac{2\,\text{HPS}\,P_{\text{step}}}
{\text{HPS}+P_{\text{step}}}.
```

- **HPS:** 정답 중간 단계 중 복원한 비율.
- $P_{\text{step}}$: 생성한 중간 단계 중 정답 단계와 대응한 비율.
- **Step F1:** 두 비율을 함께 고려한 점수.

**최종 노드를 제외한다는 조건은 부록에 명시되어 있습니다.** HPS는 답변 정답률이 아니라 **참조 단계의 복원 정도**입니다. **[p.17, Appendix B]**

#### ④ 의존관계 복원: Edge HPS

원문이 제시하는 식은 다음과 같습니다.

```math
\text{Edge HPS}
=
\frac{
|\{(u,v)\in E:\widehat m(u)\leadsto \widehat m(v)\}|
}{
|E|
}.
```

- $u,v$: 정답 간선의 시작·끝 노드.
- $\widehat m(u)$: 정답 노드 $u$에 대응하는 예측 노드.
- $\leadsto$: 예측 그래프 안에서 방향을 따라 도달할 수 있다는 뜻.
- $|E|$: 정답 간선 수입니다.

**직접 간선이 없어도 중간 노드를 거친 경로가 있으면 복원한 것으로 셉니다.** 또한 추가 간선에 대한 정밀도 벌점은 이 식에 없습니다. 따라서 A/B의 Edge F1과 C의 Edge HPS는 직접 비교할 수 없습니다. **[p.17, Appendix B]**

그 밖에 다음을 측정합니다.

$$
\Delta\text{Step}=|\widehat V|-|V|.
$$

$\widehat V$는 예측 노드 집합이며, 음수는 정답보다 적은 단계, 양수는 더 많은 단계를 뜻합니다. **[p.4, §4.1]**

근거의 Attr F1은 정렬된 비최종 노드를 대상으로, 문제 내부에서 근거 ID를 합산하여 계산한 뒤 문제별로 평균합니다. 따라서 **누락된 단계까지 포함한 전체 근거 완전성**과 동일한 지표는 아닙니다. **[pp.4, 17]**

### 3.4 Stage 2: 무엇을 비교했는가

| 방법 | 작동 방식 | 최종 신뢰도 |
|---|---|---|
| Direct-SC | 풀이 없이 최종 답을 반복 생성 | 최빈 답변군의 비율 |
| CoT-SC | 풀이와 최종 답을 반복 생성 | 최빈 답변군의 비율 |
| Decomp-SC | 정답 하위 질문을 프롬프트에 제공 | 최빈 답변군의 비율 |
| Graph-CoT-SC | 정답 하위 질문과 간선을 프롬프트에 제공 | 최빈 답변군의 비율 |
| CoT-Conf | 풀이·답·신뢰도를 한 번 생성 | 모델이 직접 말한 확률 |
| vPGM-Style | 근거 충분성·방해 문단 통제·추론 타당성에 관한 확률을 출력 | 선택 답변군 안의 최종 verbalized probability 평균 |
| **Sampled BN** | 노드별 조건부 답변 분포를 샘플링하고 그래프로 전파 | 최종 노드의 경험적 주변확률 |

**근거:** pp.6–7, §5.1; pp.13–15, Appendix A.2; pp.22–23, Appendix D.1–D.2.

> **용어**
>
> - **Self-consistency·SC:** 여러 번 생성한 답 중 가장 많이 반복되는 답을 선택하는 방식입니다.
> - **Verbalized confidence:** 모델에게 “정답일 확률을 숫자로 말하라”고 요청해서 얻은 값입니다.
> - **주변확률:** 중간 상태가 무엇이었는지 구분하지 않고, 가능한 중간 상태들의 확률을 합산해 얻는 최종 사건의 확률입니다.

정답 그래프를 사용하는 Stage 2에서도 노드의 답은 모델이 생성합니다. 정답 문자열과 정답 별칭은 답변 군집화에 넣지 않고 최종 EM/F1 채점에만 사용합니다. **[p.6, §5.1; pp.13–15, Appendix A.2]**

#### SC의 신뢰도

방법 설명을 수식으로 정리하면 다음과 같습니다.

```math
\text{conf}_{\text{SC}}
=
\frac{\max_c |C_c|}{K}.
```

- $C_c$: 정규화 후 같은 답 $c$로 묶인 생성 결과의 집합.
- $K$: 전체 생성 횟수이며 기본값은 10입니다.

이는 **동일한 답이 반복되는 빈도**입니다. 자주 반복되는 오답도 있을 수 있으므로 실제 정답 확률과 같다고 보장되지 않습니다.

#### vPGM-Style의 중요한 구현 차이

세 잠재변수는 근거 충분성 $Z_E$, 방해 문단 통제 $Z_D$, 추론 타당성 $Z_R$입니다. 그러나 이 논문의 구현은 세 변수의 확률을 수치적으로 결합해 최종 확률을 계산하지 않습니다. 선택된 답변군 안에서 모델이 말한 최종 확률을 평균합니다. **[p.23, Appendix D.2]**

```math
\text{conf}_{\text{vPGM}}(\widehat a)
=
\frac{1}{|C_{\widehat a}|}
\sum_{k\in C_{\widehat a}} r_k.
```

- $\widehat a$: 다수결로 선택된 답.
- $C_{\widehat a}$: 그 답에 속한 생성 결과들의 집합.
- $k$: 생성 결과의 인덱스.
- $r_k$: 해당 결과에서 모델이 말한 최종 답의 정답 확률입니다.

이 식은 원문 수식을 같은 의미로 간략화한 것입니다. **원래 BayesAgent 전체 구현과 동일한 방법으로 취급하면 안 됩니다.**

### 3.5 Sampled BN의 구조와 핵심 수식

**새로운 신경망을 학습하는 구조가 아닙니다.** 기존 LLM이 노드별 답을 생성하고, 외부 계산 절차가 이를 확률표로 바꾸어 결합합니다. **[pp.6–7, §5.1]**

| 구성 요소 | 역할 |
|---|---|
| 기존 LLM | 각 하위 질문의 답을 조건에 따라 반복 생성 |
| 문자열 정규화·군집화 | 같은 형태의 답을 동일한 상태로 묶음 |
| 조건부 확률표 | 부모 답 조합별 자식 답의 생성 빈도를 저장 |
| 그래프 기반 계산 | 노드별 분포를 결합해 최종 신뢰도를 계산 |
| 노드별 진단 | 불확실한 중간 단계와 오류 위치를 분석 |

#### ① 노드의 확률 상태

각 노드 $i$의 답을 확률변수 $A_i$로 취급합니다. 상태는 모델이 생성한 정규화 답변군입니다. 부모 답의 특정 조합에 대해 자식 답을 $K=10$회 생성하고 빈도를 계산합니다.

```math
\widehat p(a_i\mid a_{\text{pa}(i)})
=
\frac{c(a_i,a_{\text{pa}(i)})}{K}.
```

- $\text{pa}(i)$: 노드 $i$의 부모 노드 집합.
- $a_{\text{pa}(i)}$: 부모들이 취한 답 상태들의 조합.
- $a_i$: 자식 노드의 특정 답 상태.
- $c(a_i,a_{\text{pa}(i)})$: 해당 부모 조합에서 $a_i$가 생성된 횟수.
- $\widehat p$: 샘플로 추정한 경험적 확률입니다.

이 식은 본문의 빈도 추정 설명을 풀어 쓴 것입니다. 부모가 없는 루트 노드는 부모 조건 없이 분포를 추정합니다. **[p.6, §5.1]**

> **용어 — BN·Bayesian Network와 CPT:** BN은 변수 간 조건부 의존관계를 그래프로 나타내는 확률 모형이며, CPT는 부모 상태별 자식 상태의 확률을 저장하는 표입니다. 여기서는 현실 사건 대신 **LLM의 답변 상태**가 변수입니다.

#### ② 최종 답의 주변확률

본문의 핵심 수식은 다음과 같습니다.

```math
\widehat p(A_f=y)
=
\sum_{a_{V\setminus\{f\}}}
\prod_{v_i\in V}
\widehat p(a_i\mid a_{\text{pa}(i)}),
\qquad a_f=y.
```

- $f$: 최종 노드의 인덱스.
- $A_f$: 최종 답의 확률변수.
- $y$: 신뢰도를 계산하려는 후보 답.
- $a_{V\setminus\{f\}}$: 최종 노드를 제외한 노드들의 샘플 관찰 상태 조합.
- $\prod$: 한 상태 조합의 확률을 노드별 조건부 확률의 곱으로 계산.
- $\sum$: 최종 답이 $y$인 여러 중간 상태 조합을 합산합니다.

**원문 위치:** p.6, §5.1의 번호 없는 수식; 해설은 p.7까지 이어집니다.

**[저자 명시]** 이것은 모델이 샘플링한 답변군에 대한 경험적 BN 방식의 전파이며, **실제 정답에 대한 참된 사후확률을 추정한 것으로 보지 않습니다.** **[p.7]**

또한 비루트 노드의 프롬프트는 부모 답이 문단과 충돌해도 그 답을 주어진 전제로 취급하도록 지시합니다. 잘못된 부모 답이 후속 단계에 전달될 수 있는 구체적인 설계입니다. **[p.15, Appendix A.2]**

> **용어 — 조건부 분해 가정:** 부모 노드의 상태를 알면 나머지 선행 노드가 주는 추가 의존성을 생략할 수 있다고 가정하는 것입니다. 그래프가 실제 의존성을 빠뜨리면 이 계산이 부정확해질 수 있습니다.

#### ③ CPT 평활화: 원문의 Eq. (1)

비루트 노드의 희소한 표본 횟수에 작은 값을 더합니다.

```math
\widehat p_\alpha(a_i\mid a_{\text{pa}(i)})
=
\frac{
c(a_i,a_{\text{pa}(i)})+\alpha
}{
\sum_{a'\in S_i}c(a',a_{\text{pa}(i)})
+\alpha|S_i|
}.
```

- $S_i$: 노드 $i$의 여러 CPT 행에서 관찰한 답변군을 합친 상태 집합.
- $a'$: 분모에서 합산하는 답 상태.
- $\alpha$: 각 상태에 더하는 가상 관측량.
- $c$, $a_i$, $a_{\text{pa}(i)}$: 앞 식과 같은 의미입니다.
- $\alpha=0$이면 원래 Sampled BN입니다.

**원문 위치:** p.24, Appendix D.6, **Eq. (1)**.

### 3.6 정확도·순위 판별·확률 보정을 구분하는 평가

| 지표 | 측정 대상 | 좋은 방향 |
|---|---|---|
| EM | 정규화된 답이 정답과 정확히 같은가 | 높음 |
| 답변 F1 | 정답과 예측 답의 토큰 중첩 | 높음 |
| AUROC | 정답과 오답을 신뢰도 순으로 구별하는가 | 높음 |
| ECE | 신뢰도 구간별 평균 신뢰도와 실제 정확도가 일치하는가 | 낮음 |
| Brier | 신뢰도와 실제 정오답 사이의 제곱 오차 | 낮음 |

ECE와 Brier의 설명을 수식으로 풀면 다음과 같습니다.

```math
\text{ECE}
=
\sum_{b=1}^{B}
\frac{|I_b|}{N}
\left|\overline c_b-\overline z_b\right|,
\qquad
\text{Brier}
=
\frac{1}{N}\sum_{n=1}^{N}(c_n-z_n)^2.
```

- $N$: 평가 예측 수.
- $c_n$: 예측 $n$의 신뢰도.
- $z_n$: EM 기준 정답이면 1, 오답이면 0.
- $B$: 신뢰도 구간 수.
- $I_b$: 구간 $b$에 속한 예측들의 집합.
- $\overline c_b$, $\overline z_b$: 해당 구간의 평균 신뢰도와 정답률입니다.

**근거:** p.6, §5.1; p.17, Appendix B.

**[분석]** AUROC가 좋아져도 ECE는 나빠질 수 있습니다. 또한 Brier는 확률 예측의 종합 오차이므로 순수한 보정 정도만을 나타내는 지표로 좁혀 읽지 않는 편이 정확합니다.

**[분석]** 이 결과는 복잡한 모델 변경 전에 입력·출력 예시의 구조를 점검할 가치가 크다는 근거입니다. 다만 새로운 프롬프트 유형이나 도메인까지 잘 작동한다는 일반화 실험은 아닙니다.

### 4.4 생성 간선으로 교체하면 계산 방식이 더 크게 영향을 받는다

이 실험은 **정답 노드는 유지하고 간선만 바꿉니다.** 형식적으로 유효하지만 정답과 일치하지 않는 그래프 446개에서, 같은 문제의 정답 간선 조건과 생성 간선 조건을 비교합니다. **[p.8, §5.3, Table 7]**

| 방법 | F1: 정답→생성 간선 | AUROC: 정답→생성 간선 | ECE: 정답→생성 간선 |
|---|---:|---:|---:|
| Graph-CoT-SC | 0.622→0.620 | 0.714→0.689 | 0.324→0.313 |
| Sampled BN | **0.657→0.599** | 0.755→0.738 | 0.283→0.300 |

Sampled BN의 F1 하락은 5.8%포인트이며, $p=0.001$입니다. **[p.24, Table 26]**

**[분석]** 간선을 실제 조건부 계산에 사용하는 만큼 잘못된 간선의 영향도 직접 받습니다. 순환이 없고 모든 노드가 최종 노드에 도달하는 그래프라도, 의미적으로 잘못 연결되면 성능이 떨어질 수 있습니다.

**직접 비교 금지:** 전체 개발 세트의 AUROC 0.795와 이 부분집합의 0.738을 빼서 간선 오류의 효과라고 하면 안 됩니다. 올바른 비교는 **동일한 446개에서 0.755→0.738**입니다.

> **용어**
>
> - **위상·topology:** 노드의 내용보다 연결 모양을 뜻합니다.
> - **병합 노드·merge node:** 둘 이상의 선행 단계가 모여 다음 추론으로 이어지는 지점입니다.
> - **complex_tree:** 이 논문에서는 더 깊거나 크거나 여러 병합을 포함하는 그래프 범주입니다. 보편적인 난이도 순서를 뜻하지는 않습니다.

### 4.6 모델·데이터셋을 바꾸면 이득이 유지되는가?

이 부분이 일반화 성능을 판단하는 가장 중요한 근거입니다.

| 데이터·모델 | CoT-SC F1 | BN F1 | CoT-SC AUROC | BN AUROC |
|---|---:|---:|---:|---:|
| MuSiQue·Llama-70B | 0.680 | 0.691 | 0.766 | **0.795** |
| MuSiQue·Qwen3-32B | **0.654** | 0.638 | **0.776** | 0.756 |
| 2Wiki·Llama-70B | **0.894** | 0.875 | **0.715** | 0.706 |
| 2Wiki·Qwen3-32B | 0.883 | 0.883 | **0.723** | 0.611 |

**근거:** p.25, Table 29; p.26, Table 30.

**[저자 보고]** Qwen3-32B에서는 MuSiQue에서도 Sampled BN과 CoT-SC의 순위가 반대가 됩니다. 2Wiki에서는 두 모델 모두 Sampled BN의 AUROC가 CoT-SC보다 낮습니다.

**[분석]** 다음 세 주장을 구분해야 합니다.

- **평가 범위 확대:** 두 데이터셋과 여러 모델을 비교했다는 것은 맞습니다.
- **방법의 비교 우위가 전이됨:** 일관되게 성립하지 않습니다.
- **학습된 모델의 일반화 성능 향상:** 학습 전후 비교나 미관측 분포에 대한 향상 실험이 없으므로 입증되지 않았습니다.

여기서 일반화와 관련한 직접 기여는 **성능 향상 자체보다, 어떤 조건에서 이득이 사라지는지 드러낸 것**입니다.

### 4.7 노드별 진단과 평활화

#### 노드별 오류 진단

**[저자 보고]** 노드 신뢰도의 AUROC는 전체 평가 노드에서 0.744, 최종 답이 틀린 예제에서는 0.745입니다. 불확실한 노드를 먼저 확인하는 순위는 최초 오류 노드 탐색에서 Top-1 0.700, MRR 0.836을 얻었습니다. **[pp.7–8, §5.2]**

> **용어 — MRR:** 찾으려는 항목이 순위의 얼마나 앞에 놓이는지 평가하는 값입니다. 첫 번째면 1, 두 번째면 $1/2$, 세 번째면 $1/3$을 주고 평균합니다.

**[분석]** “어느 단계를 먼저 검토할지”에 유용한 신호입니다. 그러나 최초 오류 노드라는 운영적 정의를 사용했으며, 그 노드를 고치면 최종 답이 실제로 개선되는지까지 검증한 것은 아닙니다.

| $\alpha=0$ | 0.568 | 0.691 | 0.795 | 0.206 | 0.225 | 11.0% |

## 5. 통계적으로 취약한 부분과 직접 비교할 수 없는 수치

### 5.1 통계적 근거의 강도

논문은 주요 Stage 2 비교에 검정을 수행했습니다. 따라서 “통계 검증이 없다”고 평가하는 것은 부정확합니다. 다만 다음 한계가 남습니다.

| 표시 | 항목 | 해석에 미치는 영향 | 위치 |
|---|---|---|---|
| **통계 주의** | 주요 비교표에 신뢰구간이 없음 | 효과 크기의 불확실성 범위를 충분히 파악하기 어려움 | p.24, Table 26 |
| **통계 주의** | 다중비교 보정 여부가 명시되지 않음 | $p=0.017$을 다수 비교 전체에서 강한 확증으로 확대하면 안 됨 | p.24, §D.7 |
| **통계 주의** | 예제 bootstrap과 생성 반복 실험은 다름 | 여러 seed로 새로 생성했을 때의 변동성까지 평가했다고 볼 수 없음 | p.24, §D.7 |
| **통계 주의** | 유의하지 않은 차이 | 효과가 정확히 0이거나 두 방법이 동등하다는 증거는 아님 | p.24, Table 26 |
| **검증 범위 제한** | Stage 1·교차 모델·2Wiki 비교에는 같은 수준의 검정이 제시되지 않음 | 수치 차이와 확정적인 우열을 구분해야 함 | Tables 2, 19, 29–30 |

> **용어 — 다중비교:** 여러 차이를 동시에 검정하면 우연히 작은 $p$값이 나올 가능성이 커지는 문제입니다.

### 5.2 비교 조건과 평가 방식의 문제

| 표시 | 문제 | 정확한 읽기 |
|---|---|---|
| **계산량 불일치** | SC는 문제당 1요청·10개 생성, Llama Sampled BN은 평균 약 4.10요청·41개 생성 | 같은 $K=10$이어도 전체 계산량은 다름 |
| **정보량 불일치** | CoT-SC에는 정답 분해가 없고 일부 그래프 방법에는 있음 | 간선 효과만을 완전히 분리한 비교는 아님 |
| **표본 불일치** | Table 6은 전체 개발 세트, Table 7은 유효·비정확 그래프 446개 | 두 표의 점수를 직접 빼면 안 됨 |
| **지표 불일치** | A/B Edge F1과 C Edge HPS | 정밀도까지 고려한 간선 점수와 도달 가능성 기반 재현율은 다름 |
| **교란 요인** | hop과 topology가 완전히 교차되어 있지 않음 | 구조 차이와 추론 길이 차이가 섞일 수 있음 |
| **측정 민감성** | 노드 정렬 임베딩·임곗값에 따라 HPS가 크게 변함 | 절대 점수를 실제 논리적 정확도로 동일시하면 안 됨 |
| **평가 대상 차이** | 방법마다 최종 답 자체가 달라짐 | 같은 답변들에 신뢰도만 다르게 부여한 비교는 아님 |
| **기준선 변형** | vPGM-Style은 원 BayesAgent의 QA용 변형 | 결과를 원 방법 전체에 일반화할 수 없음 |

**근거:** p.9, §7; p.17, Appendix B; pp.19–23, Appendices C.4, C.6, D.1–D.2.

구체적으로 확인할 수 있는 사항은 다음과 같습니다.

**첫째, 계산량입니다.** Llama Sampled BN의 평균 API 요청 수는 2-hop에서 2.568, 3-hop에서 4.546, 4-hop에서 7.990입니다.  
요청 수는 토큰 수·시간·금액과도 같지 않으므로, “같은 비용에서 우월하다”는 결론은 지원되지 않습니다. **[p.22, Tables 21–23]**

**둘째, 노드 정렬 점수의 민감성입니다.** e5-large-v2에서 9개 모델의 평균 HPS는 $\tau=0.85$일 때 0.836이지만, $\tau=0.95$에서는 0.504입니다.  
모델 순위는 비교적 안정적이라는 결과가 있으나, 절대 수치는 평가 설정에 크게 의존합니다. **[p.19, Table 13]**

**셋째, 길이와 구조의 혼재입니다.** MuSiQue의 2-hop은 전부 simple_tree이며, 3-hop과 4-hop에서 비교 가능한 구조 범주가 다릅니다.  
같은 3-hop 내부에서는 Llama의 HPS가 0.715와 0.717로 비슷한데도 Edge HPS는 simple_tree 0.517에서 v_structure 0.370으로 낮아집니다.  
이는 단계 누락과 연결 실패를 구별할 필요를 보여줍니다. **[pp.19–21, Appendix C.6, Table 18]**

### 5.3 보고상 확인이 필요한 사항

- **평가 분모:** Tables 27–28에서 Sampled BN의 표본 수를 합하면 2,416개이지만, Table 24의 정오답 교차표는 2,417개입니다. 누락 사례 처리 방식은 문서만으로 확정하기 어렵습니다. 이 한 건이 결론을 뒤집는다는 뜻은 아닙니다. **[pp.24–25]**
- **생성 횟수:** 본문 일부 설명은 verbalized 방법이 한 번 생성하는 것처럼 읽히지만, Table 21과 Appendix D.2는 vPGM-Style이 10개 생성이고 CoT-Conf만 1개라고 명시합니다. 본 보고서는 상세 부록을 따랐습니다. **[pp.6, 22–23]**
- **형식 예시 수정 수치:** p.4 각주의 Qwen3-8B E3 값은 약 0.92로 서술되지만, Table 10의 정확한 Edge F1은 **0.909**입니다. **[pp.4, 18]**
- **과도한 일반화 서술:** “verbalized confidence가 항상 가장 약하다”는 표현은 표 전체와 맞지 않습니다. 2Wiki·Llama에서 CoT-Conf의 AUROC는 0.721로 CoT-SC의 0.715보다 수치상 높습니다. 통계적 우위가 입증됐다는 의미는 아닙니다. **[p.26, Table 30]**

## 6. 논문이 답하지 않는 질문

다음은 후속 연구에서 확인해야 하는 질문입니다.

1. **완전한 생성 그래프에서도 이득이 있는가?**  
   노드·답·근거·간선이 모두 생성되는 Setting C 결과를 후속 확률 계산에 연결한 전체 시스템 평가는 제시되지 않습니다. 생성 간선 실험은 정답 노드를 고정합니다. **[p.8, §5.3; p.9, §7]**

2. **같은 계산 예산에서도 유리한가?**  
   Sampled BN과 더 많은 샘플을 사용하는 CoT-SC를 동일 토큰·시간 예산에서 비교하지 않았습니다. **[p.9, §7; p.22, §D.1]**

3. **미관측 구조와 더 긴 추론에도 적용되는가?**  
   2–4-hop을 넘어서는 길이 일반화나, 특정 구조를 제외하고 설계한 뒤 그 구조에서 평가하는 실험은 없습니다.

4. **정답 표현의 차이가 신뢰도를 얼마나 왜곡하는가?**  
   답변군은 문자열 정규화에 기반합니다. 뜻은 같지만 표현이 다른 답들을 어떻게 처리하는 것이 가장 적절한지는 해결하지 않습니다. **[p.6, §5.1]**

5. **여러 올바른 그래프를 어떻게 평가할 것인가?**  
   참조 그래프와 다른 유효한 풀이를 충분히 인정하는 평가 기준이 필요합니다. **[p.9, §7]**

6. **불확실한 노드를 실제로 고치면 성능이 향상되는가?**  
   오류 위치를 찾는 결과는 있지만, 해당 노드의 재검증·수정 이후 최종 성능 개선은 보고하지 않습니다. **[pp.7–8, §5.2]**

7. **보정 설정을 다른 데이터로 옮길 수 있는가?**  
   평활화 강도나 답변 보류 임곗값이 새로운 분포에서도 유효한지 알 수 없습니다. **[pp.23–24, §§D.3, D.6]**

8. **재현에 필요한 세부 규칙은 무엇인가?**  
   Sampled BN의 최종 후보 선택 규칙, 노드 정렬의 다중 대응 처리, 일부 표본 제외 방식은 문서에서 충분히 명시되지 않습니다.

9. **진단 결과를 학습에 사용하면 일반화가 개선되는가?**  
   이 논문은 해당 진단을 이용한 추가 학습이나 학습 전후 일반화 비교를 수행하지 않았습니다.

> **용어 — 길이 일반화:** 짧은 추론에서 작동한 방법이 더 많은 단계를 요구하는 문제에서도 작동하는 성질입니다.

## 9. 결론·시사점·한계·우선 검증할 접근

### 9.1 저자가 제시한 결론과 후속 방향

**[저자 보고]** 강한 모델은 통제된 조건에서 신뢰할 만한 의존구조를 만들 수 있지만, 그 신뢰성은 자동으로 보장되지 않습니다. 모델 계열, 출력 형식 예시, 구조적 복잡도, 제공되는 정답 정보의 양에 따라 달라집니다. **[pp.8–9, §6]**

저자가 명시한 후속 방향은 **그래프 품질이 나빠져도 성능이 급격히 떨어지지 않도록 그래프 기반 신뢰도와 비그래프 기반 신뢰도를 결합하는 것**입니다. **[p.9, §6]**

학계에는 추론 구조를 독립적인 평가 대상으로 다루어야 한다는 시사점이 있습니다. 실용적으로는 신뢰도 수치 하나보다 **어느 단계·어느 근거·어느 연결을 다시 확인해야 하는지**를 제공하는 진단 기능이 더 직접적인 가치입니다.

### 9.2 저자가 명시한 한계

다음은 논문 §7에 제시된 한계입니다. **[p.9]**

1. 완성된 전체 그래프 추론 시스템보다 진단 연구에 가깝습니다.
2. 두 QA 데이터셋의 질문·근거·분해 관례에 의존합니다.
3. 한 질문에 여러 올바른 추론 그래프가 있을 수 있습니다.
4. 의미 정렬과 도달 가능성 기반 평가는 모든 대안 구조를 포괄하지 못합니다.
5. 방법별 호출 예산과 출력 형식이 다릅니다.
6. Sampled BN은 유한한 표본에서 관찰된 답 상태만 사용합니다.
7. 참조 그래프에 표현되지 않은 의존성이 있으면 조건부 분해가 잘못될 수 있습니다.

따라서 결과는 **배포 환경에서의 보편적 방법 순위보다 설계 선택을 진단하는 실험**으로 해석해야 한다는 것이 저자의 입장입니다.

### 9.4 일반화 성능 향상을 검증하려면 무엇이 추가되어야 하는가?

**[후속 연구 제안]** 일반화 향상을 주장하려면 다음 순서로 검증하는 것이 타당합니다.

**첫째, 설계에 사용하지 않은 평가 조건을 확보해야 합니다.** 프롬프트·평활화·선택 규칙을 정한 데이터와 최종 평가 데이터를 분리하고, 질문 유형이나 구조가 달라졌을 때의 성능을 확인해야 합니다.

**둘째, 같은 계산 예산에서 비교해야 합니다.** 그래프 계산에 사용한 추가 호출을 CoT-SC의 추가 샘플링에 배정했을 때와 비교해야 구조 자체의 이득을 판단할 수 있습니다.

**셋째, 정답 그래프 의존성을 줄인 조건을 평가해야 합니다.** 생성된 분해·답·근거·간선의 오류를 모두 포함한 상태에서 효과가 유지되는지 확인해야 합니다.

**넷째, 성공 지표를 분리해야 합니다.** 정답률, 신뢰도 순위, 확률 보정, 답변 보류 시 정확도, 비용을 따로 보고해야 합니다. 한 지표의 개선을 일반적인 추론 능력 향상으로 확대하면 안 됩니다.

**다섯째, 학습 효과는 별도로 검증해야 합니다.** 이 진단 결과를 추가 학습에 활용할 가능성은 있지만, 실제로 미관측 문제의 성능을 높이는지는 이 논문이 답하지 않습니다.

**최종 평가:** 이 논문에서 가장 확실한 성과는 **그래프 기반 추론의 신뢰성을 구성 요소별로 측정하고, 그 이득이 성립하는 조건과 실패하는 조건을 드러낸 것**입니다. 일반화 연구의 유용한 평가 도구가 될 수 있지만, **Sampled BN 자체를 일반화 성능 향상이 입증된 방법으로 제시하는 것은 원문을 넘어서는 해석**입니다.
