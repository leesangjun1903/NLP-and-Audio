## 1. Executive summary

Agora의 목적은 서로 다른 세션에서 활동하는 연구 에이전트들이 이전 실험·실패·가설을 잃어버리거나 같은 탐색을 반복하지 않도록 **지속적인 공동 연구 기록**을 제공하는 것입니다.  
연구 기여를 Git 커밋으로 저장하고, 기여 간 의존 관계를 DAG로 연결하며, 성능·검증 상태·덜 탐색된 방향을 함께 보여주는 것이 핵심 설계입니다〔pp. 1–5, Figure 1, Tables 1–2〕. 2609.18094v3 2609.18094v3

> **용어:** *커밋*은 특정 시점의 코드·기록을 식별하는 저장 단위이며, *DAG*는 “어떤 연구가 무엇을 토대로 발전했는가”를 순환 없이 연결한 방향 그래프입니다.

저자들은 중앙 작업 배정자 없이 13개 작업자가 약 12일 동안 협력하여, 학습 데이터와 대상 모델의 기울기 업데이트 없이 다른 사전학습 모델들의 지식을 1억 1,960만 매개변수의 혼합형 언어모델에 이전하는 실험을 보고했습니다.  
최선의 방법은 제공된 141개 모델 중 6개의 다음 토큰 예측 통계를 압축하여 입력·출력 가중치에 넣고 제한적인 문맥 처리 경로를 추가했으며, 개발 평가 점수를 무작위 초기화의 3.3923에서 1.899044 bpb로 낮췄습니다〔pp. 7–11, Algorithm 1, Tables 3–4〕. 2609.18094v3 2609.18094v3 2609.18094v3

> **용어:** *bpb, bits per byte*는 텍스트 1바이트를 예측하는 데 필요한 정보량으로, 이 평가에서는 낮을수록 좋습니다.

최종 방법의 계보에는 15개 계정이 작성한 145개 커밋이 포함되며, 전체 기록에는 95개 대상을 확인한 165건의 타 계정 재현 보고가 있고 보고된 실패는 없습니다.  
다만 전체 점수 개선의 약 98%는 처음 18개 평가 결과에서 발생했으므로, 이후의 방대한 활동량을 그만큼의 추가 발견 효과로 해석해서는 안 됩니다〔pp. 9–11, Figures 3–4〕. 2609.18094v3 2609.18094v3

이 연구는 **여러 에이전트가 공유 기록을 통해 연구를 이어 가는 과정과 실제 산출물**을 보여주지만, 동등한 계산 예산의 대조 실험이 없어 Agora 자체의 연구 효율 향상을 입증하지는 않습니다.  
또한 모든 구성요소를 같은 200개 개발용 텍스트에서 선택했기 때문에, 보고된 개선을 새로운 데이터·언어·아키텍처에 대한 일반화 성능 향상으로 간주할 근거는 아직 없습니다〔pp. 11–13〕. 2609.18094v3 2609.18094v3

## 2. 연구 목적과 필요성, 핵심 주장과 근거

### 2.1. 무엇을 해결하려는 연구인가?

**저자가 설정한 주된 문제는 새로운 언어모델 구조의 개발보다, 연구 에이전트들의 협업 기반을 만드는 것입니다.** 개별 에이전트가 좋은 실험을 수행하더라도 결과가 대화 기록이나 임시 작업 공간에만 남으면 다음 세션이 재사용하기 어렵습니다. 최고 점수만 보여주는 순위표 역시 실패한 접근, 아직 검증되지 않은 주장, 방치된 가능성을 전달하지 못합니다〔pp. 1–3, Table 1〕. 2609.18094v3 2609.18094v3

이를 위해 Agora는 **기억의 보존, 연구 진행 상황의 가시성, 근거의 추적, 탐색 다양성**을 하나의 기록 체계로 묶습니다. 가중치 이전 실험은 이 플랫폼을 실제 장기 연구에 적용한 사례이지, 플랫폼의 효과를 다른 방식과 엄밀히 비교한 벤치마크 실험은 아닙니다〔pp. 3, 6–7, 13〕. 2609.18094v3 2609.18094v3 2609.18094v3

## 3. 제안 방법 I: Agora의 구조와 핵심 수식

### 3.1. 구조: 대화 중심 협업이 아니라 공유 기록 중심 협업

**저자 보고.** 작업자는 공통 대화나 파일시스템을 공유하지 않고, API를 통해 기여를 게시하고 읽습니다. Git이 원본 연구 기록을 보존하고 SQLite가 검색용 인덱스를 제공하며, `agora analyze`가 최고 결과·미검증 결과·열린 가설·방치된 연구 방향을 보여줍니다〔pp. 4–6, Figure 1〕. 2609.18094v3 2609.18094v3 2609.18094v3

**제 해석.** 이는 **의사결정의 분산화**이지 **모든 기반 시설의 분산화**는 아닙니다. 다음 실험은 작업자가 선택하지만, 기록 접수·인증·추천 계산은 공통 서비스가 담당합니다. 따라서 “중앙 계획자가 없다”를 “중앙 서버도 없다”로 읽으면 잘못입니다.

### 3.2. 연구 기여 그래프 — 원문 식 (1)

프로젝트 상태는 다음과 같이 표현됩니다.

```math
G=(V,E),\qquad
(u,v)\in E
\iff
v\text{가 }u\text{를 토대로 작성됨}.
```

각 기여 노드는 다음 정보를 가집니다.

$$
v=(h,a,T,d,x,m,P,\tau).
$$

**기호 설명:** $V$는 기여 집합, $E$는 기여 간 연결 집합입니다. $h$는 정식 커밋 해시, $a$는 게시 계정, $T$는 태그 집합, $d$는 설명문, $x$는 구조화된 메타데이터, $m$은 선택적인 성능 지표, $P$는 부모 기여 집합, $\tau$는 서버 시각입니다. **여기서 $d$는 설명문이며, 뒤의 모델 수식에서 사용하는 은닉 차원 $d$와는 다른 문맥의 기호입니다.**〔pp. 3–4〕 2609.18094v3

> **용어:** *해시*는 특정 기록을 식별하는 값이고, *계보·provenance*는 결과가 어떤 코드와 선행 연구에서 나왔는지 추적하는 정보입니다.

### 3.3. 근거 점수 — 원문 식 (2)

$$
S(u)=
\sum_{v:(u,v)\in E}
\mathbf{1}[a(u)\neq a(v)]\,w(v).
$$

**기호 설명:** $S(u)$는 기여 $u$의 근거 점수, $a(u)$와 $a(v)$는 작성 계정, $\mathbf{1}[\cdot]$는 조건이 참이면 1인 지시함수, $w(v)$는 후속 기여 유형의 가중치입니다.

일반 결과·통찰·가설·보고 등은 직접 부모에 기본적으로 $+5$를 주고, 검증은 확인 $+20$, 부분 확인 $+10$, 실패 $-20$을 줍니다. 단순 동의와 진행 중 작업은 점수에 반영하지 않습니다. 같은 검증자가 같은 대상의 판정을 수정하면 이전 판정의 점수 효과는 최신 판정으로 교체되지만 기록 자체는 남습니다〔pp. 4–5, Table 2〕. 2609.18094v3 2609.18094v3

**제 해석.** 이 점수는 “다른 계정이 얼마나 활용·검증했는가”에 가깝습니다. 동일한 다른 계정이 여러 후속 기여를 작성할 수 있으므로, **점수가 높다고 독립적인 연구자 집단 다수가 지지했다고 단정할 수 없습니다.** 또한 $S(u)$는 아래의 예측 성능 지표 bpb와도 다른 지표입니다.

### 3.4. 탐색 다양성: 설명문 군집과 유효 군집 수

**저자 보고.** Agora는 Arctic-Embed 2.0으로 설명문을 1,024차원 벡터로 변환합니다. 기본적으로 코사인 유사도 0.90을 넘는 기여들을 단일 연결 방식으로 군집화하며, 분석 대상은 최근 5,000개 기여로 제한합니다. 이 임베딩 모델은 **실험 대상 언어모델이 아니라 연구 기록을 분류하는 별도 모델**입니다〔pp. 5–6〕. 2609.18094v3

> **용어:** *임베딩*은 텍스트의 의미를 숫자 벡터로 표현한 것입니다. *코사인 유사도*는 두 벡터의 방향이 얼마나 비슷한지 측정하며, *단일 연결 군집화*는 가까운 항목들이 연결되면 하나의 묶음으로 합치는 방식입니다.

군집 비율이 $p_1,\ldots,p_k$일 때 다음을 계산합니다.

```math
k_{\mathrm{eff}}
=
\exp\left(-\sum_{i=1}^{k}p_i\log p_i\right),
\qquad
\mathrm{Evenness}=\frac{k_{\mathrm{eff}}}{k}.
```

**기호 설명:** $k$는 군집 수, $p_i$는 군집 $i$의 기여 비율, $k_{\mathrm{eff}}$는 유효 군집 수입니다. 모두 균등하면 $k_{\mathrm{eff}}=k$, 하나에 몰리면 1에 가까워집니다〔p. 6〕. 2609.18094v3

> **용어:** 괄호 안은 *섀넌 엔트로피*로, 분포가 얼마나 한쪽에 몰리지 않았는지 나타냅니다. 여기서는 “실질적으로 몇 개의 방향이 활발하게 탐색되는가”를 읽기 쉽게 바꿔 표현합니다.

**제 해석.** 다만 이것은 **설명문의 다양성을 통한 연구 다양성의 대리 측정**입니다. 표현이 다르지만 같은 실험일 수 있고, 표현이 비슷하지만 중요한 방법론적 차이가 있을 수 있습니다.

### 3.5. 다양성을 고려한 추천 — 원문 식 (3)

```math
U(v)
=
100Q(v)
+
C\sqrt{\frac{\log(N+1)}{n(v)+1}}
+
\frac{100D}{\sqrt{1+\rho(v)}}.
```

**기호 설명:** $U(v)$는 추천 점수, $Q(v)$는 품질 백분위, $n(v)$는 후속 자손 기여 수, $N$은 프로젝트 전체의 후속 기여 수입니다. $\rho(v)$는 설명문 임베딩의 유사도 0.95 기준으로 가까운 다른 기여 수이고, $C$는 탐색 가중치, $D$는 다양성 가중치입니다.

첫 항은 좋은 결과를, 둘째 항은 아직 충분히 확장되지 않은 결과를, 셋째 항은 주변에 유사한 기여가 적은 결과를 선호합니다. 기본값은 $C=15$, $D=0.5$이며, 임베딩 확보 비율이 50% 미만이면 $D=0$으로 둡니다. 추천은 기존 최고 결과 개선, 유망하지만 덜 탐색된 방향, 새로운 방향의 세 슬롯으로 나뉩니다〔p. 6〕. 2609.18094v3

> **용어:** *탐색–활용 균형*은 새로운 가능성을 조사할지, 이미 좋은 방법을 개선할지의 균형입니다. *UCB*는 보통 불확실성이 큰 선택지에 탐색 보너스를 주는 방법을 뜻합니다.

**중요한 제한:** 이 논문의 식은 UCB에서 영감을 받은 **추천 휴리스틱**입니다. 해당 점수가 통계적으로 보정된 신뢰상한이라는 증명이나, 최적 탐색 성능을 보장하는 정리는 제시하지 않습니다. 2609.18094v3

## 4. 제안 방법 II: 에이전트들이 발견한 가중치 이전 방법

### 4.1. 실험 설정과 모델 구조

**저자 보고.** 대상은 14개 층에서 어텐션 블록과 단순화한 상태공간 블록을 교대로 사용하는 모델입니다. 은닉 차원은 672, 어텐션 헤드는 7개, 매개변수는 정확히 119,572,320개이며, 입력 임베딩과 출력 헤드의 가중치를 공유하지 않습니다〔p. 7, §4.1〕. 2609.18094v3

> **용어:** *어텐션*은 앞선 토큰들에서 필요한 정보를 모으는 연산입니다. *상태공간 모델·SSM*은 순서 정보를 내부 상태로 처리하는 계열이고, *입력 임베딩*은 토큰을 벡터로 바꾸며 *출력 헤드*는 벡터를 다음 토큰 점수로 바꿉니다.

여기서 **대상의 SSM을 원래 Mamba와 동일시하면 안 됩니다.** 대상은 Mamba의 투영·채널별 인과 합성곱·게이팅 구조 일부를 유지하지만, 선택적 스캔은 데이터 의존적인 스칼라 게이트로 대체한 단순화 모델입니다〔p. 7〕. 2609.18094v3

> **용어:** *선택적 스캔*은 입력에 따라 달라지는 상태 갱신을 시퀀스 전체에 적용하는 Mamba의 핵심 연산입니다. *게이트*는 신호를 얼마나 통과시킬지 조절하는 장치이고, *인과 합성곱*은 미래 토큰을 보지 않고 주변 과거 정보를 섞는 연산입니다.

제공된 모델 저장소에는 32개 아키텍처 계열의 모델 141개, 총 534GB가 있었습니다. 작업자는 A100을 사용하는 5개 계정과 H100을 사용하는 8개 계정으로 구성되었으며, 각각 80GB GPU 하나를 사용했습니다. 논문은 Claude Code/Claude Opus 4.7과 Codex/GPT-5.5 세션을 사용했다고 보고합니다〔p. 7, §4.2〕. 2609.18094v3 2609.18094v3

### 4.2. 평가 지표와 “학습 데이터 없음”의 정확한 의미

평가는 FineWeb-Edu 텍스트 200개를 GPT-2 토크나이저로 처리하고, 겹치지 않는 512토큰 구간에서 수행합니다. 난수 시드는 42이며, `transfer()` 내부에서 평가 데이터 로더를 호출하면 오류가 발생하도록 했습니다〔p. 7〕. 2609.18094v3

> **용어:** *토크나이저*는 문자열을 모델이 처리하는 토큰 단위로 나누는 규칙입니다. *난수 시드*는 무작위 연산을 같은 방식으로 반복하기 위한 초기값입니다.

원문의 평가 정의를 설명용으로 쓰면 다음과 같습니다.

```math
\mathrm{bpb}
=
\frac{
-\sum_{s}\sum_{t}
\log_2 p_{\theta}(x_{s,t}\mid x_{s, < t})
}{
\sum_s B_s
}.
```

**기호 설명:** $s$는 평가 구간, $t$는 예측 위치, $x_{s,t}$는 실제 토큰, $x_{s,<t}$는 해당 구간의 앞선 토큰들, $p_\theta$는 대상 모델의 예측 확률, $B_s$는 평가에 사용한 UTF-8 바이트 수입니다. 자연로그 손실을 사용한다면 비트로 변환할 때 $\ln 2$로 나누어야 합니다.

**해석상 핵심:** “학습 데이터 없음”은 **평가 데이터도 없었다**는 뜻이 아닙니다. 대상의 기울기 학습에 사용할 말뭉치는 없었지만, 작업자들은 개발 평가 점수를 보고 방법과 상수를 반복 선택했습니다. 따라서 **기울기 업데이트 없음과 평가 피드백을 이용한 최적화 없음은 다릅니다.**〔pp. 7–8, 11〕 2609.18094v3 2609.18094v3 2609.18094v3

### 4.3. Stage A: 예측 행동을 작은 행렬로 압축한다

#### A. 여섯 제공 모델을 짧은 문맥에서 조회

**저자 보고.** 최종 방법은 GPT-2 어휘를 공유하는 GPT-2 small·large와 Cerebras-GPT 계열을 합쳐 6개 모델을 사용합니다. 모든 어휘 토큰을 28개 문맥에서 조회하는데, 문맥은 무문맥, 문서 종료 토큰, 22개 단일 토큰, 4개 두 토큰 접두부로 구성됩니다. GPT-2 small의 결합 가중치는 0.725입니다〔p. 8〕. 2609.18094v3

아래는 **Algorithm 1을 수식으로 재정리한 것**입니다.

```math
\ell_{j,p}(v,t)
=
\text{clip}
\left(
[\log\text{softmax}D_j(p,v)]_t,
-25,25
\right).
```

```math
\widetilde{w}_{j,p}(v)
=
\text{clip}
\left(
\widehat{\mathrm{var}}_{j,p}(v)
\widehat{\mathrm{nat}}_{j,p}(v),
0.5,1.5
\right),
\qquad
w_{j,p}(v)
=
\frac{\widetilde{w}_{j,p}(v)}
{\sum_{p'\in P}\widetilde{w}_{j,p'}(v)}.
```

```math
M(v,t)
=
\sum_{j=1}^{6}\alpha_j
\sum_{p\in P}
w_{j,p}(v)\ell_{j,p}(v,t).
```

**기호 설명:** $D_j$는 제공 모델 $j$, $P$는 28개 문맥의 집합, $p$는 특정 문맥, $v$는 입력 토큰, $t$는 후보 다음 토큰입니다. $\ell$은 제한 범위로 잘라낸 로그 확률, $\alpha_j$는 제공 모델 결합 가중치, $w_{j,p}(v)$는 문맥 가중치, $M$은 결합된 다음 토큰 로그점수 행렬입니다. $\widehat{\mathrm{var}}$와 $\widehat{\mathrm{nat}}$는 분산·자연스러움 가중치에 해당하지만, **그 정확한 계산 정의는 Algorithm 1만으로 확정할 수 없습니다.**〔p. 9, Algorithm 1, lines 1–5〕 2609.18094v3

> **용어:** *log-softmax*는 모델의 원시 점수를 로그 확률로 바꾸는 연산이고, *clip*은 값이 지정 범위를 벗어나지 않게 자르는 연산입니다. *바이그램*은 현재 토큰을 바탕으로 다음 토큰의 분포를 표현하는 방식입니다.

**제 해석.** 여기서는 제공 모델의 내부 매개변수 좌표를 맞추는 대신, **공통 어휘에서 나타나는 예측 행동을 맞춥니다.** 내부 아키텍처 차이를 우회하는 장점이 있지만, 최종 방법이 공통 GPT-2 어휘에 의존한다는 제한도 함께 생깁니다.

#### B. 중심화와 저랭크 분해

어휘 크기를 $K=50{,}257$이라고 쓰겠습니다. 원문에서 어휘 크기와 우특이벡터에 사용한 기호의 혼동을 피하기 위해, 아래에서는 우특이벡터 행렬을 $R$로 표기합니다.

$$
u=\frac{1}{K}\sum_{v=1}^{K}M(v,\cdot),
\qquad
C=M-\mathbf{1}u^\top,
$$

$$
C\approx U\Sigma R^\top,
\qquad
r=d-1=671.
$$

**기호 설명:** $u$는 열 평균 벡터, $\mathbf{1}$은 모든 원소가 1인 벡터, $C$는 중심화된 행렬입니다. $U,R$은 좌·우 특이벡터 행렬, $\Sigma$는 특이값 대각행렬, $r$은 유지하는 랭크, $d=672$는 대상의 은닉 차원입니다.

저자들은 무작위 SVD에 추가 차원 32, 파워 반복 1회, 고정 시드를 사용합니다〔p. 9, Algorithm 1, lines 6–7〕. 2609.18094v3

> **용어:** *SVD·특이값 분해*는 큰 행렬을 중요한 패턴들의 조합으로 분해하는 방법입니다. *저랭크 근사*는 그중 제한된 수의 패턴만 남기는 압축이고, *파워 반복*은 주요 방향을 더 잘 찾아 근사의 정확도를 높이는 절차입니다.

#### C. 분해 결과를 대상의 입력·출력 가중치에 기록

$$
E_{:,0}=\mathbf{1},
\qquad
E_{:,1:}=\frac{U}{\sqrt d},
$$

$$
H_{:,0}=\frac{u}{\sqrt d\,T_u},
\qquad
H_{:,1:}=\frac{R\Sigma}{T_b}.
$$

**기호 설명:** $E,H\in\mathbb{R}^{K\times d}$는 입력 임베딩과 출력 헤드입니다. $T_u,T_b$는 평균 성분과 바이그램 성분의 크기를 조절하는 온도 매개변수이고, `:,0`은 첫 번째 열, `:,1:`은 나머지 열을 뜻합니다.

이후 모든 하위층 가중치를 0으로 만들고 정규화 관련 설정을 맞춥니다. 저자들이 직접 설명하듯, 이 시점의 대상은 **14층 신경망에 저장된 저랭크 바이그램 모델**입니다〔pp. 8–9〕. 2609.18094v3 2609.18094v3

> **용어:** *온도*는 여기서 확률 점수의 크기와 예측 분포의 날카로움을 조절하는 계수입니다.

> **용어:** *피드포워드·MLP*는 각 위치의 표현을 변환하는 신경망입니다. *SwiGLU*는 게이트를 사용하는 피드포워드 구조이고, *희소 편집*은 전체 가중치를 조정하지 않고 제한된 위치에만 값을 기록하는 것을 뜻합니다.

어텐션의 의미를 설명용으로 풀면, 인과 마스크하에서 질의·키 점수가 모두 같으므로 다음과 같습니다.

```math
W_q=W_k=0
\quad\Longrightarrow\quad
A_{ij}
=
\begin{cases}
1/i, & j\le i,\\
0, & j>i.
\end{cases}
```

**기호 설명:** $A_{ij}$는 위치 $i$가 위치 $j$에 주는 어텐션 가중치이고, 위치는 1부터 셉니다. 이는 원문의 “uniform causal attention”을 풀어 쓴 설명식이며, 별도의 학습된 선택적 어텐션을 뜻하지 않습니다. 2609.18094v3

**제 해석.** 이 방법의 대부분은 강력한 순차 추론기를 완성한 것이 아니라, **제공 모델의 국소 예측 통계를 압축한 기반에 제한적인 문맥 보정을 더한 것**입니다. 이 차이는 뒤에서 일반화 가능성을 평가할 때 중요합니다.

### 5.2. “격차의 62%를 해소했다”는 뜻

보고값을 사용한 계산은 다음과 같습니다.

```math
\mathrm{Gap\ closed}
=
\frac{b_{\mathrm{random}}-b_{\mathrm{best}}}
{b_{\mathrm{random}}-b_{\mathrm{reference}}}
=
\frac{3.3923-1.899044}{3.3923-1.0}
\approx 62.4\%.
```

**기호 설명:** $b_{\mathrm{random}}$은 무작위 초기화 점수, $b_{\mathrm{best}}$는 최선 이전 방법 점수, $b_{\mathrm{reference}}$는 학습된 GPT-2 124M의 약 1.0 bpb입니다. 기준값 자체가 근삿값이므로 저자들은 62%로 보고합니다〔pp. 7, 11〕. 2609.18094v3 2609.18094v3

이는 **정확도가 62% 상승했다거나 GPT-2 능력의 62%를 복구했다는 뜻이 아닙니다.** 더구나 기준 모델은 대상과 다른 아키텍처의 학습된 GPT-2이므로, 이 비율은 대상 아키텍처의 최적 성능까지 얼마나 접근했는지를 측정하지도 않습니다.

### 5.3. 초기 발견과 후기 미세 조정의 기여는 크게 다르다

**저자 보고:** 처음 18개 평가 결과가 전체 하락 폭의 약 98%를 만들었고, 나머지 1,106개 평가 결과가 추가로 약 0.03 bpb를 개선했습니다. 마지막 기록된 개선은 $9\times10^{-6}$ bpb였습니다〔pp. 9, 11〕. 2609.18094v3 2609.18094v3

**제 해석:** 가장 큰 기술적 전환은 초기에 일어난 **매개변수 복사에서 예측 통계 이전으로의 변경**입니다. 후기의 세밀한 상수 조정을 같은 규모의 발견으로 취급하면 연구 생산성을 과대평가할 수 있습니다.

또한 문맥을 48개로 늘리기, 특이값 구조를 평탄화하기, 다른 토크나이저를 사용하는 Pythia에서 사전분포를 구성하기 등은 개선되지 않았습니다. 이것은 **제공 모델이나 문맥을 더 많이 쓰면 자동으로 더 일반적인 방법이 된다는 해석을 지지하지 않습니다**〔pp. 9–10〕. 2609.18094v3 2609.18094v3

## 7. 가장 중요한 그림 5개 해석

### Figure 1 — 공유 연구 기억의 작동 구조〔p. 4〕

**저자 보고:** 참여자 → 인터페이스 → 인증·검증 → Git·SQLite → 분석·검색·추천 → 참여자로 돌아오는 구조입니다. Git은 원본 기여를, SQLite는 파생 검색 정보를 담당합니다. 2609.18094v3

**제 해석:** 이 그림의 핵심은 “에이전트끼리 더 많이 대화한다”가 아니라 **같은 검증 가능한 외부 기록을 읽고 행동한다**는 점입니다. 다른 세션·도구를 쓰더라도 동일한 커밋을 가져와 재실행할 수 있다는 설계가 협업의 공통 기반입니다.

**주의:** Git의 변경 추적은 코드의 출처를 보존하지만, 실험 설계의 적절성이나 주장 자체의 진실성을 보장하지 않습니다. 또한 프로젝트·인증 관련 상태까지 모두 Git에서 복원되는 것은 아니며, 저자들은 별도 데이터베이스 백업이 필요한 부분을 명시합니다〔p. 6〕. 2609.18094v3

### Figure 2 — 일별 연구 활동과 기록 방식의 변화〔p. 8〕

**저자 보고:** 13개 작업자가 가동된 뒤 대략 하루 170개 기여를 유지했으며, 5월 2일 기능 배포 뒤 `explore_novel` 및 명시적 부정 결과 태그가 나타납니다. 전체 기록에는 1,124개 평가 결과, 284개 통찰, 203개 가설, 165개 검증, 1개 보고가 있으며 태그는 중복될 수 있습니다. 2609.18094v3

**제 해석:** 장기간 연구 기록을 생성·공유할 수 있었다는 운영상의 증거입니다. 가설·통찰·검증을 별도 기여로 취급한다는 점은 최고 점수만 기록하는 시스템과 다릅니다.

**주의:** 활동량은 성과량이 아닙니다. 또한 배포 뒤 특정 태그가 늘어난 현상에는 실제 탐색 변화뿐 아니라 **기록·분류 방식의 변화**가 포함될 수 있으므로, 태그가 없던 시기에 실패 실험이 없었다고 해석해서는 안 됩니다.

### Figure 3 — 개발 점수의 시간적 변화〔p. 10〕

**저자 보고:** 첫날의 예측 통계 기반 초기화가 거의 모든 큰 개선을 만들고, 이후 제공 모델 결합·SVD·문맥 경로 편집이 작은 개선을 누적합니다. 그림은 5월 9일까지 표시되지만 본문의 주요 통계는 5월 8일까지의 첫 1,703개 기여를 사용합니다. 2609.18094v3

**제 해석:** 눈여겨볼 것은 연속적인 최고점 경신보다 **초기 접근법 변경의 효과가 압도적으로 크다**는 점입니다. 후기의 완만한 하락은 같은 개발 평가에 대한 미세 조정으로 보는 것이 적절합니다.

**주의:** 로그축과 확대된 작은 차이를 시각적으로만 비교하면 개선 폭을 과대평가하기 쉽습니다. 또한 그림의 종료 이후 최고 표시를 본문 주결과인 **1.899044 bpb**와 혼동하면 안 됩니다.

### Figure 4 — 연구 계보의 집중 구조〔p. 12〕

**저자 보고:** 최고 결과로 이어지는 긴 중심 계보와 짧게 끝난 주변 가지가 나타납니다. 본문 분석 구간에는 1,703개 노드, 1,894개 간선, 149개 다중 부모 노드가 있으며, 98.9%의 노드가 하나의 연결 성분에 속합니다. 2609.18094v3

**제 해석:** 이 그림은 공동 재사용이 실제로 발생했음을 보여주는 동시에, **많은 작업자가 있어도 연구가 하나의 계보에 집중될 수 있음**을 드러냅니다. 공유 기억만으로 폭넓은 탐색이 저절로 유지되는 것은 아닙니다.

**주의:** 실제 그림에는 분석 종료 뒤의 123개 기여가 추가되어 있고, 강조된 계보도 이후의 최고 결과에 대응합니다. 힘 기반 배치의 화면상 거리를 의미적 거리나 시간적 거리로 읽어서도 안 됩니다. 2609.18094v3

> **용어:** *힘 기반 배치*는 연결된 노드들이 시각적으로 모이도록 그래프를 배치하는 방식으로, 좌표 자체가 실험 변수는 아닙니다.

### Figure 5 — 동일 결과의 근접 게시와 최고 부모로의 집중〔p. 13〕

**저자 보고:** 왼쪽은 서로 다른 계정이 동일한 점수를 게시한 696개 쌍의 시간 간격 누적분포이며, 63%가 1시간 이내, 80%가 6시간 이내입니다. 오른쪽은 그림 축을 기준으로 보면, **6시간 안에 동일한 최고 부모를 사용한 서로 다른 작업자 수의 분포**입니다. 2609.18094v3 2609.18094v3

**제 해석:** 공동 기록이 빠른 재사용을 촉진하는 동시에 동일 방향의 중복 탐색도 허용한다는 양면성이 나타납니다.

**주의:** 왼쪽의 제목이 “Independent discovery”라고 되어 있어도 점수 일치만으로 발견의 독립성은 증명되지 않습니다. 오른쪽 역시 엄밀히는 개별 작업의 채택 지연시간 그래프가 아니라, 고정된 6시간 창 안에서의 **부모 선택 집중도**를 보여줍니다.

### 8.2. 지식 이전과 모델 일반화 연구와의 비교

방법 차이를 간단히 표현하면, Model soups는 호환되는 매개변수 공간에서 다음과 같은 연산을 사용합니다.

```math
\theta_{\mathrm{soup}}
=
\sum_{j=1}^{J}\lambda_j\theta_j,
\qquad
\sum_{j=1}^{J}\lambda_j=1.
```

**기호 설명:** $\theta_j$는 같은 구조의 모델 매개변수, $\lambda_j$는 평균 가중치, $J$는 결합 모델 수입니다. 반면 Agora 사례의 Stage A는 $\theta_j$를 직접 평균하지 않고 앞서 설명한 예측 로그점수 행렬 $M$을 결합·분해합니다. [arXiv](https://arxiv.org/abs/2203.05482) 2609.18094v3

**제 해석:** 두 접근의 차이는 **매개변수 공간에서의 결합**과 **행동 공간에서의 이전**입니다. 후자는 아키텍처 불일치를 우회할 수 있지만, 실제로 조회한 행동 범위 밖의 능력까지 전달한다는 보장은 없습니다.

### 8.3. 평가 범위의 비교: MLE-bench가 주는 기준

MLE-bench는 75개 기계학습 엔지니어링 대회를 이용해 에이전트의 데이터 처리·모델 학습·실험 능력을 평가하고, 자원 확대와 사전학습 데이터 오염 문제도 조사합니다. Agora의 후속 연구에는 이와 같은 **다수 과제에서의 평가 설계**가 필요하지만, 학습을 허용하는 MLE-bench 점수와 현재의 무기울기 이전 점수를 한 성능표에 섞어서는 안 됩니다. [arXiv](https://arxiv.org/abs/2410.07095)

> **용어:** *데이터 오염*은 평가 문제나 정답에 관한 정보가 사전학습·개발 과정에 이미 포함되어, 실제 일반화 능력보다 평가가 유리해지는 문제입니다.

### 9.2. 일반화 향상을 기대할 수 있는 이유 — 제 해석

**첫째, 행동 기반 이전은 내부 구조의 차이를 우회할 가능성이 있습니다.** 공통 출력 공간에서 예측을 수집한다면 제공 모델과 대상의 층 구조를 일대일로 대응시키지 않아도 됩니다. 다만 이번 결과는 공통 GPT-2 어휘를 가진 6개 모델에 한정되므로, 이를 모든 토크나이저·아키텍처에 적용 가능한 방법이라고 주장할 수는 없습니다. 2609.18094v3

**둘째, 저랭크 압축이 일부 불필요한 변동을 줄이는 역할을 할 가능성은 있습니다.** 그러나 이것은 이 논문에서 검증한 일반화 설명이 아닙니다. 행렬의 재구성 오차를 줄이는 것과 새로운 문서의 다음 토큰 손실을 줄이는 것은 서로 다른 목표이기 때문입니다.

**셋째, 공유된 부정 결과와 재현 기록이 더 견고한 방법의 선택을 도울 수 있습니다.** 그러나 기록이 모두 같은 개발 평가를 중심으로 생성된다면, 공동 연구가 오히려 **같은 평가에 대한 공동 과적합**을 빠르게 진행할 수도 있습니다. 현재 결과만으로 어느 효과가 우세한지는 알 수 없습니다. 2609.18094v3 2609.18094v3

> **용어:** *과적합*은 개발 과정에서 본 데이터에 지나치게 맞춰져, 새로운 데이터에서는 개선이 유지되지 않는 현상입니다.

### 9.3. 일반화에 불리할 수 있는 구조적 요소

**문맥 범위의 제한:** Stage A는 짧은 접두부에서 모은 통계를 현재 토큰별로 평균합니다. Stage B의 균등 평균 어텐션 자체는 세밀한 순서를 구분하지 않으며, 짧은 합성곱 경로가 이를 일부 보완합니다. 이 구성만으로 장거리 의존성·지시 따르기·추론 능력이 이전되었다고 말할 수 없습니다〔pp. 8–9〕. 2609.18094v3

**제공 모델의 제한:** 141개가 제공되었다는 사실과 141개의 지식을 효과적으로 통합했다는 주장은 다릅니다. 최종 방법은 6개 모델을 사용하고 GPT-2 small에 0.725의 큰 가중치를 둡니다. 제공 모델 수보다 **서로 다른 오류와 능력을 얼마나 보완하는지**를 확인해야 합니다. 2609.18094v3

**고정 개발 평가에 대한 반복 선택:** 작은 개선일수록 다른 문서에서도 유지되는지 확인할 필요가 큽니다. 하드웨어 간 실행 재현은 이 질문에 답하지 못합니다〔p. 11〕. 2609.18094v3

### 9.4. 우선순위가 높은 후속 실험 — 제안

**① 모델·방법을 먼저 고정하고, 숨겨 둔 테스트에서 평가해야 합니다.** 개발용 문서와 별도로 동일 분야의 새 문서, 다른 분야, 여러 언어, 긴 문맥을 준비하고, 작업자에게 테스트 점수를 되돌려주지 않는 방식이 필요합니다. 대상 구조를 고정한 비교에서는 무작위 초기화, 단독 저랭크 바이그램, Stage A, Stage A+B를 함께 평가하는 것이 좋습니다.

**② Agora의 효과는 같은 총 계산 예산의 여러 실행으로 비교해야 합니다.** 예를 들어 단일 에이전트, 공유 없는 13개 작업자, 단순 공유 로그, 다양성 추천 없는 Git 연구 그래프, 전체 Agora를 비교할 수 있습니다. 작업자 수나 경과 시간만 맞추지 말고 GPU 사용량·LLM 토큰·제공 모델 조회 비용도 함께 맞춰야 합니다. 이는 저자들이 요구한 대조 비교를 구체화한 제안입니다. 2609.18094v3 2609.18094v3

**③ 아키텍처·어휘 의존성을 분리해야 합니다.** 은닉 차원과 층수를 바꾸거나 Transformer 전용·SSM 전용 대상으로 확장하고, 토크나이저가 다른 제공 모델은 별도 조건으로 평가해야 합니다. 바이트·문자 수준의 확률 정렬은 탐구할 만하지만, 이는 본 논문이 구현·검증한 기능이 아니라 새로운 방법 제안입니다.

**④ 평가의 통계 단위를 올바르게 정해야 합니다.** 문서 일반화의 불확실성은 문서 단위 재표집으로, 연구 효율의 불확실성은 독립적인 전체 연구 실행 단위로 추정해야 합니다. 서로 연결된 1,703개 커밋을 1,703번의 독립 실험처럼 다루면 안 됩니다.

> **용어:** *재표집·bootstrap*은 관측 자료를 여러 번 다시 뽑아 지표의 변동 범위를 추정하는 방법입니다. 여기서는 같은 문서의 토큰이나 같은 연구 계보의 커밋을 독립 표본처럼 취급하지 않는 것이 중요합니다.

**⑤ 이후 학습에 유리한 초기화인지도 별도로 시험할 가치가 있습니다.** 무작위 초기화와 Agora 초기화를 동일한 소량 데이터·학습 예산으로 미세조정하여 새 데이터 성능과 필요한 학습량을 비교할 수 있습니다. 다만 이는 **“대상에 기울기 업데이트 금지”라는 원래 조건을 변경한 확장 연구**이므로, 현재의 무학습 결과와 별도 실험군으로 보고해야 합니다.

## 11. 결론: 저자의 시사점과 추가 연구 방향

### 저자들이 제시한 시사점과 후속 과제

저자들의 핵심 시사점은 연구 에이전트의 성과를 개별 세션의 산출물로 끝내지 않고, **다른 참여자가 재사용·반박·확장할 수 있는 공동 기록으로 누적해야 한다**는 것입니다. 실험은 이 방식으로 약 12일간 공동 연구가 지속되고, 실제 초기화 방법이 발전하며, 재현 기록이 축적될 수 있음을 보여줍니다〔pp. 12–13〕. 2609.18094v3

명시된 핵심 후속 과제는 **여러 과제에서 계산 조건을 맞춘 비교를 통해 발견 효율의 효과를 측정하는 것**입니다. 첨부 v3는 그 실험의 구체적인 일정이나 완성된 계획을 제시하지 않으며, 부록 A–B는 이를 뒷받침할 재현 기록의 요건을 제시합니다〔pp. 13, 17〕. 2609.18094v3 2609.18094v3

### 제 종합 평가와 연구에 미칠 영향

**이 논문의 가장 설득력 있는 기여는 “집단 연구의 과정 자체를 검사 가능한 산출물로 만든다”는 점입니다.** 최종 점수뿐 아니라 실패, 분기, 재사용, 검증을 기록하면 후속 연구자는 결과가 나온 경로와 놓친 대안을 조사할 수 있습니다.

다만 이 기반이 **모델의 일반화 성능을 향상시키려면**, 추천과 검증의 기준도 같은 개발 점수의 반복 개선에서 벗어나야 합니다. 다른 데이터·다른 하드웨어·다른 아키텍처에서 살아남는 결과를 우선 확인하고, 그러한 외부 검증이 연구 기록과 추천에 반영되도록 하는 방향이 중요합니다.

따라서 가장 우선할 후속 연구는 **“더 많은 커밋을 만드는 Agora”가 아니라, “동일한 계산 비용으로 보지 않은 조건에서 더 자주 재현되는 개선을 만드는 Agora”를 검증하는 것**입니다. 현재 논문은 그 가능성을 연구할 수 있는 구체적인 기반과 사례를 제공하지만, 일반화 향상이나 발견 효율 향상을 이미 확립한 결과로 읽어서는 안 됩니다.
