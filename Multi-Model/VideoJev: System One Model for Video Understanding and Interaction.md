# VideoJev: System One Model for Video Understanding and Interaction

**핵심 판단:** VideoJev는 비디오의 시간 구간과 객관식 답변을 하나의 후보 점수화 구조로 처리하고, 같은 영상에 대한 반복 질문의 계산을 공유하는 방법입니다.  
논문은 평가한 두 과제에서 성능과 효율의 개선을 보여주지만, 새로운 과제·분포 밖 환경으로의 일반화와 실제 스트리밍 에이전트 성능은 후속 검증 대상으로 남겨 두고 있습니다. **[원문 pp.2–12, Tables 1–8]**

---

## 1. Executive summary — 10문장

1. VideoJev는 비디오에서 사건이 발생한 시간 구간을 찾는 **시간 위치 추정**과 **객관식 비디오 질의응답**을 공통 후보 점수화 문제로 통합한 모델이다. **[pp.2–5, Fig.2]**
2. 사전학습 멀티모달 대형 언어 모델의 마지막 MLP와 언어 생성 출력 헤드를 조정하여, 질문과 후보의 표현 사이 유사도로 직접 결정을 내린다. **[p.3, 식 (1)]**
3. 같은 영상에 반복적으로 질문할 때는 영상 문맥을 재사용하는 **Cached inference**와 여러 질문을 한 번에 처리하는 **Joint inference**를 제공한다. **[pp.3–4, Fig.2]**
4. 세 시간 위치 추정 벤치마크의 평균 mIoU는 4B와 35B-A3B 모델에서 각각 **65.3과 67.7**이며, 기반 모델보다 **6.7포인트와 10.8포인트** 높다. **[pp.6–7, Table 1]**
5. 네 객관식 QA 벤치마크의 평균 점수는 각각 **74.3과 79.5**로, 기반 모델의 Instruct 모드보다 **8.0포인트와 5.7포인트** 높다. **[pp.7–8, Table 2]**
6. Thinking 모드와 비교하면 평균 QA 점수 차이는 각각 **−0.6포인트와 +0.7포인트**이며, 측정한 모델 순전파 시간은 약 **129배와 100배** 빠르다. **[pp.7–8, Table 2]**
7. 동일 데이터로 학습한 생성형 대조군보다 단일 단계 VideoJev-4B가 시간 위치 추정 평균에서 **1.3포인트**, QA 평균에서 **1.9포인트** 높지만, 이 비교는 점수화 헤드 하나만의 효과를 분리한 실험은 아니다. **[pp.7–8, Table 3; p.19, A.3]**
8. 구성 요소 실험에서 가장 큰 시간 위치 추정 개선은 **Soft IoU 손실 추가에 따른 4.6포인트 상승**이며, 두 과제의 공동학습도 각 과제의 평균 점수를 높인다. **[p.9, Tables 5–6]**
9. 모델의 답변 확신도는 정확도와 대체로 함께 증가하지만 과신 경향이 남아 있으며, 평균 보정 오차는 4B에서 **8.65퍼센트포인트**, 35B-A3B에서 **8.13퍼센트포인트**이다. **[p.11, Fig.4]**
10. 따라서 이 연구는 빠르고 재사용 가능한 구조화 시각 판단의 유용성을 뒷받침하지만, 범용 과제 전이·정답 없는 상황의 판단·실제 스트리밍 상호작용까지 입증하지는 않는다. **[p.12, §5; p.4, 식 (4)]**

> **용어 설명**
>
> - **시간 위치 추정, temporal grounding:** “사람이 문을 여는 장면”처럼 언어로 설명한 사건의 시작·종료 시각을 찾는 과제입니다.
> - **mIoU:** 예측 구간과 정답 구간의 겹침 비율인 IoU를 여러 질문에 대해 평균한 값입니다.
> - **System One:** 이 논문에서는 긴 답변을 생성하지 않고 후보를 직접 평가하는 모델 유형을 뜻합니다.
> - **포인트와 퍼센트:** 점수가 58.6에서 65.3으로 증가하면 **6.7포인트 상승**입니다.
> - **Thinking 모드:** 중간 추론 내용을 토큰으로 생성한 뒤 답하는 실행 방식입니다.

## 2. 연구 배경, 해결하려는 문제, 목적과 필요성

### 2.1 해결하려는 문제

**[저자 보고]** 시각 에이전트는 같은 영상을 보면서 “재료를 넣었는가?”, “현재 단계가 끝났는가?”, “다음 행동 중 무엇이 적절한가?”를 반복해서 판단해야 합니다.  
기존 비디오 언어 모델은 이러한 짧은 결정에도 시간 문자열이나 답변 문장을 순차적으로 생성하는 경우가 많습니다.  
저자들은 이 과정의 비용이 반복적인 상호작용을 어렵게 한다고 봅니다. **[p.2, §1]**

또한 기존의 판별형 시각 모델은 빠르지만 특정 과제나 고정된 라벨 집합에 묶이기 쉽고, 사전학습 멀티모달 언어 모델은 다양한 언어 표현을 이해하지만 일반적으로 생성 방식으로 결과를 내놓습니다.  
연구의 목표는 **사전학습 모델의 의미 이해 능력과 직접적인 결정 출력의 효율을 결합하는 것**입니다. **[p.2, §1]**

> **용어 설명**
>
> - **판별형 모델:** 주어진 입력에 대해 분류·점수·위치를 직접 예측하는 모델입니다.
> - **자기회귀 생성, autoregressive generation:** 앞서 생성한 토큰을 다시 입력으로 사용하면서 다음 토큰을 하나씩 만드는 방식입니다.
> - **MLLM:** 영상·이미지와 텍스트를 함께 처리하는 멀티모달 대형 언어 모델입니다.

### 2.2 연구 목적

| 목적 | 논문이 제안한 해결 방식 | 원문 위치 |
|---|---|---|
| 짧은 결정을 효율적으로 출력 | 답변 생성 대신 후보별 점수 계산 | p.3, 식 (1) |
| 서로 다른 비디오 과제를 공통 구조로 처리 | 시간 구간 후보와 텍스트 답안 후보에 동일한 점수화 헤드 적용 | pp.3–5, Fig.2 |
| 같은 영상에 대한 반복 계산 절감 | 영상 인코딩·접두 문맥 계산 공유 | p.4 |
| 사건 전체를 적절히 포괄 | 구간별 BCE에 Soft IoU 감독 추가 | p.4, 식 (2)–(3) |
| 에이전트가 사용하기 쉬운 결과 제공 | 시간 구간 또는 선택지와 점수 반환 | pp.2–4 |

**[해석]** 실용적 가치는 “동일 영상에 여러 번 판단을 요청하는 작업”에서 특히 분명합니다. 다만 논문의 실험은 시간 위치 추정과 객관식 QA에 집중되어 있으므로, 작업 절차를 실제로 완수하는 에이전트의 성공률이 향상되었다고 해석할 근거는 없습니다. **[pp.6–12]**

## 4. 방법론: 모델 구조와 수식

이 절의 수식 (1)–(8)은 원문에 있는 식입니다. 기호 설명과 명시적으로 표시한 수식 해석을 덧붙였습니다.

### 4.1 전체 구조

**[저자 보고]** 두 모델의 기반은 다음과 같습니다. **[p.5, §2.4]**

| VideoJev 모델 | 기반 모델 | 구조 |
|---|---|---|
| VideoJev-4B | Qwen3.5-4B | Dense |
| VideoJev-35B-A3B | Qwen3.6-35B-A3B | MoE |

> **용어 설명**
>
> - **Backbone, 기반 모델:** 새로운 과제를 수행하도록 수정하는 기존 사전학습 모델입니다.
> - **Dense:** 대부분의 모델 파라미터를 각 토큰 처리에 사용하는 구조입니다.
> - **MoE, Mixture of Experts:** 여러 전문가 네트워크 중 일부를 선택하여 사용하는 구조입니다.
> - **35B-A3B:** 명목상 총 350억 파라미터 중 토큰 처리에 약 30억 파라미터가 활성화되는 규모 표기입니다.

구조 변경은 세 가지입니다. **[p.3, §2.1, Fig.2]**

1. **마지막 MLP를 제거합니다.**
2. 원래의 언어 모델 출력 헤드를 **후보 점수화 헤드**로 교체합니다.
3. 후보 표현을 읽는 `<|option_end|>`와 질문 전체의 결정 표현을 읽는 `<|decide|>` 토큰을 추가합니다.

여기서 제거하는 것은 **마지막 Transformer 층 전체가 아니라 그 층의 MLP 부분**입니다.

> **용어 설명**
>
> - **MLP:** 토큰의 내부 특징을 변환하는 신경망 부분입니다.
> - **출력 헤드:** 모델의 내부 표현을 최종 점수나 예측으로 바꾸는 부분입니다.
> - **Hidden state, 은닉 상태:** 특정 토큰 위치에서 모델이 구성한 내부 표현 벡터입니다.
> - **Embedding, 임베딩:** 토큰을 모델이 처리할 수 있는 수치 벡터로 표현한 것입니다.

입력 순서는 다음과 같습니다.

```text
영상 토큰
→ 과제 지시문과 질문
→ 후보 1 <|option_end|>
→ …
→ 후보 K <|option_end|>
→ <|decide|>
```

두 새 토큰의 임베딩은 기존 `<|im_end|>`에서 초기화합니다. 인과적 처리 구조 때문에 후보 토큰의 표현은 영상·질문·앞선 후보를 참고하고, 마지막 결정 토큰의 표현은 후보 목록 전체를 참고합니다. **[p.3]**

> **용어 설명 — 인과적 attention:** 현재 위치가 자신보다 앞에 있는 토큰만 참고하도록 제한하는 방식입니다.

**[해석]** 따라서 이 구조는 후보를 서로 독립적으로 인코딩하는 방식이 아닙니다. 후보 순서에 따라 각 후보가 볼 수 있는 문맥이 달라집니다. **[p.3의 입력 구조에서 도출]**

### 4.2 공통 후보 점수화: 식 (1)

$$
u=
\frac{W_qh_d+b_q}
{\left\|W_qh_d+b_q\right\|_2},
\qquad
v_i=
\frac{W_kh_i+b_k}
{\left\|W_kh_i+b_k\right\|_2},
\qquad
s_i=10u^\top v_i+b.
$$

**기호 설명**

| 기호 | 의미 |
|---|---|
| $h_d$ | `<|decide|>` 위치의 은닉 상태 |
| $h_i$ | 후보 $i$의 `<|option_end|>` 위치 은닉 상태 |
| $W_q,W_k$ | 학습되는 선형 투영 가중치 |
| $b_q,b_k$ | 각 투영의 편향 |
| $u,v_i$ | 길이가 1로 정규화된 **512차원** 표현 |
| $\|\cdot\|_2$ | 벡터의 유클리드 길이 |
| $s_i$ | 후보 $i$의 확률 변환 전 점수 |
| $10$ | 고정된 점수 배율 |
| $b$ | 학습되는 공통 스칼라 편향 |

직관적으로는 **질문 전체의 결정 표현과 각 후보 표현의 방향이 얼마나 유사한지**를 점수로 사용합니다. **[p.3, 식 (1)]**

> **용어 설명**
>
> - **투영:** 내부 표현을 다른 차원의 벡터로 변환하는 연산입니다.
> - **정규화:** 여기서는 벡터의 길이를 1로 맞추는 것입니다.
> - **Logit:** sigmoid나 softmax를 적용하기 전의 점수입니다.

### 4.3 시간 구간 후보와 정답 라벨

**[저자 보고]** 기반 모델의 시간축 압축 구조에 맞춰 **두 프레임당 하나의 시간 구간 후보**를 만듭니다. **[p.4, §2.2]**

$$
B_i=[\ell_i,r_i],
\qquad
y_i=\mathbf{1}\{t_i\in G\},
\qquad
p_i=\sigma(s_i).
$$

**기호 설명**

- $B_i$: 후보 $i$의 시간 구간.
- $\ell_i,r_i$: 그 구간의 시작·종료 시각.
- $t_i$: 해당 프레임 쌍의 두 타임스탬프 평균.
- $G$: 주석된 사건 구간들의 합집합.
- $\mathbf{1}\{\cdot\}$: 조건이 참이면 1, 거짓이면 0.
- $y_i$: 후보의 이진 정답 라벨.
- $\sigma$: 점수를 0과 1 사이로 변환하는 sigmoid 함수.
- $p_i$: 후보가 사건에 속한다고 예측한 확률.

후보 사이의 경계는 인접한 프레임 쌍 사이 시각의 중간으로 정합니다. 첫 구간은 0초에서 시작하고, 마지막 구간은 영상 끝에서 종료합니다. 입력에는 타임스탬프 문자열을 사용하되, 정답 라벨과 경계 계산에는 반올림하지 않은 시각을 사용합니다. **[p.4]**

**중요한 구분:** 양성 라벨은 “후보 구간이 정답과 조금이라도 겹치는가”가 아니라, **대표 시각 $t_i$가 정답 구간 안에 있는가**로 결정됩니다.

### 4.4 구간별 소속 학습: 식 (2)

```math
\mathcal{L}_{\text{BCE}}
=
-\frac{1}{K}
\sum_{i=1}^{K}
\left[
y_i\log p_i
+
(1-y_i)\log(1-p_i)
\right].
```

**기호 설명**

- $K$: 유효한 시간 후보 수.
- $y_i$: 후보의 정답 소속 라벨.
- $p_i$: 예측 소속 확률.
- $\mathcal{L}_{\text{BCE}}$: 후보별 이진 교차엔트로피 손실.

한 사건은 여러 후보 구간에 걸칠 수 있으므로, 각 후보에 대해 사건 안인지 밖인지 감독합니다. **[p.4, 식 (2)]**

> **용어 설명 — BCE:** 정답이 1인 후보에는 높은 확률을, 정답이 0인 후보에는 낮은 확률을 주도록 학습하는 손실입니다.

### 4.5 사건 전체의 포괄 범위 학습: 식 (3)

BCE만으로는 사건 전체를 충분히 덮도록 직접 보상하지 않으므로, 구간 길이를 고려한 Soft IoU 손실을 추가합니다. **[p.4]**

```math
\mathcal{L}_{\text{IoU}}
=
1-
\frac{
\sum_i d_i p_i y_i
}{
\sum_i d_i
\left[
y_i+p_i(1-y_i)
\right]
},
\qquad
d_i=r_i-\ell_i.
```

**기호 설명**

- $d_i$: 후보 구간의 시간 길이.
- 분자 $\sum_i d_i p_i y_i$: 정답 사건 안의 후보를 얼마나 높은 확률로 포괄하는지 나타내는 값.
- 분모: 정답 양성 구간 전체와 사건 밖에 발생한 예측 반응을 함께 반영하는 값.
- $\mathcal{L}_{\text{IoU}}$: 확률을 이용한 IoU 대체 손실.

> **용어 설명**
>
> - **IoU:** 예측과 정답의 겹친 구간 길이를 두 구간의 합집합 길이로 나눈 값입니다.
> - **Soft IoU:** 확정적인 0·1 예측 대신 확률을 사용하여 학습 과정에서 미분할 수 있게 만든 형태입니다.
> - **대체 손실, surrogate loss:** 직접 최적화하기 어려운 평가 지표를 대신하도록 설계한 학습 목적입니다.

**[수식 해석]** 이 식은 실제 연속 정답 구간 $G$와의 정확한 IoU가 아니라, 대표 시각 라벨 $y_i$로 이산화한 후보 집합에 대한 대체 손실입니다. 구간 길이 가중치가 시간 해상도의 한계까지 없애 주는 것은 아닙니다.

원문은 **양성 대표 시각이 하나도 없는 경우 Soft IoU를 생략한다**고 명시합니다. **[p.4, 식 (3) 아래]**

### 4.6 하나의 연속 사건 구간으로 복원: 식 (4)

```math
(a^\star,b^\star)
=
\text{arg\,max}_{1\leq a\leq b\leq K}
\sum_{i=a}^{b}
\left[
s_i-\log\frac{\tau}{1-\tau}
\right].
```

**기호 설명**

- $a,b$: 선택할 첫 후보와 마지막 후보의 인덱스.
- $a^\star,b^\star$: 점수 합을 최대화하는 인덱스.
- $\tau$: 확률 임계값으로, 모든 실험에서 **0.25**로 고정.
- $K$: 시간 후보 수.
- 이 식의 $b$는 구간 인덱스이며, 식 (1)의 편향 $b$와 역할이 다릅니다.

최종 예측 구간은 다음과 같습니다.

$$
[\ell_{a^\star},r_{b^\star}].
$$

저자들은 **Kadane 알고리즘**으로 이 구간을 $O(K)$ 시간에 찾으며, 평활화 창 크기는 1로 설정합니다. 조정한 점수가 모두 음수여도 가장 강한 후보 하나를 반환합니다. **[p.4]**

> **용어 설명**
>
> - **Kadane 알고리즘:** 나열된 수 중 합이 가장 큰 연속 부분을 한 번 훑어 찾는 알고리즘입니다.
> - **$O(K)$:** 후보 수에 비례하는 계산량이라는 뜻이며, 여기서는 최종 구간 디코더에만 해당합니다.

**[수식 해석]**

- 이 방법은 단순히 $p_i>0.25$인 후보만 이어 붙이는 방식이 아닙니다.
- 전체 점수 합을 높이는 데 유리하다면 중간의 낮은 점수 구간도 포함할 수 있습니다.
- 출력은 항상 **하나의 비어 있지 않은 연속 구간**입니다.
- 따라서 사건 부재를 표현하는 빈 출력과 서로 떨어진 여러 사건 구간을 그대로 반환하는 출력은 제시되지 않습니다.

또한 원문은 마지막에 가벼운 경계 후처리를 수행한다고 설명하지만, 문서 안에는 구체적인 후처리 규칙이 충분히 제시되어 있지 않습니다. **[p.4]**

### 4.7 객관식 QA: 식 (5)

객관식 QA는 정답이 하나라는 전제에서 후보 점수를 softmax로 정규화합니다. **[p.5, §2.3]**

$$
p_i=
\frac{\exp(s_i)}
{\sum_{j=1}^{K}\exp(s_j)},
\qquad
\mathcal{L}_{\text{CE}}=-\log p_y.
$$

**기호 설명**

- $K$: 답변 선택지 수.
- $s_i$: 선택지 $i$의 점수.
- $p_i$: 선택지 $i$의 정규화된 확률.
- $y$: 정답 선택지의 인덱스.
- $\mathcal{L}_{\text{CE}}$: 정답 선택지에 높은 확률을 부여하도록 하는 교차엔트로피 손실.

추론 시에는 가장 높은 확률의 선택지를 반환합니다.

> **용어 설명 — Softmax:** 여러 점수를 합이 1인 확률 분포로 바꾸는 함수입니다. 여기서 확률은 **제공된 후보 집합 안에서의 상대적인 확률**입니다.

**[저자 보고]** 선택지 위치에 의존하는 편향을 줄이기 위해 적격 학습 질문의 선택지 순서를 정답과 독립적으로 섞습니다. 다만 선택지 위치나 이전 대화를 직접 언급하는 질문은 의미 보존을 위해 원래 순서를 유지합니다. 추론에서는 제공된 순서를 그대로 사용합니다. **[p.5]**

**[해석]** 이는 위치 편향을 완화하려는 설계입니다. 후보 순서가 달라져도 예측이 항상 유지된다는 보장은 아니며, 별도의 순서 강건성 실험은 보고하지 않습니다.

### 4.8 두 단계 학습: 식 (6)–(8)

| 단계 | 사용하는 영상 | 학습하는 부분 | 고정하는 부분 |
|---|---|---|---|
| 1단계 | 30% | 새 점수화 헤드 | 기반 모델과 새 토큰 임베딩 |
| 2단계 | 나머지 70% | 언어 기반 모델, 새 토큰 임베딩, 점수화 헤드 | 시각 인코더와 merger |

**[p.5, §2.4]**

1단계의 목적 함수는 다음과 같습니다.

$$
\mathcal{L}_{\text{TG}}=\mathcal{L}_{\text{BCE}},
\qquad
\mathcal{L}_{\text{QA}}=\mathcal{L}_{\text{CE}}.
\tag{6}
$$

2단계에서는 grounding에 Soft IoU를 추가합니다.

```math
\mathcal{L}_{\text{TG}}
=
\mathcal{L}_{\text{BCE}}
+
2\mathcal{L}_{\text{IoU}}.
```

```math
\mathcal{L}_{\text{QA}}
=
\mathcal{L}_{\text{CE}}.
```

**기호 설명**

- $\text{TG}$: 시간 위치 추정.
- $\text{QA}$: 객관식 질의응답.
- 계수 $2$: Soft IoU 손실의 가중치.

시각 인코더와 merger는 두 단계 모두 고정합니다. 각 단계는 별도의 최적화 설정으로 한 번의 epoch를 수행하며, 손실은 질문별로 동등하게 평균합니다. **두 과제를 반드시 50:50으로 샘플링한다는 설명은 아닙니다.** **[p.5]**

> **용어 설명**
>
> - **Merger:** 시각 토큰을 합치거나 언어 모델이 사용할 표현으로 연결하는 부분입니다.
> - **Epoch:** 해당 단계의 학습 데이터를 한 차례 사용하는 단위입니다.
> - **동결:** 해당 부분의 가중치를 학습 중 변경하지 않는 것입니다.

### 4.9 Cached와 Joint inference

| 구분 | Cached inference | Joint inference |
|---|---|---|
| 영상 계산 | 영상 인코딩과 접두 문맥 계산을 한 번 수행 | 영상 계산을 여러 질문이 공유 |
| 질문 처리 | 각 질문이 동일한 영상 캐시에서 독립적으로 분기 | 여러 질문과 후보를 한 인과 시퀀스로 연결 |
| 앞선 질문 접근 | 없음 | 뒤 질문이 앞 질문과 후보를 볼 수 있음 |
| 정답·예측 답변 이력 | 넣지 않음 | 넣지 않음 |
| 언어 모델 실행 | 질문마다 한 번 | 질문 그룹 전체에 한 번 |
| 사용 상황 | 질문이 순차적으로 도착 | 여러 질문을 함께 알고 있음 |

**[p.4; pp.7–8; pp.19–20, A.4]**

> **용어 설명**
>
> - **Prefill:** 입력 문맥을 모델에 넣어 이후 처리에 필요한 내부 상태를 계산하는 과정입니다.
> - **캐시:** 이미 계산한 상태를 저장하여 재사용하는 것입니다.
> - **순전파, forward:** 입력을 넣어 모델의 출력을 계산하는 실행입니다.

**[저자 보고]** Joint는 최적화된 attention 연산을 활용하기 위해 질문을 서로 격리하는 별도 마스크를 사용하지 않습니다. 학습도 같은 질문 연결 구조를 사용합니다. **[p.7]**

**[해석]** 정답이나 생성 답변을 삽입하지 않았다는 사실과 질문 간 문맥 효과가 없다는 것은 다릅니다. 앞 질문의 표현이나 후보가 뒤 질문의 판단에 영향을 줄 가능성은 남아 있으며, 이 영향의 크기와 방향은 별도 실험이 필요합니다.

### 5.1 학습 데이터

| 용도 | 데이터 | 원문 설명 |
|---|---|---|
| 시간 위치 추정 | TimeLens-100K | 시간 구간 주석을 후보별 라벨로 변환 |
| 시간 위치 추정 | TimeLens2-93K | 동일한 후보 소속 학습에 사용 |

**[p.5, §2.4]**

QA 데이터는 게임·스포츠·요리·음악과 춤·야외 활동·공예 등을 포함합니다. 질문은 객체·행동 인식, 시공간 추론, 정보 검색, 사건 이해, 개수 세기, 화면 글자 읽기, 요약을 다루며, 영상 길이는 4분부터 거의 2시간이고 선택지는 4개 또는 5개입니다. **[p.5]**

동일 데이터 대조 실험 설명에서는 전체 학습 파티션에 걸친 규모를 **404,037개 질문과 58,424개 영상**으로 명시합니다. 데이터셋 이름의 100K·93K와 약 240K를 단순 합산해 실제 학습량으로 사용해서는 안 됩니다. 각 데이터의 최종 포함량과 필터링 내역은 문서에 충분히 설명되어 있지 않습니다. **[p.19, A.3]**

### 5.2 평가 데이터

| 과제 | 벤치마크 | 문항 수·분할 | 지표 |
|---|---|---:|---|
| Grounding | Charades-STA | 3,363개 test 질의 | mIoU, R1@0.3/0.5/0.7 |
| Grounding | ActivityNet Captions | 4,500개 test 질의 | 동일 |
| Grounding | QVHighlights | 1,541개 test 질의 | 동일 |
| QA | LVBench | 1,549개 test 질문 | 정확도 |
| QA | Video-MME | 2,700개 test 질문 | 정확도 |
| QA | LongVideoBench | 1,337개 validation 질문 | 정확도 |
| QA | MLVU | 2,174개 development 질문 | 7개 객관식 과제의 M-Avg |

**[p.6; pp.18–19]**

> **용어 설명**
>
> - **R1@0.7:** 최상위 예측 구간이 정답과의 IoU 0.7 기준을 충족하는 질문의 비율입니다.
> - **M-Avg:** MLVU의 여러 과제 점수를 평균한 값입니다.
> - **Validation / development:** 개발·검증용으로 정의된 데이터 분할입니다.

**평가 조건에서 중요한 점은 다음과 같습니다.**

- Grounding은 원래 주석이 아니라 **TimeLens-Bench에서 정제한 주석**을 사용합니다. **[p.6]**
- 모든 주요 평가는 **영상 프레임만 입력**하며 별도 자막이나 음성은 사용하지 않습니다. **[pp.6,18]**
- Grounding 성능 평가에는 4fps와 144K 문맥 예산을 사용합니다. **[p.19]**
- VideoJev QA는 256K 문맥 예산, 요청 2fps, 최대 2,048프레임을 사용하며 필요하면 프레임 수와 해상도를 줄입니다. **[pp.7,19]**
- 프레임당 최대 면적은 $640\times640$픽셀이고, QA의 시각 토큰은 문맥 예산의 80% 이내로 제한합니다. **[p.7]**

> **용어 설명 — fps와 문맥 예산:** fps는 초당 샘플링하는 프레임 수이고, 문맥 예산은 모델이 한 번에 처리할 수 있도록 허용한 토큰 수입니다.

### 5.3 주요 학습 설정

두 모델 모두 **64대의 NVIDIA H200**, BF16 연산, 전역 배치 64개 packed sequence로 학습합니다. 학습 영상은 2fps, 최대 144K 토큰이며 단계별 업데이트 수는 160회와 375회입니다. **[p.6]**

점수화 헤드의 학습률은 1단계 $3\times10^{-4}$, 2단계 $10^{-4}$이고, 2단계 언어 모델 학습률은 4B에서 $5\times10^{-6}$, 35B-A3B에서 $2\times10^{-6}$입니다. **[p.6]**

> **용어 설명**
>
> - **BF16:** 계산량과 메모리 사용량을 줄이기 위한 수치 표현 형식입니다.
> - **Packed sequence:** 여러 학습 예제를 긴 시퀀스 안에 묶어 처리하는 방식입니다.
> - **학습률:** 한 번의 가중치 갱신에서 변화량을 조절하는 값입니다.

## 8. 가장 중요한 그림의 선정과 해석

### 8.1 Fig.2 — 모델의 핵심 구조, p.3

**그림의 내용:** 시간 구간과 텍스트 답안을 공통 후보 형식으로 입력하고, 공유 점수화 헤드에서 얻은 점수를 과제별로 변환하는 구조입니다.

**해석:** 공통적인 부분은 후보를 평가하는 방식이고, 다른 부분은 **정답 구조와 출력 규칙**입니다. Grounding은 여러 후보가 동시에 양성이 될 수 있어 sigmoid를 쓰고, QA는 정답 하나를 선택하므로 softmax를 씁니다.

**주의:** 그림의 확률과 시간 구간 예시는 구조 설명용이며 실험 통계가 아닙니다. 캡션도 이를 명시합니다.

### 8.2 Fig.3 — 반복 질문의 추가 비용, p.10

**저자 보고:** 10개 질문에서 VideoJev-4B Joint는 grounding **0.39초**, QA **1.64초**입니다. Cached는 각각 **0.85초와 2.17초**입니다. 질문 수가 1개에서 10개로 증가할 때 Joint의 추가 시간은 각각 **55ms와 31ms**입니다.

**해석:** 영상 처리 비용을 공유하는 방식의 가치는 질문이 여러 개일 때 뚜렷하게 나타납니다.

**중요한 대조군:** 선택지 한 토큰만 읽는 Qwen Direct Joint는 QA 시간 **1.67초**로 VideoJev와 비슷합니다. 별도 LVBench 정확도는 **58.7% 대 67.9%**입니다. 따라서 이 그림은 직접 출력이 이미 가능한 기준선과 비교했을 때, VideoJev가 비슷한 시간에서 더 높은 품질을 보였다는 근거도 제공합니다.

**주의:** QA 시간은 Video-Holmes에서, 끝에 적힌 정확도는 LVBench에서 얻은 값입니다. 또한 1–10개 질문에서의 결과를 임의로 많은 질문에 대한 상수 비용 보장으로 확대할 수 없습니다.

### 8.3 Fig.4 — 확신도의 유용성과 과신, p.11

**그림의 내용:** 예측 확신도와 실제 정확도의 관계를 보여 주며, 대각선은 완벽한 확률 보정을 의미합니다.

**해석:** 확신도가 높을수록 정답률도 대체로 높아지므로 선별 응답에 사용할 정보는 있습니다. 그러나 많은 점이 대각선 아래에 위치하여 모델이 실제 정답률보다 높은 확률을 내놓는 경향을 보여 줍니다.

**주의:** “확신도와 정확도가 함께 증가한다”는 사실만으로 확률이 정확히 보정되었다고 판단할 수 없습니다.

### 8.4 Fig.1 — 전체 성능과 시간의 요약, p.1

**그림의 내용:** 여러 벤치마크의 평균 성능과 특정 벤치마크의 질문당 시간을 함께 배치합니다.

**해석:** VideoJev의 품질·효율 위치를 빠르게 파악하는 데 유용합니다.

**주의:** 세 grounding 벤치마크의 평균 품질과 Charades 시간, 네 QA 벤치마크의 평균 품질과 LVBench 시간이 짝지어져 있습니다. 모든 벤치마크에서 같은 시간–품질 관계를 직접 측정한 그림은 아닙니다.

### 8.5 Fig.9 — 긴 영상의 다중 질문 처리 사례, p.21

**저자 보고:** 3,665.5초 영상에 대해 18개 질문을 Joint 한 번으로 처리하고, 그중 화면 글자 검색과 날씨 인식 두 결과를 제시합니다.

**해석:** 긴 영상에서 여러 판단을 같은 실행에 묶는 사용 형태를 구체적으로 보여 줍니다.

**주의:** 선정된 정성 사례입니다. 18개 질문 전체의 정답률이나 장시간 영상 전반의 일반화 성능을 이 그림만으로 판단할 수 없습니다. 화면에 포함된 글자를 읽는 것은 별도 자막 입력을 사용하는 것과도 다릅니다.

### 8.6 Fig.13 — 작은 객체 세기의 공통 실패, p.23

**저자 보고:** 정답이 책 4권인 질문에서 두 모델 모두 오답을 선택합니다.

**해석:** 의미적 판단과 긴 문맥 처리 능력이 좋아져도 미세한 시각 정보의 식별 문제는 남을 수 있음을 보여 줍니다.

**주의:** 그림만으로 실패 원인을 해상도, 프레임 샘플링, 시각 인코더 중 하나로 특정할 수는 없습니다. 이는 후속 분리 실험이 필요한 부분입니다.

> **용어 설명**
>
> - **일반화:** 학습에 사용한 예제 외의 입력에서도 원하는 성능을 유지하는 능력입니다.
> - **분포 밖, OOD:** 학습 데이터와 종류·환경·표현 방식 등이 달라진 입력입니다.
> - **Zero-shot 전이:** 해당 새 과제의 학습 예제를 사용하지 않고 수행하는 것입니다.
> - **강건성:** 입력 표현이나 환경이 변해도 성능이 크게 흔들리지 않는 성질입니다.

**[해석]** 일반화와 직접 연결되는 가장 유력한 근거는 **두 과제의 공동학습 효과**입니다. 다만 “시간 감독이 근거 위치 파악을 강화하고 QA가 의미 구분을 강화한다”는 설명은 저자의 가능한 기제 해석이며, 내부 표현 분석이나 별도의 인과 실험으로 입증한 것은 아닙니다. **[p.9, Table 5]**

공유 후보 인터페이스는 새로운 질문 형식을 받아들이기 쉽게 만드는 구조적 장점이 있습니다. 그러나 **입력할 수 있다는 것과 정확하게 판단할 수 있다는 것은 별도 문제**입니다. 새로운 과제에 대한 성능 검증이 필요합니다. **[p.12, §5]**

### 9.2 저자가 직접 인정하거나 후속 과제로 제시한 한계

원문에는 별도의 **Limitations** 절이 없습니다. 다음 범위는 주로 **Future Work**에서 후속 과제로 제시합니다. **[p.12, §5]**

1. **평가 과제의 범위:** 행동 인식, 사건 탐지, 장면 상태 분류, 시각 조건 검증으로의 확장.
2. **개방형 에이전트 연결:** 상위 에이전트가 목표를 시각적 확인 질문과 후보로 분해하고, 결과를 계획·실행에 연결하는 구조.
3. **실제 스트리밍:** 새 프레임의 점진적 인코딩, 메모리 관리, 판단 문맥의 갱신.
4. **신뢰성:** 확률 보정, 불확실성 추정, 불확실한 경우 상위 추론으로 넘기는 선택적 판단.

> **용어 설명 — 선택적 예측:** 모든 입력에 무조건 답하지 않고, 정해진 신뢰 기준을 만족하는 경우만 답하거나 나머지를 다른 처리 단계로 넘기는 방식입니다.

### 9.3 수식에서 드러나는 추가적인 적용 범위

**[해석]** 다음은 실제 실패율이 보고된 결과가 아니라, 모델의 라벨·출력 정의에서 도출되는 한계입니다. **[p.4, 식 (2)–(4)]**

- **사건이 없는 영상:** 모든 후보 점수가 낮아도 하나의 구간을 반환합니다.
- **서로 떨어진 여러 사건:** 학습 라벨은 여러 구간을 포함할 수 있지만 최종 출력은 단일 연속 구간입니다.
- **매우 짧은 사건:** 어떤 대표 시각도 사건 안에 들어가지 않으면 양성 라벨이 없어집니다.
- **정답이 없는 선택지 집합:** QA는 제공된 선택지 중 하나를 고르는 구조이며, 별도의 “해당 없음” 판단 성능은 보고하지 않습니다.

## 11. 결론과 시사점, 유망한 접근법의 신속 검증

### 11.1 저자들이 제시한 시사점

**[저자 보고]** VideoJev는 시간 위치 추정과 객관식 QA를 직접적인 후보 판단으로 통합하고, 영상 계산을 공유하여 반복적인 판단을 효율적으로 수행하는 기반을 제시합니다. 저자들은 이러한 구조화 판단을 조합하여 개방형 작업을 수행하는 시각 에이전트로 확장할 수 있다고 제안합니다. **[p.12, §6]**

후속 계획은 상위 에이전트가 사건·행동·상태 후보를 만들고, VideoJev가 이를 영상 증거와 비교하며, 불확실하거나 예상 밖의 관찰에서는 후보 수정 또는 추가 추론을 수행하는 구조입니다. 실제 스트리밍 지원과 신뢰도 개선도 명시적인 후속 과제입니다. **[p.12, §5]**

### 11.2 학계와 실용 분야에 대한 해석

**[해석]** 학술적으로 중요한 기여는 **출력 형식과 학습 목적을 실제 의사결정 구조에 맞추는 것**입니다. 시간 문자열 생성 대신 구간 소속을 학습하고, 답변 문장 생성 대신 후보 선호를 학습하여 효과를 보였습니다. 특히 동일 데이터 대조 실험과 Soft IoU 실험은 이러한 방향을 뒷받침합니다. **[Tables 3,6]**

실용적으로는 같은 영상에 대해 상태 확인·근거 검색·선택지 평가를 반복하는 작업에서 활용 가능성을 검토할 수 있습니다. 다만 실제 응용 효과를 판단하려면 영상 처리 전체 시간, 메모리 사용량, 잘못된 후보 생성, 판단 실패 후 복구까지 포함해야 합니다. 이 수준의 검증은 원문에 없습니다. **[pp.18–20; p.12]**

| 우선 검증할 접근 | 선택한 근거 | 최소 실험 | 확인할 항목 |
|---|---|---|---|
| **Soft IoU 보조 손실** | grounding 평균 +4.6포인트로 큰 기여 | 작은 동일 데이터에서 BCE와 BCE+Soft IoU만 비교 | 사건 길이별 mIoU, 짧은 사건의 양성 라벨 누락 |
| **영상 문맥 공유와 Joint 처리** | 1→10질문의 작은 추가 비용 | 기존 체크포인트로 1·2·5·10개 질문을 Cached/Joint 실행 | 전체 시간, 메모리, 질문 순서 변경에 따른 예측 차이 |
| **공통 후보 점수화 헤드** | 동일 데이터 AR 대조군보다 높은 평균 | 같은 기반 모델·데이터·예산에서 기존 LM의 한 토큰 읽기와 새 헤드 비교 | 성능 이득이 학습·헤드·출력 규칙 중 어디에서 나오는지 |
| **TG+QA 공동학습** | 두 과제의 평균 점수 개선 | 총 질문 수와 연산량을 맞춘 단일·공동학습 비교 | 학습에 포함하지 않은 영상 도메인에서의 전이 |
| **확률 보정과 선별 응답** | 과신과 고확신 집단의 높은 정확도 | 영상 단위로 분리한 보정 세트에서 온도 조정 | 보정 오차와 답변하는 비율별 오류율 |

> **용어 설명**
>
> - **체크포인트:** 저장된 모델 가중치입니다.
> - **온도 조정, temperature scaling:** 점수의 날카로움을 하나의 계수로 조절하여 확률을 보정하는 방법입니다.
> - **답변 비율별 오류율:** 더 확실한 질문만 답하도록 할 때 얼마나 많은 질문에 답할 수 있고 얼마나 자주 틀리는지 함께 보는 평가입니다.

### 11.4 일반화 향상을 위한 후속 연구의 우선순위

**1. 데이터 분리와 중복 감사부터 강화해야 합니다.**  
영상 단위로 학습·검증·평가를 분리하고, 전체 도메인이나 과제군을 학습에서 제외한 평가를 추가해야 합니다. 이렇게 해야 7개 벤치마크에서의 성능과 새로운 종류의 문제에 대한 전이를 구분할 수 있습니다. **[원문의 데이터 설명과 평가 범위에 대한 검증 제안: pp.5–6,19]**

**2. 후보 형식과 질문 구성의 변화에 대한 안정성을 확인해야 합니다.**  
정답 의미를 유지한 채 후보 순서·표현·개수·오답 구성을 바꾸고, Joint에서는 질문 순서와 조합도 바꾸어야 합니다. 구조 변경 없이 기존 모델로 시작할 수 있는 검증입니다. **[근거: pp.3–5,7–8]**

**3. 시각 증거를 실제로 사용하는지 검증해야 합니다.**  
정답에 필요한 장면을 가린 경우와 같은 양의 무관한 장면을 가린 경우를 비교하면, 답변이 영상 근거에 얼마나 의존하는지 평가할 수 있습니다. 객관식 정확도만으로 이 의존성을 확정할 수는 없습니다. **[현재 QA 평가 범위에 대한 검증 제안: pp.6–8]**

**4. 무사건·다중 사건·짧은 사건을 별도 평가해야 합니다.**  
이 실험은 대표 시각 라벨과 단일 구간 디코더의 적용 범위를 직접 확인합니다. 그 결과를 본 뒤 빈 출력이나 여러 구간 출력이 필요한지 판단하는 순서가 적절합니다. **[근거: p.4, 식 (2)–(4)]**

**5. 확률 보정의 전이를 별도로 확인해야 합니다.**  
한 도메인에서 보정한 확률이 다른 도메인에서도 유효한지, 선택지 집합이 달라져도 같은 기준을 사용할 수 있는지 평가해야 합니다. 원문이 보인 정확도 개선만으로 이 성질을 보장할 수는 없습니다. **[근거: p.11, Fig.4]**

**6. 이후 실제 스트리밍과 에이전트 연결을 검증해야 합니다.**  
새 프레임 유입, 제한된 메모리, 오래된 근거 회수, 후보 수정, 실패 복구를 포함하는 작업에서 판단 품질과 전체 실행 비용을 측정해야 합니다. 이는 저자가 제안한 확장 방향을 실험 가능한 단계로 구체화한 것입니다. **[근거: p.12, §5]**

**최종 평가:** 현재 가장 강한 근거는 **사건 전체를 포괄하도록 하는 감독, 두 과제의 공동학습, 반복 질문에서의 계산 공유**에 있습니다. 일반화 성능의 다음 검증은 모델 규모를 확대하는 것에 앞서, **어떤 과제와 입력 변화까지 이 이점이 유지되는지**를 명확히 밝히는 데 두는 것이 타당합니다.
