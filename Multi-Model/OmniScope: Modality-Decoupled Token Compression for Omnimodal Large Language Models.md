# OmniScope: Modality-Decoupled Token Compression for Omnimodal Large Language Models 

> **참고 자료**: Su, J., Luo, Y., Ma, Y., Hu, Y., Jin, M., & Zheng, X. (2026). *OmniScope: Modality-Decoupled Token Compression for Omnimodal Large Language Models*. arXiv:2607.23193v3. GitHub: https://github.com/MAC-AutoML/OmniScope

---

## 1. Executive Summary (10문장 이내)

OmniLLM(Omnimodal Large Language Model)은 시각·청각·텍스트를 동시에 처리하지만, 긴 비디오에서 토큰 수가 폭증해 추론 효율이 급격히 저하된다.  
기존 토큰 압축법들은 한 모달리티의 중요도 점수를 다른 모달리티 압축에 그대로 적용하는 단방향 교차 모달 가이던스를 채택해왔다.  
그러나 동일한 쿼리에 대해 오디오와 비디오의 중요도가 서로 다른 시점에서 피크를 보이는 **교차 모달 현저성 불일치(Cross-modal salience mismatch)** 현상이 광범위하게 존재하며(78.3% 샘플에서 Spearman $|\rho| < 0.3$ ), 이는 단방향 가이던스가 핵심 정보를 버릴 위험성을 내포한다.  
본 논문은 이 문제를 해결하기 위해 **OmniScope**를 제안한다.  
OmniScope는 쿼리를 공유 의미 앵커로 삼되, 각 모달리티가 독립적으로 압축 예산을 결정하는 훈련 불필요(training-free) 프레임워크다.  
시각 측에는 앵커-델타 시공간 압축(AD-STC)을, 오디오 측에는 초당 토큰 병합(per-second Token Merging)을 적용한다. 4개 벤치마크, 2개 모델 규모(7B, 3B) 전 설정에서 최고 평균 정확도를 달성하며, 45% 유지 시 사실상 무손실 성능을 보인다.  
25% 유지에서도 평균 정확도 0.35포인트 하락에 불과하며, 최대 3.53배 프리필 속도 향상과 15% 이상 GPU 메모리 절감을 제공한다.

### 1-1. 연구의 목적과 필요성

**목적**: OmniLLM 추론 시 발생하는 오디오-비디오 토큰 과부하 문제를, 모달리티별 독립적 압축을 통해 효율성과 정확성을 동시에 달성하는 것.

**필요성**:
- OmniLLM은 비디오 길이에 비례해 $N_v + N_a$ 토큰이 증가하여 메모리·계산 비용이 폭증함 (p.1)
- 기존 시각 전용 압축법(FastV, ToMe 등)은 오디오-비디오 결합 압축에 직접 적용 불가 (p.1)
- OmniZip 등 기존 옴니모달 압축법은 단방향 교차 가이던스 사용 → 크리티컬 정보 손실 위험 (p.2, Fig.1)
- 78.3%의 쿼리-비디오 쌍에서 시각-오디오 중요도 상관관계가 낮음 ($|\rho| < 0.3$) → 단방향 접근의 구조적 한계 실증 (Appendix F, Fig.7)

## 2-1. 해결 문제, 제안 방법, 모델 구조, 성능, 한계 상세 설명

### 🔴 해결하고자 하는 문제

**문제 1: 토큰 폭증으로 인한 추론 비효율**

OmniLLM은 비디오를 시각 프레임 $X_\text{vid}$와 오디오 세그먼트 $X_\text{aud}$로 분해하고, 각각 인코더로 토큰화한다:

$$Z_v = \Phi_v(X_\text{vid}) \in \mathbb{R}^{N_v \times D}, \quad Z_a = \Phi_a(X_\text{aud}) \in \mathbb{R}^{N_a \times D} $$

시간 윈도우 인터리빙 메커니즘에 의해 LLM 입력 시퀀스는:

$$X_\text{LLM} = [B_1, B_2, \ldots, B_W], \quad B_i = [Z_v^{(i)}; Z_a^{(i)}] $$

비디오가 길어질수록 $N_v + N_a$가 급증 → 계산량 및 메모리 overhead.

**문제 2: 단방향 교차 모달 가이던스의 실패**

기존 OmniZip은 오디오 중요도로 비디오를 프루닝하는 단방향 전략을 채택한다. 그러나 같은 쿼리에서도 오디오와 비디오의 중요도 피크가 다른 시점에 발생한다(Fig.1). 1,197개 쿼리-비디오 쌍 분석 결과, 78.3%에서 $|\rho_\text{Spearman}| < 0.3$ (Appendix F).

---

### 🟢 제안하는 방법 (수식 포함)

**OmniScope 3단계 파이프라인** (Fig.3):

#### Stage 1: Query-Aware Scoring (쿼리 인식 중요도 점수화)

**시각 점수화** - 외부 CLIP을 사용하여 프레임-쿼리 코사인 유사도 계산:

$$s_v^{(t)} = \frac{\mathbf{f}_I^{(t)} \cdot \mathbf{f}_Q}{\|\mathbf{f}_I^{(t)}\|_2 \|\mathbf{f}_Q\|_2} $$

**오디오 점수화** - 임베딩 놈(norm) 기반 게이팅 신호:

$$g_j = \frac{\|\mathbf{E}_Q^{(j)}\|}{\max_k \|\mathbf{E}_Q^{(k)}\|} $$

게이팅된 교차 모달 유사도 및 중요도 집계:

$$S_{ij} = \bar{z}_a^{(i)} \cdot \bar{e}_Q^{(j)}, \quad w_{ij} = \text{softmax}_j\!\left(\frac{g_j S_{ij}}{\tau}\right), \quad s_\text{audio}^{(i)} = \sum_j w_{ij} S_{ij} $$

인근 고점수 초(second)의 점수 전파 (시간 연속성 반영):

$$b_s = \max_{s' \in \mathcal{H},\, 0 < |s-s'| \leq R} \!\left(1 + (\beta - 1) \cdot \gamma^{|s-s'|}\right), \quad \hat{s}_a^{(s)} \leftarrow \hat{s}_a^{(s)} \cdot b_s $$

**토큰 예산 배분** - 위치별 중요도에 비례한 토큰 수 배분:

$$n_\text{keep}^{(i)} = \left\lfloor \frac{s^{(i)}}{\sum_j s^{(j)}} \cdot N^\text{budget} + 0.5 \right\rfloor $$

#### Stage 2: AD-STC - 시각 토큰 압축

**앵커 프레임** (짝수 인덱스): DPC-KNN 밀도 기반 공간 선택

$$d_i = \frac{1}{k} \sum_{\mathbf{h}_j \in \text{KNN}(\mathbf{h}_i)} \text{sim}(\mathbf{h}_i, \mathbf{h}_j) $$

밀도가 낮은(고유한) 토큰 $n_\text{keep}^{(t)}$개 유지.

**델타 프레임** (홀수 인덱스): 압축률에 따른 적응적 전략 전환

- **낮은 압축** ($r \geq \tau_r$): 공간·시간 비교체성(replaceability) 곱:

$$\alpha_i^\text{intra} = \max_{j \neq i} \text{sim}(\mathbf{h}_i, \mathbf{h}_j), \quad \alpha_i^\text{inter} = \max_l \text{sim}(\mathbf{h}_i, \mathbf{h}_l^\text{prev}) $$

$$\text{replaceability}_i = \alpha_i^\text{intra} \times \alpha_i^\text{inter} $$

- **높은 압축** ($r < \tau_r$): 위치별 코사인 유사도 기반 최대 변화 토큰 유지:

$$c_i = \text{sim}(\mathbf{h}_i, \mathbf{h}_i^\text{prev})$$

#### Stage 3: 오디오 토큰 병합

초(second) 단위로 짝수/홀수 인덱스로 소스(A)·목적(B) 집합 분리 후 유사도 행렬 계산:

$$\mathbf{M} = \bar{\mathbf{H}}_\mathcal{A} \bar{\mathbf{H}}_\mathcal{B}^\top $$

유사도 상위 $m = N - n_\text{keep}^{(s)}$ 쌍을 선택하여 평균 병합:

$$\mathbf{h}'_\text{dst} = \frac{\mathbf{h}_\text{dst} + \sum_{i \in \mathcal{S}(\text{dst})} \mathbf{h}_i}{1 + |\mathcal{S}(\text{dst})|} $$

### 🔵 모델 구조

```
입력 비디오
    ├── 시각 프레임 → [CLIP 시각 점수화] → 프레임별 예산 배분
    │                    ↓
    │              AD-STC 프루닝
    │              ├── 앵커 프레임: DPC-KNN 밀도 선택
    │              └── 델타 프레임: 적응형 전략 (Eq.9-10 or c_i)
    │
    └── 오디오 세그먼트 → [내부 임베딩 점수화] → 초당 예산 배분
                              ↓
                        초당 BiSoft 토큰 병합 (Eq.11-12)
                              ↓
                    [시각 토큰 | 텍스트 | 오디오 토큰] → LLM
```

- **기반 모델**: Qwen2.5-Omni [7B, 3B]
- **시각 점수화**: CLIP ViT-L/14@336px (외부)
- **오디오 점수화**: OmniLLM 내부 오디오 인코더 임베딩 재활용
- **훈련 불필요(Training-free)**

### 🔴 한계점

1. **CLIP 고정 오버헤드**: 45% 유지 시 E2E 레이턴시가 FastV/OmniZip보다 높음 (5.284s vs. 4.508~4.584s) (Table 2)
2. **단일 백본 의존**: Qwen2.5-Omni에만 실험. 타 OmniLLM으로의 일반화 실험 부재
3. **디코딩 단계 미최적화**: QA 태스크에서 짧은 답변만 생성 → KV 캐시 최적화 미포함
4. **OmniSIFT 비교 불가**: 코드 미공개로 재현 불가 (p.9)
5. **오디오 점수화 모달리티 비대칭**: 시각은 외부 CLIP, 오디오는 내부 임베딩 사용 → 이질적 기준

## 5. 통계적 취약점 및 비교 불가 수치 ⚠️

| 항목 | 취약점 유형 | 설명 |
|------|------------|------|
| **벤치마크 수 (4개)** | 🔴 **표본 제한** | 4개 벤치마크는 OmniLLM 평가의 대표성 확보에 불충분 |
| **모델 규모 (7B, 3B)** | 🔴 **일반화 미검증** | 13B, 72B급 모델 또는 타 아키텍처(VITA, GPT-4o)에서의 검증 부재 |
| **OmniSIFT 비교 불가** | 🔴 **공정 비교 불가** | 코드 미공개로 재현 불가, OmniSIFT는 fine-tuning 기반이어서 training-free인 OmniScope와 직접 비교 자체가 불공정 (p.9) |
| **78.3% 통계** | 🟡 **데이터셋 제한** | DailyOmni 1,197쌍에서만 측정. 다른 도메인/데이터셋에서는 다를 수 있음 |
| **$\tau$ = 0.05 (온도 계수)** | 🟡 **민감도 분석 부분적** | $\tau_r$ 이외 오디오 하이퍼파라미터($\beta, \gamma, R, P$) 민감도 분석 없음 |
| **E2E 레이턴시** | 🟡 **조건 불균형** | OmniScope 45% E2E가 OmniZip 45% E2E보다 느림 (5.284s vs. 4.508s). CLIP 오버헤드 포함 시 단기 생성 시나리오에서 불리 |

| **정확도 소수점 단위 차이** | 🟡 **통계적 유의성 미검증** | 0.3~0.35포인트 차이에 대한 신뢰구간 또는 유의성 검정 없음 |

## 7. 가장 중요한 그림 5개 해석

### 📊 Figure 1 (p.2) — 교차 모달 현저성 불일치 동기 부여

**내용**: "After the whistle, what does the referee signal?" 쿼리에서, 오디오 중요도는 휘슬 소리(초반)에서 피크, 시각 중요도는 심판의 손 신호(후반)에서 피크.

**해석**:
- 오디오→비디오 가이던스: 오디오 피크 구간을 기준으로 비디오 압축 → 시각 답변(손 신호)이 손실됨
- 비디오→오디오 가이던스: 비디오 피크 구간 기준 오디오 압축 → 오디오 단서(휘슬)가 손실됨
- **모달리티 분리**: 양쪽 모두 독립적으로 쿼리 관련 토큰 유지 → 두 정보 모두 보존

이 그림은 논문의 핵심 동기를 직관적으로 시각화하며, 단방향 가이던스의 실패 모드를 명확히 보여준다.

---

### 📊 Figure 2 (p.4) — 어텐션 맵 변화: 압축이 크로스 윈도우 상호작용 강화

**내용**: Qwen2.5-Omni-3B Layer 3의 어텐션 맵. Full Token 설정에서는 대각선(로컬 윈도우) 집중, Random Pruning 후 비대각선(크로스 윈도우, 빨간 점선 박스) 영역이 강화됨.

**해석**:
- Softmax 정규화된 어텐션에서 토큰 수 감소 → 제한된 attention budget이 비대각 영역으로 재분배
- 이는 의도하지 않은 압축의 **부작용이 아닌 이점**으로 해석될 수 있음
- 그러나 단방향 가이던스로 잘못된 토큰이 남으면, 이 강화된 크로스 윈도우 어텐션이 오히려 부차적 단서에 집중되는 역효과 발생 → OmniScope의 모달리티 분리 설계 근거 제공

---

### 📊 Figure 3 (p.5) — OmniScope 전체 파이프라인 개요

**내용**: 3단계 파이프라인: (1) Query-Aware Scoring, (2) Vision Pruning (AD-STC), (3) Audio Merging.

**해석**:
- **좌측 (Query-Aware Scoring)**: CLIP 유사도와 E-norm 기반 오디오 점수를 쿼리에 대해 독립적으로 계산 → 토큰 예산 배분
- **중앙 (AD-STC)**: 짝수 프레임(앵커)은 DPC-KNN으로 공간적 독특성 유지, 홀수 프레임(델타)은 압축률에 따라 공간+시간 결합 또는 시간 차이만 적용
- **우측 (Audio Merging)**: 홀수/짝수 인덱스 분리 후 유사도 행렬로 병합 → 정보 손실 없이 토큰 수 감소
- 세 단계 모두 쿼리를 공유하되, 각 모달리티가 독립적으로 압축 결정 → 핵심 설계 원칙 구현

---

### 📊 Figure 4 (p.9) — 압축률별 안정성 분석 (Ablation)

**내용**: Qwen2.5-Omni-3B, WorldSense에서 $\rho_v$와 $\rho_a$를 각각 독립 변화시킨 정확도 곡선.

**해석**:
- **좌측** ($\rho_v$: 0.4→0.8): OmniScope는 전 범위에서 가장 높은 정확도, 가장 완만한 하강 곡선. OmniZip과 FastV는 $\rho_v > 0.6$에서 급격 하락
- **우측** ($\rho_a$: 0.15→0.55): 동일 패턴. OmniScope가 가장 graceful degradation
- ⚠️ **주의**: 이 그림은 WorldSense 단일 벤치마크에서만 측정됨. 다른 벤치마크에서의 패턴이 동일하다고 보장할 수 없음
- OmniScope의 디커플링 전략이 극단적 압축에서도 핵심 정보를 보존하는 능력을 가짐을 시각적으로 확인

---

### 📊 Figure 7 (Appendix F, p.17) — 교차 모달 현저성 상관관계 분포

**내용**: 1,197개 쿼리-비디오 쌍의 시각(CLIP)·오디오(CLAP) 중요도 점수 간 Spearman 상관계수 분포 히스토그램.

**해석**:
- 분포가 0을 중심으로 집중, 78.3%가 $|\rho| < 0.3$의 약한 상관
- 이는 단방향 가이던스의 전제(한 모달리티의 중요도가 다른 모달리티의 중요도를 대리함)가 근본적으로 잘못됨을 통계적으로 입증
- ⚠️ **통계적 주의**: DailyOmni 데이터셋 단일 분석이므로, 이 수치를 모든 OmniLLM 시나리오에 일반화하기는 어려움. 또한 CLIP과 CLAP을 외부 프록시로 사용했으므로, 실제 OmniScope 내부 점수화와는 다를 수 있음

## 8. 결론, 시사점, 후속 연구

### 8-1. 저자 제시 시사점 및 후속 연구 계획

**저자 시사점 (p.11)**:
- OmniLLM 추론의 핵심 설계 원칙: **"share the query across modalities, but not the salience estimates"**
- 훈련 없이도 cross-modal token compression이 가능하며, 모달리티 분리 설계가 핵심임
- 교차 모달 현저성 불일치는 단순 기술적 문제가 아닌 OmniLLM의 구조적 특성

**저자가 명시적으로 언급한 후속 연구**: 논문 본문에 명시적 후속 연구 방향은 기술되어 있지 않음. ⚠️ 억지로 지어내지 않음.

---

### 8-1-1. 모델의 일반화 성능 향상 가능성

논문에서 관찰된 일반화 관련 내용:

1. **하이퍼파라미터 고정 일반화**: Table 7의 하이퍼파라미터를 4개 벤치마크, 2개 모델 규모 전체에 **동일하게 적용**하고도 일관된 성능 달성 → 파라미터 민감도가 낮음을 시사

2. **모델 규모 일반화**: 7B와 3B 모두에서 OmniScope가 최고 성능. 단, 3B에서 성능 하락 폭이 더 큼 (25%: −1.50 vs. −0.35) → 소형 모델에서 표현 용량의 한계가 압축 취약성 증가와 결합됨

3. **도메인 일반화**: Table 6에서 WorldSense 8개 도메인 전반에 걸쳐 OmniScope가 가장 균형 잡힌 성능. OmniZip은 특정 도메인(Culture & Politics)에 편향됨

4. **시각 스코어링 일반화**: Appendix D (Table 8)에서 CLIP이 없어도 Self-Embed로 동작 가능하며, 7B에서는 성능 차이가 0.47포인트에 불과. 단, 3B에서는 0.8~0.93포인트 하락 → 모델 크기에 따른 내부 정렬 품질 의존성

**추가 분석자 제안 — 일반화 향상 방향**:

- **적응형 하이퍼파라미터**: $\tau, \beta, \gamma, R$ 등을 도메인 특성(오디오 에너지 분포, 장면 전환 빈도)에 따라 자동 조정하는 메타 학습 접근
- **범용 비주얼 스코어러 탐색**: CLIP 외 SigLIP, InternViT 등 OmniLLM의 내부 비전 인코더와 정렬이 더 잘 되는 스코어러 탐색
- **다국어 쿼리 일반화**: 비영어권 쿼리에서 임베딩 놈 기반 게이팅(Eq.4)의 동작 검증 필요

#### OmniScope가 연구에 미치는 영향

1. **패러다임 전환**: 단방향 교차 가이던스에서 **모달리티 분리 압축**으로의 패러다임 전환을 선언. 이는 향후 OmniLLM 효율화 연구의 설계 원칙으로 채택될 가능성 높음

2. **교차 모달 현저성 불일치의 실증**: 78.3% 통계는 이후 연구자들이 새로운 방법론을 설계할 때 반드시 고려해야 할 실증적 근거를 제공

3. **훈련 불필요 접근의 실용성 입증**: OmniSIFT와 달리 fine-tuning 없이도 경쟁력 있는 성능 달성 → 산업 배포에 유리

4. **비디오 압축 연구의 오디오 확장 촉진**: 기존 시각 전용 연구들이 오디오를 포함한 진정한 옴니모달 설정으로 확장해야 함을 시사

#### 앞으로 연구 시 고려할 점 (분석자 제안)

1. **멀티-스케일 토큰 예산**: 현재 프레임 레벨·초 레벨 예산 배분 외에, 개별 토큰 레벨 세분화와 윈도우 레벨 거시 조정을 결합한 **계층적 예산 할당** 연구 필요

2. **비전-오디오 스코어러 통일**: 현재 CLIP(외부)과 내부 임베딩을 각각 사용하는 이질성을 해결하기 위해, OmniLLM 자체의 **joint embedding space**를 활용한 통일된 스코어링 프레임워크 개발 권장

3. **스트리밍 압축**: 실시간 오디오-비디오 스트림에서 온라인으로 토큰 중요도를 추정하고 압축하는 **온라인 OmniScope** 변형 연구

4. **KV 캐시 압축 결합**: 현재 OmniScope는 프리필 단계만 최적화. **H2O**, **StreamingLLM** 등 KV 캐시 압축과의 결합으로 디코딩 단계까지 확장 가능

5. **다중 모달리티 확장**: 오디오-비디오 외 **IMU 센서, 깊이 카메라, 텍스트 문서** 등 추가 모달리티가 포함된 진정한 옴니모달 시나리오에서의 확장성 검토

6. **공정한 벤치마크 설계**: OmniSIFT 등 training-based 방법과 training-free 방법을 분리하여 평가하는 **표준화된 OmniLLM 효율화 벤치마크** 필요

7. **적대적 오디오-비디오 쌍 평가**: 불일치가 극단적인 케이스(예: 무음 비디오, 암흑 오디오)에서의 **엣지 케이스 강건성** 체계적 평가 필요
